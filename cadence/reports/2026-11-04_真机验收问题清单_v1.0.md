### P-001（测试配方，非产品缺陷）规格 §0 的掩码 PATH 配方挡不住 claude / codex

- **状态**：✅ 已定位，已在本机给出替代配方；**待 owner 在浏览器侧复跑 12.3 / 12.5 / 12.6 时使用替代配方**
- **性质**：**测试配方缺陷**。产品代码无问题；但若照规格 §0 原文执行，12.3 的「只装 pi 的机器」前提**不成立**，12.3 / 12.5 的判据会被污染。
- **现象**：规格 §0 写
  ```
  env PATH="/tmp/aria-accept/mask-pi/bin:/usr/local/bin:/usr/bin:/bin" ...
  ```
  但本机 `/usr/bin` 下存在全局 npm 软链：
  ```
  /usr/bin/claude -> ../lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe
  /usr/bin/codex  -> ../lib/node_modules/@openai/codex/bin/codex.js
  ```
  ⇒ 只要 PATH 里带 `/usr/bin`，**claude 与 codex 照样可解析**，「只装 pi 的机器」被破坏。
- **实测证据**（本机 `command -v` 实测）：
  ```
  env PATH="/tmp/aria-accept/mask-pi/bin:/usr/local/bin:/usr/bin:/bin" bash -c 'command -v claude'
  → /usr/bin/claude
  env PATH="/tmp/aria-accept/mask-pi/bin:/usr/local/bin:/usr/bin:/bin" bash -c 'command -v codex'
  → /usr/bin/codex
  ```
- **根因**：掩码用了「白名单 + 系统 PATH」的加法，而不是「纯白名单」。规格未察觉本机 `/usr/bin` 有 provider 的全局 npm 装。
- **替代配方（本会话已备好，owner 直接用）**：
  ```
  # 系统工具链白名单（不含任何 provider CLI）：/tmp/aria-accept/maskbin
  # provider 白名单目录：
  #   /tmp/aria-accept/mask-pi/bin    → pi, node, codegraph          （12.3 / 12.4）
  #   /tmp/aria-accept/mask-nopi/bin  → node, codegraph, claude, codex, kimi（12.5，无 pi）
  #   /tmp/aria-accept/mask-nocg/bin  → pi, node                      （12.6，无 codegraph）
  # 起实例时：
  env PATH="/tmp/aria-accept/mask-pi/bin:/tmp/aria-accept/maskbin" aria web --workspace <ws> --port 4319
  ```
  实测解析结果（`command -v`）：
  ```
  mask-pi   → pi=Y node=Y codegraph=Y claude=- codex=- kimi=- git=Y
  mask-nopi → pi=- node=Y codegraph=Y claude=Y codex=Y kimi=Y git=Y
  mask-nocg → pi=Y node=Y codegraph=- claude=- codex=- kimi=- git=Y
  ```
  `maskbin` 内含 57 个系统工具软链（git/sh/bash/coreutils 等），`git --version` 与 `sh` 在掩码下均正常。
- **建议修法**（若要回写规格）：规格 §0 的 PATH 改为 `<provider白名单>:/tmp/aria-accept/maskbin`，并补一句「本机 `/usr/bin` 含 claude/codex 全局 npm 装，不可直接放行 `/usr/bin`」。
- **优先级**：P2（不改产品，但不改配方会让 12.3/12.5 的结论无效）
- **复测范围**：12.3、12.5、12.6（用替代配方重跑即可）
