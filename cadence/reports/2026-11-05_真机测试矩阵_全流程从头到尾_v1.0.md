## 2. 阶段 A · 准备与受控环境

> 零消耗、零进程。**每个阶段做完记一行回执**。

### A-1 · 四家 provider CLI + codegraph 都在 PATH 上
- **原始编号**：阶段 0.3（2026-11-04 手册）
- **前置**：无
- **操作**：
  1. 开终端跑：
     ```bash
     for n in claude codex pi kimi codegraph; do printf '%s -> %s\n' "$n" "$(command -v $n || echo MISSING)"; done
     ```
  2. 记录四家版本号（后面 B-2 的「版本落后」判据要用）：
     ```bash
     claude --version; codex --version; pi --version; kimi --version; codegraph --version
     ```
- **要验收的点**：五个命令都解析得到、版本号有输出；四家 provider + codegraph 全装
- **成功判据**：五个名字全部有路径（无 `MISSING`）；四个版本号有具体数字（不是空）
- **失败判据**：任一命令 `MISSING`；或版本号命令报错/无输出
- **证据**：终端输出贴进回执
- **消耗**：零（各 CLI 的 `--version` 不消耗额度）

### A-2 · 两个夹具聚合根形态正确
- **原始编号**：阶段 0.1 / 0.2
- **前置**：无
- **操作**：
  1. 核对目录结构：
     ```bash
     ls -a /tmp/aria-accept/my-lc-root-nomarker/     # 应有 backend/ frontend/，【无】AGENTS.md、无 .claude/
     ls -a /tmp/aria-accept/my-lc-root-marker/        # 应额外有 AGENTS.md 与 .claude/rules/language.md
     git -C /tmp/aria-accept/my-lc-root-marker/backend rev-parse --is-inside-work-tree   # 期望 true
     git -C /tmp/aria-accept/my-lc-root-marker/frontend rev-parse --is-inside-work-tree  # 期望 true
     ```
  2. 确认聚合根本身**不是** git 仓：
     ```bash
     git -C /tmp/aria-accept/my-lc-root-marker rev-parse --is-inside-work-tree 2>&1 | head -1
     ```
     期望输出 `false`（或 fatal: not a git repository）。
- **要验收的点**：聚合根是普通空目录、成员仓是它的**直接子目录**且各自是 git 仓；marker 夹具两个判定文件都在
- **成功判据**：两条 `rev-parse` 对成员仓返回 `true`；对聚合根返回 `false`/fatal；marker 根下两个判定文件都在，nomarker 根下两个都不在
- **失败判据**：成员仓在聚合根**二层**（根/x/成员）；或聚合根本身是 git 仓；或判定文件只放了一个
- **证据**：命令输出贴回执
- **消耗**：零

### A-3 · 三套掩码 PATH 自检（纯白名单）
- **原始编号**：12.3 / 12.5 / 12.6 的环境前置；问题清单 P-001
- **前置**：无（只读命令，不改任何全局 PATH）
- **操作**：逐套跑自检（**注意是纯白名单，不加 `/usr/bin`**）：
  ```bash
  for m in mask-pi mask-nopi mask-nocg; do
    echo "== $m"
    for n in pi claude codex kimi codegraph node git; do
      printf '  %s -> %s\n' "$n" "$(env PATH=/tmp/aria-accept/$m/bin:/tmp/aria-accept/maskbin bash -c "command -v $n" 2>/dev/null || echo -)"
    done
  done
  ```
- **要验收的点**：掩码**真的**挡住了不该有的 provider CLI
- **成功判据**（逐字对照下表）：
  | 掩码 | pi | claude | codex | kimi | codegraph | node | git |
  |---|---|---|---|---|---|---|---|
  | mask-pi | 有 | 无 | 无 | 无 | 有 | 有 | 有 |
  | mask-nopi | 无 | 有 | 有 | 有 | 有 | 有 | 有 |
  | mask-nocg | 有 | 无 | 无 | 无 | **无** | 有 | 有 |
- **失败判据**：mask-pi 里 `claude`/`codex` 解析得到（本机 `/usr/bin` 有全局 npm 软链，加 `/usr/bin` 就会漏）；或 mask-nocg 里 codegraph 解析得到
- **证据**：自检输出贴回执
- **消耗**：零（不启动任何实例）
