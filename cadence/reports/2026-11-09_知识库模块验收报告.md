## 4. 未在本环境验证的部分（诚实声明）

| 项 | 原因 | 覆盖方式 |
|---|---|---|
| 真正跑一次 `/knowledge-base-bootstrap` 与 `/knowledge-base-update` | 本机 provider 未核验（`needs_verification`），且真实执行会消耗 provider 额度、调用真实 LLM；前端确认框在无头环境被自动接受，无法代表真实交互 | 代码路径由单元/集成测试覆盖（command 文本、preflight、变更包门禁 P1–P9、写入面审计、单飞）；真机需 owner 核验 provider 后手动点一次 |
| 变更包模板创建 + 逐字段门禁的真实界面走查 | 需要一份填好的变更包 | `change_package.rs` 25 条门禁用例 + `templates.rs` 模板创建/不覆盖/幂等用例覆盖 |
| 7 个知识库 skill 的真实可用性（`skills_available=true`） | 本机未安装 Cadence-skills | `preflight.rs` 用例覆盖「缺任一 skill ⇒ 失败」 |

## 5. 验收中发现并已修复的缺陷

| 缺陷 | 修复 |
|---|---|
| `GET /knowledge-base/initializations/{id}` 对未知 id 返回 **500** | 改用 `knowledge_base_store_api_error` ⇒ 404 + `knowledge_base_operation_not_found`（commit `01bbcb4e`） |
| 知识库集成测试**并行挂死**（`cargo test --test it_web knowledge_base_http` 永久挂住，CI 阻塞） | 根因是测试夹具的 health 快照 TTL=1s 导致选择链每次都 refresh、持 `refresh_lock` 跨 `tokio::fs` 让出，与 poll 内同步 `join` 构成三元死锁；改为预刷快照（generation≥1、degraded=false、checked_at=now），全程零 refresh。回归用例 `concurrent_status_and_create_do_not_deadlock`（无修复版 exit=124 可复现） |
| 知识库失败面显示**英文原文** | 改走 `failure_copy` 中文成品文案（commit `b1bad131`），`code` 与 `details` 保持透出 |
| 四个聚合 provider 选择失败码未登记 HTTP 状态 ⇒ 落 **500** | 登记为 422（commit `880a86c8`）；同时让聚合初始化面受益 |
| `cargo clippy -D warnings` 因本需求代码失败（7 条） | 全部修复（commit `fd732d93`） |
| `tests/it_core/large_file_guard` 因并发会话的 `ProviderCapabilityCard.test.tsx`（1238 行）报红 | 拆分该测试夹具（commit `fd194fb6`），主文件 992 行 + 新夹具 268 行 |

## 6. 遗留与后续（交 owner 排期）

| 项 | 说明 |
|---|---|
| 生产侧 `select_aggregate_provider_blocking` 在 async 任务里同步 `join` | 与聚合初始化同款反模式（非本需求引入），多线程 runtime 下危害有限；建议后续改为独立线程承载 |
| 知识库 turn 持 `.aggregate-index.lock` 最长 1800s | 运行期隔离的代价；turn 开始会等在跑的索引重建 |
| 变更包语义门禁（Diff/DDL/快照指纹/影响链） | 由 Cadence-skills 的 skill 门禁判定，平台只做机械可判定子集 |
