## 实现

- **`web/src/api/client.ts`**：`DeleteLifecycleEntityOptions {confirmed?:boolean}`；
  `deleteStorySpec`/`deleteDesignSpec`/`deleteWorkItemPlan` 增第 4 参——默认 URL 无
  query，`confirmed===true` 才经 URLSearchParams 追加 `?confirmed=true`（§0.2：query
  不是安全授权，服务端三分类权威）。`deleteWorkItem`（独立 WI）与
  `deleteCodingAttempt` 原签名不动。
- **`web/src/components/lifecycle/IssueLifecycleWorkbench.tsx`**：
  `handleDeleteLifecycleCard` 删除请求改为显式可二次调用的 `sendDelete(options)` 闭包
  （非预创建 Promise）；首删无 query，唯一弹窗分支 `ApiRequestError.code ===
  "deletion_confirmation_required"`（ApiRequestError code/details 为权威，不做前端
  确认历史判断），弹窗文案「确定永久删除？此操作将永久清除内容、工作项、会话和
  review，且不可恢复。」；同意后第二 delete 带 `{confirmed:true}`；取消零出站破坏
  请求、无 refresh/clear selected/closeDrawer/退场（finally 仅复位 deletingCardKey）。
  coding/reference/busy 等其余错误沿原 `errorMessage` 模式直达错误面（服务端
  message 即「先删后置/等待收口」提示），零弹窗、不自动重试。成功路径沿原
  exit-animation+refresh 模式。`handleDeleteLifecycleCardFromDrawer`：group 移除旧
  无条件确认（Story/Design/group 同走服务端单次确认流，不双弹）；独立 WI 保原一次
  本地确认，文案改为不再声称自动删除 Coding Workspace（存在时服务端
  `coding_workspace_exists` 拒删）。
