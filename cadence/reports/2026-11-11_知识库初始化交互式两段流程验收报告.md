## 1. 起因（用户反馈的真机事实）

用户在 LC `aggregate-root`（`logical_codebase_cdb436b146e14b1aaa67d0ce81d6c8be`，Pi provider）跑完起草后，界面停在卡片上的「completed / prepare_user_input / 本次使用 Pi」——**没有任何下一步入口**：不知道要去补充 9 份 `user-input` 文件，也不知道确认后怎么建库。9 份文件已生成但 0 份已确认（`GET /knowledge-base/user-input` ⇒ `confirmed_count=0/9`）。

用户给出的五步目标：①先看 `user-input` 有无内容，没有就调 `knowledge-base-user-input` 起草 → ②起草完成后打开这些文件让用户补充（打开方式同【查看知识库详细内容】）→ ③引导用户怎么改、尤其哪些要确认 → ④改完点确认按钮即调用 `knowledge-base-bootstrap` → ⑤最后落到【查看知识库详细内容】页继续改，以用户修改为准。

## 4. 验收中发现并已修复的既有缺陷

| 缺陷 | 现象 | 修法 |
|---|---|---|
| **工作台抽屉焦点同步把跨路由导航顶回工作台** | 点【查看知识库详细内容】/【打开输入文件并补充】后，地址先 push 到知识库详情页、随即被 `replace` 回 `/workbench` ⇒ 详情页进不去（**既有缺陷**，与本 change 无关，但卡住了整个流程） | `router.tsx`：`syncDrawerFocus` 只在「当前路由就是 `/workbench`」时写地址；`navigate` 用 ref 固定，避免回调身份随位置变化导致下游 effect 重跑 |
| 起草完成后无下一步入口 | 卡片停在「completed」，用户无从下手 | 卡片 CTA + 起草完成自动跳转 |
| 详情页确认区无引导 | 只有一行计数 | 四步指引 + 进度 + 未填阻塞说明 |
| 确认与建库分离 | 确认完还要回卡片再点一次初始化 | 【确认并初始化】= 批量确认 + 立即建库 |

## 5. 未在本环境执行的部分（诚实声明）

| 项 | 原因 | 覆盖方式 |
|---|---|---|
| 点【确认并初始化】后**真实跑一次** `/knowledge-base-bootstrap` | 会真实调用 Pi provider、消耗用户额度；且会覆盖用户正在补充的输入文件 | 组件测试断言「先批量确认（携带当前 digest）→ 再创建 bootstrap operation（kind=bootstrap）」；建库链路由后端既有契约保证。**由 owner 在自己的节奏里点一次**才算真机证据 |
| 确认过期（409）在真实并发编辑下的表现 | 需要两个客户端同时改同一份文件 | 组件测试断言「确认失败不发起建库 + 提示可执行文案 + 刷新投影」 |
