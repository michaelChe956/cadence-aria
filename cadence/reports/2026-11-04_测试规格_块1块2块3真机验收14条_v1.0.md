**隔离 PATH 白名单目录做法（只影响服务进程，不动全局 PATH）**：

```bash
# ① 造白名单目录（/tmp 下）

ln -sf "$FNM/pi"        /tmp/aria-accept/mask-pi/bin/pi
ln -sf "$FNM/node"      /tmp/aria-accept/mask-pi/bin/node
ln -sf "$FNM/codegraph" /tmp/aria-accept/mask-pi/bin/codegraph   # 12.4 需要；见各条说明
# ② 造隔离工作区（服务数据根 = 进程 CWD/.aria）
mkdir -p /tmp/aria-accept/ws-pi
# ③ 用隔离 PATH 起独立实例（4319；二进制用绝对路径，不受掩码影响）
cd /tmp/aria-accept/ws-pi && \
env PATH="/tmp/aria-accept/mask-pi/bin:/usr/local/bin:/usr/bin:/bin" \
  ARIA_API_TRUSTED_ORIGINS="http://127.0.0.1:5173,http://localhost:5173" \
  /home/michaelche/workspace/github/cadence-aria/.worktrees/bugfix-b-11-02/target/debug/aria web --port 4319
# ④ 前端 dev server（单独进程，用正常 PATH，代理指向 4319）
cd /home/michaelche/workspace/github/cadence-aria/.worktrees/bugfix-b-11-02/web && \
ARIA_E2E_PORT=4319 pnpm dev     # 访问 http://127.0.0.1:5173
```

**复原 = 三步，无全局改动可回滚**：停掉 4319 实例与 vite → `rm -rf /tmp/aria-accept/mask-pi /tmp/aria-accept/ws-* /tmp/aria-accept/agg-*` → 全局 PATH 从未被改（掩码只发生在 `env PATH=…` 那一条命令的进程树里）。
注意事项：① curl 直连 POST 需带 `Origin: http://127.0.0.1:5173` 头，否则 403 `forbidden_origin`（白名单按设计生效，《验收报告》§1 已实测）；② provider 健康快照有 10 分钟条件刷新（块2 tasks 1.2），**改完掩码后若界面仍显示旧可用性，点失败面上的「重新检测」**（`POST /api/providers/recheck`，实现：`BootstrapFailureLine.tsx:165-178`）。
