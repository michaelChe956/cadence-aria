## 5. 交付过程中被审查拦下并已修复的问题

| 问题 | 修复 |
|---|---|
| 12 个知识库端点只有 2 个有前置门，其余 10 个可在冷启动未完成时读写 | 统一门（`knowledge_base_read_context` + create 内单独门），12/12 覆盖，失败 422 + 稳定码 + 中文文案 + `details.bootstrap_step`；零写副作用有测试钉住 |
| 前置口径用「根规则文件 + 政策 artifact」两文件判定，与冷启动投影口径不一致 | 统一到冷启动投影的「规则/政策」步 completed（旧判定删除，不并存两套口径；测试用负例锁定） |
| 起草 operation 无处安放（枚举穷尽 match 编译不过） | 新增 `UserInput` kind + `PrepareUserInput` 步 + `user_input_command`，旧记录反序列化实测仍成功；写入面审计收窄为 `cadence/knowledge-base/user-input/**` |
| 变更包从未扫描 `attachments/`（最易带连接串/口令） | 附件扫描纳入 P6；子目录与不可枚举目录**显式记违规**而非静默跳过；不回显命中值 |
| 机器管理文件（manifest.yaml 等）在详情页可写可存 | 按 `editable` 只读呈现：不传 `onChange`、保存禁用 + 兜底零写请求、显示「机器管理文件，只读」 |
| 卡片零轮询 ⇒ 运行中终态最长 1800s 不上屏 | `running` 时每 2s 轮询，复用既有 revision/过期守卫，终态/收起/卸载清理 |
| 失败面绕过文案单一来源（同一码三套文案，其中一份描述已删除的旧判据） | 门 message 改走 `failure_copy`；码表条目改写为新口径并补恢复路径；两个新稳定码登记状态映射（422/409） |
| 详情页 Monaco 折叠文件树时被 `key` 强制重挂载（清空撤销栈、打断输入法） | 删除 `key`（`@monaco-editor/react` 默认已开 `automaticLayout`） |
| `coordinator_tests.inc.rs` 1230 行超门禁 | 拆为 1088 + 147 两个片段 |
