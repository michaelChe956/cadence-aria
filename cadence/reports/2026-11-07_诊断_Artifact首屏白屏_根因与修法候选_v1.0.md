## 1. 一句话摘要

**现象**：owner 报「Artifact 会出现白屏的情况，刷新之后才会出现」；**根因**：产物正文的渲染器 monaco 走 `@monaco-editor/loader` 的默认 CDN 懒加载，在资源就绪的加载窗口内 `ViewerSkeleton` 只渲染一个**没有任何文字的空 div**，于是用户看到的是「有外壳、无正文、无任何提示」的空白区，而刷新后 CDN 命中缓存使该窗口塌缩；**本报告给出的是定位结论与四条修法候选，未实施任何修改**。

## 2. 现象与实测证据

### 2.1 报障原文

`cadence/notes/2026-11-03_问题记录_四问题清单_Artifact白屏_节点详情404_group禁手动_codex技能错位_v1.0.md:19`：

> Artifact 会出现白屏的情况，刷新之后才会出现。

### 2.2 A 类：有 artifact，但首屏存在约 365ms 的空窗且零提示（本次主诉）

**会话**：`workspace_session_0011`（design_spec_0002，状态 confirmed，存在 artifact v1/v2）。
**实测方式**：内置浏览器点开「产物审核」页签后，对产物面板以 **16ms 间隔采样，共 70 个采样点**，记录面板 `innerText` 长度与关键 DOM 存在性。

> **前置事实**：产物审核面板**是点开「产物审核」页签才渲染**的 —— 页面加载完成后 DOM 中**不存在** `[data-testid="artifact-review-panel"]`。因此「首屏白屏」只可能发生在**点开页签之后**，而不是页面初始加载时。

#### 采样时间线（节选关键采样点）

| 采样时刻 | 面板 `innerText` 长度 | 内容判定 | 状态 |
|---|---|---|---|
| t+31ms | **51** | 含「正在加载 v2」字样（版本头 + 加载提示仍在） | 尚未进入空窗 |
| t+77ms | **43** | **只剩头部，正文区为空骨架**（无任何正文文字） | ★**白屏窗口开始** |
| t+375ms | **47** | 仍只有头部 + 极少量文字，正文未渲染 | ★**白屏窗口持续** |
| t+396ms | **950** | monaco 就绪，正文（markdown 全文）渲染 | 白屏窗口结束 |

- 空窗区间：**t+77ms → t+396ms**，即 **约 365ms**（以 t+31ms 为起点计约 365ms，与下述采样一致）。
- 渲染完成后长度从 47 跃升到 950 ⇒ 空窗期**确实没有正文**，不是「正文太短看不见」。

#### 空窗期的状态判定（关键：不是「无产物」，是「壳在、正文区空、零提示」）

| 判定项 | 空窗期实测 | 含义 |
|---|---|---|
| `waiting` 状态（含「等待 Artifact」兜底） | **false** | 前端**没有**把用户引导到「等待 Artifact」这一兜底态 |
| `artifact-unavailable` 卡片 | **不存在** | 前端**没有**给出「内容未加载」这一错误/空提示 |
| 结论 | — | ★**壳在、正文区空、零提示** —— 这正是「白屏」的观感来源 |

#### 网络行为

- 点开页签时发出 **两次** `GET /api/workspace-sessions/workspace_session_0011/artifact-versions/2`，**两次均返回 200**。
- ⇒ **正文数据本身取得到、也取到了**；白屏与「后端没数据/接口失败」无关。

### 2.3 B 类：本来就没有 artifact（正常空态，**不是**本次白屏）

**会话**：`workspace_session_auto_09be5642-…`（状态 failed，无 artifact）。

| 观测项 | 实测 |
|---|---|
| 点开后面板 `innerText` 长度 | **48**（内容为「Artifact / 版本 v0 / 显示 Diff / 折叠 Artifact / 1 / 等待 Artifact」） |
| `GET .../artifact-versions/0`、`/1`、`/2` | **全部 404**，错误码 `artifact_version_not_found` |
| 判定 | ★**正常空态**：本来就无 artifact，界面显示「等待 Artifact」提示 |

### 2.4 ★ A 类与 B 类的区分（不得混为一谈）

| 维度 | **A 类：白屏（本次主诉）** | **B 类：正常空态** |
|---|---|---|
| 是否存在 artifact | **存在**（v1/v2，confirmed） | **不存在** |
| 正文接口 | `artifact-versions/2` **200** | `{0,1,2}` **全 404** |
| 面板文案长度 | 43 → 47 → 950 | 恒为 48 |
| 是否有「等待 Artifact」提示 | **无**（`waiting=false`） | **有** |
| 是否有 `artifact-unavailable` | 无 | 无（走的是「等待」兜底，不是错误卡） |
| 是否本次问题 | ★**是** | 否，属正常语义 |

> **结论**：两类空白在**观感上都「偏空白」**，但根因完全不同。修 A 类**不得**用 B 类的语义去套（例如不得把「等待 Artifact」兜底当作 A 类的解释），也不得用「无 artifact ⇒ 空态正常」来否定 A 类。

## 3. 根因链（代码级事实，逐条带 文件:行号）

### 步骤 1：monaco 没有被打进前端 bundle

| 事实 | 证据 |
|---|---|
| 依赖里声明了 monaco | `web/package.json:19` → `"monaco-editor": "^0.55.1"`；`web/package.json:14` → `"@monaco-editor/react": "^4.7.0"` |
| 但**没有任何源码直接引入 monaco 本体** | `grep -rn 'from "monaco-editor' web/src` ⇒ **0 命中** |
| 也**没有配置 loader 指向本地** | `grep -rn "loader.config" web/src` ⇒ **0 命中** |

⇒ 结论：**`monaco-editor` 这个包被声明为依赖，但实际走的是 CDN 版本**，本地 node_modules 里的那份从未被打包。

### 步骤 2：因此落到 `@monaco-editor/loader` 的默认 CDN 配置

`@monaco-editor/react@4.7.0` 依赖 `@monaco-editor/loader@1.7.0`（`web/pnpm-lock.yaml:2018-2021`）。loader 的默认配置：

```
node_modules/.pnpm/@monaco-editor+loader@1.7.0/.../lib/es/config/index.js:3
→ vs: 'https://cdn.jsdelivr.net/npm/monaco-editor@0.55.1/min/vs'
```

⇒ 未做 `loader.config` ⇒ **运行时从 jsDelivr CDN 拉取 monaco**。

### 步骤 3：monaco 未就绪期间，正文区渲染的是**无文字空 div**

`web/src/components/shared/MonacoViewer.tsx`（★实测路径在 `components/shared/` 下，不在 `components/chat-workspace/` 下）：

- `:4-6` —— `Editor` 用 `lazy(() => import("@monaco-editor/react"))` 懒加载；
- `:22` —— `<Suspense fallback={<ViewerSkeleton height={height} />}>`；
- `:27` —— `<Editor ... loading={<ViewerSkeleton height={height} />}>`；
- `:47-55` —— `ViewerSkeleton` 本体：

```tsx
function ViewerSkeleton({ height }: { height: string }) {
  return (
    <div
      data-testid="monaco-viewer-skeleton"
      style={{ height }}
      className="animate-pulse rounded-md border border-[var(--aria-line)] bg-[var(--aria-panel-muted)]"
    />
  );
}
```

★**这个骨架只有高度与背景色，没有任何文字节点**。
⇒ **Suspense 兜底（chunk 还没下载完）与 monaco 自身的 loading（CDN 资源还没就绪）两个阶段，渲染的都是同一个「无文字空 div」**。

### 步骤 4：正文区**就是** monaco，没有第二套渲染路径

- `web/src/components/chat-workspace/ArtifactPane.tsx:292` —— `<MonacoViewer value={markdown} language="markdown" height="100%" />`（正文分支）；
- `web/src/components/chat-workspace/ArtifactPane.tsx:277` —— `<MonacoDiffViewer .../>`（仅「显示 Diff」分支才挂载）。

⇒ 在 monaco 就绪之前，正文区**没有别的内容可显示**，骨架就是全部。

### 步骤 5：CDN 本身可达，不是「加载失败」而是「加载有窗口」

```
curl https://cdn.jsdelivr.net/npm/monaco-editor@0.55.1/min/vs/loader.js
→ HTTP 200，耗时 0.87s，39848 bytes
```

⇒ CDN 可达；问题是**首次访问需要一次网络往返**，而不是不可用。

### 步骤 6：刷新后缓存命中 ⇒ 窗口塌缩 ⇒ 「刷新之后才会出现」

- 首次进入：需从 CDN 取 monaco ⇒ 存在加载窗口 ⇒ 看到空白骨架；
- 刷新后：浏览器缓存命中 CDN 资源 ⇒ 加载窗口大幅缩短甚至消失 ⇒ **看起来「刷新之后才有内容」**。

> ⚠️ **诚实标注**：上述「首次 = CDN 往返、刷新 = 缓存命中」是**代码事实 + 网络实测 + 现象吻合**的**推断**；**精确的 365ms 构成（懒加载 chunk 约 15KB vs CDN `vs/editor/editor.main`）未做浏览器侧计时**，见 §7。

### 3.7 因果链合流

```
monaco 未打进 bundle（步骤1）
  → loader 默认 CDN（步骤2）
    → monaco 就绪前渲染「无文字空骨架」（步骤3）
      → 正文区本身就是 monaco，无兜底内容（步骤4）
        → CDN 可达但首次有往返 ⇒ 存在数百毫秒窗口（步骤5）
          → 空窗期 waiting=false、artifact-unavailable 不存在 ⇒ 用户看到「零提示白屏」
            → 刷新后缓存命中 ⇒ 窗口塌缩 ⇒ 「刷新后才有」（步骤6）
```

★**与实测的吻合点**：空窗期**没有任何提示**（`waiting=false`、`artifact-unavailable` 不存在）—— 这与「后端没数据」「接口报错」都会触发的**有提示态**截然不同，恰好指向「组件本身在渲染、只是渲染了一个空骨架」。

## 5. 待裁的修法候选（★**不替 owner 拍板**，按「信息量 / 成本」列出）

### 5.0 判定依据（仓内规则）

- `rule://openspec-superpowers-workflow` 第四节「OpenSpec 强制阈值与豁免」：
  - **阈值**：新功能、行为变化、公共接口或数据变化、跨模块重构、架构或验收变化 ⇒ **必须**使用 OpenSpec；
  - **豁免**：纯问答、只读调查、无语义文档修正可不使用；**恢复已有明确契约的小型 Bug 默认不建新 change**，但仍必须 systematic-debugging、TDD 和验证；
  - **无法判断是否达到阈值时，停止并向用户说明分歧点**。
- `AGENTS.md:28` 铁律：达 OpenSpec 阈值（新行为 / 公共契约 / 验收边界变化）先 `brainstorming` → OpenSpec；**无已确认 Plan 不改实现**；TDD 先失败测试。
- 若走实施：需 `brainstorming` → `openspec-propose`（proposal/design/specs/tasks）→ `writing-plans`（Plan 落 `cadence/plans/`）→ `test-driven-development` → 实施 → 验证。

| **是否需走 OpenSpec？** | **倾向「不需要新建 change」**：属于「恢复已有明确契约的小型 Bug」的豁免范畴（呈现层加提示，不改公共契约、不改数据、不改架构）。**但需 owner 先确认一件事**：现有 spec/验收里是否已存在「产物审核面板首屏应给出加载反馈」这类 requirement ——<br>· 若**已有** ⇒ 走**既有契约的实现补齐**（systematic-debugging → TDD → 验证），必要时对既有 spec 做 `openspec-sync-specs` 措辞同步，不新建 change；<br>· 若**没有**、且要把它写成新的 MUST 验收条款 ⇒ 则**已达「验收边界变化」阈值**，需新建 OpenSpec change（brainstorming → propose）。★此处存在规则分歧点，按规则应向 owner 说明而非自行拍板 |
| **连带面** | `MonacoViewer` / `MonacoDiffViewer` 被 **5 个生产文件**使用（清单见 §5.6）。骨架文案改动会体现在**所有**这些位置的加载期 ⇒ 视觉一致性需一并检查（尤其 `WorkItemPlanArtifactContent.tsx` 的 JSON 视图与 `RevisionDiffView.tsx` 的 420px 固定高度容器） |
| **风险** | 低。风险点：① 提示文字自身造成布局跳动（`ArtifactReviewPanel` 明确要求「唯一滚动交给 Monaco 渲染区」，测试 `ArtifactReviewPanel.test.tsx:86` 断言面板内**不得出现**原生滚动容器 `overflow-auto/overflow-scroll`）⇒ 提示必须是**纯文本行**，不能自带滚动容器；② 文案要与 §2.2 的「等待 Artifact」兜底语义**区分**，避免与 B 类空态混淆；③ 文案不得承诺时长（无法稳定保证） |

### 5.3 候选 (c)：monaco **本地化**（打进 bundle 或 `loader.config` 指向本地） —— **治窗口不治观感**

| 字段 | 内容 |
|---|---|
| **改哪层** | 构建/配置层 + 加载层。`web/src/components/shared/MonacoViewer.tsx`（或新增统一 loader 配置文件）设 `loader.config({ paths: { vs: <本地路径> } })`；或改 `web/vite.config.*` 把 `monaco-editor` 纳入 bundle（含 worker 打包等配套配置） |
| **代价** | 中。前端包体积显著增大（monaco 本体通常数 MB 量级）；worker / `vs` 资源打包配置有坑位；首次加载成本从「按需 CDN」转移到「首屏包体」⇒ **首屏反而可能更慢**（加载的是主 bundle） |
| **owner 可见行为变更？** | **是**（首屏加载表现、包体大小、首字时间） |
| **是否需走 OpenSpec？** | **建议走（达阈值：行为变化 + 验收边界变化）**。若只当作「构建配置修复」，可援引「恢复已有明确契约的小型 Bug 默认不建新 change」，但由于**首屏加载表现与包体属于 owner 可见行为**，且可能触及既有性能验收 ⇒ **倾向新建 OpenSpec change**（至少要写进既有 spec 的验收条款）。★同样存在「是否已有对应 requirement」的判断分歧点 |
| **连带面** | 见 §5.6。**关键**：该配置是**全局**的 —— 一旦设 `loader.config`，**所有** `MonacoViewer` / `MonacoDiffViewer` 使用点同时从 CDN 切本地 ⇒ 影响面比 (a)、(b) 都大；同时**离线 / 内网环境**会从「不可用」变成「可用」（附带收益） |
| **风险** | ① 包体膨胀可能反过来恶化首屏（**未必**能让「白屏窗口」变小，因为窗口从「按需 CDN 往返」变成「主 bundle 下载」）；② monaco worker 与资源路径配置错误 ⇒ 运行时报错；③ 需要处理 CSP / 静态资源路径；④ **不解决「骨架无文字」这一观感根因** —— 若只做 (c) 而不做 (a)，加载窗口内仍是零提示空 div |

### 5.5 ★ 独立缺陷候选（与白屏**分开立项**）：`MonacoViewer` 只渲染可见行 ⇒ 长文档截断显示

| 字段 | 内容 |
|---|---|
| **现象** | monaco 采用虚拟化渲染，DOM 中只保留**可见行**；`MonacoViewer.tsx:34` 另设 `scrollBeyondLastLine: false`。★**推论**：任何依赖「读取 DOM 全文」的路径（导出、复制、全文检索、外部校验、文本比对）只能拿到**截断文本**；长文档的完整内容在视图里也不易一次看全 |
| **是否独立缺陷？** | ★**是，建议独立立项**。它与首屏白屏**不同根因**：白屏是「加载窗口 + 无提示骨架」，截断是「虚拟化渲染 + 全文不可达」。两者恰好会被 (b) 一并消解，但**在 (a)/(c) 路径下截断依然存在** |
| **是否本轮一并处理？** | ★**由 owner 裁定**。建议：<br>· 若选 (b) ⇒ 截断**顺带解决**，无需单独立项；<br>· 若选 (a) 或 (c) ⇒ 截断**需单独立项**（可与白屏同批但**不同 requirement**，避免验收条款互相掩盖） |
| **证据强度** | ⚠️ **本条为代码结构推断，未做浏览器侧实测**（未构造超长 artifact 并验证 DOM 行数/复制结果）⇒ 见 §7 |
| **改动面** | 若单独立项：`web/src/components/shared/MonacoViewer.tsx`（选项层：`scrollBeyondLastLine`、是否开启全文渲染/虚拟化策略），以及 `web/src/components/shared/MonacoDiffViewer.tsx` 的对应行为；是否需要「导出全文 / 复制全文」能力属**新功能**，按规则须走 `brainstorming` → OpenSpec |
