## ① owner 现象与根因链（proposal.md 磁盘实证）

真机现象（owner 2026-11-06）：同一 issue 建 WIG#1 → 删 WIG#1 → 建 WIG#2 →「启用自动化」里把 Reviewer 从 pi 改成 codex ⇒ 409 `automation_enrollment_conflict`，前端文案「重新开启的自动化授权与终止记录不一致（原授权源仍有效但与当前不同）：请先通过自动化控制面执行『换代 / 重新绑定（rebind）』…」。

根因链：
1. 登记按 (project, issue) 唯一（`src/product/issue_automation_store.rs:59-70`），无 WIG 主键；
2. 删除 WIG 只调 `terminate_plan`（写 enabled=false/terminated_at/revision+1），source/target/binding/plan_id 原样保留 ⇒ 终止记录仍指向已删 plan ⇒「绑定实体已删」进入悬空源重授权路径；
3. 悬空源路径上 options（含 provider）漂移被拒（`cas_internals.inc.rs` 漂移分治：options 漂移仅在悬空源路径构成拒绝条件）⇒ 旧登记被新 WIG 继承 ⇒ 换 provider 被堵死。

## ⑦ concerns

1. **有没有任何路径能绕过「删除工作项组」产生作废态？**——没有。全仓 `voided_at = Some` 的生产写入仅 `void_enrollment_for_deleted_plan` 一处；该命令只被 `deletion.rs::void_enrollment_after_plan_deletion` 调用（两处调用点：⑩ complete 之后、Deleted 墓碑重入——后者是前者的崩溃窗口收敛，语义仍是「删除已成功之后」）。`supersede_terminated_enrollment` 只把 `voided_at` 清为 `None`（换代，不产生作废态）。测试夹具的直写仅存在于 `#[cfg(test)]` 模块。
2. 作废的 `NotBoundToPlan` 判定用 `enrollment.plan_id == 被删 plan`：未绑定（None）或绑定他组的登记不作废——不会误伤新 WIG 的新登记。
3. `enabled+作废` 是不可达组合（删除路径必先终止/禁用）；即便出现，Enable 仍走 PayloadImmutable fail-closed，不经放行分支。
4. 6.3 真机验收（建 WIG→删→新建→换 provider 一次完成等 5 项）留给 controller，本报告全部证据是测试台/构建台实跑输出。
5. 悬空判定口径（REQ-DRG-18「只判存在性」）、「执行中禁删」现状（①.5 自动终止、失败才 409）、「销账不删 enrollment」均零改动。
