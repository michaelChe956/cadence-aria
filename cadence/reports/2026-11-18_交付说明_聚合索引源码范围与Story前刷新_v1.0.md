# 交付说明：聚合索引源码范围判定 + Story 前共享索引刷新 · v1.0

**分支**：`feat/aggregate-index-source-scope`（基于 `origin/main`）　**交付形态**：PR，**不合 main**

## 一、起因（用户原始问题）

逻辑代码库里混着**纯配置仓**（只有 `.json`/`.md`，没有源码）。原规则要求「每个成员仓至少 1 个可索引代码文件」，于是 **1 个配置仓就让整库聚合索引构建失败** → 冷启动不 ready → 规划被挡住 → 其余几十个有源码的仓全部不可检索。页面只显示一串英文机器串，看不出原因。

## 二、交付的三项用户可见行为

| # | 行为 | 落地位置 |
|---|---|---|
| 1 | **配置仓不拖垮整库索引**：索引未收录时做一次有界盘检，确认无源码 ⇒ 跳过该成员（**只跳过代码检索**，仓仍是成员、仍可选为目标仓）；卡片显示「已跳过无源码成员：X。」 | `aggregate_index/source_scan.rs`、`operation.rs`（交叉验收）、`types.rs`（`skip_reason`）、`failure_copy_table.inc.rs`（码表）、`web/handlers/aggregate_index.rs` + `AggregateIndexCard.tsx` |
| 2 | **每次生成 Story 前先更新共享索引**：无索引 ⇒ 建库；**仅 `Active` 世代**且四条判据成立 ⇒ 复用；有变化或不能确认没变（含两次都脏）⇒ 增量同步 + 重新验收；失败 ⇒ **停在 AI 启动前**并给稳定码 + 中文三段成品（外层 `aggregate_index_unavailable` ⇒ 422）。**不新增后台轮询**；Design/WorkItemPlan/续接维持 LKG + 告警 | `story_index_refresh.rs`、`freshness.rs`、`planning_context_resolver.rs`、`web/handlers/lifecycle.rs` |
| 3 | **改配置不靠 CodeGraph**：配置仓作目标时不发起任何 CodeGraph 查询（200 + 显式 `not_searched: {code, message_zh}` + 预算照算 + 审计记零命中与原因）；选仓行标注「未纳入代码搜索，可修改配置或文档」，**仍可勾选提交** | `evidence_mediator.rs`、`evidence_not_searched.inc.rs`、`evidence_audit.rs`、`logical_codebase_members.rs`、`CreateLifecycleIssueDialog.tsx` |

附带：失败面统一为**中文三段 + 机器码**，三个出口（冷启动卡片 / HTTP 重建错误 / 只读诊断接口）**同码同文案**。

## 五、已知欠账（如实列出，非缺陷）

1. `planning_ready` **未做全真断言**（需 provider 驱动的规则/配方链，本轮注入点够不着）；集成用例改以「冷启动经 Story 入口真实发生：前置 missing → durable active + bootstrap `aggregate_index_active` 步 completed + object_id 一致」为观察面。
2. 「AI 不启动」以「不新增 Story / 既有 Story id 不变」为观察面，**provider 层零启动计数未直接断言**（需 A03 级 provider 工厂）。
3. **既有读路径语义提醒**（非本 PR 引入）：连续两次失败重建且无 LKG 会积累两个 `Stale` 世代 ⇒ `active_required` 报 `aggregate_index_active_ambiguous` ⇒ Story 停机且文案落中性兜底。Story 现在是该语义的唯一硬停机消费者，**建议在运维指引里写明「多点两次重建」**。

## 六、回退

- 每片一个 commit，可单独 `git revert`；共享文件片（片8A→片8）**必须按顺序**回退。
- durable 形状只加了**可选**字段（`skip_reason`、`not_searched_reason`，均 `#[serde(default)]`）⇒ 老记录仍可读，**回退后不需要迁移**。
- 布局/文案/前端是纯加法，回退不影响既有路径。
