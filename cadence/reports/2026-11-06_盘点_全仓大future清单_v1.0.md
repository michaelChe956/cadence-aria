## 1. 方法与量纲

- **分档阈值**（本 change 既定口径，tasks 5.1）：dev **2,048 B** / release **16,384 B**（tokio spawn 栈帧检查阈值分档）。
- **raw_bytes 量纲 = poll 帧预留上界**：与 `src/web/workspace_ws_handler/run/provider_run/poll_frame_budget.rs` 门禁同口径——`nm -C` 取符号地址 + `objdump -d` 序言 0x400 B 窗口内三类栈预留立即数（`sub $imm,%r11` 内联 split-probe 帧守卫 / `sub $imm,%rsp`（≥0x1000 才计，避免普通小调整混入）/ `__rust_probestack` 前 `mov $imm,%rN`）取最大值。这是**栈成本**量纲（poll 一次在该符号上预留的栈），不是 `size_of::<Fut>` 状态体积量纲。
- **第二证据源 = clippy `large_futures`**（量的是 future **状态尺寸**、只在 `.await` 位点触发）：stable 1.99.1 无 nightly ⇒ 临时阈值 `clippy.toml: future-size-threshold = 2048` 扫 `--lib`。**两个量纲分开登记，互不冒充。**
- **扫描对象**：lib 单元测试二进制（debug + release 双 profile）内全部自有 async 体（符号名以 `::{closure#N}` 结尾的 poll 体）。**冻结快照**：
  - debug：`/tmp/frozen-debug-bin`，sha256 `d4208fabe65b79c7e20fc99799176cd04cddc1520853d10597716e23f57ecfbd`（git HEAD `f677a189` 时点 + 并行开发中 worktree 的 19:55 重链件）
  - release：`/tmp/frozen-release-bin`，sha256 `bfd2729593508fbdf0a9adff0763698e6586c0d42a0860eb275785cada1754c3`（18:45 构建；`CARGO_PROFILE_RELEASE_STRIP=false` 环境变量覆盖构建——不改任何仓文件，原因：仓 `[profile.release] strip=true` 会剥掉符号表使 nm 探针失效）
  - ⚠ 两件**非同一源码快照**（并行开发进行中，见 §6-L1）；release 侧 LTO(`lto=true`)+`opt-level="s"` 会把大量符号内联合并。
- **边界判定（boundary_kind）**：产品侧 49 个 spawn 位点逐位点读参数形态（async 块 / fn 直呼 / `Box::pin`）；Box 包装判定用 98 处 `Box::pin` + 24 处 `Pin<Box<dyn …Future>>` 类型标注位点交叉符号名。
- **产品/测试域判定**：符号路径 `::tests::` 等段 + 声明处 `#[cfg(test)]` 模块**花括号区间**跟踪 + `.inc.rs` 包含链继承（被包含文件继承包含方的测试域属性）。
- **字段对照**（§4.1 表列）：`debug 帧/release 帧`=nm/objdump 实测（evidence_source=nm/objdump 实测）；`clippy 尺寸`=clippy 实测；`boundary_kind`/`boxed`=源码读判（evidence_source=人工读码推导）；`conf`：高=实测字节+源定位唯一，中=实测字节+源定位启发，低=实测字节但源定位失败（宏体/泛型）。

## 3. 三类工具缺口（先读，再看清单）

1. **Box 包装盲区（boxed_blind_spot=true）**：future 被 `Pin<Box<dyn Future>>`（或 `Box::pin`）包装后，**尺寸类证据（clippy large_futures / size_of）量到的是指针大小 ⇒ 恒绿**。最小 crate 对照实验（/tmp/clippy-probe，零仓内落盘）已确证：raw await 报警（4,824 B），同一 future 换 `Box::pin` + dyn 包装后**静默**。⇒ 尺寸证据链上这类对象**不可判**；本报告用 **poll 帧探针**补盲（Box 只把状态搬到堆，inner 的 poll 帧仍在符号表可量——帧维度不盲），但帧探针量不到状态体积。**两个量纲都不许用来宣称对方安全。**
2. **spawn 参数缺口**：clippy large_futures 只在 `.await` 位点触发，**spawn 参数 future 不经 await ⇒ 尺寸类证据对 spawn 边界全盲**（对照实验：同一 future 喂给 spawn 形参 ⇒ 静默）。spawn 边界只由 nm/objdump 帧探针 + 人工读码覆盖。
3. **未执行分支 / 静态不可判**：clippy 只覆盖 lib 编译路径；`#[cfg(...)]` 分支、测试域代码不入 clippy 面（391 个测试 spawn 位点、2,498 条测试文件 async fn 不在尺寸证据内；帧证据覆盖测试二进制内已编译符号）。
4. **release LTO 合并**：release 符号数 51,485（debug 519,856）——大量 async 体被内联合并或消除。**release 侧「未量到」≠「0 字节」**：其成本可能折入存活符号（例：`provider_run_drive_body` debug 4,096 → release 36,864，child poll 被合并进来反而变大；`spawn_engine_event_forward_task` debug 4,096 → release 73,728）。
5. **依赖库单态化帧**（tokio/axum/serde 以自有类型实例化的帧）单列为 spawn_transport/runtime_core/foreign 三类（§4.7），不计入自有 async 体清单。

## 6. 局限声明（每条都影响结论边界）

- L1 **快照非同一源**：debug 冻结件（19:55 重链，含并行 WIGA-VOID 在改文件）与 release 冻结件（18:45）非同一次构建产物；并行开发仍在进行（flock 持有者曾于扫描中途重链 debug 二进制——已通过冻结拷贝规避）。双件 sha256 见 §1。
- L2 **release LTO 合并**：release 只量到存活符号（51,485 个）；被合并/消除的 async 体「未量到」，成本折入存活者（drive_body 4,096→36,864、spawn_engine_event_forward 4,096→73,728 即此效应）。
- L3 **序言窗口启发式**：0x400 B 窗口 + `sub %rsp` ≥0x1000 下限，沿用门禁同款口径；量测为 0 的符号不输出（≠0 字节）。
- L4 **帧是「预留上界」非「实耗」**：poll 帧预留 ≠ 运行期实际使用峰值；不与 VmStk/RSS 直接换算。
- L5 **源定位启发**：宏体（plan_revision/followups）、深嵌套闭包、`boxed_child` 泛型参数内联名定位失败（主表 conf=低 87/288）；boundary_kind 对 async 块的归属为启发式（spawn 位点表为准）。
- L6 **尺寸证据三缺口**（§3）：Box 恒绿、spawn 全盲、未执行分支不可判——**本清单不能反向证明任何对象「安全」**。
- L7 **泛型多实例去重取最大**：同名 demangled 的多个单态化实例按最大帧计（`run_kimi_session_inner::<ChildStdin>` 与 `::<DuplexStream>` 分列）。
- L8 **未覆盖**：`tests/it_*.rs` 集成测试二进制内的 async 体、`src/main.rs`（bin 无 async fn/spawn，已核）、nightly 专属工具（future-size 报告器等）。
