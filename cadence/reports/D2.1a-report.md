## 实现

- **`src/product/provider_workspace_runner.rs`（scope 归约＋acquire 公共面＋REST
  lease）**：`resolve_session_run_scope`——D1.0 会话身份索引优先（墓碑
  fail-closed；Conflict/NotFound 均回落记录归约，阶段分类交 acquire_run 锁内
  精确判定）；记录归约 Story/Design/WorkItemPlan 直接映射、WorkItem 先
  `work_item_child_binding.plan_id` 再 issue 计划 `work_item_ids` 反查（D1.3a
  `owning_plan_scope` 同链语义，按独占面约束在此实现公开面）。全链耗尽（旧无
  owner 档案）→ None 保持原行为。`acquire_run_lease_for_session` 供 manager/REST
  共用。`run_next` 载入 session 后、provider 运行前 acquire，`_run_lease` 持有
  到函数尾部全部 store writes（review/version/messages/status）完成；稳定码
  `entity_deleting|entity_deleted|entity_busy|entity_admission_failed` 以
  message 前缀携带。
- **`src/web/workspace_ws_handler/run/provider_run.rs`（WS 单一收口）**：
  `spawn_provider_run_with_start_mode` 在**任何** engine/session 锁之前
  `acquire_run`（§0.4 锁序），entry.rs 三入口/gateway_start claiming_idle/
  durable_projection 恢复链全部经此收口（author/review/revision/event-recovery
  全覆盖）；lease move 进任务体随全生命周期持有——drive/取消臂收口/最终 store
  writes 完成后释放；supersede 接力 run 自行另持新 lease（重叠期 shared 相容）；
  Deleting/Deleted/Busy 稳定拒。ClaimIfIdle 认领失败（Ok(false)）等提前返回
  路径 lease 即取即释。
- **`manager/mod.rs`＋`runs.rs`＋`attachment.rs`（invalidate 面）**：
  `invalidate_for_entity_deletion` 置 `invalidated_for_deletion` AtomicBool
  （无 cancel 副作用：不 abort 活 run、不写 durable、不把 registry remove 当
  stop）；dispatch 检查在 `start_run_from_attachment`/`try_start_run_if_idle`
  临界区前（`ENTITY_DELETED_STABLE_MESSAGE` 稳定拒）；attach 检查在
  `register_attachment`（回执错误帧后不登记，不投递直播）。
- **`manager/mod.rs` create（registry 重建面）**：会话记录载入后、任何 durable
  写（ensure_workspace_context_message）之前按 `resolve_session_run_scope` 读
  墓碑——purging/deleted 会话拒绝重建 manager（旧 Arc 驱逐后的复活口闭合）；
  scope 解析为只读文件访问，在 registry creation lock 内侧执行、与 scope flock
  无等待交互（非阻塞、固定序无环）。
- **`lease_diagnostics.rs`/`degraded_diagnostics.rs`（诊断准入）**：两
  `append_durable` 接 `with_workspace_session_live_write`（D1.3b usage 诊断同款
  纪律，准入在日志 Mutex 之前）——purging/deleted 会话迟到打点（旧连接
  disconnect 的 release、degraded enter/exit）不凭缓存 path 重建已删除
  timeline；准入失败静默跳过，未删除实体原诊断故障降级语义不变；生产
  create 与 test_fixture_with_parts 注入 admission（fixture 诊断路径同时改随
  app_paths state root 唯一，消除 record id 跨 fixture 重号共享 temp 路径）。
