## 竞态语义（REQ-DEL-05/06）

1. **create 先得 lease**：guard 持 owning Plan 共享准入 → 删除独占立即 `entity_busy`、零墓碑零
   pending（零破坏拒绝，对应 D2.2 `cascade_delete_entity` ② 的非阻塞 try-exclusive）。
2. **attempt 落盘后**（准入收口）：删除独占可得，coding 门禁判据（attempt 记录存在即拒
   `coding_workspace_exists`，group 与所属 WI 双路）在场。
3. **delete 先赢**（purging 墓碑）：direct（`create_attempt`）/group（`create_group_attempt`）/
   journal 恢复（guard 获取、legacy guard＋journal 兜底、journal 再准备）全拒
   `Conflict{entity_deleting}`、attempt 数 0；Deleted 完成态同样稳定拒绝（同族 entity_deleting，
   与 N2 P2/coding_plan_run 惯例一致）。
4. **其他 Plan 创建正常**：删除窗口只收窄到 owning Plan scope（per-plan 锁键隔离）。
5. **guard 已取旧 arbitration 锁路径也不得绕墓碑**：advance 编排在 arbitration 锁内取 creation
   guard 的旧路径，guard 自身准入仍 fail-closed 拒墓碑（try 非阻塞、无死锁；D2.1d 将在 advance
   入口外层持同 Plan lease，届时内层只消费已持准入）。
6. **原并发唯一 attempt 仍只一个**：`attempt_creation_concurrency` 原两项回归全绿（guard 归属
   解析对无 lifecycle 记录的 fixture 返回 None，零行为漂移）。

## 锁序与边界

- 固定序 **scope → creation/arbitration 对象锁**：guard 的 scope 准入在 creation 文件锁之前；
  `create_group_attempt`/prepare 无先持对象锁，准入天然在外层。advance 链（initialize_inner/
  advance_split 在 arbitration 内调 prepare/ensure/guard）中本包的 try 准入嵌套于 arbitration——
  非阻塞 fail-closed（拒墓碑、绝不等待 scope），死锁不可能（try 语义）；按 plan §0.4 由 D2.1d
  在 advance 入口外层取完整 Plan run lease 收口为「只消费已持准入」。
- 不改：guard identity 校验、active uniqueness/per-(plan,target) 唯一性、admission 状态机、
  不自动 abort/delete coding、不把残 lock 当 attempt；`group_validation.rs`/`advance_split.rs`
  零修改（N 已释放面保持原样，本包全部接线落在 store 入口）。
- `ensure_group_initialization_plan_binding`/`ensure_group_initialization_unit` 不加准入：其写只
  发生在 attempt 已持久化后，attempt 记录在场时删除被 coding 门禁整体拒绝，无竞态窗口。
- `validate_materialized_group_initialization_attempt` 为只读回放，不阻断（读路径不受删除
  窗口影响，同 N2 get 语义）。
