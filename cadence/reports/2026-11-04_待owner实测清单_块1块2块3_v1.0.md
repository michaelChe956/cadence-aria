### 块1 7.8 —— 当前卡重建 / 重连 SHALL 刷新同门当前事实；旧卡只读历史

**怎么测**
```
1. 起一个会停在人工门的会话（门卡可见）
2. 记下门卡上「还可重写/可用额度」的数字
3. 在【同一门】上让额度发生变化（例：owner 反馈消耗 1 次 / 另一路自动重写消耗 1 次）
4. 刷新页面 / 断开重连 / 让当前门卡重建
5. 观察：当前卡上的数字是否【跟着变】
```

**判据**
```
✔ 当前卡  → 数字是【最新】的（不是卡片创建时的旧值）
✔ 旧卡    → 仍是历史值（不被回溯改写）
✘ 若当前卡仍显示创建时的快照 ⇒ 未修复
✘ 若历史卡的数字也被改了 ⇒ 破坏了「旧卡只读历史」（既有测试钉着这条）
```

### 块2 11.10 —— codegraph【安装】按钮出现在 codegraph 缺失的失败面上

**怎么测**
```
1. 造一个 codegraph 缺失（或版本不在支持区间）的环境
   · 最省事：在同一台机器上临时把 codegraph 从 PATH 移开（做完复原）
     PATH 里去掉 ~/.local/share/fnm/aliases/default/bin，或用隔离 PATH 起服务
2. 触发聚合初始化 ⇒ 出现失败面
3. 在失败面上找【安装】按钮
```

**判据**
```
✔ 失败面上出现【安装】按钮（不是只有文案）
✔ 点它能拉起 codegraph 的安装流程（走镜像源的那套）
✔ 【安装】与【重新检测】是两个独立按钮、语义不重叠
   （安装 = 装 codegraph；重新检测 = 装好后重新探测版本/可用性）
✔ 对照：registration wizard 面的 codegraph 安装按钮仍是原样（那块本来就对）
```
