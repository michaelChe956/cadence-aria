## 锁序与边界（plan §0.4/任务 Interfaces）

- 单一 run admission 只在 engine 方法顶层取得（不在 engine/session/object 锁内首次取
  scope；探针/内层写全部消费外层已持事实）；内层各 store 写沿用 D1.2a/b、D1.3a/b 既有
  已准入 helper（try-shared 与外层共享锁跨 OFD 兼容，无自死锁面——全量回归佐证）。
- 外层已持同 scope lease（D2.1a spawn 全周期 run lease／enter 状态机帧）时，重取为共享
  flock 幂等重入（try-shared 非阻塞、外层共享在持则内层必成、墓碑复核幂等）——即任务
  Interfaces「manager已持lease时只复用」的可重入等价形态；不以重复 try-shared 逐写包裹
  规避锁序（整个提交段单一 admission）。
- 不改：compile reservation CAS、发布 freshness（`verify_publish_freshness`/SG 图算法）、
  SC 结构复验门、原 failpoint 机制、`record_single_candidate_compile_failure` 诊断落点、
  恢复动作三臂既有语义（准入失败只是先于其发生）。
