## 0. 摘要（TL;DR）

1. **为什么必须加独立 job**：仓级 `.cargo/config.toml` 有 `RUST_MIN_STACK = { value = "33554432", force = true }` ⇒ **所有测试线程都拿 32 MiB 栈** ⇒ 栈类缺陷在常规测试里**永远测不出来** ⇒ 「provider run 爆栈打死整个服务」这类回归会再次悄悄进来。补一个在 2 MiB 栈下跑真实链路门禁的 CI job ⇒ 让「栈回归」变红。
2. **新 job 名**：`stack-2mib-gate`（显示名 `2 MiB stack regression gate (C-layer real WS)`）。
3. **job 内三条命令（本机实跑全绿）**：2 MiB 送审轮门禁 `ok`、2 MiB 真实 WS 场景矩阵 `ok`、8 MiB 对照面 `ok`（三条各 `1 passed; 0 failed`）。
4. **不需要覆盖 `RUST_MIN_STACK`**：C 层门禁**自带显式 2 MiB runtime**（`provider_run_small_stack.rs` 的 `run_ws_child_scenario_with_stack` → `.worker_threads(1).thread_stack_size(stack_bytes)`）⇒ 显式栈值覆盖环境变量 ⇒ 仓级 32 MiB force 对这批用例无影响 ⇒ **owner 裁决保留的 32 MiB force 一字未动**。
5. **门禁不会「永远绿」**：无 `continue-on-error`、无 `if: always()`、无 `|| true`、无 skip/allow ⇒ 栈回归就是 job 红。

## 1. 落地内容

### 1.1 新增 job（`.github/workflows/ci.yml`）

```yaml
  stack-2mib-gate:
    name: 2 MiB stack regression gate (C-layer real WS)
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: stable
      - name: Cache cargo artifacts
        uses: Swatinem/rust-cache@v2
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: "20"
      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 10
      - name: Build frontend
        run: pnpm -C web install --frozen-lockfile && pnpm -C web build
      - name: Install codegraph (C-layer real WS fixtures need the real CLI)
        run: npm install -g @colbymchenry/codegraph@1.6.2
      - name: "2 MiB stack gate: real WS review round"
        run: flock /tmp/aria-cargo.lock cargo test --locked --test it_core provider_run_2mib_real_ws_review_round_gate -- --nocapture
      - name: "2 MiB stack gate: real WS scenario matrix"
        run: flock /tmp/aria-cargo.lock cargo test --locked --test it_core provider_run_2mib_real_ws_matrix -- --nocapture
      - name: "8 MiB control: real WS review round (proves the 2 MiB red is stack-depth-caused)"
        run: flock /tmp/aria-cargo.lock cargo test --locked --test it_core provider_run_8mib_ws_review_round_control_gate -- --nocapture
```

**设计要点与依据**：

| 点 | 依据 |
|---|---|
| **先构建前端** | aria 通过 rust-embed 在编译期嵌入 `web/dist`；`build.rs` 在 `web/dist/index.html` 缺失或为空目录时**硬失败**（`build.rs:8-28`）。`web/dist` 被 `web/.gitignore` 忽略、不在版本控制中 ⇒ 干净 checkout 后必须先构建，否则 cargo 直接失败。做法与 rust job **完全一致**。 |
| **装 codegraph CLI** | C 层真实 WS 夹具（`scenario_cases.rs` / `scenario_review.rs` → `part_05.rs` 的 `create_workspace_session_fixture_with_providers`）会走**生产** aggregate-index rebuild 端点（`POST /api/projects/.../aggregate-indexes/rebuild`）；该端点经 `AggregateInitializationDependencies::production` 装配 `CodeGraphCli::new(state.command_runner, "codegraph")`（`src/web/handlers/aggregate_initialization/production_dependencies.inc.rs:943`），`rebuild` 会 `verify_version()` + `sync_or_reinit()` + `files()` **shell out 真实 CLI** ⇒ runner 上没有该工具时端点非 200 ⇒ 夹具断言失败。钉版本 `@colbymchenry/codegraph@1.6.2`（与 rust job、本地一致）。 |
| **每条 cargo 带 `flock`** | 与仓内既有约定一致（`openspec/.../tasks.md` 2.2 条目「每条 cargo 带 `flock`；**不 matrix 并发同 target**」）。本 job 三条命令**顺序执行**、不 matrix、不并发同 target。 |
| **不加 `-j 1`** | 仓规禁止（`.cargo/config.toml` 注释：`-j 1` 会退化为单核串行，测试从 ~1.5min 涨到 6min）；仓级 `jobs = 8` 已在 `.cargo/config.toml` 里定好。 |
| **不加 `--ignored` / skip / allow** | 三条门禁都是**常规** `#[test]`（非 `#[ignore]`）⇒ 不需要 `--ignored`；门禁红就是红，不许跳过。 |
| **不动 `.cargo/config.toml`** | owner 2026-11-06 裁决：保留 `RUST_MIN_STACK = { value = "33554432", force = true }`。本 job 因此**不覆盖** `RUST_MIN_STACK` 环境变量——C 层门禁自带显式 2 MiB runtime，显式栈值覆盖环境变量，仓级 force 对这批用例无影响。 |
| **不动 rust job** | rust job 的既有步骤（fmt / clippy / check / test / 前端构建 / codegraph 安装）**一字未改**。 |
| **8 MiB 对照面一起跑** | 对照面证明「2 MiB 的红确实落在栈深上」，而不是「场景根本没走到送审轮」的假阳性。**门禁判据永远是 2 MiB 那条**，对照面不替代它。 |
