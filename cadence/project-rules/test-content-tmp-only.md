# 测试内容 /tmp 隔离规则(强制)

> 🔴 强制规则(用户裁决 2026-10-10):本规则启用后无例外,适用于所有会话与全部 subagent。

## 规则正文

1. **一切测试产物只能创建在 `/tmp` 下**——包括但不限于:
   - 测试夹具仓(成员仓/聚合根/fixture 仓库)
   - 测试构建产物与隔离 target 目录(`CARGO_TARGET_DIR` 必须指向 `/tmp` 子目录)
   - 测试运行日志、看门狗状态、快照、补丁、备份等一切中间产物
   - E2E/页面测试的环境装配目录与证据临时面
2. **禁止**在以下位置创建任何测试内容:
   - 仓库工作区与父级目录(如 `workspace/github/`、各仓根目录)
   - 用户家目录(`$HOME` 直属层,含日志/夹具/索引等)
   - 仓内任何非专门声明的目录
3. **例外(非测试内容,不受限)**:
   - `cadence/reports/` 下的**正式验收证据**(cells/snapshots/验收报告)——交付凭据,不是测试临时物
   - `e2e/` 等仓内**测试代码资产**(spec/脚手架,受版本管理)
   - 产品源码与测试代码本身
4. **清理责任**:测试会话结束时应清理自建的 `/tmp` 产物(或明确告知用户保留项);发现历史散落在非 /tmp 的测试遗留,报告并按用户指令清理。
5. **派工传导**:所有 subagent 的任务 brief 必须携带本规则;worker 违规创建即产出作废并回滚。

## 背景

2026-10-10 用户清理了散落在 `workspace/github/`(p1-member-alpha/beta、p3-manual-carrier、工作区级 .codegraph)与家目录(cadence-night-4t、eval-runs、night 系日志、provider 配置内 125+ 测试段)的历史测试遗留后,确立本强制规则。
