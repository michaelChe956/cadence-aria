# Round 6 协作式取消与 Git 操作日志实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 本任务禁止委派子 Agent，步骤使用 checkbox 跟踪。

**Goal:** 消除 runner future drop、不可取消 flock waiter 与 Git 多阶段副作用在 Abort/Delete 后迟到的问题。

**Architecture:** runner取消后继续等待同一业务future；Engine在event/gate/provider/Git边界协作返回`Aborted`。Git process统一kill/reap，并用Attempt级严格单调journal进行reconcile/compensation。

**Tech Stack:** Rust 2024、Tokio、tokio-util CancellationToken、Axum、flock、Serde JSON store、Git CLI。

## Global Constraints

- 严格 TDD：每项先写并运行 RED，再写最小实现并确认 GREEN。
- 禁止子 Agent、`-j 1`、E2E、Playwright、browser、真实 Provider与网络 CLI。
- 不新增依赖、HTTP route或`src/web/app.rs` diff。
- Git push已完成时权威记录Completed，不伪回滚；commit补偿必须保留工作区内容。
- journal identity严格、phase单调、无历史兼容。
- 所有修改/新增 Rust、TS 文件不超过800行。
- 最终一个新原子提交，不 amend、不 push；不创建中间提交。
