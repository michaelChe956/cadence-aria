## 1. 决策一：通道 C 的资格、池归属、单槽与账本

### 1.1 推荐与依据

**取消独立 structure 槽；保留 structure 修复能力，但并入同一耐久 RepairOnce。C 不入 A 池，也不入 B 池。** “独立有界”仅是资格/计费归属，不是再叠加一个物理启动池。

1. 主规格 `openspec/specs/work-item-plan-single-candidate/spec.md:478-490` 的 REQ-WSC-09 明文“**每 candidate 至多一次额外驱动**”，先后命中两个可教学类别“**总共仍至多一次**”。现 handler `src/web/workspace_ws_handler/run/single_candidate.rs:1200-1212,1227,1307,1386-1402` 的双布尔槽最多造成原调用加两次重驱，必须收敛。
2. `openspec/specs/workspace-structural-governance/spec.md:82,86,91` 要求“**实际start MUST 有ledger**”“上限/授权无法证明则**零额外调用**”，SC 初轮是“**仅已批准 RepairOnce 才原+1=2，否则1；不伪造人工 turn**”。因此不能把布尔槽改成一个后即称完成。
3. WSC-21 的触发域是门段 `final_compile_*`，见主规格 `:817-846`；`fix-author-rewrite-quota-pool/design.md:41-58` 把 A 池定位为评审发现驱动的聚合返修，B 池定位为门段 author 重写。不能通过 C 的 handler 复用同一个 provider 函数就推断其属于 A/B。
4. `openspec/specs/work-item-plan-single-candidate/spec.md:885-897` 的 WSC-25 要求每次候选生成/编译追加流水，但流水写失败不得阻断；SG-05 的授权账本写失败则必须阻断。**两者不可互相替代。**
5. `src/product/planning_failure.rs:310-338,392-435` 已有 `GenerationRun` 授权 kind、attempt_no/max_attempts、unknown/waiting 以及整批失败判据，应复用，不从 message 或模型标签推导资格。

### 1.2 三种预算备选的否决理由

| 备选 | 代价与否决理由 |

### 1.3 可直接采用的 REQ-WSC-28 全文

建议新建 change **`bound-sc-generation-teaching`**，在新文件 `openspec/changes/bound-sc-generation-teaching/specs/work-item-plan-single-candidate/spec.md` 放以下 ADDED 条款；WSC-26/27 已占用，不复用编号。

> ### Requirement: generate 段教学重驱的统一授权窗口、预算归属与可观测性（REQ-WSC-28）
>
> SC generate 段的教学重驱 SHALL 绑定原生成 run/reservation/phase，并使用 REQ-SG-05 的 SC 初轮载体。资格 SHALL 以 REQ-WSC-09 为唯一清单：parse 语法、事实完整的 typed lowering、事实完整的 typed IR 校验和确定性结构拒收均只可消费该同一窗口；MUST NOT 因失败阶段、诊断数量、provider 节点变化或类别变化建立独立机会。mixed Unknown/Operational、事实不完整、权限/上下文/基线不可证明的失败 MUST NOT 授予教学重驱。
>
> 同一候选生成链 SHALL 以原生成授权身份为锚，而非以重驱后新 source hash 为锚；每 candidate 至多一次额外教学驱动。只有已批准且耐久绑定的 RepairOnce 才可使用原调用之外的一个物理机会，原调用在内最多两次；无批准时最多一次。原窗口中的运行恢复已使用第二次物理机会时，教学重驱 MUST NOT 再产生第三次。新 source revision、新 native 会话、重连、恢复及同请求重放 MUST NOT 重置窗口。
>
> 通道 C SHALL 是独立有界的生成教学机会，不消耗评审机械池 `max_repairs`，不消耗 author 重写/反馈池 `max_manual_repairs`；MUST NOT 增加 `repairs_used`、`manual_repairs_used` 或伪造用户 turn/hold/receipt。该归属不改变 A/B 池原有触发域、余额或计费语义，也不得由 A/B 池余额为 C 的第三次调用兜底。
>
> 每次机会 SHALL 在任何外部启动前原子 claim，耐久绑定 authorization kind、原 generation/node/run 身份、业务请求及材料摘要、失败 source 引用与 hash、context digest、允许修改闭包、机器指令 digest、完整 prompt 引用与 digest、attempt key 和物理上限。初次调用尚无候选 source 时 SHALL 明确记录该事实并绑定原请求/材料，MUST NOT 伪造候选引用；重驱前失败原文与其 hash 必须可验证。授权、材料、上限或持久 claim 不可证明时 MUST 零额外调用并显式系统故障。
>
> claim 与 actual start SHALL 分账。真实启动观察 MUST 以同一 attempt key 写入既有 provider-start ledger，并可关联真实 provider/run 与启动证据；预留占位、调用前时间戳、WS 事件及旧 `started=true` MUST NOT 冒充真实启动。外部结果 Unknown 时 SHALL 沿原等待/对账，不自动重播。所有允许启动仍须经过原 gateway admission/full fingerprint；显式 fresh 保留原授权/窗口/冻结输入，不获取新 RepairOnce。
>
> 候选完整输出及每次 compile/IR/structure 判定 SHALL 按 REQ-WSC-25 追加可追溯流水，关联同一 generation 与 provider attempt，包含 source ref/hash、阶段、稳定码、typed 种类、环指纹、规范化/修复事实和处置结论。原始输出无法形成 source 时 SHALL 明确记录缺失原因，不伪造引用。流水只用于审计/度量，不作为启动许可；流水写失败按 WSC-25 记日志且不阻断，授权/ledger 的持久执法失败则按 SG-05 停止或进入 Unknown 等待，二者不得混用。
>
> 第二次交付仍失败或出现修复范围越权时 MUST 停止该生成自动链、保留 last-valid refs 与失败历史，MUST NOT 提升坏 candidate、发起 review/confirm 或旁路至另一自动重写入口。后续只有真实新业务授权可按其既有合同继续，MUST NOT 由平台自动制造新 turn、candidate 或 generation 来补机会。
>
> #### Scenario: IR 拒收使用唯一额外机会
> - **WHEN** 原调用产生事实完整的 typed IR 失败，原生成授权批准 RepairOnce，尚有一个剩余物理机会
> - **THEN** 平台以完整失败 source、typed 定位和允许修改闭包 claim attempt2，原 author 重驱一次，形成两个真实 start 证据；C 消费一次，A/B 池均不扣。
>
> #### Scenario: 跨类别不乘法
> - **WHEN** 同一生成链 attempt1 命中 parse/IR，attempt2 又命中 structure，或顺序相反
> - **THEN** 不产生第三次启动，不新开 structure 槽，按 typed 工程故障停止并保持合法 refs。
>
> #### Scenario: 业务或运行错误不借教学
> - **WHEN** 失败集合含 Operational/Unknown、基线读取失败、授权缺失或缺少必要 typed 事实
> - **THEN** 零额外 author 调用；按已有等待/失败面回显真实原因，不把其渲染成模型可修语法错误。
>
> #### Scenario: 同键重放与不确定启动
> - **WHEN** claim 后崩溃、启动回执未知、重连重投或显式 fresh
> - **THEN** 读取同一 durable 窗口；已启动不重播、Unknown 等待；确定未启动才可在原 key/授权下恢复合法动作，不新增预算或物理机会。
>
> #### Scenario: 旧记录不可补造授权
> - **WHEN** 历史会话只有旧 `started` 占位或没有可证明的原授权/窗口
> - **THEN** 读取历史不产生授权，零额外调用并说明证据缺失，不从计数为零推断存在机会。
>
> #### Scenario: 流水与启动账本失败处理不同
> - **WHEN** WSC-25 流水追加失败，或者 SG-05 claim/实际启动记录持久化失败
> - **THEN** 前者记运行日志且不阻断；后者不得继续无账启动/重试，已发生外部动作按真实证据进入 Unknown/补偿，不伪装未启动。
