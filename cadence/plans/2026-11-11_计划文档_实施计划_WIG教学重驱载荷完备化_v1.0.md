# WIG 教学重驱载荷完备化（teach-sc-compile-reredrive-feedback）实施计划 v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 SC compile 结构失败教学重驱这一次机会「喂什么」补齐（五段式诊断 + 结构契约三件套 + 上一版完整 source），并在机会用尽进入终态前发出「SC 结构失败诊断包」事件——零新增模型调用、零新增重试次数、零新增教学资格码、固定规范面 23,500 B 与上下文面 32,000 B 零触碰。

**Architecture:** 五段式渲染抽成 `CompilerDiagnostic` 上的唯一方法（`work_item_plan_compiler/types.rs`），runner 侧 `format_compile_failure_reasons` 与引擎侧 `format_compiler_diagnostics` 两侧委托同一实现（D2 防分叉）；三件套（section 清单 / 必需字段表 / 最小合法 source）全部运行时取自既有单源（`grammar::STRUCTURED_SECTIONS`、经 `grammar.rs` 重导出的 `REQUIRED_FIELDS`、`work_item_plan_minimum_legal_source()`），装配进决策六迁出后的 `workspace_engine/prompts/sc_compile_teaching.rs`；`[previous_source]` 与诊断包的 source 引用/hash 一律从 bound（序 3）的耐久教学窗口模型取数，不自建第二套管线。

**Tech Stack:** Rust（宿主机直接跑 cargo；tokio 既有集成测试 harness `ProviderRunFixture` + `SequenceOutputProvider`）。

**Spec:** `openspec/changes/teach-sc-compile-reredrive-feedback/specs/work-item-plan-single-candidate/spec.md`（**ADDED REQ-WSC-32**，7 个场景）
**Design:** `openspec/changes/teach-sc-compile-reredrive-feedback/design.md`（D1–D9）
**方案：** `cadence/designs/2026-11-11_技术方案_WIG三缺陷与多仓事实供给修复_v1.0.md` §4.3 / §5.1 / §6.1 / §7.3 / §8 / §10.2

## Review Focus

1. **空修复示例退化为三段式**：诊断未产出 `repair_example`（空串）时，五段式对应位置仍占位——同一通道不得同时产出两种形态（解析方要分支）。→ Task 2 单元 `five_segment_reason_keeps_placeholder_for_empty_segments` 钉住。

5. **诊断包挤掉/改写既有终态 message，或事件触发额外启动**：既有失败面（终态句式「after one teaching re-drive」、显式重开指引）依赖终态 message 原文；诊断包是纯观测。→ Task 5 集成断言终态 message 三项原文仍在 + `no_more_provider_inputs`（无第三次启动）。
