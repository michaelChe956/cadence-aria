# 门卡收口态 / 在途态 / 中断态修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** reviewer 人工分诊门在「已收口 / 修订在途 / 被中断」三态下不再以全新待办形态呈现，且因终止导致的修订失败记为 `aborted` 并在对话流明说「你的选择未生效」。

**Architecture:** 前端：`GatePromptEntry` 对 `resolved` 卡走只读陈述分支（标题 / 选项块 / meta 行 / 徽章说明），对「刷新后 `humanGateTurn` 丢失」的在途态由新选择器 `selectGateInflightPhase` 从 `activeRunId + 活动节点类型` 派生并上锁；后端：只补失败分类（中止哨兵 → `Cancelled`）与节点收口分流（`Cancelled` → `Aborted`），复用既有 `RunAbortOutcome` / `Aborted` / `Cancelled` 三件套，零新状态、零 wire 变更。对话流明说句由 durable 节点 `summary` 经 `buildChatEntries` 派生，live 路径由 `timeline_node_updated` 处理器补一条同 id 条目。

**Tech Stack:** React 18 + Zustand + Vitest + Testing Library（`web/`）；Rust + tokio（`src/`）；OpenSpec。

**Spec:** `openspec/changes/gate-card-resolved-and-inflight-state/`（`proposal.md` / `design.md` / `specs/work-item-plan-single-candidate/spec.md` REQ-WSC-26、27 / `specs/work-item-plan-conversational-gate/spec.md` REQ-CG-10）。

## Review Focus

1. **已收口卡被在途选择器重新激活**（会话 `terminated` 但 store 里 `activeRunId` 与 `active` 的 `author_run` 陈旧存在）→ 期望仍是只读陈述卡，无状态行 / 编辑器 / 确认按钮。→ Task 4 负向用例。
2. **`activeRunId` 陈旧导致门卡被永久锁死**（run 已结束但没收到新 `session_state`）→ 期望随节点终态自动解锁。→ Task 4「节点终态后解锁」用例。
3. **idle watchdog / 选择等待超时同样 `cancel.cancel()` 后返回错误**，不得被误判成 owner 终止 → 期望仍是 `provider_err` + `Failed`。→ Task 1 分类函数用例。
4. **provider 被 abort 后事件通道先于取消臂关闭**（返回 `provider completed without output`）→ 期望带取消标记时同样归 `Cancelled`。→ Task 1 分类函数用例。
5. **普通中止（`运行已中止`，非修订）不得被误加「修订被中断」句**，且无证据时已终止卡不得宣称「修订被中断」。→ Task 2 / Task 3 用例。
