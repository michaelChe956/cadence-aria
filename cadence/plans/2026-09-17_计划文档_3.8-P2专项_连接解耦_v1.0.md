# 3.8 P2 专项实施计划：连接解耦——run 生命周期与连接解绑 + 广播（WP4.2–4.7）

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，严格按 Task 顺序实施（Phase A→E 族内串行，同 Phase 内 Task 亦串行——同一批文件高频交叉）。步骤使用 checkbox（`- [ ]`）语法跟踪。本计划为 3.8 最大引擎专项（84–130h），**分阶段可部署**：每个 Phase 结束是一个可独立部署、可独立验证的增量，不要求一次切完；但**不跳阶段交付**（D4：只交付 cursor 不交付 manager 之类的半成品 = 制造更危险的双所有权，禁止）。

**Goal:** 把 workspace 会话的 run 生命周期与 WebSocket 连接解耦：session-owned `WorkspaceSessionManager` 唯一持有 engine/run/事件源，连接降为可替换 attachment；Hello 增可选 `role`/`after_event_seq` 双字段（双字段容忍，零 flag-day）；连接关闭不再写 `aborted_by_disconnect`/不整流回 prepare_context；重连经 session-scoped 单调 `event_seq` cursor 重订阅并获 session 级广播；RCA §6 四条断连矩阵全量真跑为 done 定义（REQ-WCR-01..07）。durable schema 零变更、回退旧二进制读新数据安全。

**Architecture（P2 四层）:** ① **session-owned run manager**——每会话一个 `WorkspaceSessionManager`（registry 挂 `WebAppState`），唯一持有单一 `WorkspaceEngine`（创建一次，运行期不随连接销毁）、`ActiveRun { token, cancellation, command_tx, state, lease_epoch }` 与事件源；run 的开始/abort/命令/完成/lease 释放进入 manager 内单一原子临界区（token + lease epoch 判等生效）；内存回收点 = run 终态且无订阅者；进程重启从 durable 诚实重建（不虚称 in-flight 跨进程连续）。② **driver/observer 协议与会话级 lease**——Hello 可选 `role`（缺席归一为内部 legacy-driver 常量，仲裁只认内部角色）；observer 写服务端拒绝；lease 会话级单活性 driver，连接持有、关闭只撤销不取消 run，新连接接管 epoch 递增、旧 epoch 迟到写被拒；supersede 显式语义保留并收窄到 driver。③ **事件广播 + cursor 重订阅**——事件以 session-scoped 单调 `event_seq` 为序（不复用 node id），manager 持有界事件 journal（run 期间全量保留，终态后裁剪），Hello 可选 `after_event_seq` 重订阅：cursor 过旧/缺口先发带基线 seq 的完整 snapshot 再续事件，客户端按 seq 去重；慢订阅者有界通道溢出→标记降级重取 snapshot，不反压 provider；每连接只管自己的出站泵。④ **连接关闭语义重写**——close（任一形态）不写 `aborted_by_disconnect`、不把活动节点标 Failed、不触发 `transition_to_prepare_context_after_disconnect`；只有 provider token 实际取消/provider 失败/明确人类 abort 写真实终态；完成与 close 并发只产生一个真实 terminal reason；中性连接诊断（首批 T1 `da795042` 已落地的 `ConnectionDiagnostic`）成为唯一连接级事实源。

**Tech Stack:** Rust（axum、tokio mpsc/CancellationToken/Notify、tokio-tungstenite 集成测试）、TypeScript/React（Zustand、Vitest）。

```rust
    pub app_paths: ProductAppPaths,
    provider_registry: Arc<ProviderRegistry>,
}
struct ManagerState {
    attachments: HashMap<String, mpsc::Sender<OutboundControl>>, // connection_id → 出站通道
}
impl WorkspaceSessionManager {
    /// socket.rs 427-547 的 engine 构建链整体迁入（session_record 加载/
    /// ensure_workspace_context_message/repository/checkpoint/logical gateway/
    /// ensure_plan_repair_artifacts 全在此执行，每 session 一次）。
    pub async fn create(state: &WebAppState, session_id: &str)
        -> Result<Arc<Self>, String>;
    pub fn engine(&self) -> Arc<Mutex<WorkspaceEngine>>;
    /// attach：注册 attachment 出站通道 + 返回初始 session_state（含 restored
    /// choice request）。**不得被 provider 持锁阻塞**：engine `try_lock()` 短超时
    /// （250ms 轮询一次，两次失败即回退）失败时，用「一次性 durable 投影器」
    /// （按 socket.rs 现状 427-547 的只读路径重建临时 engine 渲染 session_state
    /// 后丢弃——纯渲染器，绝不驱动 provider、绝不持有 run，不构成第二 engine
    /// 所有权视图）。
    pub async fn attach(
        &self,
        connection_id: &str,
        outbound_tx: mpsc::Sender<OutboundControl>,
    ) -> (WsOutMessage /* session_state */, Option<WsOutMessage> /* restored choice */);
    pub async fn detach(&self, connection_id: &str);
    /// manager 持有的事件 router（取代 per-socket spawn_engine_event_forward_task）：
    /// 消费 engine_rx → map_engine_event → 序列化 → try_send 每个 attachment；
    /// 单 attachment 通道满/失败 → 跳过该 attachment 并 eprintln 诊断（T9/T11 升级
    /// 为 journal+降级标记）。ProviderRunRequested 由 manager 自行 spawn run
    /// （run_context 由 manager 构造——本 Task 先保留旧 ProviderRunContext 形状，
    /// T2 收编）。
    fn spawn_event_router(self: &Arc<Self>, engine_rx: mpsc::Receiver<EngineEvent>);
}
```

- 关键架构决策（写进代码注释）：provider task 全程持 engine 锁（`provider_run.rs:162-165`），因此 **attach 的 session_state 构建（`build_session_state`，`&self` 只读）不得依赖竞争 engine 锁**——try_lock + durable 投影器回退。今天「第二连接自建 engine 立即可读」的能力由投影器保留；今天「第二 engine 视图」的缺陷（run 所有权分裂）由 manager 消除。投影器是 run 期 attach 的**常态路径**而非边角（run 期间 try_lock 必失败）——oracle F3（r1）以三钉子测试钉死其边界：零 durable 写入/不入 run 面/不订阅事件面（防实施演化中投影器膨胀为第二状态源），断言见 Step 1 attach 用例与 Phase A 门。
- 事件广播语义变化（本 Task 即生效）：engine 事件从「只发给建 run 的那个 socket」变为「发给全部在线 attachment」（REQ-WCR-04「被动连接实时收事件」的 server 面提前达成；cursor/去重/降级在 Phase D）。
- 既有行为保持：`handle_workspace_socket` 的 stage 校验读循环、诊断（`:873-898`）、close 清理（`:900-921`，本 Task 原样保留——`current_run`/registry 语义未动）全部不变；human-gate 恢复与 outline resume（`:616-754`）暂留 socket 路径（T3 迁入 manager 创建）。

- lease 规则（D5）：
  1. **获取**：role=Driver 的 attachment 绑定时——lease 空闲则获取（holder=connection_id，epoch 不变或首次置 1）；**lease 已被其他连接持有则接管**（epoch+1，holder 换新，旧 holder 降级为 stale-driver）。「接管」= 连接为 driver 即显式行为（现实=单会话单 driver，新 tab 接管旧 tab）；无 role 连接（legacy 脚本）同规则——保住「第二连接可中止 run」的今日语义（`part_03.rs:618` 用例在 epoch 保护下仍绿：接管后新连接的写生效）。role=Observer 的绑定**不获取、不接管 lease**（oracle F1，r1：前端 observer 声明自 T6 前置在场，真 driver 写面不受 observer 连接影响——钉子=Step 1 第三用例）。
  2. **撤销**：holder 连接 close → lease 置空（记录 last_holder/epoch 供诊断）；**不取消 run、不改写状态**（REQ-WCR-02 场景三）。
