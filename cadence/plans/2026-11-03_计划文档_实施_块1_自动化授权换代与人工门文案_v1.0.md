# 块1 实施计划：自动化授权换代一步完成 + 人工门文案可行动化

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「换 provider」从三步塌缩成一步（terminated 记录上直接带新 provider 的 Enable 被接受并完成换代），把授权写失败面按语义拆成两个稳定码，把过期门卡按 durable 停点分流指引，并把三个额度各用各的名字、如实分别呈现两个账面事实。

**Architecture:** 六个可独立提交的切片，后端两片（放宽判定 → 错误码分诊）串行、前端三片（拆分 → 门卡分流 → 额度呈现）串行，跨栈并行。判定放宽严格按 `original_source_dangling` 分路径；错误码用 `ConflictKind` 判别位穿透 `CasResolution` 透传层；门卡分流用新增 WS 字段 `plan_continue_available` 承载「本页底部是否真有『继续自动化』入口」这一服务端权威事实；额度呈现只改呈现层，不动账本/执法点/CAS。

**Tech Stack:** Rust（`src/`，`include!` 片段 + `#[path]` 模块两种接线）、TypeScript / TSX（`web/src/`，React 19 + Zustand + vitest）、测试门禁 `tests/it_core/large_file_guard.rs`（硬线 1200 行，扫 `src` / `tests` / `web/src`）

**Spec:** `openspec/changes/fix-automation-enrollment-provider-swap/`（`specs/work-item-group-autopilot/spec.md` 的 MODIFIED REQ-WIGA-02 / REQ-WIGA-09 + ADDED REQ-WIGA-SWAP-01 / REQ-WIGA-SWAP-02；`specs/human-gate-convergence/spec.md` 的 MODIFIED REQ-HGC-01 + ADDED REQ-HGC-04）—— **需求以这两份 delta 为准，本 Plan 只展开契约，不重新定义范围/架构/验收**。设计依据 `cadence/designs/2026-11-02_技术方案_块1_自动化授权换代一步完成_v1.0.md`（owner 2026-11-02 审阅通过）；额度口径依据 `cadence/notes/2026-11-03_会审_额度池语义_最终裁决_v1.0.md`（三方会审最终裁决，覆盖技术方案 §3.5 的原写法）。

#### 3-F 穷举模式补齐：`gates.rs` 零余量死结的解法（**本版新增，必须按此实施**）

**问题**：`src/product/coding_workspace_engine/gates.rs:1001`（函数 `lease_takeover_store_error`）是 `EnrollmentError::Conflict` 的**穷举结构模式**；该文件实测 **1436 行 / 祖父上限 1436 ⇒ 零余量**（`tests/it_core/large_file_guard.rs:77`），**净增 1 行即红**。

**为什么「同行加 `, ..`」不可行（rustfmt 1.10.0 实测）**：本仓库 `rustfmt.toml` 只设 `style_edition = "2024"`（未改 `max_width`，默认 100），但默认 `use_small_heuristics` 下 **struct 模式的内容宽度上限 = 18 字符**。`{ current_revision }`（14 字符）保持单行；加 `..` 后 `{ current_revision, .. }`（20 字符）会被 rustfmt **拆成 3 行**：

```rust
        EnrollmentError::Conflict {
            current_revision, ..
        } => ProductStoreError::Conflict {
```

⇒ **+2 行**，门禁必红。**这就是「加字段 vs 零余量」的死结所在**（不是行宽超标，而是 struct 模式的 `struct_lit_width = 18`）。

**解法（已实测净 0 行）**：把该臂改成 **rest-only 模式 + 前置 `ref` 绑定 + 访问器**，`id` 改为等价调用。

现状（`:1001-1004`，4 行）：

```rust
        EnrollmentError::Conflict { current_revision } => ProductStoreError::Conflict {
            kind: "enrollment_command_ledger",
            id: format!("current_revision={current_revision:?}"),
        },
```

改为（仍 4 行）：

```rust
        ref err @ EnrollmentError::Conflict { .. } => ProductStoreError::Conflict {
            kind: "enrollment_command_ledger",
            id: format!("current_revision={:?}", err.conflict_revision()),
        },
```

**格式稳定性（rustfmt 1.10.0 实测）**：`ref err @ EnrollmentError::Conflict { .. } => ProductStoreError::Conflict {` = **83 字符单行**（`{ .. }` 内容仅 2 字符 ≤ 18），arm 体 3 行不变 ⇒ **整臂仍 4 行，净增 0**。

**配套访问器（加在片 3 自己的文件里，不占 `gates.rs` 行数）**：`src/product/models/automation.rs`（实测 **561 行 / 上限 1200**）新增：

#### 5-D 前端分流单一事实源（新文件 `gate-stale-guidance.ts`）

```
staleGateGuidance(
  sessionStatus: WorkspaceSessionStatus | null,
  actionBlockReason: GateActionBlockReason,     // 必带：区分「已过期」与「正在等你拍板」
  planContinueAvailable: boolean | null,          // WS 事实
): { copy: string; action: "continue" | "none" | "terminate_optional"; showTerminate: boolean }
```

**分流表（主键 = durable `sessionStatus`）**：

| durable 状态 | 文案（成品） | 指向 | `showTerminate` |
|---|---|---|---|
| `confirmed` | 「这一版已确认完成，此卡是历史记录，无需处理」（**沿用现有 `GATE_STALE_COMPLETED_COPY`，逐字不改**） | 无 | `false` |
| `terminated` | 「这次自动化已经终止了，这张卡是历史记录，不用再处理。」 | 无 | `false` |
| `stopped_needs_human`（**且 `planContinueAvailable === true`**） | 「自动化停在等你回话的地方，这张卡已经过期了。请在页面下方的输入框里写一两句说明，然后点『继续自动化』—— 它会带上你的说明接着跑，不用重新开始。」 | 底部输入框 +「继续自动化」 | **`false`** |
| `stopped_needs_human`（**且 `planContinueAvailable !== true`**） | 「自动化停下来了，但这张卡已经过期。自动化当前不接受新的输入，请刷新页面看最新状态，或到自动化控制面处理这一轮。」 | 刷新 / 控制面 | `false` |
| `failed` | 「这一轮自动化跑失败了，这张卡已经过期了。请在页面下方点『继续自动化』重试；也可以先写一两句说明，一并带给 AI。」 | 底部输入框 +「继续自动化」 | **`false`** |
| 其余（推进到别的门） | 「会话已经走到下一阶段了，这张门卡不再接收操作。请以页面最新的一张门卡为准；如果这一轮确实要作废，可以点下面的『终止此门』。」 | 最新门卡 | **`true`**（保留为可选出口） |

**⚠️ 非过期卡（`actionBlockReason === null`）不在本表管辖**：其 `showTerminate` **默认 `true`**（**owner 正在用的「终止此门」按钮必须保留** —— 现状 `GatePromptEntry.tsx:773-784` 的终止按钮**不在** `action_block_reason !== null` 分支内，除「已确认完成」外**所有**门卡都有）。**若只按「过期卡走分流表」实现而不处理非过期卡 → 所有普通门卡的「终止此门」按钮会消失。**

**文案与真实按钮措辞一致**：分流文案里引用的按钮名（「继续自动化」「终止此门」）**必须与页面上真实按钮的文案逐字一致** —— 「继续自动化」取自页面既有文案，「终止此门」= `GATE_TERMINATE_BUTTON_LABEL`（`web/src/state/gate-prompt-copy.ts:238`，值「终止此门」）。

## 验收命令自检（**每条 `cargo test --lib <filter>` 落地前必须过这道机械闸**）

**为什么必须有这一节**：`cargo test <filter>` 匹配 **0 个用例时退出码仍为 0**（块2 已实测：`root_recipe_receipt` → 15 tests、`failure_copy` → 0 tests，**两者退出码都是 0**）。⇒ **退出码不能当门禁判据**，必须机械判定匹配数。

**统一自检式**（每组过滤器跑一次，`$filter` 替换）：

```bash
n=$(flock /tmp/aria-cargo.lock cargo test --locked --lib "$filter" -- --list 2>/dev/null | grep -c ': test$')
test "$n" -gt 0 || { echo "FAKE FILTER: $filter 匹配 0 个用例"; exit 1; }
echo "OK $filter -> $n tests"
```

- 输出行格式固定 `<module::path>::<test_name>: test`，末行是 `N tests, M benchmarks` ⇒ 用 `grep -c ': test$'` 数**真用例**。
- 冷启编译约 2 分钟/单元；`flock` 串行化（C-6）。

**本 Plan 全部过滤器的逐条机械核对**（2026-11-03 静态核验：`grep -rn "fn .*<filter>" src --include=*.rs`，与 `--list` 等价——过滤器匹配的是「模块路径 + 测试名」的子串）：
