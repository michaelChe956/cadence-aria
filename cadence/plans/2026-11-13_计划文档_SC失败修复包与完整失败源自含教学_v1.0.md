# SC 失败修复包与完整失败源自含教学 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先让 SC 每轮失败事实、真实 raw 与教学正文耐久可核验，再交付严格发布的只读失败包，并让三类教学使用完整失败 source、超过 262144 UTF-8 字节时零新增启动。

**Architecture:** 按 controller 已选顺序执行：A4 evidence DTO/store → round binding/integration → strict package publication/frontend consumer → A3 resolver/render/三类失败集成。沿现有 LifecycleStore、split handle、ArtifactVersion/ArtifactRef/ArtifactUpdate 与教学窗口实现，不新增模型调用、另一套预算或恢复状态机。新证据是 append-only 底座；工件是用户载体；发布回执是可见屏障，不把三个概念混为一个成功标记。

**Tech Stack:** Rust edition 2024（Cargo.lock／rust-toolchain.toml 既有工具链）、serde/serde_json、SHA-256、现有文件锁与原子写；TypeScript/React/Zustand、pnpm/Vitest；页面验收只用 controller 的内置 browser。

**Spec:** `openspec/changes/deliver-sc-failure-repair-package/{proposal.md,design.md,tasks.md,specs/work-item-plan-single-candidate/spec.md}`；人读设计 `cadence/designs/2026-11-13_技术方案_SC失败修复包与完整失败源自含教学_v1.0.md`；接地 `cadence/analysis-docs/wig-product-flow-2026-11-13/a4a3-grounding.md`。本 Plan 展开 W01–W20（含 W11a–g），不以 tasks.md 替代 Plan。

## Global Constraints

- 仅 SC 原轮／教学轮统一 split 身份，包含非 LC 直连；非 SC legacy 不新增身份／raw／SC 日志，已有 Logical legacy 审计保留。
- 仅 A4 新增严格发布入口；普通 `update_artifact`、全局事件结构与全局吞错策略不重构。禁止先调用旧入口再补查。
- 保留 typed 资格、准入、claim／真实启动分账、A/B 池、最多两次实际作者调用（原轮＋至多一次教学）、失败码与旧 candidate attempt 身份。RoundBound／split 序号／claimed attempt 均不是实际启动证明。
- SHA-256 = 同一文本 UTF-8 原字节的 64 位小写 hex；bytes = 同一字节长度，不含 JSON 转义、source 包装与围栏。source 不 trim、不截断、不摘要替代。
- `WORK_ITEM_PLAN_MARKDOWN_PROMPT_MAX_BYTES = 262_144` 唯一来源是 `src/product/work_item_split_engine/prompts.rs:39`；最终教学全文 `<=262144` 允许，`>262144` 显式拒绝，完整超限正文仍先审计。A1 的 `MAX_PARSE_FACT_BLOCK_BYTES = 32_000`、四条指令限制及整条省略不变。
- raw/source/prompt 必须是 `available { locator, sha256, bytes }` 或 `missing { code, detail, round_id }`，不以 None／空串／全零摘要伪造已保存。missing 可出现在 incomplete 包，绝不能成为教学 fallback。
- 成功 Candidate、Routed、admission waiting、健康 Superseded、失败前取消不产终局包；失败后取消可组包但保留原取消状态；启动 Unknown 保持既有等待／对账，不自动改终局。

### 1.4 红绿与可提交的含义

- 每片≤3文件（测试和模块登记算文件），单片预计≤3h，独占清单外命中只报告，不让 worker 自行扩大迁移。

### 2.3 日志、身份和store接口（P05定义，非现有API）

`ScFailureEvidenceEntry { schema_version:u32=1, entry_seq:u64, entry_key:String, chain:ScFailureChainIdentity, event:ScFailureEvidenceEvent }`；entry_seq仅store分配、1起连续。**entry_key固定逻辑槽、不含body digest**（chain目录已隔离）：RoundBound=`round/{round_id}`，FailureObserved=`failureobserved/{round_id}`，两Prompt事件共用=`prompt/{failed_round_id}/{target_round_ordinal}/{disposition}`，ChainTerminal=`terminal`单槽。正文独立计算摘要并比较完整事件内容，不新增持久元字段；same key＋same body原字节幂等不增seq，same key＋different body显式Err且文件不变，禁止body变化自动改key绕过冲突。Prepared→Sent是disposition不同的显式事实槽，不覆盖旧行；PromptPrepared/Unavailable若其余逻辑槽相同而event正文不同也必须冲突。
