## Global Constraints

- LC root identity 取 manifest `provider_context_root` 的 canonical path；产品 LC record id 用于 `for_lc` scope，manifest `logical_codebase_id: Uuid` 用于政策 identity/locator，两者不得混用。
- 五步保持 `MachineSkills → AggregatePreflight → PreCheck → RuleAndMcpConfig → OpenspecAndExamples`；四命令精确为 `/pre-check --no-interrupt --upgrade 用大陆镜像`、`/rule-config --no-interrupt`、`/mcp-configuration --no-interrupt`、`/project-rules-examples --no-interrupt`。命令身份消费 `root_recipe_command_index()`，不另写索引表。
- 首次 `ensure_bootstrap` 保留现有 identity 检查与已有 artifact 原样返回；临时政策只供有效 bootstrap credential 相位，不删除既有调用，不把真正文降回桩。
- 正文来源固定为根 `AGENTS.md` 与 `.claude/rules/` 全部常规 `.md` 文件；入口优先、其他规范相对路径按字节序排列，必须含 `.claude/rules/language.md`。原 UTF-8 字节、CRLF、front matter 均保留；不拼接 CLAUDE/provider 副本、MCP/settings 凭据、成员规则或 examples 模板。
- 正文格式冻结为 `# 聚合政策\n\n`，每个来源依次追加 `## 来源：<相对路径>\n\n`、完整源文件字节、`\n\n`。插入的标题/分隔用 LF，源字节不 trim、不改换行；正文不含 revision、policy_id、时间或绝对 root。
- 根正文位置是 `canonical_root.join(policy_id)`，`policy_id = policy/{project_id}/{manifest UUID}/{revision}`，无扩展名；artifact 仍为 LC scope 的 `aggregate-policy.json`，最终 receipt 仍为 `aggregate-recipe-receipts/{operation_id}.json`。不新增公开发布 API或状态机。
- `policy_digest` 是聚合完整正文原字节 SHA-256；`rule_digest` 仍只取 `AGENTS.md` 原字节 SHA-256，二者不要求相等。摘要形态是 `sha256:<小写十六进制>`。
- 同 operation 重入复用不可变候选及时间；实际新 operation 发布当前 revision+1，正文相同也递增 revision；终态同 key 保持既有 conflict，不 reopen 旧 Completed、不改旧 receipt、不删除历史正文。
- 唯一新增消费谓词是已知桩识别，且仅在原 RulesPolicy 将返回 Completed 的位置生效。其他 operation、root、policy/receipt/rule、索引与能力判定不变；resolver、admission、gateway、envelope、bootstrap dispatcher 与 UI 零修改。
- Completed 存量桩迁移入口为 `POST /api/projects/{pid}/logical-codebases/{lcid}/initializations`，JSON 含新 `idempotency_key`。Completed 没有可见 UI 启动按钮；RulesPolicy 的通用 Retry 不执行根 recipe，不以 accepted 代替实际迁移。
- root `policy/**` 不加入 `ROOT_RECIPE_ALLOWLIST`。产品发布发生在四命令审计窗口全部关闭之后，仅新增精确本次 locator/目录；不写规则来源、成员仓或 Git metadata，不宣称 OS 级隔离。
- `.aria` 仍属原所有权冲突，不在已有根复用豁免中；首次注册用户 AGENTS/CLAUDE 仍拒绝。trust、bootstrap credential、成员重核验、单仓四命令/cwd/GitFinalize 不变。
- 按 `cadence/project-rules/build-test-commands.md` 使用 `cargo test --locked --lib <过滤名>`；不带 `-j`，不使用省略 `--lib` 的快反馈命令。新增代码注释和文档使用中文。

## Review Focus

1. **旧桩的一次性 waiting 迁移语义：** 升级后旧证据不变、GET 不重跑，用户明确新 key 才建立新 operation；迁移完成后唯一 guard 不再命中。Task 2 的 `bootstrap_placeholder_with_valid_receipt_waits_for_explicit_recipe_api` 与 Task 5 的存量迁移弧固定该行为。
2. **发布中断恢复幂等：** 命令审计后、正文后、artifact 后、receipt 后中断，Continue 只补材料，不再启动成功命令、不涨同 operation revision、不换 finalize 时间。Task 4 的四个 `root_policy_resume_after_*` 用例固定。
3. **digest 漂移：** 输入清单/源字节变更、root/UUID/scope/base revision 变化、根 locator 不同正文均冲突；非桩的既有 drift reason 不能被新 guard 覆盖。Task 1 发布负例、Task 2 precedence 回归、Task 4恢复负例固定。
4. **重跑预检负例：** receipt 不存在、错 LC/root、四命令缺失或 Rejected、AGENTS/CLAUDE 未证明字节、用户新文件、symlink/.aria 均拒绝，不以存在文件名表示产品归属。Task 3 的负例矩阵及原首次注册测试固定。
5. **E2E 无 fixture 物化：** fresh-LC 必须经真实产品登记与 Claude recipe生成政策；迁移必须实际跑 API，禁止 stageF 物化、直写 policy/receipt/index 或 mock provider 代证。Task 5 记录完整 HTTP、provider、原生读取、三方 SHA 与成员基线。
