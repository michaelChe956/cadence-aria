# 多仓执行安全桥 C-1 实现计划（WP5a 收尾 + WP5b 执行核心）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让多仓库 issue 的每个 WorkItem 在各自目标仓的独立 worktree 真正 coding 且安全隔离（attempt 冻结 target 快照 + 统一 admission + 三元键 worktree + mixed-target 拒绝 + post-hoc 越界检测），单仓行为完全不变。

**Architecture:** 承接阶段 B 产出的 per-item `target_repository_id`。product 层加 snapshot factory（从 WorkItem/group unit target 冻结三层身份）；admission 用 API 可见性保证不可绕过（`save_coding_attempt_with_status` 私有化 + 受控转换消费 AdmissionTicketRecord CAS）；shared worktree 单仓老路径不变/多仓三元键新路径（无迁移）；mixed-target routing-aware 三处拒绝；COD-01 分层(c)——worktree+cwd 完整 + post-hoc 越界检测（事中配置级阻断随 C-2）。

**Tech Stack:** Rust（axum + tokio + serde），single crate `src/`；前端 React + TypeScript + vitest。

**设计依据：** `cadence/designs/2026-08-11_方案设计_多仓执行安全桥C1_v1.4.md`（4 轮 reviewer 收敛）
**权威需求：** `openspec/changes/2026-08-05-add-logical-codebase/specs/per-repo-coding-execution/spec.md`（REQ-COD-01~04）

## Global Constraints

- **单仓红线**：所有改动只影响 Logical（多仓）分支；单仓（Legacy，`logical_codebase_ref=None`）attempt `target_snapshot=None`、shared worktree 走老路径 `issue-shared-worktree.json`、跳过 mixed 校验，全程不变
- **错误码契约**：`repository_routing_*` / `involved_repositories_undetermined` / `change_order_required_for_logical_codebase` 等既有稳定码不漂移；新码进 `error.rs` 显式映射（见 §4.6 稳定码表）
- **TDD 红线**：不删测试、不弱化断言、禁 `-j 1`；每 Task 先失败测试后实现
- **experimental + supervised**：C-1 后多仓 coding 仍标 experimental（design.md §5.2「路由级 fail-closed ≠ 端到端 supported」），事中配置级阻断随 C-2
- **Rust 命令**：`cargo test --locked --lib <名>`（定向）、`cargo clippy --all-targets --all-features --locked -- -D warnings`、`cargo fmt`；前端 `cd web && pnpm test` / `pnpm tsc -b`（禁 npm/yarn）
- **门禁基线**（B 收尾后）：lib 2038/0、it_web 331/0、前端 vitest 806/0
