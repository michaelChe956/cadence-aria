# WIG · SC 作者努力档位显式化（explicit-sc-author-effort，串行序 4）实施计划 v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Claude SC 作者轮的努力档位从隐式变成显式：新增服务端内部冻结执行策略 `ProviderEffortConfig`（`policy_version` / `provider` / `author_effort` 三元组，默认档 **high**，裁决 §3.3 已定案 low 否决），新的 Claude + SingleCandidate author 原运行在**创建时冻结**；SC author 出口（初轮 / 教学重驱 / SC 人工修订 / resume / 明确 fresh）经新模块 `prompts/sc_author_input.rs` + `prompts/sc_launch_policy.rs` 装配 caller env（G-1 `CLAUDE_CODE_EFFORT_LEVEL=high` + G-2 `MAX_MCP_OUTPUT_TOKENS=4000` + G-3 `BASH_MAX_OUTPUT_LENGTH=8000`；**G-6 TTL 本期不启用**）；冻结事实逐字段贯穿创建 / 恢复 / 接管；无冻结事实的存量运行保留旧继承并披露未知；`policy_version` 不可识别 ⇒ 零 provider 启动 + typed 错误（fail-closed）。

**Architecture:** 三层分工——① 承载面：durable 记录上的可缺省内部字段（**不扩**公共 `ProviderConfigSnapshot`，wire / TS / coding 转换链零改动）；② 作用域：**出口分流**——SC 专用构造器挂在 `WorkspaceEngine` 上（`impl WorkspaceEngine` 落子模块文件，先例：`compile/single_candidate.rs` 等），共用 builder 家族（legacy outline / PlanRevision / Draft/Batch）保持空 env 不动；③ 注入：caller env 显式覆盖层走**既有透传路径**（`run/gateway_start.rs` 的 caller `input.env_vars` 原样透传注释段、`provider_gateway.rs` 保留 caller 显式覆盖、Claude direct/validated spawn 已消费 `input.env_vars`）——**零 adapter 改动、零新注入机制**。

**Tech Stack:** Rust（`src/`；`#[cfg(test)]` 单测 + `include!`/`mod` 两种测试接线）、sha2 0.10.9 + hex 0.4.3（已在依赖树，**禁新增依赖**）、thiserror（已用先例 `provider_availability_gate.rs`）、tracing（已用先例 `workspace_engine/conversational_gate_parts/*.inc.rs`）、行数门禁 `tests/it_core/large_file_guard.rs`。

**Spec:** `openspec/changes/explicit-sc-author-effort/`（proposal.md / design.md / tasks.md 46 工作包 / specs/** 三份 delta——**Plan 与 change 目录同行**，实施者必读）；串行序唯一权威 `cadence/designs-reviews/2026-11-09_裁决_WIG四change审阅问题处置_v1.0.md` §2.2 与 §2.2:106；上游裁决 `cadence/designs-reviews/2026-11-08_决策_WIG六项owner裁决_v1.0.md` §3.1–§3.5。
