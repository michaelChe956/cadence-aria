## 二、UI-1/UI-3 的共享契约(先定, 两项都依赖)

抽屉定位状态需统一表达: 面板种类 · planId · 详情 attemptId · workItemId · gateId/choiceId; 扩展现有 /workbench search 并**合并**既有 search(现仅写 focus 会覆盖定位)。建议主开发先冻结字段命名, 两项共用。

## 三、验收要点(实施后由 owner 走 UI 复验)

1. 总览从 Issue 工作台打开为抽屉, 点行看单仓详情、返回总览; 全程 Issue 定位不丢
2. 旧总览链接可用(重定向到抽屉形态)
3. 抽屉关闭停止其轮询; 详情仅单实例(无双 store)
4. 「仅删除当前 Coding 工作区」按钮消失; 全量删除与生命周期抽屉清理入口仍在; 独立 WI 清理路径未被误删
5. 分类/分诊/choice 等待项出现在待处理抽屉, 可直接答复/操作, 不跳 Coding 页
6. 通知点击打开同一抽屉并聚焦事项, 不新增第三套入口
7. 引导入口在右上角, 旧位置消失, 首次展示与已读行为不变
8. 前端无 console 报错; 既有测试(WorkItemPlanOptionsDialog / CodingWorkspacePage / group-delete / delete-race / router)全绿
