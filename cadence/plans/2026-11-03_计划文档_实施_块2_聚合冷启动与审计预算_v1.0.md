## 0. 全局约束（违反即返工）

1. **`failure_copy.rs` 是依赖中枢** —— 由**片2 一次性写全**块2 涉及的全部 `reason_code` 码表条目（含片3/4/5 产出的码）。**片3/4/5 一律不得编辑 `failure_copy.rs`**：它们只负责让记录带上正确的 `reason_code`。片7（安装/更新）是**另一个能力面**，其文案在 `provider_installation/failure_classify.rs` 内自持，也不写 `failure_copy.rs`。
2. **审计预算的元数据差分法必须保留全仓两遍扫描** —— 只把「读内容算哈希」缩小到「元数据变化过的文件」。**禁止**改成只扫改动路径，**禁止**引入 inotify/事件驱动（REQ-AUD-01 明文禁止）。
3. **npm 必须一个包一次装** —— 五个包（claude/codex/pi/codegraph）**禁止**合并成一次 `npm install -g a b c ...`。devbox 2026-10-28 实测：五个包同批会 >20 分钟无进展、磁盘零增长。
4. **provider 走 request，不进 driver 字段** —— `GatewayFactoryProviderTurnDriver` 是 state 级单例（`src/web/handlers/aggregate_initialization/production_dependencies.inc.rs:44-70`、装配点 `:873`），`for_lc` 不派生它；塞进字段会跨 LC 串味。
5. **选择器与 gateway 共用同一判定函数** —— `launch_cell_state` 只有一份实现，`require_supported` 与选择器都调它；**准入不放宽一个字节**（只有 `Confirmed` 放行）。
6. **不自动触发能力核验** —— `provider_capability_revalidate` 的「不点击不运行任何探针」契约不变；失败面只指**单个**「核验 X」，**不得**指向块3 的「一键核验全部」（块2 上线时它还不存在）。
7. **不 `git add`** —— 各片落地后由 controller 统一提交；worker 只在报告里显式列改动文件。
8. **不改 spec delta / 技术方案 / `proposal.md`**；不改 `tests/it_core/large_file_guard.rs` 的登记表（本计划已把改动压到零余量以内，不需要新增登记项）。
9. **不改**（owner 裁定，见技术方案 §3.7 / §4）：B-5 残项 R1（重新初始化预览+备份）/ R2（workbench 透出 details）、`with_snapshot_budget()` 生产接线、`AggregateIndexStatus::Degraded` 的 rebuild/sync 语义、「已初始化」判定文件、`aggregate_root_ownership_conflict` 兼容映射臂。

### 7.2 契约

````rust
// 元数据差分（两遍全仓扫描，第二遍不读内容）
struct SnapshotMeta { path: PathBuf, size: u64, mtime_ns: i128 }
// 变化判定：size 或 mtime 变化 → 该文件读内容算 hash；.git 子树在第一遍就被整体跳过
// **预算口径 = 本次变更量（REQ-AUD-01）**：`bytes` 与 `entries` **都只对「进入变更清单的路径」计**；
//   未变化路径与 .git 子树一律不计字节、也不计条目（否则 >20 000 文件的存量仓仍会因
//   `max_entries` 失败，与「存量体量不再压垮预检」场景冲突）
// 计费时机：流式读（块 64 KiB）时边读边累加字节并算 sha256，越限立刻停
// .git 跳过：路径任一段 == ".git" → 整棵子树不计条目/字节/快照
// classify_member_git 的 MemberGit/MemberWorktree 分类保留（用于「命令试图改 .git」判定）
````

**分组键语义**：`top_groups` 的 key = `<成员仓目录名>/<一级目录或 <文件>>`（例：`pms/target`、`busi/target`、`root/AGENTS.md`），按字节降序取前 10；`member_summaries` = 每个成员仓的 `{ member, bytes, entries }`。
