## 2. 批次 1：Issue 1 — `work-item-group-autopilot`（新 OpenSpec change）

流程：brainstorming（本计划已含大部分输入）→ proposal → 用户批准 → writing-plans → TDD 实施。

### 2.1 架构决策（oracle+max-task 收敛）

| 决策 | 结论 | 要点 |
|---|---|---|
| D1 编排者 | **B：同进程独立 AutopilotOrchestrator（薄）** | 只决定「何时请求下一动作」（EnsurePreparedPlan/StartPlanGeneration/AdvancePlan/StartCodingOnce 四动作）；动作经共用应用服务执行（plan 走 manager spawn、coding 走共用 StartCoding 服务）——不建第二 provider 驱动点（REQ-WCR-01 保持）。否决 A（manager 边界=单 session 且会被内存回收，enrolled 链跨多聚合）与 C（引擎内联≈REQ-ADV-05 禁止的「随 advance 形态落地」） |
| D2 enrollment | issue 级 durable `IssueAutomationEnrollment`（独立小记录，非 issue 布尔字段）+ attempt 物化 `CodingStartRunPolicy`（默认 Manual；AutoStartOnce{enrollment_id, policy_revision, source_plan_revision}） | **plan session run_policy 保持 Interactive**（既有 AutoIfValid 会跳人工门，禁止复用）；精确绑定 source design/plan/session；未消费的执行许可可被当前授权撤销（max-task 语义，严于 oracle） |
| D3 choice 回复 | REST `POST /api/workspace-sessions/{session_id}/choices/{choice_id}/response`，与 WS 共用 claim/resolve 入口 | observer 保持只读（REQ-WCR-02）；需真实交付回执（bridge oneshot 解析结果，非仅 mpsc send）；coding 阶段 choice 需对应入口 |
| D4 coding 启动 | 抽共用 typed `StartCoding` 应用服务（origin: Manual \| Enrolled），WS 与编排器都调它；**不裸调 runner** | 同一 attempt 临界区内完成：reload→状态矩阵→授权核验→Ready 检查（复用 SC_CODING_REQUIRES_ADVANCE 语义）→单发认领→启动；重复命令命中幂等结果 |
| D5 完成通知 | durable 事实派生 info 条目进 CockpitInbox（kind=info）：plan confirmed=成功 publication/compile 的 Completed milestone；coding 完成=attempt.status=Completed | 不进待处理计数、稳定 key 去重、TTL 从 occurred_at 算不因刷新续期；CockpitShell 拆 displayItems/actionableCount/notificationCandidates；补有界近期完成读取（observer K=8 窗口外也能发现） |
| D6 前端退位 | session 投影暴露 `automation:{owner}`；owner=server 时 useCockpitAutopilot 不再 sendAdvance | 非 enrolled 行为不变；「零回归」口径=业务/门禁/错误/恢复语义不变（非字面零改动） |

### 2.2 Spec delta 清单（change 必交付物）

1. **MODIFY `work-item-plan-conversational-gate` REQ-CG-04**：原文「门关闭 SHALL NOT 自动触发 advance；advance 由客户端显式调用」需为 enrolled 服务端推进写显式例外（门关闭≠成功；仅 durable Confirmed + 仍 enrolled 才可由编排器请求 advance）。
2. **MODIFY `work-item-plan-advance` REQ-ADV-05 + Purpose**：条件 defer 转显式定义；逐字承接五条红线（opt-in 持久化 run_policy / 默认 off / per-attempt 单发 / 绝不批量 / 不动唯一人工门）；同步 `advance_split.rs:37` 注释。
3. **MODIFY `multi-target-group-coding` REQ-MTG-03 边界澄清**：按 §4-R1 用户裁决落例外或限制。
4. 人工门宿主唯一性不破（REST choice 只转发 ApprovalBridge，不建第二门）。

### 2.3 Phase 切分（max-task 版，控制面先行）

| Phase | 交付 | 关闸验收（替身+真实链双清单） |
|---|---|---|
| **P0 控制面** | 3 份 delta；enrollment/epoch/幂等基础；automation 归属投影+D6 退位；**choice REST+驾驶舱无 driver 操作闭环**；既有门/recovery 入口无 driver 联动。自动触发不开放 | choice HTTP/WS 竞争/重试/冲突/过期；observer 写仍拒；真实链：手动启动→关闭 driver→仅驾驶舱操作 choice/门/recovery |
| **P1 后台 plan** | design 确认后选择框；幂等 enroll→prepare→start_generation（经 manager）；人工批准后既有 compile 链；plan confirmed 通知 | 重复 enroll/中窗崩溃/活 run 不 supersede/不跳人工门；真实链：确认 design→选自动化→关页面→驾驶舱完成人工动作→Confirmed+通知；重启可恢复 |
| **P2 后台 coding** | 共用 StartCoding 服务+单发；无页面启动/恢复；**修 amendment 的 coding socket 承重依赖**（业务推进与观察投递解耦）；coding 完成通知 | 全 journal 中窗/并发启动/无 socket 下 choice+amendment+resume；真实链：plan 批准后不开 coding 页完成 advance+coding；覆盖一次 choice 与一次 amendment；重启不等 attach |
| **P3 补读与关闸** | 近期完成投影、TTL/去重、跨刷新通知联动；15 条全映射+非 enrolled 对照链；多 target 边界确认 | 乱序/丢失唤醒/K 外完成/无通知风暴/enrolled 与手动不串授权；两条完整真实链对照 |

### 2.4 风险 Top3（max-task，实施时缓解）

1. 多主体竞争+跨对象半提交 → 重复计划/重复启动（enrollment-bound 创建身份+稳定 action key+attempt 单发+epoch 线性化核验）。
2. 表面后台化、实际 WS/长锁/进程内对象承重（choice REST 不得等 engine 锁；重启后旧 oneshot 失效；amendment 不等 live socket）。
3. 授权扩大/零回归破坏（不用 AutoIfValid、不继承历史 plan、不 fan-out、保留 Final Confirm）。
