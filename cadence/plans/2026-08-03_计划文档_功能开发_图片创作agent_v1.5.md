# 图片创作 Agent 实施计划（Implementation Plan）v1.5

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Cadence Aria 新增独立顶层的图片创作 Agent——用户多轮对话迭代图片 prompt（复用现有 CLI 执行器），确认后由 Aria 后端调用 gpt-image-2 网关生成单张图片并在前端展示。

**Architecture:** 后端新增 reqwest 图片客户端（按有无参考图选 `/generations` 或 `/edits`）+ image-create 会话/设置 handler（复用 `StreamingProviderAdapter` 做 prompt 迭代、`AriaStatePaths` 做持久化）；前端新增 `/image-create` 顶层路由与图片创作页面（复用 chat-workspace 展示组件思路，独立 entry 模型）。两阶段解耦：执行器只聊文本，Aria 后端统一调图片 API。

**Tech Stack:** Rust（edition 2024）/Axum/Tokio + reqwest(json,multipart,rustls-tls) + image；TypeScript/React 19/TanStack Router/Zustand/Tailwind/Vitest。

**契约来源：** `openspec/changes/add-image-create-agent/`（4 轮独立 review 收敛）；PRD `cadence/prds/2026-08-03_概要需求_图片创作agent_v1.2.md`。本 Plan v1.5 按 5 轮 Plan review 修订（修正 nonce 契约、依赖 feature、任务依赖顺序、scripted fake、key 清除语义、session id 校验、现有代码零侵入约束）。

  ```text
  <ARIA_STRUCTURED_OUTPUT nonce="a1b2c3d4">
  {"suggested_prompt":"..."}
  </ARIA_STRUCTURED_OUTPUT nonce="a1b2c3d4">
  ```

  - `axum = { version = "0.8", features = ["ws", "multipart"] }`（当前仅 `ws`，必须加 `multipart` 否则 `axum::extract::Multipart` 编译失败）。
  - `reqwest = { version = "0.12", default-features = false, features = ["json", "multipart", "rustls-tls"] }`。
  - `image = { version = "0.25", default-features = false, features = ["png", "jpeg", "webp"] }`（**不启用 gif**；GIF 一律按 `InvalidFormat` 拒绝，因为允许 MIME 仅 png/jpeg/webp）。
  - dev: `mockito = "1"`。
- **🔴 API key 更新语义（可判别）**：`ApiKeyUpdate` 枚举 `{ Retain, Replace(String), Clear }`（`Option<String>` 无法区分「保留」与「清除」）；DTO 序列化为可判别形式（如 `{ "api_key_action": "retain"|"clear", "api_key": "..." }`，replace 时两者同时传）。
- **🔴 session id 校验**：所有 `SessionStore` 公共方法首行调用 `crate::product::json_store::validate_relative_id(id)`（防 `../`/绝对路径/分隔符目录穿越）；REST/WS 的 `{id}` 路径参数非法 → 400。
- **🔴 provider 选择（实现必需）**：`ImageCreateSession` 必须含 `provider_name: ProviderName` 字段（创建会话时由用户选，默认第一个可用执行器）。`PromptIterationEngine::iterate` 用 `session.provider_name` 从 `ProviderRegistry::get()` 取 adapter，`StreamingProviderInput.role = AdapterRole::Executor`（复用现有枚举，不新增 role；见 `src/protocol/contracts.rs:35`）。无可用 provider 时 iterate 返回可读错误。
- **🔴 ProviderAvailabilityGuard 位置**：`/image-create` 路由**放在 guard 外**（图片创作只依赖用户配的 image2 key，不依赖 claude/codex CLI；guard 在 `realWorkflowBlocked` 时整页替换为 dialog，会阻止无 CLI 用户进入）。实现：为 image-create 单独建一个不经过 `ProviderAvailabilityGuard` 的 root layout（或调整 `router.tsx` 结构），现有 workbench/coding 路由仍留在 guard 内不变。
- **🔴 不复用 `FakeStreamingProvider`**：它是不可配置单元结构体，无法注入 `suggested_prompt`/session 失效；prompt 迭代测试用**自建 scripted fake**（见 Task 7）。
- **🔴 不复用 `requestJson`** 于 multipart：它是私有且强制 `content-type: application/json`；generate 的 multipart 直接 `fetch` + `FormData`（**不**手动设 Content-Type，保留 boundary）。
- **🔴 配置路径（与契约 design.md 一致）**：settings 存 `.aria/image_create.json`（**非** `.aria/image_create/settings.json`）；sessions 存 `.aria/image_create/sessions/<id>.json`（契约未约束，Plan 自定）；scratch 存 `.aria/image_create/scratch/<id>/`。
- **🔴 ApiKeyUpdate wire（前后端一致）**：定义独立 REST 请求 DTO `SettingsUpdateRequest { base_url: Option<String>, api_key_action: "retain"|"replace"|"clear", api_key: Option<String>, defaults: Option<DefaultParams> }`；handler 反序列化此 DTO 后转领域 `SettingsUpdate { api_key: ApiKeyUpdate }`（retain→Retain，clear→Clear，replace+v→Replace(v)）。前后端共用同一 JSON shape。
- 图片参数枚举（逐字）：`size` ∈ {1024x1024, 1536x1024, 1024x1536, auto}；`quality` ∈ {low, medium, high, auto}；`background` ∈ {transparent, opaque, auto}；`output_format` ∈ {png, jpeg, webp}；`input_fidelity` ∈ {low, high}。
- 参考图约束（逐字）：单张；仅静态图 png/jpeg/webp（GIF 一律 UnsupportedMime）；≤10 MB；解码后单边 ≤4096、总像素 ≤4096×4096；按实际文件内容校验；受限解码；**多帧检测用 `image::ImageDecoder::is_animated()`（覆盖 APNG/animated WebP，非仅 GIF）**；不持久化。
- 出站安全（逐字）：`base_url` 仅 HTTPS 或本地回环；默认禁用自动重定向；如允许仅同 origin（scheme+host+port 全同）、拒绝 HTTPS→HTTP 降级、跨 origin/降级不携带 Authorization；日志/诊断/测试夹具不明文记录 `api_key`。
- 生图：每次恰好一张；不自动重试；单会话任一时刻最多一个进行中后端操作；会话删除为线性化（tombstone→等待在途终止/条件写入→无在途写入才清理，删除后异步完成不回写）。
- key 边界：`api_key` 仅后端 reqwest 鉴权；绝不传 CLI 子进程；GET 返回脱敏；PUT 用 `ApiKeyUpdate` 语义。
- 语言：面向用户文案/文档用中文。
- Plan 只能展开契约，不重定义范围/架构/验收。
