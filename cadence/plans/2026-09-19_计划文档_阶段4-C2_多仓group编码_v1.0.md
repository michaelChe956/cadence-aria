## 全局约束

1. **范围铁律（tasks 全局边界）**：仅决议一期四项+增殖审计，不加不减。跨 attempt 依赖门自动编排=二期凭一期证据另行立项，任何「简化版编排」变体（按 plan 内 units 依赖跨 attempt 映射、自动顺序拉起、依赖驱动拉起）均越权（REQ-MTG-03 红线句+D5）。
2. **单值 schema 红线（D1，REQ-COD-02 保全）**：`CodingExecutionAttempt` 单值字段（`worktree_path`/`head_commit`/`stage`/`target_snapshot`/`branch_name`/`base_branch`）零改动，MUST NOT 数组化或集合承载；REQ-COD-02「创建、恢复、重放一律使用冻结快照、不得从活 Work Item 重新猜测」per-attempt 原样适用；REQ-COD-01/03/05/06 语义不动（T4 仅适配核查非重建）。
3. **守卫零变化红线（D2）**：`StartCoding` 唯一入口与 `SC_CODING_REQUIRES_ADVANCE` fail-closed 语义 per-attempt 适用不改文本；`AdvanceRecord` 每 plan 恰一条（`put_record` 冲突语义不变，advance_store.rs:268-281）+绑定扩展仅 additive（serde default，存量零迁移）；判定扩展=「单值精确匹配或集合包含」，未匹配/缺记录/未 Ready 一律拒绝——fail-closed 语义零变化，不引入 plan 级聚合 Ready。
4. **同批交付红线（决议括号原文+oracle 增殖 UI 风险双锚）**：聚合只读视图（含前端呈现）与拆分能力同批验收（T2+T3 一体关闸），不存在「拆分已交付而聚合视图缺席」的中间态。
5. **单 target 零变化（每 Task 验收）**：单 target 场景（含 0-target focus 唯一）建组/路由/advance/执行/恢复行为与本 change 前完全一致——既有测试族零改语义通过或仅改锚不改断言语义；存量单 target advance record 判定逐字节等价回归锁死（REQ-MTG-03 scenario「绑定关系 additive 扩展兼容存量」）。
6. **unit 级基座不动（REQ-GCE-01..05）**：unit 级依赖门（`admission_kind=sc_advance` 判据+共享 worktree 单 active unit）/失败处理/amendment 链/per-WI 投影语义 per-attempt 原样适用，不因多 attempt 改 unit 级机制。
7. **additive-only durable 红线（Migration Plan）**：advance record 新增绑定字段（serde default）、per-target journal 子路径（存量单 target journal 原路径零迁移）、增殖审计新记录类型；既有单 target attempt/advance/journal 记录读取行为零变化；无 wire 破坏性变更（既有 WS/API 语义保留，新载荷字段 additive）。
8. **无快照存量退化红线（D2.1 定案，k3 F5 可测化）**——四断言（T2/T3 测试锚）：
   - **A1 唯一性豁免**：无快照 attempt 不参与 per-`(plan, target)` 唯一性判定——同 plan 存在无快照 attempt 时新建 target-attempt 不被 `coding_attempt_group_already_exists` 拒绝；per-`(plan,target)` 检索不返回无快照 attempt（不入任何 target 桶）。
   - **A2 不静默归属**：检索不将无快照 attempt 静默归属任何 target 桶（含「最早桶」）——「取最早」检索语义在增殖后由 per-`(plan,target)` 检索+审计面取代（REQ-MTG-05），无快照 attempt 永不作为某 target 的命中返回。
   - **A3 fail-closed 路由**：无快照 attempt 的路由 fallback 保持现行 units 收敛语义（单 target 收敛唯一/0-target focus 唯一/否则 TargetAmbiguous|TargetMissing 稳定码拒绝）——不猜测重路由、不新增归属（REQ-COD-02 先例：display-only/人工恢复）。
   - **A4 display-only**：无快照 attempt 在聚合视图不进 per-target 投影（按 issue 级 attempt 列表既有形态呈现）；其在 per-`(issue,target)` 单 active 检查中不计入任何桶（物理互斥由三元键 worktree lock 兜底——同 target 仓的 lock 竞争仍拒绝）。
9. **三值终态判据红线（REQ-MTG-04+spec「未启优先」句，k3 F4 可测化定案）**：
   - **已达 provider 启动**的可测判据 = attempt 离开初始二元组：`!(status == Created && stage == PrepareContext)`（`StartCoding` 是唯一入口，离开 `(Created, PrepareContext)` 必经 `admit_and_transition_attempt_to_executable`——lifecycle.rs:217-222；stage 离开 `PrepareContext` 同源）。
   - **未启**（判定优先于「部分」）：无 target-attempt，或全部 target-attempt 均满足 `status==Created && stage==PrepareContext`。
   - **全部交付**：存在 target-attempt 且每 target 取最新 attempt `status==Completed` 且最新 ReviewRequest `push_status==Pushed`（review_request 在案）——对齐 `compute_issue_delivery_summary` 口径（issue_delivery.rs:110-113）。
   - **部分**：其余一切（任一 target 已达 provider 启动且非全部交付；「部分启动+部分未启」自然落入）。MUST NOT 伪装全局成功。
10. **与 C3 并行边界（design「change ③ 归档时序说明」）**：落地序 ①→③→②——本 change 实施时 ③（retire-legacy-workitem-protocol）应已归档（REQ-ADV-05/06 在主 specs）；requirements 零重叠（② MODIFIED REQ-ADV-01/02 vs ③ REMOVED 03+ADDED 05/06，k3 §2.2 实读确认）。若实施启动时 ③ 尚未归档：代码面无依赖（③ 动的是 legacy 决策面/wire，本 change 动的是 group 建组/advance 绑定面，产码面除 src/web/handlers/lifecycle.rs（③T5 删 :647-708 legacy fallback vs ②T2 :169+T3 :22-——按落地序 ③→② 串行无冲突，② 锚点均在删除区前行号不漂移；若并行实施该文件须串行交接；测试面 plan_repair 域同域锚点重核总则覆盖）），spec delta 文本互不改；仅 T6 归档时序按 design 双分支说明处置（② 先归档则 ③ delta 不受影响，Purpose 通道以 T6 手工同步并集兜底）。
11. **计划编写阶段不执行 formatter、linter、构建、全量测试或提交**（writing-plans 纪律）；实施时 `cargo`/`openspec` 命令在仓库根执行，前端命令在 `web/` 下执行。
