## Global Constraints

1. **不做物理只读 / no-exec。** owner 2026-10-22 原话：“不需要物理只读，0 写对账 + 恢复就行了。” 不新增能力探针、不恢复旧 deny 口径。
2. **ZeroWrite 仅 plan reviewer。** coding reviewer / internal reviewer 保持单 attempt target 与 B 档 `RecoverableVerification`（临时构建残留恢复后可采信）；任何文案/验收不得声称“全部 Reviewer 已统一零写”。
3. **整轮 fail-closed。** 任一成员不可评审、provider/解析失败、扫描/恢复未完成 → 集合不通过；PARTIAL 仅诊断（`completeness=partial` + `acceptance=not_ready`），不推进 pass / 自动返修 / 交付。
4. **双范围硬分离。** 可读面 = LC 根全树：所有角色 `working_directory = manifest.provider_context_root`、`readable_roots = [LC root]`；对账面 = Issue 选集成员仓及其既有 Git 观察域。二者不得互相收窄。
5. **根级非成员条目不纳入对账域**，报告逐项披露“根域未对账：<root-relative-path>”。固定披露项：`.agents`、`.claude`、`.codex`、`.codegraph`、`.kimi-code`、`.omp`、`.pi`、`.mcp.json`。
6. **成员仓内部同名目录仍完整对账**（含 ignored 产物）。按 **LC 根级路径归属**判定，不按 basename 全局过滤。
7. **重复 common-dir → `plan_review_window_common_dir_conflict`**，整轮零启动、不跳过成员；路线（i）通用内核改造不在本次范围。
8. **禁止首仓/阶段声明收窄。** 外层码沿用 `plan_review_window_target_unresolved`，结构化 reason：`effective_member_empty`、`selection_invalidated`、`member_checkout_unresolved`、`member_not_git_worktree`、`member_identity_ambiguous`。不回落 primary / Story focus / Design involved / 进程 cwd。
9. **预算沿用现行参考上限，不是 N 倍无界配额**：单窗 `max_entries: 200_000`、`max_total_bytes: 2 * 1024 * 1024 * 1024`（`drive.rs:1788-1791`）。实测三仓前不得放大；超限必须报“对账未完成”并阻断，不得截断条目。
10. **测试产物只放 `/tmp`**（`cadence/project-rules/test-content-tmp-only.md:7-21`）：夹具仓、`CARGO_TARGET_DIR`、日志、快照一律在 `/tmp` 子树。
11. **cargo 编译窗口串行。** 同一时间只允许一个 cargo 进程；worker **不得**并行起 cargo，由 controller 统一排队执行本计划的命令。
12. **不触发 Draft Prompt 规则。** 本计划只改 reviewer 报告合同与窗口/对账合同，不改 Work Item Draft Prompt、Canonical Contract 或 Draft 候选 JSON 约束，故不触发 `cadence/project-rules/work-item-draft-prompt-validation.md:5-19`；若实施中发现必须连带，**停下**并按其提醒取得 Case A/B 授权。
