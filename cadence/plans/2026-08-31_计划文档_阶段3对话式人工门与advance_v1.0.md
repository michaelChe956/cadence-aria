# 阶段 3 对话式人工门与 advance 实施计划 v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. 每个步骤均须先写失败测试、看到预期失败，再做最小实现并验证；不要把本计划当作契约修改入口。

**Goal：** 在不重定义阶段 1/2 契约、不删除 legacy WS/入口、不启动自动 coding provider 的前提下，交付 `human_gate_feedback` 多轮 durable 人工门、SC 专属 revision、现有 takeover 的接管后恢复、Confirmed plan 的显式幂等 `advance`、SC-linked group coding 依赖就绪门、同一 attempt 内失败/amendment 恢复，以及从既有 group attempt/unit 派生的只读进展/成果数据面；以 campaign 端到端证明 14 个 REQ 和 37 个 scenario。

**Architecture：** typed WS 命令是唯一对话门/advance 写入口；`WorkspaceSessionRecord` 与 lifecycle store 通过锁内 CAS 保存门快照、turn reservation、预算和 provider-start ledger；`HumanGateTurn`、`AdvanceRecord`、`PlanAmendmentContext` 是独立 durable 记录但通过同一 reservation/journal 的引用关系恢复。SC revision 只读取当前候选全文、typed feedback、grammar 边界和规定的规则上下文，输出完整 markdown 后进入既有 SC compiler/canonical validator，绝不经过 legacy 中文标题约束链。`advance` 只建立/恢复唯一 `WorkItemGroup` attempt、不可变 plan binding、shared worktree lock 和依赖拓扑 units，返回 Ready，不启动 coding provider；coding workspace 是唯一执行/观察权威，SC 子 session 只读投影。legacy group attempt 由持久化 `admission_kind=legacy_group` 隔离并保持原 `order_index` 行为。

**Tech Stack：** Rust 2024、Serde、Tokio、现有文件型 lifecycle/coding attempt/group journal stores、SHA-256/确定性 hash、Axum WebSocket/HTTP、Node.js `.mjs` campaign driver、仓库现有 Rust 单元/handler 测试。

## Global Constraints

- **契约不可改写：** 本计划只实施已批准的阶段 3 proposal/design/tasks/spec；不得新增 requirement、改变字段语义、改变旧协议兼容边界、把 `advance_completed` 解释为 coding 完成，或把 SC 子 session 变成第二 coding 状态机。若实施中发现契约必须修改，立即停止并报告，不在代码或计划中臆造替代契约。
- **阶段边界：** 复用阶段 1 typed outcome、classifier/fingerprint、防环、预算语义、`HumanGateSnapshot`、CAS、provider-start ledger、auto stopped 前提；复用阶段 2 SC compiler/canonical validator、fail-closed、group 初始化 journal、plan binding、shared worktree lock。不得重做或复制这些契约；不得删除任何 legacy WS 消息、`HumanConfirmDecision::RequestChange`、legacy group 入口或旧 REST runtime advance。
- **HumanGate 语义：** 只把 typed `human_gate_feedback { command_id, feedback }` 计为回合；普通 `UserMessage`、重连、ack、approve、abandon 不触发 provider/不耗预算。预算在 durable reservation 时扣减且失败不退；每门最多一个非终态 turn；新 feedback 及 in-flight 期间 approve/abandon 都返回 `gate_busy`，不排队、不关门。相同 `command_id` 返回相同 `turn_id`；同 `turn_id` 的重试不重复扣预算/启动 provider；瞬断在同 turn_id 递增 `attempt_no`，超上限 `Failed(provider_err)`。
- **SC revision 边界：** 新增并只使用独立 `SC_MANUAL_REVISION_PROMPT_QUALITY_BUDGET_BYTES`；不得修改 SC author prompt 的 19,000 字节红线。prompt 必须注入 `.claude/rules/language.md` 全文、grammar 边界和“只改反馈点名内容，其余逐字保留”及删字段/空 Outputs/省略 Handoff Schema 三字段反面清单；不得注入 `code-usage.md`/`code-reading.md` 摘要，不经过 `src/product/workspace_engine/artifact_constraints.rs:189-215` legacy 中文标题链。反馈和 prompt bounded-field 超限必须在创建 turn 前零副作用拒绝；每次真实 provider start 写 ledger，逻辑预算每回合只扣一次。
- **approve/abandon 边界：** `Confirm`/approve 只允许关门并启动现有确定性 compile，compile 成功后才 durable `Confirmed`；`Terminate`/abandon 关门进入终态；compile fail-closed 保持既有语义。预算为零时门保持开启、仅接受 approve/abandon；门关闭不自动调用 `advance`。
- **接管边界：** 只扩展 `src/web/handlers/workspace_session.rs:52-75` 现有 `takeover_stopped_needs_human`，不新增端点。仅无 fatal/persistence diagnostic 的 resumable `stopped_needs_human` auto session 可接管；child 继承 parent 门快照/候选与诊断引用/剩余预算，parent 状态、历史、事件前缀不可篡改；重复接管返回同一 child。
- **advance 边界：** 首次 advance 才执行 `Confirmed`、子 session 存在、无 active compile/revision 前置校验；同 command 或同 plan 幂等命中优先于前置校验。首次拒绝不得创建 `AdvanceRecord` 或其它副作用；成功顺序为 durable record → group journal → 唯一 attempt(`admission_kind=sc_advance`) → plan binding/worktree lock → 依赖拓扑 units → Ready/`advance_completed`；不得启动 coding provider。已有 Initializing/Ready/Running/AwaitingPlanAmendment/Completed/Failed/Aborted attempt 均按 durable 状态返回，Failed/Aborted 不隐式重建。
- **依赖/投影边界：** 依赖图是 SC-linked attempt 的权威顺序，`order_index` 仅确定性 tie-breaker；直接依赖必须 Completed、handoff 已发布且 revision 匹配当前 plan binding；未就绪保持 Pending，全不就绪进入等待态；环/未知/自依赖/handoff mismatch durable fail-closed。`admission_kind=legacy_group` 完全保持既有 order_index 选择。进展/成果只从 attempt/unit 派生：每 WI 的状态/stage、当前/最终 commit、review、handoff、失败/阻塞原因、binding、group 聚合进度；不新增第二状态源。
- **amendment 边界：** `BlockedByPlanDefect → AwaitingPlanAmendment` 复用现有状态；写 durable `PlanAmendmentContext`（plan session、attempt、unit、finding、previous revision、resume target）；反馈回原 SC plan session 门并接续其 `manual_repairs_remaining`，attempt 侧不新开预算。新 revision 通过 SC compiler/validator 后更新 binding，按 Reexecute/Revalidate/AwaitHandoff 恢复同一 attempt；approve 不复用首次 compile 入口，不兼容时 fail-closed。
- **大文件/模块树约束：** `src/product/workspace_engine/tests.rs` 继续使用既有 `include!("tests/part_XX.rs")` 扁平树；新增测试按当前 `part_XX` 和子目录模式放置，禁止把大型测试重新合并进入口文件。实施者先以 `ast-grep outline` 定位符号，再用 `rg`/`nl -ba` 读取目标窗口；不整文件 dump。`src/product/work_item_split_engine/prompts.rs` 当前约 1,110 行，阶段 3 不触碰 author prompt 19,000 字节红线；新增 revision prompt 独立文件/模块并用符号边界编辑。
