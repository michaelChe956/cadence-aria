# 评审范围与跨仓最终评审 实施计划 v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在**不改变单仓库代码库任何行为**的前提下，为多仓库逻辑代码库打通「story / design / work item 三环节评审」并新增「coding issue 级跨仓最终评审（advisory）」。

**Architecture:** 两条互不干扰的改造线。**规划线**（阶段一、二）：以唯一形态门禁 `is_logical_codebase_issue()`（`WorkspaceEngine` 方法）把全部新逻辑挂到多仓分支——多仓不开评审窗、身份改会话 UUID、仓库清单全量注入并进 `[canonical_inputs]` 稳定重放、逐仓实况与逐仓基线进材料、多仓 must-fix 四类、finding 证据完整性、旧轮证据保留、splitter 摘要分层。**Coding 线**（阶段三）：删多仓每仓评审（GroupFinalReview 执行入口物理删除 + 每仓 internal review 条件化停用），新增 issue 级跨仓最终评审（模型 → 持久化 → engine 执行 → 触发接线 → advisory 呈现与留痕），并把 `source_stage` 扩一个枚举成员。

**Tech Stack:** Rust 2024（crate `cadence-aria` / lib `cadence_aria`）、serde、uuid v4（`Cargo.toml:42`）、tokio；测试用 Rust 内联 `#[cfg(test)] mod tests`（惯例见 `src/product/issue_baseline.rs:145-146`）。

## Global Constraints

1. **单仓库代码库（`logical_codebase_id == None`）行为逐字不变**——prompt 字节、事件序列、门控、评审窗口记录、合同 digest 一律不变；所有新行为**只在多仓（`Some(_)`）生效**。（设计 A 硬约束）
2. 多仓**文档环节**评审**不开窗、不做零锁恢复**；单仓保留评审窗口与零锁恢复。
3. 仓库清单**全量**注入，绝对上限 **500 KiB**；超限报 `planning_material_over_budget` 并**阻断**评审启动（不静默缺员、不静默截断）。
4. 逐仓基线 = 各仓 `git rev-parse --abbrev-ref HEAD`；detached / 空仓 → 该仓标「基线未识别」并**继续**；单仓仍 fail-closed（`main`→`master` 猜测链一行不改）。
5. 身份 = **每会话新生成 UUID**，与会话一一绑定，**会话删除即解绑**；单仓维持窗口编号 `{session}-{run}-w01`。
6. coding 跨仓评审 **advisory**：不进交付门 / T19 采信门 / 返工 / 人工分诊；**不阻断确认**；**不做零锁恢复**（不开 reviewer 窗口、不产出 `acceptance` / `review_window_id`）。
7. 删多仓**每仓评审**；**保留 code reviewer（仍是门）**；**保留组形态**（组终审执行入口物理删除，单仓路径逐行不变）。
8. `source_stage` 新增枚举成员 `IssueCrossRepoReview`（序列化名 `issue_cross_repo_review`）；既有 7 个成员取值与 `order()` **相对序不变**。
9. **cargo 编译/测试由 controller 统一串行排队执行**；worker 不得并行起 cargo；**禁 `-j 1`**（`cadence/project-rules/build-test-commands.md:19-21`）。
10. 夹具 / 构建产物 / 日志 / 快照**只放 `/tmp`**（`cadence/project-rules/test-content-tmp-only.md:7-21`）；`CARGO_TARGET_DIR` 指向 `/tmp` 子目录。
11. **行号口径**：本计划所有行号均为 2026-10-23 **bash 实测**（`grep -n` / `wc -l` / `sed -n`）；与仓内 `read`/`grep`/CodeGraph 过期快照冲突**以 bash 为准**。
12. **契约口径**：契约 delta **全部为 ADDED**（无 MODIFIED）——本计划**不得**表述为「修订既有条款」，只表述为「新增多仓行为，单仓不变」。**归档顺序硬门**：若 `provider-desandbox-full-open` 先归档，须先以 MODIFIED 修订主规范 `REQ-ENV-REVIEW-B` 的适用范围，否则与 `REQ-ENV-14` 矛盾（见该 change 的 `design.md`「与在途 change 的重叠面与归档顺序」）。本计划**不碰** `openspec/`，该门由 controller 在归档时处理。

## Review Focus

规格暗示、但没有测试覆盖、最可能咬人的 5 个失效模式（每条挂到具体 Task 的测试）：

1. **单仓「无窗口」路径被误放行**——改造 `reviewer_verify_policy` 时若把 `None` 一律变成 UUID 策略，本该被 provider 启动检查拒绝的单仓调用会通过。→ **Task 4** 测试 `single_repo_without_window_yields_no_reviewer_verify_policy`。
2. **空成员集合被当成「材料齐备」**——lc 会话若成员集合为空却放行，reviewer 会看到空清单并误以为只有一个仓。→ **Task 2** 测试 `lc_review_with_empty_member_set_is_blocked_as_material_unresolved`。
3. **500 KiB 上限写成「截断」而非「阻断」**——超预算时若静默裁成员，评审会在少人的清单上跑通并给出 approve。→ **Task 5** 测试 `inventory_over_500kib_is_rejected_not_truncated`。
4. **跨仓 `request_changes` 被误当成门**——findings 一旦流进 `plan_defect_routing` / `CodeReviewFlowDecision`，就会触发 `RunCoderFix`，用户看到的是自动返工而不是 advisory。→ **Task 18** 测试 `cross_repo_request_changes_does_not_trigger_coder_fix`。
5. **provider 缺失回退写成「跳过」**——存量旧 JSON 缺 `internal_reviewer` 时若直接 `Skipped`，多仓 issue 永远没有跨仓结论，连 attention 提醒都不会出现。→ **Task 16** 测试 `cross_repo_review_falls_back_to_code_reviewer_provider`。
