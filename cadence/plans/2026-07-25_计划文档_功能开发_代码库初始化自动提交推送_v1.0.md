# 代码库初始化自动提交推送 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在代码库初始化的前五步和 Repository 持久化均成功后，执行可见、可诊断且不回滚注册结果的第六步 `git_finalize`，自动暂存、提交并按条件推送初始化产生的改动。

**Architecture:** `RepositoryInitializationStepKind` 扩展为六步；operation 状态机允许唯一例外：operation 为 `completed` 时最后一步 `git_finalize` 可以是 `failed`，并在成功结果中携带手动处理警告。协调器复用已有受限 `BoundedCommandRunner` 在目标 Git 根目录依次运行 Git 命令，所有前置步骤或 Repository 持久化失败仍按既有失败路径处理；只有收尾失败被降级为 `completed + failed step + warning`。前端继续以服务端 operation 为状态来源，在成功面板同时展示第六步失败的红色提示，且仍刷新代码库列表。

**Tech Stack:** Rust 2024、Tokio、Serde/JSON 文件 operation store、既有 `BoundedCommandRunner`、Axum DTO、React 19、TypeScript、Tailwind CSS、Lucide React、Vitest、Testing Library。

## Global Constraints

- Change：`add-repository-initialization-git-finalize`；实现只能覆盖其 `proposal.md`、`design.md`、两个 delta spec 与 `tasks.md`，不得添加 CI、Hook、Provider turn 或第三方依赖。
- 用户已于 2026-07-25 明确确认：目标仓库存在未提交改动时也执行 `git add -A`；Git 自然遵守目标仓库自身 `.gitignore`。
- 固定且唯一的步骤顺序必须为 `cadence_skills`、`pre_check`、`rule_config`、`mcp_configuration`、`project_rules_examples`、`git_finalize`；只有前四个命令步骤通过 Claude Code，`git_finalize` 不得调用 Provider。
- 先完成五个步骤、采集 `changed_paths`、持久化 Repository，再运行 `git_finalize`；前五步或持久化失败均保留原来的 operation `failed` 语义。
- `git_finalize` 执行 `git add -A`；无暂存改动时不创建空提交且标记完成；有改动时以提交信息 `初始化cadence-aria 代码库` 提交。
- 无 remote 或当前分支无 upstream 时不执行 push、步骤仍 `completed`，在 `git_finalize_warning` 中说明需要手动推送；commit 或 push 失败时步骤 `failed`、operation 仍 `completed`、Repository 记录保留。
- `git_finalize_warning` 只携带经现有 `sanitize_summary` 处理的简短诊断；不得把绝对路径、凭证或完整 Git 输出暴露到 HTTP/前端。
- 所有自动化测试必须模拟 `BoundedCommandRunner`，不得在测试中对真实远端执行 `git push`。
- Rust 测试命令必须使用宿主机工具链和 `--locked`，禁止所有 Cargo 命令携带 `-j 1`；前端包管理器固定为 pnpm。

- [ ] **Step 3: 实现 `git_finalize` 命令序列和错误降级**

在 `RepositoryRegistrationCoordinator` 内新增下列私有方法；所有 argv 必须是单独 `String`，工作目录固定 `git_root`，并复用每个调用的 `CancellationToken`：

```rust
async fn git_finalize(
    &self,
    git_root: &Path,
    cancellation: CancellationToken,
) -> Result<Option<String>, String> {
    self.require_git_finalize_success(
        git_root,
        vec!["add".into(), "-A".into()],
        cancellation.clone(),
        "git_finalize_add",
    ).await?;

    let staged = self.run_git(
        git_root,
        vec!["diff".into(), "--cached".into(), "--quiet".into()],
        cancellation.clone(),
    ).await.map_err(|error| format!("git_finalize_diff: {error}"))?;
    match staged.exit_code {
        Some(0) if !staged.timed_out && !staged.cancelled && !staged.stdout_truncated && !staged.stderr_truncated => return Ok(None),
        Some(1) if !staged.timed_out && !staged.cancelled && !staged.stdout_truncated && !staged.stderr_truncated => {}
        _ => return Err(format!("git_finalize_diff: {}", command_diagnostic(&staged))),
    }

    self.require_git_finalize_success(
        git_root,
        vec!["commit".into(), "-m".into(), "初始化cadence-aria 代码库".into()],
        cancellation.clone(),
        "git_finalize_commit",
    ).await?;

    let remotes = self.run_git(git_root, vec!["remote".into()], cancellation.clone())
        .await.map_err(|error| format!("git_finalize_remote: {error}"))?;
    if !command_succeeded(&remotes) || remotes.stdout_truncated || remotes.stderr_truncated {
        return Err(format!("git_finalize_remote: {}", command_diagnostic(&remotes)));
    }
    if remotes.stdout.trim().is_empty() {
        return Ok(Some("git_finalize: 无 remote，已跳过 push，请手动推送".to_string()));
    }

    let upstream = self.run_git(
        git_root,
        vec![
            "rev-parse".into(),
            "--abbrev-ref".into(),
            "--symbolic-full-name".into(),
            "@{u}".into(),
        ],
        cancellation.clone(),
    ).await.map_err(|error| format!("git_finalize_upstream: {error}"))?;
    if !command_succeeded(&upstream) || upstream.stdout_truncated || upstream.stderr_truncated {
        return Ok(Some("git_finalize: 无 upstream，已跳过 push，请手动推送".to_string()));
    }

    self.require_git_finalize_success(
        git_root,
        vec!["push".into()],
        cancellation,
        "git_finalize_push",
    ).await?;
    Ok(None)
}

async fn require_git_finalize_success(
    &self,
    git_root: &Path,
    argv: Vec<String>,
    cancellation: CancellationToken,
    stage: &str,
) -> Result<(), String> {
    let result = self.run_git(git_root, argv, cancellation)
        .await.map_err(|error| format!("{stage}: {error}"))?;
    if command_succeeded(&result) && !result.stdout_truncated && !result.stderr_truncated {
        Ok(())
    } else {
        Err(format!("{stage}: {}", command_diagnostic(&result)))
    }
}
```

`require_git_finalize_success()` 只包装 `run_git()`、exit code、取消、超时和截断检查；调用方再以 `sanitize_summary(..., 4 * 1024)` 构造 warning。它不得转换为 `RepositoryRegistrationError`，因为本阶段任何 Git 收尾错误都必须保留已持久化 Repository。

在 `execute_initialization()` 的 `create_repository(..)?` 之后、构造最终 `RepositoryRegistrationSuccess` 之前执行：

```rust
reporter.step_started(RepositoryInitializationStepKind::GitFinalize).map_err(|error| *error)?;
let git_finalize_warning = match self.git_finalize(&git_root, cancellation.clone()).await {
    Ok(warning) => {
        reporter.step_completed(RepositoryInitializationStepKind::GitFinalize).map_err(|error| *error)?;
        warning
    }
    Err(reason) => Some(format!(
        "git_finalize: {}；请手动提交推送",
        sanitize_summary(&reason, 4 * 1024),
    )),
};
```

收尾失败时故意保持第六步 `Running` 并返回 `Ok(RepositoryRegistrationSuccess { git_finalize_warning: Some(..), .. })`；Task 1 的 `finish_completed()` 将它原子转换为失败末步与 completed operation。不要在这一分支调用 `finish_failed()`、删除 Repository、重试 Provider 或执行第二次 push。

更新现有 `RecordingRunner` / `ConfigRunner` fixture，使其根据完整 argv 识别 status 与收尾命令；现有 `StaticInitializer` 的 `filter(|step| step.command().is_some())` 仍只生成四条 Provider command summary。
