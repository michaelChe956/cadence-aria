# 多仓库生产入口补齐实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐 Task 实施本计划。步骤使用 `- [ ]` checkbox 跟踪。

**Goal:** 为按 Project opt-in 的多仓库逻辑代码库补齐登记、初始化、聚合索引、Issue selection 与 Web UI 的生产入口，使人工 P0 主线可经真实 HTTP 从 REG-01 走到 PLN-01，同时保持单仓项目行为零变化。

**Architecture:** 先将 `multi_repo` 作为 Project 的持久化事实源，并以 `RepositoryStore::for_project` 把 feature 开关收敛到构造点；随后以同步登记端点和持久化 preflight 快照形成成员事实源。聚合初始化使用 AppState 共享的执行租约/取消令牌后台推进，索引由同一个 single-writer 状态机承接首建、读时同步和手动重建；多仓 Issue 创建在服务端以补偿事务写入 all-members selection，前端仅消费稳定 HTTP DTO。

**Tech Stack:** Rust edition 2024、axum、tokio、tokio-util `CancellationToken`、serde JSON 文件存储、CodeGraph CLI 1.5、React + TypeScript、Vite、Vitest、Zustand、TanStack Router、Tailwind CSS、pnpm。

## Global Constraints

- **权威依据与范围：** 以 `cadence/designs/2026-08-18_方案设计_多仓库生产入口补齐_v1.2.md` 的 D1–D8 和 `openspec/changes/add-logical-codebase-production-entrypoints/` 为准；不实现 selection 显式编辑 UI、索引定时轮询生产 scheduler、单仓→多仓升级迁移、50 成员生产压测。
- **D1 不可逆 opt-in：** `ProjectRecord`、`CreateProjectInput`、`CreateProjectRequest`、`ProjectDto` 都有 `multi_repo: bool`，其中所有 serde 反序列化 record/request 字段带 `#[serde(default)]`；创建时唯一可设置，之后没有更新端点或切换路径；旧 JSON 缺字段必须解码为 `false`。
- **D2/D6 同步 UI：** 登记向导在逻辑代码库页面完成“聚合根→预检分类→确认→同步提交→结果/恢复”；登记提交、索引重建、初始化触发期间对应按钮禁用并显示 loading，不引入后台登记任务。
- **D3 初始化：** POST 仅返回 `202` 和 operation DTO，但必须在同一请求内完成 `begin → shared registry lease → tokio::spawn(execute)`；worker 持有 lease，取消经 `CancellationToken` 在步骤边界生效，GET 发现 Running 且无 lease 时持久化为 interrupted-Failed。
- **D4 Issue selection：** 多仓 `POST /api/projects/{project_id}/issues` 的请求体保持不变；`repository_id` 仍必填且表示 active member 中的 primary repository，selection 恒为 `IssueCodebaseSelection::all_members`。
- **D5 索引触发：** 仅实现初始化成功尾步首建、规划读取 stale 时同步、手动同步 rebuild；`poll_due` 保留库能力但绝不注册生产 scheduler。所有写路径使用同一 per-project single-writer 锁。
- **D7 manifest：** 登记提交根必须与既有 `manifest.provider_context_root` 一致；真首批在 manifest store 的 single-writer 临界区内原子创建 manifest 与首成员，任何不一致返回 409 且不得改变成员。
- **D8 快照：** preflight 的完整 `RegistrationCandidate`、`aggregate_root`、`created_at` 写入 `logical-codebase/preflights/{preflight_id}.json`；读取时惰性删除/忽略超过 24 小时的快照，重启后仍可读取未过期快照。
- **稳定错误码（设计 §6，逐码锁定 HTTP）：** `logical_codebase_feature_disabled`→409；`registration_preflight_not_found`→404；`registration_batch_not_found`→404；`registration_batch_conflict`→409；`registration_batch_not_cancelable`→409；`aggregate_root_mismatch`→409；`aggregate_root_is_git`→422；`aggregate_root_member_outside_root`→422；`aggregate_root_member_symlink_escape`→422；`aggregate_root_nested_worktree`→422；`aggregate_root_ownership_conflict`→409；`aggregate_index_rebuild_in_progress`→409；`aggregate_index_unavailable`→422；`legacy_repository_endpoint_on_multi_repo`→409；`issue_selection_write_failed`→422。既有 `project_not_found`、`manifest_missing`、routing 和 `change_order_required_for_logical_codebase` 码不改语义。
- **Rust 命令：** 所有命令从 worktree 根执行；定向单测必须是 `cargo test --locked --lib <过滤名>`，集成测试使用 `cargo test --locked --test <测试二进制> <过滤名>`；**禁止**对任何 cargo 命令传 `-j 1`，也不传其他 `-j` 覆盖 `.cargo/config.toml` 的 jobs=8。
- **阶段/全量门禁：** 每阶段完成后至少运行 `cargo fmt --check`、`cargo clippy --all-targets --all-features --locked -- -D warnings`、`cargo check --locked`、`cargo test --locked`，并在收尾单独运行 `cargo test --locked --test it_core`；前端使用 `cd web && pnpm test` 与 `cd web && pnpm tsc -b`，禁止 npm/yarn。
- **large_file_guard：** `src/` 下每一个 `.rs`（包括 `.inc.rs`）不超过 1200 行。当前 `src/web/handlers/support.rs` 恰为 1200 行，增加错误映射前必须拆为 facade + `support_parts/*.inc.rs`；当前 `aggregate_initialization.rs` 为 626 行，但加入 production dependencies/worker 后预计超限，必须拆为 facade + `aggregate_initialization/*.inc.rs`；新增登记 handler 预计超限，必须从首次实现就拆成 `logical_codebase_registration/{preflight,submit,query,resume_cancel,dto}.inc.rs`，每个文件独立低于 1200 行。Task 4.1 在为现有 1117 行 `aggregate_index/operation.rs` 增加状态机测试前，先把现有测试模块移入 `operation_tests.inc.rs`。
- **单仓零变化红线 1：** 省略或显式 `multi_repo=false` 的新 Project、以及旧 project JSON，均保持 feature disabled；原有单仓 Project/Repository/Issue JSON 字段与路径兼容。
- **单仓零变化红线 2：** 单仓继续使用 legacy `GET/POST/DELETE /repositories` 与 legacy repository initialization；这些端点的既有成功、错误码、异步初始化和 repository 投影不可被多仓 guard 改写。
- **单仓零变化红线 3：** 单仓调用 registration、aggregate-index、aggregate-initialization 专属端点只得到 409 `logical_codebase_feature_disabled`，不得创建 manifest、batch、index 或 operation。

- **单仓零变化红线 5：** 单仓 Issue 仍按现有 `repository_id`/`IssueStore::create_with_repository` 路径创建，不写 `codebase-selection.json`，且单仓 Design 的 `change_order` 仍允许为空。

- **提交纪律：** 每一个编号 Task 至少一个 Conventional Commit；提交只含该 Task 的源、测试、必要类型/路由，禁止混入 `.pi/subagents/`、审阅输入或无关 notes。

## 执行方式

本计划采用 **subagent-driven** 执行：每个编号 Task 分配一个新的 worker，worker 固定使用 `my-openai/gpt-5.6-terra`，reviewer 固定使用 `tydic-openai/deepseek-v4-pro`。每个 Task 必须执行 **TDD（先红→最小实现→绿）→ review-package → fix loop（最多 5 轮）→ ledger**：

1. worker 只读取本 Task 的 Files、Interfaces、前置 task ledger 与相关现有代码；先提交失败测试和定向红证据。
2. worker 做最小实现、运行本 Task 定向命令、提交一个 Conventional Commit；不跨 Task 顺手重构。
3. 产出 review package（变更摘要、命令输出、错误码/接口断言、风险、精确 diff）；reviewer 按独立拒绝判据审查。
4. 有 finding 时在同一 Task 建失败回归测试、最小修复、复跑定向测试，最多 5 次；超过次数或存在范围/契约冲突时停止并升级裁决。
