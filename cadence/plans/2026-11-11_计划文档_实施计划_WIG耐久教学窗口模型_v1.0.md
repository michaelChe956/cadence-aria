# WIG 耐久教学窗口模型（bound-sc-generation-teaching）实施计划 v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 SC generate 段教学重驱建立**单一耐久授权窗口**（通道 C）：一个窗口承载原 generation/node/run 身份、业务请求与材料摘要、失败 source 引用与 hash、context digest、允许修改闭包、机器指令 digest、prompt 引用与 digest、attempt key、物理上限 max ∈ {1,2}（由 RepairOnce 批准状态决定）、RepairOnce 批准状态、批准规则版本、冻结输入摘要、冻结执行策略摘要（通用字段，值由 `explicit-sc-author-effort` 填写）、已消费 attempt 序号；窗口仅在初轮新授权（首次教学授权）时建立，A/B 合法接力不得重建；claim 与真实启动分账；替换并**删除** handler 的两个进程内布尔槽 `compile_ir_rerun_used` / `structure_rerun_used`，四类可教学失败共享同一窗口、原调用在内最多两次；不新增任何模型调用（把「几次机会、怎么记账、何时停」从进程内布尔量收敛为耐久记账，关闭某项即等价于只回退该项）。

**Architecture:** 五段纵向闭环（design D5，不可拆开上线）：耐久窗口模型（`work_item_plan_policy/types.rs` + `models/workspace.rs` 记录字段）→ store CAS（新文件 `lifecycle_store/workspace_sc_teaching_window.rs`，会话排它锁下建立/批准/claim/observe/close）→ 真实 spawn 观察（`start_work_item_plan_author` 返回后、协议驱动前同步回填 `provider_start_ledger` 占位条目；会话尾注销前验证）→ handler 单槽收口（`run/single_candidate.rs` 删双布尔槽，消费窗口 claim 结果）→ 流水/故障重放（`candidate_attempts.rs` 阶段细化 + provider attempt 关联）。attempt 键形如 `sc_generation:{session}:{generation}:attempt:{1|2}`；provider launch 身份键 `single_candidate_author:{id}:{n}` 保留为 ledger 自身键，ledger 条目新增 attempt 键关联字段。窗口缺省即「未知、零额外调用」；历史会话缺字段不产生授权、不倒填证据。

**Tech Stack:** Rust（`src/**`；`#[cfg(test)]` 内联测试 + 既有 fixture 体例）；durable 存储为 JSON 文件 + `with_exclusive_lock` 会话排它锁 CAS；行数门禁 `tests/it_core/large_file_guard.rs`。

**Spec:** `openspec/changes/bound-sc-generation-teaching/`（proposal.md / design.md D1–D9 / tasks.md 32 个工作包 / specs/** 全两份 delta）。串行序权威：`cadence/designs-reviews/2026-11-09_裁决_WIG四change审阅问题处置_v1.0.md` §2.2（本 change = 序 3，前置 = 序 0 决策六、序 1 mechanicalize、序 2 quota-pool）与 §2.2:106（迁出归属）。归档硬门禁：mechanicalize 的 MODIFIED REQ-WSC-09 完成 typed IR + structure 资格扩充前本 change 不得归档（design「归档硬门禁」，由集成 owner 执行）。

## Review Focus

1. **重连/恢复/同请求重放后凭空多发**：窗口若被新 source revision、新 native 会话、重连或重放重置（或凭 handler 再次进入重建窗口），教学重驱会再次获批 —— 合理预期是读取**同一** durable 窗口、已启动不重播、Unknown 等待、确定未启动才在原 key/原授权下继续。⇒ 钉在 Task 9（`replay_same_key_no_second_start` 等）与 Task 3（`establish_is_idempotent_and_ab_relay_does_not_rebuild`）。
2. **历史旧会话被判为「还有机会」**：缺窗口字段、无可证明原授权、只有旧 `started` 占位或空 ledger 的记录被解释为「还剩两次」或被事后倒填 grant/actual-start —— 合理预期是零额外调用 + 显式证据缺失说明，且不从计数为零推断存在机会。⇒ 钉在 Task 3（`historical_record_without_window_yields_no_authorization_and_no_backfill`）与 Task 9（`legacy_record_teaching_request_zero_extra`）。
3. **记一次 C 后 A 路径键漂移**：`ledger.len()` 派生的键序会把 C 的教学条目计入，导致 A 池预领键挤占/误接（占位被误当 reservation、新键撞旧键）—— 合理预期是 A 的 reservation 键按原键消费、新预领键不冲突且序号单调、窗口 attempt 数与账本长度解耦。⇒ 钉在 Task 5（`teaching_record_does_not_shift_a_path_keys`、`window_attempt_count_decoupled_from_ledger_length`）。
4. **占位/自报冒充真实启动或同次启动双记录**：占位条目被判为已启动、调用方自报「已启动」被采信、同键重复观察插入第二条 —— 合理预期是 `started=false` 占位不算实际启动、回填只原位补全、同键幂等。⇒ 钉在 Task 3（`claim_pushes_started_false_placeholder_with_attempt_association`、`observe_completes_in_place_idempotent_no_second_record`）与 Task 4（`spawn_backfill_failure_stops_process_as_unknown`）。
5. **流水失败与执法失败互相冒充**：流水写失败被当成执法失败阻断生成，或 ledger/claim 持久化失败被当成 best-effort 吞掉继续无账启动 —— 合理预期是前者记日志不阻断、后者 fail-closed 进入 Unknown。⇒ 钉在 Task 8（`attempt_log_write_failure_degrades`（既有，须保持）与 `ledger_write_failure_fails_closed`，两用例期望相反且都通过）。
