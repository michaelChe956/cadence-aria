## 一、Goal

让「本机没有装 claude code / codex / pi / kimi code / codegraph」的用户，在页面上点【安装】后**真的装上并立刻可用**；同时让聚合索引在大型聚合根上不再因 codegraph 输出被截断而报 `codegraph_files_invalid_json`。

## 二、症状（用户现场）

| # | 症状 | 现场证据 |
|---|---|---|
| 1 | 本地没装四家 provider 中任意一个或多个，点【安装】**没有效果，从未装成功** | 用户报告 |
| 2 | 本地没装 codegraph，点【安装】**没有效果** | 用户报告 |
| 3 | 聚合索引 degraded，错误 `aggregate_index_failed:codegraph_files_invalid_json: parse JSON from codegraph files: EOF while parsing a string at line 32565 column 48` | 用户截图 |

## 三、根因与证据（容器实测，非推理）

### 根因 A（症状 3）：codegraph 输出被 1 MiB 抓取上限截断，且截断事实被丢弃

| 环节 | 位置 | 事实 |
|---|---|---|
| 上限 | `src/product/logical_codebase/aggregate_index/codegraph_cli.rs:39` | `const OUTPUT_LIMIT_BYTES: usize = 1024 * 1024;`，在 `:283-284` 套给**所有** codegraph 调用 |
| 截断 | `src/cross_cutting/bounded_command_runner.rs:191-209` | `read_limited` 恰好保留 `limit` 字节、丢弃其余并置 `truncated`（达到上限后**继续读取并丢弃**，子进程不会因管道阻塞而挂死 ⇒ 现象是「exit 0 但 JSON 解析失败」） |
| 丢标志 | `codegraph_cli.rs:345-350` | `fn command_result` 只取 `stdout/stderr/duration_ms`，`stdout_truncated` 被丢掉 |
| 误报 | `codegraph_cli.rs:216-219` | 截断文本喂 `serde_json::from_str` → `codegraph_files_invalid_json`（伪装成「协议不符」） |

**容器实测（真实 codegraph 1.6.2，node:24-bookworm）**：9k~20k 文件的 `files --json` 为 1.3~3.9 MB；把前 1,048,576 字节交给**仓库同版本 serde_json 1.0.149** 与 `CodeGraphFile { path: PathBuf }` 解析 → 逐字复现 `EOF while parsing a string at line 32565 column 48`；同一载荷不截断 → 解析成功（20000 entries）。已排除：格式变化（1.6.2 仍是 pretty JSON 数组）、stdout 混日志（stderr 实测 0 字节）、并发写文件、编码问题。

### 根因 B（症状 1/2）：装到的目录不在服务进程 PATH 上 ⇒ 装完探测仍失败 ⇒ 界面仍显示「未安装」

| 环节 | 位置 | 事实 |
|---|---|---|
| 前缀回落 | `src/product/provider_installation/runner.rs:397-412` `resolve_effective_prefix` | CLI 缺失时回落到 `npm prefix -g`；**不检查**该前缀的 `bin` 是否在 PATH 上 |
| 前缀探测 | `effective_prefix.rs:38-45` `visible_cli_prefix` | 只认「PATH 上已有该命令」的前缀（CLI 缺失时此路不通） |
| 装后探测 | `runner.rs:201-236` `HealthRefreshProber` | codegraph 分支跑 `codegraph --version`（PATH 查找）；四家 provider 走 `provider_health.refresh()`（同样只按 PATH 找） |
| 提示缺失 | `runner.rs:245-264` `npm_path_hint` | 只对 `row.npm_package.is_some()` 产出 ⇒ **Kimi 完全没有提示** |

**容器实测（5 种布局，podman `localhost/diag-installfix:latest`）**：
- 布局 A（npm 前缀 bin 不在 PATH，服务 PATH=`/shim:/usr/bin:/bin`，`npm prefix -g=/opt/node`）：`npm install -g --prefix /opt/node …@colbymchenry/codegraph@latest` **exit 0**，二进制落 `/opt/node/bin/codegraph`，但装后探测 → `env: 'codegraph': No such file or directory`（127）⇒ 作业 completed、`installed_version` 为空、界面仍「未安装」⇒ 用户点一次没效果、再点一次再没效果。claude-code / codex 同形。
- 布局 C（Kimi 官方脚本）：脚本输出 `Installed to /root/.kimi-code/bin/kimi` + `Added /root/.kimi-code/bin to PATH in /root/.bashrc` ⇒ **只改 shell rc**，运行中服务进程 PATH 不变 ⇒ 探测 127 ⇒ 必然「没有效果」，且无 `path_hint`。
- 布局 B1（fnm 式目录软链农场）：`visible_cli_prefix` 规范化后能命中真实前缀 ⇒ 探测成功 ⇒ **不是**根因（避免误判）。
- 布局 B2（逐文件软链农场当 prefix）：npm `EEXIST` exit 1。
- 布局 D（root 拥有的 `/usr/local`）：见根因 C。

### 根因 C（症状 1 的次因）：可写性判定只看权限位 ⇒ 选到根本写不进去的系统前缀

`src/product/provider_installation/effective_prefix.rs:61-84`：`is_writable_dir` → `dir_is_writable` 只看 `mode & 0o222`。root 拥有的 `/usr/local`（0755）⇒ `mode & 0o222 = 0o200` ⇒ 对任意用户都判「可写」⇒ npm 报 `EACCES … mkdir '/usr/local/lib/node_modules/@colbymchenry'`（exit 243）⇒ `$HOME/.npm-global` 兜底永远走不到。容器实测同点 `os.access(W_OK) → False`。

### 根因 D（放大器）：前端把后端整句提示再包一层

`web/src/components/lifecycle/ProviderInstallActionButton.tsx:290-292`（修复前）：后端 `path_hint` 本身已是完整句子（「已安装到 /opt/node；若 `codegraph` 不在 PATH 上，请把 /opt/node/bin 加入 PATH 后重试」），前端又拼成「…；若命令不在 PATH，可把 <整句> 加入 PATH」⇒ 用户看到破碎双句，更像「没效果」。

### 已排除的机制（有执行证据）

- npm 子进程缺 HOME / 环境不继承：`src/cross_cutting/process_manager.rs:428-441` `env_clear` 已删，子进程继承宿主环境，`request.environment` 只是覆盖层 ⇒ 排除。
- 按钮不渲染 / 请求丢失 / 作业卡死：路由与前端调用链完整、作业落盘后才 spawn ⇒ 排除（仅留边缘项：重启后 stale `running` 作业无对账，见 §8 风险 R4）。

**既有规格漂移（记录，本 change 不改）**：主规格 `openspec/specs/logical-codebase-aggregate-index/spec.md` REQ-IND-01 仍写「exact version 钉定 v1.5.0」，与实现的 `>=1.6.0, <2.0.0` 不符。版本门本轮**不动**，归档同步时由双审对齐。

### 契约影响（需 OpenSpec delta 同步；逐条成行，禁缩写）

- **REQ-PCI-02（安装/更新按钮显示规则与本地状态探测）**：澄清「探针结果」的**口径** = 宿主 PATH ∪ **平台登记目录（PATH overlay）**；装完 CLI 不在宿主 PATH 上但在 overlay 内 ⇒ 视为「已安装、探针通过」。
- **REQ-PCI-03（npm 镜像源与安装执行形态）**：澄清「`--prefix <可写前缀>`」中的「可写」= **真实写入探测**（mode 预筛 + 实际创建/删除临时文件）判定，MUST NOT 只看权限位；系统级不可写前缀 MUST NOT 被选中。
- **REQ-PCI-05（异步安装作业与装完重新探测）**：澄清「装完重新探测」的判定口径 —— 平台可见（overlay 合并后的 PATH 探测成功）即判成功，MUST NOT 在装完后仍显示「未安装」；本条**不是新增 requirement**，是既有 MUST 的实现化。
- **REQ-IND-01（聚合索引建立）**：增补 —— `codegraph files --json` 使用有文档上限的**专用抓取配额（64 MiB）**；stdout 被截断时 SHALL 以专用机器码 `codegraph_files_output_truncated` 报告，MUST NOT 伪装成 `codegraph_files_invalid_json`。
- **REQ-IND-04（索引生命周期与故障恢复）**：增补 —— 截断属「构建失败」路径：保留 last-known-good 并标记 degraded，不伪造 active。
- **REQ-IND-05（工具缺失的致命与降级分界）**：**不改** —— `codegraph_files_output_truncated` **不是**工具缺失码，**不进入** `bootstrap_projector.inc.rs:104` 的致命匹配集（该集合只含 `codegraph_missing` / `codegraph_version_mismatch`）⇒ 自动走「有 LKG ⇒ degraded」一般规则。
- **API 可见性变化**：`CodeGraphCommandResult`（re-export 于 `src/product/logical_codebase/aggregate_index/mod.rs:11`）新增 `stdout_truncated: bool` 字段。
