# LC 根初始化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `subagent-driven-development`（推荐）或 `executing-plans` 逐任务实施。步骤使用 checkbox（`- [ ]`）跟踪；本计划只展开已批准的 OpenSpec change，不代表代码已经完成。

**Goal：** 交付 `lc-root-initialization`：LC 根准入确定 canonical root 后，先完成 Codex/Kimi trust 硬前置门，再由固定 Claude Code 执行既有五步 durable operation 在根执行四命令 recipe，闭合 bootstrap readiness，并冻结全部后续 LC 会话的 root cwd + 独立 target 合同；Codex/Pi/KimiCode 的实际 LC gateway launch 由后续 `lc-gateway-multi-provider` change 承担。

**Architecture：** 复用 `AggregateInitializationCoordinator` 的五步 durable operation、`AggregateInitializationOperationStore` 的 checkpoint、既有 provider gateway/admission 和 bootstrap projection；trust 登记是 LC 根准入后的独立硬前置门，不属于五步、不插入步骤之间，失败时五步 operation 不创建/不启动并进入可重试 fail-closed waiting。以 `working_directory`（canonical LC root）、`target/worktree`（成员身份）和 `writable_roots`（逻辑授权）三字段解耦 provider cwd 与操作目标；root recipe receipt/filesystem auditor、D1-D4 回归锁和真实 CLI/E2E 证据共同限制副作用。

**Tech Stack：** Rust 2024、Tokio、serde、sha2、现有 JSON store/文件锁、Axum；真实 Claude Code/Codex/Pi/Kimi CLI；既有 Cargo 集成测试。不得新增外部依赖。Rust 测试依赖仓库已固化的 `.cargo/config.toml` 中 `RUST_MIN_STACK = "33554432"`，命令不得携带 `-j 1`。

**Spec：** `openspec/changes/lc-root-initialization/{proposal.md,design.md,tasks.md,specs/non-interrupt-repository-bootstrap/spec.md,specs/logical-codebase-registration/spec.md,specs/logical-codebase-aggregate-planning/spec.md,specs/session-policy-envelope/spec.md}`；权威设计 `cadence/designs/2026-09-30_方案设计_LC根初始化_v1.0.md`（v1.3）；预研证据 `cadence/reports/2026-10-01_预研报告_LC根初始化provider实测_v1.0.md`。

## Global Constraints

- LC root identity MUST be the canonical path of manifest `provider_context_root`; root 准入时即确定，registration、recipe、workspace/coding gateway、aggregate factory、envelope 和 receipt 必须 canonical-equal；不一致时 provider spawn 前 fail-closed。
- LC 初始化 SHALL 在 canonical root 执行四条命令各一次：`/pre-check --no-interrupt --upgrade 用大陆镜像`、`/rule-config --no-interrupt`、`/mcp-configuration --no-interrupt`、`/project-rules-examples --no-interrupt`；不得启动逐成员初始化 provider、向成员仓复制配置或调用成员 GitFinalize。
trust 生命周期顺序固定为：LC 根准入冻结 canonical root → 独立完成所选 Codex/Kimi trust 登记、核验及副作用审计 → 仅在登记成功后启动 Claude Code 五步 recipe `MachineSkills → AggregatePreflight → PreCheck → RuleAndMcpConfig → OpenspecAndExamples`；trust 登记不是 operation step，不插入步骤之间，但它是五步 recipe 的硬前置门。任一 trust 登记失败时，初始化整体 fail-closed 等待且可重试，五步 operation 不创建/不启动，不降级或部分放行。
- Codex trust MUST 写用户级 `~/.codex/config.toml` 的 `[projects."<canonical_lc_root>"] trust_level = "trusted"`，LC root 启动 argv MUST 含 `--skip-git-repo-check`；Kimi trust MUST 写 `wd_<basename>_<sha256(canonical_root)[:12]>` workspace-trust 记录。
- trust 登记 MUST 幂等、只影响当前 canonical root；用户既有可信条目原样复用且标记为非本 LC 归属，不覆盖、不撤销用户或其他 LC 的条目；外部修改、归属冲突、格式冲突、写入或撤销失败均进入 fail-closed waiting。
- Bootstrap phase credential MUST 仅由当前 durable Running aggregate operation 的 LC、operation、current step、input digest 和 canonical root 派生；只豁免“根规则尚未生成”，不得豁免 policy、authority、capability、gateway、canonical cwd、target 或 availability；普通 session 不得自报凭据。
- `SessionPolicyEnvelope`、`SessionLaunchRequest`、validated provider inputs、`StreamingProviderInput` 和 `AdapterInput` MUST 使用独立 canonical `working_directory`；`worktree_path`/`target` 继续表达成员 checkout/worktree，不得回退到 member cwd。
- Planning/Review 的 `writable_roots` MUST 为空；Coding 的唯一 writable root MUST 是当前 target worktree；逻辑 writable roots、receipt、git status 或 MCP 成功均不得被宣称为 OS 级隔离。
- resume fingerprint MUST 包含 canonical `working_directory`；cwd、target、policy、provider version/dialect、capability snapshot 任一漂移均 supersede 旧 session 并新建会话。
- AGENTS.md 是通用根入口，CLAUDE.md 是兼容副本；provider 原生自发现与 Aria 注入 bundle 是独立通道；不新增 prompt、环境变量、sidecar、成员复制或薄指针 fallback，机器级 managed skills links 零改造。
- `planning_ready` MUST 同时依赖 bootstrap 五步 projection、最终可解析 policy、独立根规则摘要、root recipe receipt、MemberIndex 和 AggregateIndexActive；recipe Completed 本身不等于 ready；只读 GET 不得启动副作用。
- 单仓初始化、单仓 cwd/target、单仓 operation、GitFinalize、legacy direct provider、role tool-policy、既有受控 pointer 和 Kimi Aria bundle 语义 MUST 保持不变。
- 新增/变更代码不得引入外部依赖；任务内仅运行定向检查。Rust 定向命令使用 `cargo test --locked --lib <测试过滤名>`，集成测试使用 `cargo test --locked --test <target> <过滤名> -- --nocapture`；不得显式指定 `-j 1`。项目级 `cargo fmt --check`、`cargo clippy --all-targets --all-features --locked -- -D warnings`、`cargo check --locked`、`cargo test --locked` 由主控在全部任务合入后统一执行。
recipe provider 固定为 Claude Code；后续 Story/Design/Plan/Coding/Review 的 Codex/Pi/KimiCode LC gateway 接入由后续 change `lc-gateway-multi-provider` 承担，本 change 不新增 gateway dialect、fallback、shim 或放宽现有 provider 门。

## Review Focus

1. **根路径边界：** canonical LC root 含空格、通过 symlink 别名、父目录存在祖先 Git 或 root/target 字符串相同但 canonical 不同；系统应 canonicalize 后放行合法 root，拒绝 symlink escape、authority 越界和双工厂不一致。由 Task 1.5、2.8、3.1 覆盖：断言 `canonical_root` 相等/不等和 zero spawn。
2. **trust 文件并发与归属：** 两个 LC 同时写用户 trust、用户已有 trusted/untrusted entry、撤销前被外部修改；系统应 root-scoped 幂等、CAS/锁保护、保留用户条目，归属不明时 waiting。由 Task 1.3 覆盖：断言其他 key 不变、同命令重放不重复写、撤销摘要匹配才删除。
3. **存量 LC waiting 重冻结：** 已有 per-member digest 但 root receipt/policy 尚未冻结时，系统应进入 waiting → Prepare → root recipe → 新 root digest/receipt 冻结，不能静默双读、成员 fallback 或自动迁移。由 Task 1.6、3.5 覆盖：断言 `planning_ready == false`、普通 session zero spawn。
4. **provider 版本升级与 trust 格式变化：** CLI 版本变化、Codex anchor/config 限制、Kimi trust 记录格式或原生 root allowlist 变化；系统应记录准确版本/argv/前后摘要，证据不足或格式不兼容时 fail-closed，不扩大 allowlist 或增加注入 shim。由 Task 3.3、3.4 覆盖，证据落点为 `cadence/reports/` 验收报告。
5. **大 LC 超时与非 target 写入：** 数十成员根启动上下文膨胀、provider 尝试写非 target 成员或 main checkout；系统应保留取消/超时/失败事实，D4 baseline 捕捉 HEAD/porcelain 漂移，未达到 provider-specific evidence gate 时阻断支持结论。由 Task 1.5、1.7、3.4、3.5 覆盖，证据落点为 receipt、provider event log、成员快照和成本报告。
