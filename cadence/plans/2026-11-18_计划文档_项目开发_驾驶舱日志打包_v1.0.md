# 驾驶舱日志打包实施计划

> **For agentic workers:** 使用 `subagent-driven-development`；逐项验收，不读取真实用户日志。

**Goal:** 下载一次经宿主授权的诊断包，支持第三方分析而不导出会话正文。

**Architecture:** 驾驶舱公共入口 → 实例内一次性授权 → 只读采集与有界事件投影 → 私有文件中完成 tar.gz → 浏览器附件。与控制面登录、provider 执行链和既有 runtime-info 契约隔离。

**Tech Stack:** Axum、Rust（rustix、tempfile、tar、flate2）、React/TypeScript、Vitest。

**Spec:** `openspec/changes/add-cockpit-log-bundle/{proposal.md,design.md,specs/cockpit-log-bundle/spec.md,tasks.md}`。

## Global Constraints

- 工作树 `feat/cockpit-log-bundle`；所有临时验证产物在 `/tmp`，不触碰共享服务或真实家目录。Linux/macOS 使用 OS 文件权限；不能证明安全时拒绝，不放宽。
- 授权 5 分钟、每家 3 个不同会话、无远程明文 HTTP、无会话正文选项、无通配下载/上传。包的时间使用 UTC，出口为 gzip 附件。
- 诊断代码集中在 `src/web/handlers/log_bundle/`。除私有子模块引入，既有公开函数签名、provider 的运行时权限和工作区路径计算不变。

## Review Focus

1. 域名/回环反代、未授权、重放、过期、私人授权文件能否从其它已挂载文件读取路径获取 → T4。
2. 链接（含父目录）、硬链接、特殊文件、扫描量限制和记录丢失 → T1/T3。
3. Kimi/Claude 子代理、重复会话 ID、并列时间、不足 3 个 → T2。
4. 提示、代码、工具 stdout、嵌套的自由文本或伪装成字段值的令牌污染导出 → T2/T3。
5. 点击取消、重复点击、错误响应误存附件、成功后解包不是本实例数据 → T5/最终验收。

## T2 会话枚举与事件轨迹（工作包 2.1）

- [ ] 新 `sessions.rs` 的测试：不同日期与并列 mtime、Pi/Codex ID 去重、Kimi 多 agent 与 Claude 孤儿不占名额。实现 `discover(provider:&str, root:&super::fs::Root, warnings:&mut Vec<&'static str>) -> Vec<Session>`，`Session { modified:SystemTime, members:Vec<PathBuf> }` 成员均为根内相对路径。稳定排序后只取 3，固定原生布局，探头/目录项/组成员有界。不得收进同目录其它 JSONL、锁或配置。
- [ ] 新 `trace.rs` 先写四家事件的正例和 canary 隐私测试。`project(provider:&str, record:&serde_json::Value) -> serde_json::Value` 只从协议的确定位置提取已知类型、角色、工具类别、经过约束的模型、时间、退出码和错误类型；未知值归为 other/省略。绝不序列化原始对象、错误详情、任意 ID 或自由文本。两项可并行。

## T3 快照与压缩（工作包 1.1、2.2、4.1）

- [ ] 新 `archive.rs`（测试可独立 `archive_tests.rs`）。`from_host(runtime:serde_json::Value) -> io::Result<std::fs::File>`；内部构造函数允许测试注入 HOME 与四个原生根，不在测试设置全局环境。证实同源 JSON、嵌套 `commands`、缺项、秘密不入会话文件及可解压性。
- [ ] 运行信息由外层调用当前 `health::runtime_info(State(...))` 并传 `.0`，不二次 HTTP，忽略任意客户端路径。`$HOME/.aria/projects` 内仅匹配两种完整目录分量的 JSON；用 `fs::Root` 打开。配置中的已知 provider 数据根按正常优先级，默认取运行账号 HOME。成员为 `runtime-info.json`、`aria/projects/...`、`providers/<provider>/<rank>/<stream>.jsonl`、`manifest.json`。
- [ ] 对 Aria JSON 保持相对层次，遮盖常见凭据键；超大或无效 JSON 整个跳过并给出原因。日志读取有界尾窗（每文件至多 8 MiB，不追新增），仅完整、可解析 JSON 行经 `trace::project` 入包。总输入/输出预算 128 MiB，限成员/目录项，写明覆盖是否完整。临时文件完成 gzip/tar 再返回，seek 到开头；只写普通文件头、无绝对路径或属主，禁止原始 JSONL fallback。

## T4 宿主授权、HTTP（工作包 3.1）

- [ ] 新 `permit.rs` 以两种 origin、错码、重放、权限、过期和并发为边界：`Grants::default()`、`issue(&mut self, origin:&str, workspace:&Path) -> io::Result<PathBuf>`、`redeem(&mut self, origin:&str, code:&str)->bool`。私有短生命周期授权文件只含强随机码，生成不依赖文件名；不得放在任何可经 Web 读取的根。单实例有界，关闭/过期清理。若现有 Web 文件读取能力使授权文件不可保护，拒绝该环境；不以来源校验代替授权。
- [ ] 新 `log_bundle/mod.rs` 暴露 `pub(crate) fn routes() -> axum::Router<WebAppState>`，局部 Extension 持有每 router 的 Grants/并发门；`handlers/mod.rs` 声明模块；`app.rs:42` 前合并 `handlers::log_bundle::routes()`。`POST /api/diagnostics/log-bundle/authorize` 只返回 `{authorization_file, expires_in_seconds:300}`，不扫源、不返回码。`POST /api/diagnostics/log-bundle/download` 接受严格 JSON `{confirmed:true,code}`；经过现有信任门、精确 Origin/HTTPS（直接回环允许 HTTP）、宿主证明一次性核销后才读档。错误使用固定诊断，不含码/源数据。`spawn_blocking` 生成，返回 `application/gzip`、`Content-Disposition: attachment`、`Cache-Control: no-store`，限并发。
