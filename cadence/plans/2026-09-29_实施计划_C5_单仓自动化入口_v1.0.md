**Goal：** 交付 `single-repository-automation-entry`（C5）：单仓（Single-Repository）issue 可经 `GET /automation-target` 与 `PUT /automation-enrollment` Enable 进入与逻辑代码库（LC）同等的自动链（prepare→生成→人工门→advance→typed 首启→coding→FinalConfirm 前停等）；Enable 前按 author→coder→reviewer 完整角色链静态预检（稳定 422 逐角色列违规）；Claude 单仓初始化失败进入驾驶舱停等并以冻结输入"恢复后继续"；enrollment 载体身份收敛到 `EnrollmentTarget` 单一权威（BREAKING 删冗余 `logical_repository_id`），满足 A01、A02、A05、A10。

**Architecture：** 先完成后端 wire/model 收敛，再由 C4 `RepositoryAuthorityResolver::resolve_for_issue` 判定载体：GET 投影与 PUT Enable 的单仓分支读取 `IssueRecord.repo_id` 并解析真实 `RepositoryRecord.id`，LC 分支保持单 target 约束，authority 冲突沿 `repository_routing_*` 映射 fail-closed。身份收敛为纯删面：冗余 `logical_repository_id` 从 enrollment／Enable 命令／冻结意图／DTO／前端 TS 全链删除，旧 enrollment 与旧意图分别经显式 legacy reader 转为“旧代无绑定”并 fail-closed，不能因缺 target 直接反序列化失败。role-chain 预检把 GAP-F reviewer 谓词泛化为逐角色循环，GET/PUT 调同一函数，单仓跳过 gateway 谓词。单仓自动链不新建路径：prepare 沿既有 Legacy 分支，advance／StartCoding 各加一个按 enrollment target 的载体分派分支；`validate_group_single_target` 与 `verify_current_binding` 零改动复用。GAP-J 由产品层恢复入口串联 registry/guard、可注入 deterministic operation id、冻结 input、operation store create/list 与完整 begin→execute；C1 waiting item 以 parent/resume 关联稳定消隐，HTTP 与驾驶舱消费同一 project 投影。

**Tech Stack：** Rust 2024、Axum、Tokio、serde、uuid v5（在 T6 修改 `Cargo.toml` 的既有 uuid features 并同步 `Cargo.lock`；不新增 crate；固定 `Uuid::NAMESPACE_URL` namespace 与 UTF-8 名称编码 `cadence/repository-initialization/v1\0{original_operation_id}\0{command_id}`，不把 uuid v5 再描述为“sha1 外包”）；React、TypeScript、Vitest、Testing Library。

## Global Constraints

- **自动推进＋人到点处理：** 自动链只在 durable、已授权、身份可证明的状态下推进；choice、人工计划门、story/design 确认、FinalConfirm 一律由人处理，系统 MUST NOT 代点。预检拒绝（422）、authority 冲突（409）、载体／身份漂移、初始化失败一律转可操作停等（通知＋带身份的用户操作＋原链继续）：等待项提示重新绑定／更换配置／恢复后继续，零 enrollment 写入、零 provider 启动、零直改数据。运行期 503 走既有 `BlockedProviderUnavailable` 停等（`autopilot_orchestrator.rs:385` 附近），不自动切换 provider、不盲重、不回滚 enrollment。manual／off enrollment 在 reconcile 入口即返回 `NoEnrollment`（`autopilot_orchestrator.rs:87/:90/:115`），补偿扫描零动作。

## Review Focus

1. **旧 durable 数据无 target：** 旧 enrollment JSON（有 `logical_repository_id` 无 `target`）与旧冻结意图文件读入不炸，自动链按“旧代无绑定”fail-closed，手动链零回归（Task 1 Step 1）。
2. **authority 冲突与 legacy 别名：** 单仓物理仓与另一登记记录解析到同一 git 根、或与 legacy 逻辑代码库 active 成员来源冲突时，409 `repository_routing_source_identity_mismatch`／`repository_routing_legacy_conflict`（实际错误字符串产生于 `repository_routing.rs:414-418`、`:446-449`、`:555-587`，HTTP 映射在 `product_store_error.inc.rs:49-97`／`error.rs:122-125`，非 stable-code enum 变体），不选择任一记录继续、不猜“最新”（Task 2 Step 1）。
3. **中途载体漂移：** issue 改属 LC 而 enrollment 是单仓、repo_id 变更、attempt 携带 LC snapshot 而单仓 enrollment——advance／StartCoding 逐门 fail-closed 零副作用，等待项提示重新绑定，当前绑定不被覆盖（Task 4／Task 5 Step 1）。
4. **resume 滥用面：** 非 `Failed` 终态 operation 请求 resume 被拒；同 command_id 重放返回同一新 operation；同 git 根已有登记或正在初始化按既有互斥拒绝；网关仍不可用时再次 Failed 停等、不伪造成功、不直写登记数据（Task 6 Step 1）。
5. **GET/PUT 判定分叉与单仓误拒：** 同一输入 GET 投影与 PUT Enable 给出同一判定；单仓载体跳过 gateway 谓词不误拒（Pi／KimiCode 本机可用即授权）；`test_provider_enabled` 仅豁免 Fake，不放行 Pi／KimiCode（Task 3 Step 1）。
