# C5 单仓自动化入口实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `subagent-driven-development`（推荐）或 `executing-plans` 逐任务实施。任务步骤使用 checkbox（`- [ ]`）跟踪；本计划只定义实现，不代表代码已经完成。

**Goal：** 交付 `single-repository-automation-entry`（C5）：单仓（Single-Repository）issue 可经 `GET /automation-target` 与 `PUT /automation-enrollment` Enable 进入与逻辑代码库（LC）同等的自动链（prepare→生成→人工门→advance→typed 首启→coding→FinalConfirm 前停等）；Enable 前按 author→coder→reviewer 完整角色链静态预检（稳定 422 逐角色列违规）；Claude 单仓初始化失败进入驾驶舱停等并以冻结输入"恢复后继续"；enrollment 载体身份收敛到 `EnrollmentTarget` 单一权威（BREAKING 删冗余 `logical_repository_id`），满足 A01、A02、A05、A10。

**Architecture：** 载体判定 resolver-first——GET 投影与 PUT Enable 先调 C4 `RepositoryAuthorityResolver::resolve_for_issue`，`Ok(None)` 走单仓分支（`IssueRecord.repo_id → find_repository → RepositoryRecord.id` 权威链），`Ok(Some)` 保持 LC 单 target 约束，冲突沿 `repository_routing_*` 稳定码 fail-closed。身份收敛为纯删面：冗余 `logical_repository_id` 从 enrollment／Enable 命令／冻结意图／DTO／前端 TS 全链删除，旧 JSON 按 serde 忽略、按"旧代无绑定"fail-closed。role-chain 预检把 GAP-F reviewer 谓词泛化为逐角色循环，GET/PUT 调同一函数，单仓跳过 gateway 谓词。单仓自动链不新建路径：prepare 沿既有 Legacy 分支，advance／StartCoding 各加一个按 enrollment target 的载体分派分支；`validate_group_single_target` 与 `verify_current_binding` 零改动复用。GAP-J 复用 `C1WaitingItemDto` 等待项家族与 `RepositoryInitializationOperationStore::create` 同 id 幂等，resume 以确定性 uuid5 派生新 operation，零新账本。

**Tech Stack：** Rust 2024、Axum、Tokio、serde、uuid v5（确定性派生为本计划新引入；仅沿用 `src/product/repository_store/registration.rs:388` 的 `repository_initialization_` **前缀格式**先例——该处实为随机 `Uuid::new_v4()`，仓库内不存在 uuid5 既有用法可对齐，不新增外部依赖）；React、TypeScript、Vitest、Testing Library。

**Spec：** `openspec/changes/single-repository-automation-entry/{proposal.md,design.md,tasks.md,specs/work-item-group-autopilot/spec.md,specs/web-runtime-repository-routing/spec.md,specs/multi-target-group-coding/spec.md,specs/work-item-plan-advance/spec.md,specs/repository-initialization-progress/spec.md}`；上位合同为 `cadence/designs/2026-09-28_方案设计_真实链缺口修复总方案_v1.2.md` §4.1（GAP-I／GAP-J／单仓入口行）、§4.3 #10、§5.4、§5.5、§6.1–6.3、§7；格式参照 `cadence/plans/2026-09-29_实施计划_C2_coding段韧性_v1.0.md`。

## Global Constraints

- **自动推进＋人到点处理：** 自动链只在 durable、已授权、身份可证明的状态下推进；choice、人工计划门、story/design 确认、FinalConfirm 一律由人处理，系统 MUST NOT 代点。预检拒绝（422）、authority 冲突（409）、载体／身份漂移、初始化失败一律转可操作停等（通知＋带身份的用户操作＋原链继续）：等待项提示重新绑定／更换配置／恢复后继续，零 enrollment 写入、零 provider 启动、零直改数据。运行期 503 走既有 `BlockedProviderUnavailable` 停等（`autopilot_orchestrator.rs:385` 附近），不自动切换 provider、不盲重、不回滚 enrollment。manual／off enrollment 在 reconcile 入口即返回 `NoEnrollment`（`autopilot_orchestrator.rs:87/:90/:115`），补偿扫描零动作。

## Review Focus

1. **旧 durable 数据无 target：** 旧 enrollment JSON（有 `logical_repository_id` 无 `target`）与旧冻结意图文件读入不炸，自动链按"旧代无绑定"fail-closed，手动链零回归（Task 2 Step 1）。
2. **authority 冲突与 legacy 别名：** 单仓物理仓与另一登记记录解析到同一 git 根、或与 legacy 逻辑代码库 active 成员来源冲突时，409 `repository_routing_source_identity_mismatch`／`repository_routing_legacy_conflict`，不选择任一记录继续、不猜"最新"（Task 1 Step 1）。
3. **中途载体漂移：** issue 改属 LC 而 enrollment 是单仓、repo_id 变更、attempt 携带 LC snapshot 而单仓 enrollment——advance／StartCoding 逐门 fail-closed 零副作用，等待项提示重新绑定，当前绑定不被覆盖（Task 4／Task 5 Step 1）。
4. **resume 滥用面：** 非 `Failed` 终态 operation 请求 resume 被拒；同 command_id 重放返回同一新 operation；同 git 根已有登记或正在初始化按既有互斥拒绝；网关仍不可用时再次 Failed 停等、不伪造成功、不直写登记数据（Task 6 Step 1）。
5. **GET/PUT 判定分叉与单仓误拒：** 同一输入 GET 投影与 PUT Enable 给出同一判定；单仓载体跳过 gateway 谓词不误拒（Pi／KimiCode 本机可用即授权）；`test_provider_enabled` 仅豁免 Fake，不放行 Pi／KimiCode（Task 3 Step 1）。
