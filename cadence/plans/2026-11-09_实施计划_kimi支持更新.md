# 实施计划：Kimi Code 也支持「更新」

- **OpenSpec change**：`openspec/changes/kimi-provider-update-support/`（已 `openspec validate --strict` 通过）
- **契约**：MODIFIED REQ-PCI-01 / REQ-PCI-05；REMOVED REQ-PCI-04 + ADDED REQ-PCI-07
- **原则**：TDD（先红后绿）；每个工作包独立提交；构建与发布按
  `cadence/project-rules/local-service-deploy.md`（dist 先于二进制；只经
  `scripts/aria-web-start.sh`；`--check` 6 项自检）。

## T1 安装源表：版本来源与安装来源分离

- 文件：`src/product/provider_installation/source_table.rs`
- 测试（先红）：五类对象的**版本来源包**断言 —— npm 四类 = 各自安装包；
  Kimi = `@moonshot-ai/kimi-code`；且 Kimi 的**安装源**仍是官方脚本
  （`npm_package` 仍为 `None`，`install_script` 仍为官方 URL）。
- 实现：`InstallSourceRow` 新增 `version_package: Option<&'static str>`；
  `INSTALL_SOURCE_TABLE` 逐行填；`npm_package` 的文档语义收敛为「安装源」。
- 验证：`cargo test --locked --lib provider_installation::source_table`

## T2 handler：latest 查询改用版本来源

- 文件：`src/web/handlers/provider_installation.rs`
- 测试（先红）：`install-targets` 对 Kimi 返回 `latest_version`（用既有 durable
  版本缓存打桩，不打真网络）；Kimi 本地落后时 `action = "update"`；
  Kimi 未安装时仍是 `action = "install"`。
- 实现：`get_install_targets` 的 latest 查询从 `row.npm_package` 改为
  `row.version_package`；`resolve_install_action` 保持通用（无 Kimi 特例）。
- 验证：`cargo test --locked --lib web::handlers::provider_installation`

## T3 前端：Kimi 渲染【更新】

- 文件：`web/src/components/lifecycle/ProviderInstallActionButton.tsx`
- 测试（先红）：Kimi 版本落后（`cliAvailable=true`、`capabilityConfirmed=true`、
  `localVersion=2.4.1`、`latestVersion=2.5.2`）⇒ 渲染【更新】+ 当前/最新版本；
  点击【更新】先弹来源告知（不直接发 POST），确认后才 POST
  （`acknowledge_remote_script=true`）。
- 实现：`showUpdate` 去掉 `target !== "kimi_code"` 排除；来源告知文案覆盖
  「安装/更新」；其余显示规则不变。
- 验证：`pnpm -C web test`（全量）+ `pnpm -C web build`
