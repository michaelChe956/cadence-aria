# 图片创作文件存储改造 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 图片创作生成结果从"会话 JSON 内联 base64"改为"文件存储 + 引用 + URL 懒加载"，打开会话的响应不再包含图片字节。

**Architecture:** 后端把每次生成的图片字节原子写入 `.aria/image_create/images/<image_id>.<ext>`，`GenerationResult` 只存 `image_id` + `media_type` 引用；会话读取路径对旧内联 `b64` 记录做惰性无损迁移；新增会话隔离的图片读取端点；前端 `<img>`/下载改用端点 URL。写入顺序固定为"先图片文件、后会话引用"，会话 JSON 更新失败复用既有 `pending_results` 重试。

**Tech Stack:** Rust (axum + tokio + serde + uuid)、React + TypeScript + Zustand + Vitest。

**Spec:** `openspec/changes/image-create-file-storage/`（proposal.md / design.md / specs/image-create-agent/spec.md / tasks.md；工作包编号 WP1–WP7 对应本计划 Task 1–8）。

## Global Constraints

- 命令规范：`cargo test --locked --lib <过滤名>` 做定向快反馈；🔴 禁止 `cargo test -j 1`；全量检查 `cargo fmt --check`、`cargo clippy --all-targets --all-features --locked -- -D warnings`、`cargo test --locked`；前端 `cd web && pnpm test`、`pnpm tsc -b`。
- 会话记录 API 响应体（`GET /api/image-create/sessions/{id}` 与 `GET /api/image-create/sessions`）任何情况下不得包含 `b64` 字段（spec：MODIFIED「生成结果按媒体类型直接展示」/「打开会话不传输图片字节」）。
- `image_id` 必须是 UUIDv4 simple/hyphenated 合法值，任何以其构造路径的操作前必须校验，禁止路径穿越（spec：ADDED「图片读取端点与会话隔离」）。
- 迁移失败不得丢失或篡改旧 `b64` 数据；已迁移记录的 JSON 中不得再出现 `b64` 字段（spec：ADDED「生成图片崩溃一致写入与旧数据迁移」）。
- 不改生图网关协议（`src/cross_cutting/image_client.rs` 的请求构造与错误归一）、prompt 迭代链路、参考图上传行为（proposal Non-Goals）。
- 每个任务完成即 commit；commit message 用中文、conventional 前缀。

- [ ] **Step 5: 实现原子写入**

```rust
use std::path::PathBuf;

use crate::cross_cutting::aria_state_paths::AriaStatePaths;
use crate::product::image_create::ImageCreateError;

pub fn media_type_extension(media_type: &str) -> Option<&'static str> {
    match media_type {
        "image/png" => Some("png"),
        "image/jpeg" => Some("jpeg"),
        "image/webp" => Some("webp"),
        _ => None,
    }
}

pub fn valid_image_id(image_id: &str) -> bool {
    uuid::Uuid::parse_str(image_id).is_ok()
}

pub async fn write_image_atomic(
    paths: &AriaStatePaths,
    image_id: &str,
    media_type: &str,
    bytes: &[u8],
) -> Result<PathBuf, ImageCreateError> {
    let destination = paths
        .image_create_image_file(image_id, media_type)
        .ok_or_else(|| {
            ImageCreateError::Store(format!("invalid image id or media type: {image_id}/{media_type}"))
        })?;
    let parent = destination.parent().expect("image file has parent");
    tokio::fs::create_dir_all(parent)
        .await
        .map_err(|error| ImageCreateError::Store(format!("create {}: {error}", parent.display())))?;
    let temp_path = parent.join(format!(".{}.tmp", uuid::Uuid::new_v4().simple()));
    use tokio::io::AsyncWriteExt;
    let result = async {
        let mut file = tokio::fs::OpenOptions::new()
            .create_new(true)
            .write(true)
            .open(&temp_path)
            .await
            .map_err(|error| ImageCreateError::Store(format!("create {}: {error}", temp_path.display())))?;
        file.write_all(bytes)
            .await
            .map_err(|error| ImageCreateError::Store(format!("write {}: {error}", temp_path.display())))?;
        file.sync_all()
            .await
            .map_err(|error| ImageCreateError::Store(format!("sync {}: {error}", temp_path.display())))?;
        drop(file);
        tokio::fs::rename(&temp_path, &destination)
            .await
            .map_err(|error| ImageCreateError::Store(format!("rename {}: {error}", destination.display())))
    }
    .await;
    if result.is_err() {
        let _ = tokio::fs::remove_file(&temp_path).await;
    }
    result.map(|_| destination)
}
```

```rust
pub async fn get_session_image(
    State(state): State<WebAppState>,
    Path((session_id, image_id)): Path<(String, String)>,
) -> HandlerResult<Response> {
    let session_id = checked_session_id(session_id)?;
    if !image_files::valid_image_id(&image_id) {
        return Err(ImageCreateApiError::invalid_request("invalid image id"));
    }
    let record = session_store(&state)
        .get(&session_id)
        .await?
        .ok_or_else(ImageCreateApiError::not_found)?;
    let result = record
        .generation_results
        .iter()
        .find(|r| r.image_id.as_deref() == Some(image_id.as_str()))
        .ok_or_else(ImageCreateApiError::not_found)?;
    let bytes = if let Some(path) = paths(&state).image_create_image_file(&image_id, &result.media_type) {
        match tokio::fs::read(&path).await {
            Ok(bytes) => bytes,
            Err(_) => decode_legacy(result)?, // 文件缺失回退 b64
        }
    } else {
        decode_legacy(result)?,
    };
    let headers = [
        (header::CONTENT_TYPE, HeaderValue::from_str(&result.media_type).expect("mime")),
        (header::ETAG, HeaderValue::from_str(&format!("\"{image_id}\"")).expect("etag")),
        (header::CACHE_CONTROL, HeaderValue::from_static("private, max-age=31536000, immutable")),
    ];
    Ok((StatusCode::OK, headers, bytes).into_response())
}
```

`app.rs` 追加：`.route("/api/image-create/sessions/{id}/images/{image_id}", get(handlers::image_create::get_session_image))`。`decode_legacy` 在 `result.b64` 为 `None` 时返回 404（对应 spec 场景「图片文件缺失」）。`invalid_request`/`not_found` 辅助若缺则在 `ImageCreateApiError` 上补（对齐现有 40-67 行错误映射风格）。
