# 3.7 Phase 4 实施计划：advance / 接管操作收口

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:subagent-driven-development`（推荐：每个 Task 派新 subagent，完成后两阶段复核）或 `superpowers:executing-plans`，严格按 Task 顺序实施。步骤使用 checkbox（`- [ ]`）语法跟踪；本计划经 k3 + oracle 双审、用户批准后才可执行。
> **版本：v1.1（按本轮“原地更新”约束保留文件名）**。本版本已吸收 k3 + oracle 双审 findings 及 2026-09-15 用户裁决；用户批准后才可执行。

**Goal:** 在不改引擎的前提下，将对话驾驶舱与编码工作区已经分散的确认、反馈、接管、advance / start coding 操作收口为同一套可审计的前端操作语义：先消除重复交互实现，再提供两页一致快捷键、受限批量确认、可回查历史审计、UI 启动编码补口以及子会话返回父级。

**Architecture:** 以纯 TS 的共享操作语义层为唯一动作入口：它声明键位→语义映射、二次确认的 10 秒状态机、可批量白名单和 `recordAudit` 回执；两页只把各自既有 WS / REST 发送器适配到该层，绝不合并本来不同的 wire 协议。审计采用两层数据：发送成功时的前端**会话级增量**命令日志（`Date.now()` + ISO、操作者固定为“本地浏览器”）补齐即时事实；刷新后的历史则用现有 `session_state`、`getIssueLifecycle` 与 `getCodingAttemptSnapshot` 的 durable 快照重新推导，明确不虚构身份或后端命令历史。Takeover REST 响应中的父 id 仅镜像到前端 store，并以 `sessionStorage` 保存接管子会话→父会话关系；plan-repair 则直接消费已有 `state.planRepair.link.parent_session_id`。

**Tech Stack:** React 19、TypeScript 5.7 strict、Vite 6、Vitest 2.1（jsdom）、Zustand 5、TanStack Router、Tailwind 3、lucide-react；不新增前端依赖。

## Global Constraints（controller 裁决全录）

1. **改动边界 / 引擎零改动**：实现只可修改 `web/src/`，以及关闸时新建 Phase 4 证据报告；`src/` 必须零改动，不新增后端 REST、WS 事件、持久化或前端依赖；不修改 `ImageCreatePage` 及 `web/src/components/image-create/*` 页面内容（tasks §6.1、REQ-UI37-13、设计 C1/C3）。编码侧不得新增插话入口（设计 C7）。
2. **并存与收口**：保持 `ChatWorkspacePage` 的 `cockpit` / `legacy` 双轨开关与 `CodingWorkspacePage` 既有路由；只将 Phase 1–3 的动作 UI 汇向共享实现，禁止新造平行 action facade、计时器、键盘监听器、审计出口或 wire 变体。旧 legacy 页面继续消费同一 `createCockpitActionFacade`，不得回退直发。
3. **操作协议不混用**：对话侧 typed 门反馈仍为 `{type:"human_gate_feedback", command_id, feedback}`；typed 门确认 / 终止、legacy 门确认 / request-change / 终止仍为 `human_confirm`；advance 仍为 `{type:"advance", command_id}`；编码 `start_coding` / `final_confirm` / `stage_gate_confirm` / `gate_response` / `confirm_plan_amendment` 仍分别走既有 coding WS 或 plan-repair workspace WS。前端只适配，不合并 wire（勘察 A.2 :23-58、R2）。
4. **TDD 与验证节奏**：每 Task 必须先写出本文列出的失败用例，运行该精确测试确认红灯，再写最小实现、运行该精确测试绿灯，随后执行 `cd web && pnpm tsc -b && pnpm test` 全绿，才可提交。不得用删除 / 放宽用例替代修复；不运行 `pnpm build`、playwright 或 cargo。
5. **提交纪律**：每 Task 最后一步显式 `git add <逐文件路径>`，禁止 `git add .` / `git add -A`，不 push；本计划不要求创建或修改任何引擎提交。提交由实施 controller 负责；本计划编写任务不执行 `git commit`。
6. **UI / 可访问性纪律**：复用现有 `min-h-11`、`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[var(--aria-primary)]`（勘察 B :79-93、R3）与语义色；不增 token、图标只用 Lucide SVG、触达目标 ≥44px、转换只用现有 150–300ms 模式、弱动效不新设动画。`textarea` / `input` / `select` 聚焦时快捷键不得抢键。
7. **审计如实性（Ruling-2）**：操作人字段一律显示 **“本地浏览器”**，因为前端与既有 durable REST 均无用户身份面；时间为 client 侧 `Date.now()` 同步产生的 ISO 字符串；跨刷新回查以 `session_state` / 已有 REST durable 事实为主，本地命令日志仅为当前标签页增量。严禁展示虚构的登录用户、服务端发令时间或不存在的永久命令历史（勘察 C.1–C.3，R4）。
8. **takeover 父会话暂存（Ruling-3）**：仅用 `sessionStorage` 保存 `childSessionId → parentSessionId`，以接管临时性为语义边界：刷新存活，关闭标签页失效；不得改 URL、不用 `localStorage`、不引入持久化。plan-repair 的父 id 不写 storage，直接读 durable `state.planRepair.link.parent_session_id`。
9. **P3 留档顺修**：Task 1 独立、低风险、最先实施；其余 Task 必须基于 Task 1 后的 P3 组件状态。
10. **关闸硬门**：最后 Task 必须运行 `cd web && pnpm tsc -b && pnpm test`，并运行 `git diff --stat -- src/`，预期空输出；同时核对 `web/package.json` 没有依赖 diff 与 ImageCreate 页面未改。REQ-UI37-12 自动化替身不能替代人工真实链。

### Controller Rulings（Ruling-1 至 Ruling-7）

1. **Ruling-1：顺序与归一优先。**先以独立 Task 修正 P3 留档 F1–F4；再归一动作语义，之后才接快捷键，避免快捷键绑定到三套旧实现。
2. **Ruling-2：审计事实边界。**操作者固定显示“本地浏览器”；成功发送时用 `Date.now()` 与 `new Date(atMs).toISOString()`；刷新后的回查以 existing durable REST / `session_state` 为主，本地日志只补当前标签增量。
3. **Ruling-3：takeover 父链生命周期。**子→父关系只保存于 `sessionStorage`；刷新存活、关闭标签丢失；plan-repair 一律使用 durable link，禁止把两类关系写进 `localStorage` 或 URL。
4. **Ruling-4：范围与出处透明。**正式 REQ-UI37-17 的①②③及 5.4，连同 UI 启动编码、返回父级、P3 顺修和审计时间戳四项附加范围，必须逐项列出出处与边界，见下一节。
5. **Ruling-5：实施计划可执行。**每个实施 Task 都给出 Files、Interfaces、可运行的红 / 绿 TDD 命令、全量类型 / 测试收尾门和逐文件提交命令；T9 是纯关闸核验，不制造空提交。
6. **Ruling-6：REQ-UI37-12 双层证据。**T9 必须包含自动化矩阵和用户亲自完成的人工真实链清单；人工项覆盖两页快捷键、批量确认、审计回查、UI 启动编码→实时日志 / 贴底 / 多节点、返回父级与双轨回滚，均保留截图或勾选，不预填结论。
7. **Ruling-7：快捷键同一性。**两页必须 import 并消费**同一个**导出映射对象；自动化以 `toBe(COCKPIT_HOTKEYS)` 断言引用同一性，禁止两套 map 各自通过等值测试。

import { forwardRef, useCallback, useEffect, useImperativeHandle, useState } from "react";
import {
  DANGEROUS_CONFIRM_TIMEOUT_MS,
  type ConfirmTwiceButtonHandle,
} from "../../../state/cockpit-operation-semantics";

export const ConfirmTwiceButton = forwardRef<ConfirmTwiceButtonHandle, {
  label: string; confirmLabel: string; onConfirm: () => void;
}>(function ConfirmTwiceButton({ label, confirmLabel, onConfirm }, ref) {
  const [armed, setArmed] = useState(false);
  const arm = useCallback(() => {
    if (armed) { setArmed(false); onConfirm(); return; }
    setArmed(true);
  }, [armed, onConfirm]);
  useImperativeHandle(ref, () => ({ arm }), [arm]);
  useEffect(() => {
    if (!armed) return;
    const timer = window.setTimeout(() => setArmed(false), DANGEROUS_CONFIRM_TIMEOUT_MS);
    return () => window.clearTimeout(timer);
  }, [armed]);
  return <button data-testid="confirm-twice-button" type="button" onClick={arm} className="inline-flex min-h-11 items-center gap-1 rounded-md border border-red-200 bg-white px-3 text-xs font-semibold text-red-700 hover:bg-red-50 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[var(--aria-primary)]">
    {armed ? confirmLabel : label}
  </button>;
});

import { useEffect } from "react";
import {
  COCKPIT_HOTKEYS,
  isTextEditingTarget,
  type CockpitHotkeyAction,
  type CockpitHotkeyHandlers,
} from "../state/cockpit-operation-semantics";

export function useCockpitHotkeys(handlers: CockpitHotkeyHandlers): void {
  useEffect(() => {
    const onKeyDown = (event: KeyboardEvent) => {
      if (event.defaultPrevented || event.altKey || isTextEditingTarget(event.target)) return;
      const action = (Object.keys(COCKPIT_HOTKEYS) as CockpitHotkeyAction[]).find((candidate) => {
        const binding = COCKPIT_HOTKEYS[candidate];
        return event.code === binding.code && (event.ctrlKey || event.metaKey) === binding.ctrlOrMeta && event.shiftKey === binding.shift;
      });
      if (!action) return;
      event.preventDefault();
      handlers[action]();
    };
    document.addEventListener("keydown", onKeyDown);
    return () => document.removeEventListener("keydown", onKeyDown);
  }, [handlers]);
}
