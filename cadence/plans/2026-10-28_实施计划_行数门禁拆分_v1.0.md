# 行数门禁拆分 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 24 个超行数上限的源码文件拆到每个 ≤ 1200 行，使它们在门禁登记表里的登记项可被移除，行数门禁转绿，**零行为变化**。

**Architecture:** 纯移动拆分 —— 把大文件里连续的职责块原样搬到若干小文件，模块接线按两种既有机制处理（`include!` 文本内联 / `#[path]` 真模块）。可见性只允许一个方向的调整：私有 → `pub(super)`，或子模块内 `use super::*;`。

**Tech Stack:** Rust（`src/`，`#[cfg(test)]` 内联测试与 `include!` / `#[path]` 两种接线）、TypeScript / TSX（`web/src/`）、测试门禁 `tests/it_core/large_file_guard.rs`

**Spec:** `cadence/notes/2026-10-28_决策记录_行数门禁处置与销账留痕落点_v1.0.md`（§三 执行原则 D-02 方案 A）；门禁规则本体 `tests/it_core/large_file_guard.rs`；范围实测见本计划「目标清单」

## Global Constraints

- **零行为变化**：被搬走的代码**逐字不变**（函数体、注释、测试断言、`#[]` 属性一并搬）；不得借拆分之名改逻辑、改签名、改文案、改断言
- **可见性只允许**私有 → `pub(super)` 放宽（或子模块内 `use super::*;`）；**不得**放宽到 `pub`；**不得**收窄
- **每个产出文件（含原文件）必须 ≤ 1200 行** —— 否则登记项无法移除，拆分白做
- **不得**改 provider 适配层 / `ProviderToolPolicy` / 网关信封 / 流式输入结构；不得改任何协议 / 契约 / 错误码 / 文案；不得引新依赖
- **不得**改 `tests/it_core/large_file_guard.rs`（登记表由 controller 统一改）
- **拆分优先于上调**：拆完从登记表**移除该项**；确需新增登记项须用户裁决
- **无法零行为切开 → 停下上报**，由 owner 决定是否改走「更新上限」路线（**不硬拆**）
- 并发纪律：多个 agent 同一工作树，**不由 agent 提交**（避免 `index.lock` 竞争），由 controller 统一提交

## Review Focus

（这些是纯拆分最容易悄悄破坏、而测试未必覆盖的点；每条在下面对应任务里都要有对应检查）

1. **测试归属漂移**：测试从 `foo.rs` 搬到 `foo/bar.rs` 后，若 `#[cfg(test)]` 门或 `mod` 名变了，测试可能**静默不再运行**（用例数减少但无失败）→ 每个拆分都要比对**测试用例数**（`cargo test --lib` 的 `N passed` 不得减少）
2. **`include!` 片段跨界**：纯文本插入的 `.inc.rs` 片段若把一个 `mod xxx { … }` 块劈成两半 → 语法错或语义漂移
3. **可见性放宽过头**：为拆文件把原本私有的项放宽成 `pub` → 扩大了公开 API 面，等于改了契约
4. **`use` 语句作用域漂移**：`include!` 内联的 `use` 落到宿主模块作用域，与真模块的 `use super::*` 语义不同 → 换机制时可能改变名字解析
5. **前端拆分引入循环依赖 / 副作用执行顺序变化**：TS 文件拆出后若产生循环 import，模块初始化顺序会变
