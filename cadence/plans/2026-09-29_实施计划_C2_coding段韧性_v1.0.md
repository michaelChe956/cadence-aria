# C2 coding 执行韧性与产品分诊实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `subagent-driven-development`（推荐）或 `executing-plans` 逐任务实施。任务步骤使用 checkbox（`- [ ]`）跟踪；本计划只定义实现，不代表代码已经完成。

**Goal：** 交付 `coding-execution-resilience-and-product-triage`（C2）：coding 链在断连、双 kick、abort 后重启、人工继续、reviewer 空配置、执行区间证据、返修指令消费、验证命令不可满足、受限政策读取与大候选返修上，全部转为"错误→通知→产品操作→原链继续"的可操作停等，收敛 BYPASS-17／18／19 三条直写旁路，并满足 A06、A08、A09（coding 部分）、A10（reviewer 部分）、A11、A14、A15。

**Architecture：** 复用 C1（`enrollment-recovery-surface`）已落地的租约三态判定（`classify_worktree_lease`／`confirm_takeover`）、C1WaitingItemDto 驾驶舱只读投影与命令账本幂等（`payload_digest`）模式。产物一律先写既有持久面再发观察事件；coding admission 临界区（`ensure_provider_run_allowed` 所在临界区）接入租约三态实现最小编码互斥；新增 attempt-scoped 命令账本与验证处理记录两个持久面；execution 提交区间按认领前真实 HEAD 派生；SC 人工返修按完整预算与完整有序传输；政策读取消费 C4 resolver。不新增 durable owner／fence／incarnation、第二套 durable operation 状态机或服务端通用命令执行器。

**Tech Stack：** Rust 2024、Axum、Tokio、serde、既有文件锁／CAS／journal durable store；React、TypeScript、Vitest、Testing Library；不新增外部依赖。

**Spec：** `openspec/changes/coding-execution-resilience-and-product-triage/{proposal.md,design.md,tasks.md,specs/coding-run-operability/spec.md,specs/coding-verification-triage/spec.md,specs/work-item-group-coding-execution/spec.md,specs/coding-code-review-triage/spec.md,specs/group-final-review-triage/spec.md,specs/coding-workspace-completion/spec.md,specs/coder-owned-work-item-commit/spec.md,specs/work-item-plan-conversational-gate/spec.md,specs/session-policy-envelope/spec.md}`；上位合同为 `cadence/designs/2026-09-28_方案设计_真实链缺口修复总方案_v1.2.md` §5.2、§5.5、§6.2、§7；格式参照 `cadence/plans/2026-09-29_实施计划_C1_enrollment恢复操作面_v1.0.md`。

## Global Constraints

- **自动推进＋人到点处理：** coding 链只在安全、已授权、当前 lease／attempt／checkpoint 均可证明的 durable 状态下自动推进；断连、完成状态不明、租约冲突、配置缺失、验证不可满足、预算超限一律转可操作停等（通知＋带身份的用户操作＋原链继续）。系统 MUST NOT 自动重启完成状态不明的运行、MUST NOT 自动抢占活跃或未知租约持有者、MUST NOT 自动批准任何验证结论／豁免／FinalConfirm、MUST NOT 自动反馈或重放未知副作用。
- **Non-Goals（proposal 逐字口径）：** 不实现 durable runner owner、run incarnation、worktree fence／epoch、双主检测、统一 context evolution、自动 retry 未知 provider 副作用；不扩展或改写 `coding_output_human_triage` 两动作与三个 Code Review 分诊门四动作，不向原门塞 plan repair 动作；不清除、改写历史 finding、旧 execution、旧 artifact、旧 hash 或旧 gate 证据，不以改 JSON／consumed／note／findings 作为恢复手段；不自动批准 FinalConfirm、危险命令或验证豁免；不新增服务端通用命令执行器；不负责 #9 计划权限语义（C1）、LC authority resolver 本身（C4）、单仓 role-chain 预检与 pi recipe（C5／延期）。
- **零回归：** 既有 CAS、attempt 文件锁、工作树锁、gate／journal／DTO 与驾驶舱投影只扩展不新建；非本 change 故障面的既有行为与测试期望零变化。全计划仅两处必改既有测试：`src/web/coding_ws_handler/tests.rs:1012-1037`（manual_continue 不续跑断言，Task 4 行为反转）与 `tests/it_product/product_coding_models.rs:73` `coding_role_provider_config_snapshot_falls_back_to_author_when_reviewer_is_missing`（author 回填 pin 毒测试，Task 5 必删／改）；其余既有测试不得修改期望来换取通过。
- **幂等与版本：** 所有操作携带稳定 `command_id`、对象身份与 expected 版本；同 command 同 payload 返回首次 durable 结果（复用 C1 命令账本 `payload_digest` 模式），同 command 异 payload、过期版本或错对象 fail-closed（返回"请刷新"，不触发 provider）。通知／WS 投递失败 MUST NOT 回滚业务事实，驾驶舱经 GET 补读。
- **绿灯过滤词纪律：** 每个任务绿灯步骤的既有回归只允许使用本文档"防假绿实名测试清单"中的测试名（Rust 用 `cargo test --locked --lib <函数名子串>`，前端用 `pnpm -C web exec vitest run <文件>`）；不得以新造测试名冒充既有回归，不得以"通过数量增加"替代实名测试。任务内新写的失败测试以各任务 Step 1 定义的名称为准。
- **计划自检纪律：** 本计划编写完成后已执行 grep 自检——所有 cargo 过滤词与防假绿清单逐字一致；所有 `src/`、`web/src/` 路径仅来自备料简报锚点与 OpenSpec 契约文件；新增符号均标注所属任务，未冒称已存在。
- **C4 依赖边界：** #17 政策读取硬依赖 C4 `logical-codebase-bootstrap-and-repair-surface` 的 authority／policy resolver 输出；resolver 未交付时该子面以"resolver 不可用"停等呈现，MUST NOT 实现本地 fallback 路径；联验阶段与 C4 一次集成。
- **提交与验证纪律：** `git add` 逐文件列出，禁止整目录提交；任务内只运行定向测试，项目级 build／lint／全量测试由主控在所有任务合入后统一执行。

## Review Focus

1. **断连／观察通道全失效时的完成路径：** 无 WS 订阅者、relay 失败或投递失败时，业务结果与 attempt 状态照常持久化、驾驶舱可补读、不产生失败或中止终态（Task 1）。
2. **迟到旧持有者、旧 run 回执与过期版本：** 接管后旧持有者迟到写入被拒；restart 后旧 run 回执不复活旧 run；旧页面对已推进对象操作返回"请刷新"，均不启动 provider、不改当前状态（Task 2、Task 3、Task 12）。
3. **中断窗口的指令消费与恢复：** 渲染失败不消费；认领后 spawn 前中断可经用户操作以同一认领与同一上下文 hash 恢复；同一指令至多被一次 role run 消费（Task 7）。
4. **旧 durable 数据与门动作集合兼容：** 旧 role provider 快照缺三值字段按空 effective 解释并停等，不回填 author／Codex；已有 `start_commit` 的历史 UnitRun 不重算、重连不改写起点；coder 输出门恰两动作、Code Review 门恰四动作零变化（Task 5、Task 6、Task 8）。
5. **验证处理滥用面：** 零测试执行且 check 要求非零测试的证据被拒；plan revision 过期、scope 过宽、重复转入、证据不完整均 fail-closed；无用户批准零推进，findings 只标注不清空（Task 8）。
