# 3.7 Phase 1b 实施计划：就地动作、提醒、聚合、autopilot 与接管

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐，逐 Task 派新 subagent + 两阶段复核）或 `superpowers:executing-plans`（本会话批量执行 + 检查点）按 Task 逐个实施。步骤使用 checkbox（`- [ ]`）语法跟踪。

**Goal:** 在既有单会话只读驾驶舱上交付全局卡壳可见性、受界跨会话聚合、门面正确的就地动作、保守 autopilot、四层提醒、设置和 stopped 接管，使人工只在收件箱处理异常。

**Architecture:** 将可持久的用户偏好放在一个 localStorage-backed 配置模块；将所有跨会话只读事实放在独立的 session observer store，绝不让多个会话复用现有单例 `useWorkspaceStore`。由 observer 投影出跨会话收件箱、计数与提醒输入；当前会话继续使用既有 `useWorkspaceWs(sessionId)` 和 `ChatCockpitPage` 的单会话 store，动作经现有发送 helper 或既有 takeover REST 发出。根路由挂全局 shell，保证工作流路由与 `/image-create` 都共享 L2/L3/L1 表面；②区只读，③区仍复用虚拟化 `ChatEntryList`。

**Tech Stack:** React 19 + TypeScript 5.7（strict、`tsc -b`）+ Vite 6 + Vitest 2.1（jsdom）+ Zustand 5 + Tailwind 3 + lucide-react + 既有 `@tanstack/react-virtual`；不新增依赖。

5. **运行纪律**：跨会话不可以直接并行渲染多个 `useWorkspaceWs(sessionId)`，因为它们会改写同一个 `useWorkspaceStore`。watch 会话必须由独立 observer store/连接控制器持有；当前页单会话连接保持原行为。
6. **人工面边界**：typed `single_candidate` 门的反馈只发 `sendHumanGateFeedback(feedback, commandId)`；其确认/终止只发 `sendHumanConfirm("confirm" | "terminate")`；legacy 门三种决策都发 `sendHumanConfirm("confirm" | "request-change" | "terminate", payload?)`。分诊是 gate 亚型；②区不新增输入；hard error 不出现接管。
7. **验收分层**：fake provider/review-fixture 与 Vitest 仅是自动化证据，绝不代替轻语料 + `pi` 的真实链人工验收；每个 Phase 关闸同时产出两份清单。
8. **提交纪律**：每个 Task 的最后一步显式 `git add <逐文件路径>`，提交信息用中文 `feat:` / `fix:` / `test:`；禁止 `git add .`、`git add -A`；**不 push**。
9. **零占位**：本计划及实现均不得出现 `TODO`、`TBD`、`implement later`、`fill in`、`适当处理`、无行为断言的测试或注释掉的实现。
