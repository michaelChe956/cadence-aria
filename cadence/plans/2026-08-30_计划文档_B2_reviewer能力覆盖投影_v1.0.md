# B2 Reviewer 能力覆盖投影实施计划 v1.0

**Goal：** 在不改变 canonical validator、scope/digest/CAS、scope 文本、digest、CAS、legacy/story/design reviewer 或 `.aria/` 数据边界的前提下，为单候选 reviewer 注入与 `report_contract_requirements` 同源计算的只读契约能力覆盖投影；当任一 `WI→contract` edge 存在能力缺口时，reviewer 被明确要求产出 `must_fix`、`contract_gap` finding，并以测试证明投影与 validator 的 `missing` 集一致、且非单候选 reviewer 路径不接收该投影。

**Architecture：** `DependencyContractGraph` 继续是由 `build_dependency_contract_graph` 从 `CanonicalWorkItemContract` 构建的唯一图输入；将现有 `report_contract_requirements` 中“按 contract_id 收集 provider capabilities、按 `RequireAll` 差集/`RequireAny` 不相交判定缺口”的纯计算抽为共享 helper。新增 `ContractCapabilityCoverage` 与 `project_contract_capability_coverage(&DependencyContractGraph)` 产出逐 edge、逐所引 contract 的只读投影；validator 仅复用该 helper 生成既有 findings，保持 fail-closed 对外行为。`build_single_candidate_plan_review_input` 从 IR item 的 canonical contracts 构图、调用投影函数，并在既有 `Dependency Contract Graph` section 后经 `append_review_context_section` 追加 `Reviewer Capability Coverage Projection`；初评与复评共用该 single-candidate builder，legacy/story/design builder 不调用它。`single_candidate_dependency_graph` 纯 helper 从 `review.rs` 移到 `prompts/review_context.rs`，行为不变，以独立 parity 测试证明。single-candidate prompt 的预算检查统一由 `ensure_single_candidate_review_prompt_budget(&str)` 完成：builder 末尾检查一次，scope 追加后对最终 prompt 再检查一次；仅单候选分支使用同一个 64 KiB 常量和同一个函数。

**Interfaces:**

- **Consumes：** `DependencyContractGraph`，其中 `edges[].required_contracts[]` 提供 edge、contract、required capabilities 与 `compatibility_policy`，`contracts[edge.from].output_contracts[]` 提供 provider capabilities。
- **Produces：** `project_contract_capability_coverage(&DependencyContractGraph) -> Vec<ContractCapabilityCoverage>`；validator 继续产生既有 `ContractValidationReport`/`required_capability_missing` findings。

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub(crate) struct ContractCapabilityCoverage {
    pub from: String,
    pub to: String,
    pub contract_id: String,
    pub required_capabilities: Vec<String>,
    pub provided_capabilities: Vec<String>,
    pub missing_capabilities: Vec<String>,
    pub compatibility_policy: ContractCompatibilityPolicy,
}

fn missing_capabilities_for_policy(
    required_capabilities: &[String],
    provided_capabilities: &BTreeSet<&str>,
    compatibility_policy: &ContractCompatibilityPolicy,
) -> Vec<String>;

pub(crate) fn project_contract_capability_coverage(
    graph: &DependencyContractGraph,
) -> Vec<ContractCapabilityCoverage>;
```

`project_contract_capability_coverage` 的输入只接受 `DependencyContractGraph`；对每个 `DependencyContractEdge` 的每个 `RequiredDependencyContract` 产出一项，`from`/`to`/`contract_id`/policy 直接来自 edge；provider 的 `output_contracts` 按 `contract_id` 聚合去重后以排序 `Vec<String>` 输出。provider 不存在或 provider 没有被引用的 `contract_id` 时，投影仍产出该 edge 行，`provided_capabilities=[]`，`missing_capabilities` 按 `RequireAll`/`RequireAny` 规则从 required 集得到（因此非空 required 在缺失 contract 时 fail closed）；`report_contract_requirements` 仍先按现有逻辑产出 `unknown_provider_logical_work_item` 或 `required_contract_missing`，并继续跳过 capability findings。这样 reviewer 不会得到缺失 edge 的假完整 coverage，validator 对外 finding 仍保持原样。

能力判定必须只有一处：`RequireAll` 的 `missing = required - provided`；`RequireAny` 且 required 非空且与 provided 不相交时 `missing = required`，否则 `missing = []`。`required_capabilities`、`provided_capabilities`、`missing_capabilities` 均去重、排序；边和 required contract 沿现有 graph 确定性顺序输出。同一 helper 的结果同时供 `report_contract_requirements` 生成 `required_capability_missing` findings 和 reviewer projection，禁止 reviewer 自行读取 canonical item 再比较。

```rust
pub(crate) const SINGLE_CANDIDATE_REVIEW_PROMPT_MAX_BYTES: usize = 64 * 1024;

pub(crate) fn ensure_single_candidate_review_prompt_budget(
```
