# 删除工作项组时取消在途 run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 删除工作项组时，先取消该实体绑定的在途 provider run 并等其真实收口，使删除独占可获得；删除不再以 `entity_busy`（HTTP 409）长期阻塞，同时被中止的 run 在时间线中以「中止」而非「失败」表达。

**Architecture:** 复用既有非 WebSocket 取消入口 `WorkspaceSessionManager::abort_active_run_and_wait_completion`（真实 completion 语义），在删除路径 `:159` 终止 CAS 之后、`:161` 「② try 删除独占」注释之前插入一段按 `entity_id` 精确匹配的有界取消块；取消返回值升级为三态枚举（无活跃 run / 已收口 / 兜底超时），删除路径按三态如实分支，超时只报占用者、不谎称已取消、不阻塞删除。时间线侧新增 `TimelineNodeStatus::Aborted`（沿用既有 `aborted` 词汇），节点进入终态时 `stage` 归一为唯一终态 stage，消除「stage=running + 终态 status」组合；WS 与前端值域同步镜像。

**Tech Stack:** Rust 2024、Tokio、axum 0.8、既有 `WorkspaceSessionRegistry` / `EntityOperationStore`（flock 共享/独占）、serde（snake_case 契约面）、Vitest + React（前端）、libtest 集成测试（`tests/it_web`）。

**Spec:** `openspec/changes/work-item-delete-cancels-inflight-run/`（`proposal.md` + `tasks.md` + `specs/work-item-group-autopilot/spec.md` 的 REQ-WIGA-15/16/17 + `specs/lifecycle-entity-deletion/spec.md` 的 MODIFIED REQ-DEL-06）——本 Plan 从该 change 展开，契约与证据随文档一起走，实施者必须同时读 change 的四份文件。

## Review Focus

1. **目标实体没有在途 run 时的删除语义完全不变**：不额外等待、不产生额外副作用、不改变删除结果与既有错误码；既有用例 `delete_work_item_plan_removes_all_artifacts_and_preserves_issue` 等继续逐字通过（Task 2）。
2. **取消不得越界**：同一 issue 下另一个实体（或另一个 session）的在途 run MUST 保持运行、`CancellationToken` 未触发、run 仍在位；取消动作只作用于 `entity_id` 与被删实体精确匹配的 session（Task 2）。
3. **取消未在兜底内收口时不得谎称已取消、也不得因此阻塞删除**：删除路径不得记录/宣称「已取消/已停止」这类与事实相反的事实，仍按既有独占判定推进，拿不到独占时按既有语义报出占用者（Task 3）。
4. **被中止的 run 的 `status`/`stage`/`summary` 三者一致且与真实失败可区分**：`status` 不是 `failed`、表达「中止」；`summary` 表达「已中止」而非失败原因；不得出现「`stage=running` + 终态语义」；`completed_at` 落盘；真实失败路径仍为 `failed`（Task 4）。
5. **既有删除语义不被削弱**：墓碑幂等、门禁拒绝时零破坏（墓碑未立起）、enrollment 只终止一次（`terminated_at` 非空、`policy_revision` 恰好 +1）、`command_ledger` 旧条目逐字未变、enrollment 记录不被物理删除（Task 6）。
