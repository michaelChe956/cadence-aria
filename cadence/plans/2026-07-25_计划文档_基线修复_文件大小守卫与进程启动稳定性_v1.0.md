# 基线文件大小守卫与进程启动稳定性 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前五个超过 800 行的源/测试文件按既有职责拆分，并让短暂的 `ETXTBSY`（Text file busy）进程启动错误有界重试，恢复全量测试基线。

**Architecture:** 不改变 Repository 初始化、Workspace 上下文、WebSocket 或 Work Item Draft 的业务契约。每次拆分只移动完整私有函数或完整测试组至同一父模块下的子文件，保留原函数签名和可见性；`ProcessManager` 在 Unix `ETXTBSY` 时最多重试两次，以涵盖并发测试中刚关闭脚本的短暂不可执行窗口，而其它启动错误保持原映射。

**Tech Stack:** Rust 2024、Tokio、现有 `ProcessManager`/`BoundedCommandRunner`、Rust module/include 测试组织、Cargo。

## Global Constraints

- 当前 worktree 为 `feat-b-0722-add-workspace`；先完成 `add-repository-initialization-git-finalize` 的既有功能，再处理本基线修复。
- 不改变任何 Git finalize 命令、固定提交信息 `初始化cadence-aria 代码库`、失败降级语义或 HTTP/前端契约。
- 800 行守卫阈值固定为 `tests/it_core/large_file_guard.rs` 中的 800；所有新建 Rust 文件也必须低于该值。
- 只按职责移动完整函数/测试，不复制实现，不改变公开符号、序列化格式、Provider Prompt 或 Work Item Draft 结构化契约。
- Cargo 命令必须使用 `--locked`，禁止 `-j 1`；测试 fixture 不执行真实 Git push 或真实 Provider。
- `ETXTBSY` 只重试由 `ManagedProcessChild::spawn` 返回的 raw OS error 26；`NotFound` 仍映射为 `ProviderCommandMissing`，其它 I/O 错误仍立即映射为既有 `ProviderAdapterError`。

fn text_file_busy_is_retryable_but_not_a_missing_command() {

    assert!(is_retryable_spawn_error(&busy));

```

运行：

```

预期：因 `is_retryable_spawn_error` 尚不存在而编译失败。

- [ ] **Step 2: 实现有界、仅限 ETXTBSY 的 retry loop**

在 production 区定义：

```rust
const TRANSIENT_SPAWN_RETRY_COUNT: usize = 2;
const TRANSIENT_SPAWN_RETRY_DELAY: Duration = Duration::from_millis(10);

fn is_retryable_spawn_error(error: &std::io::Error) -> bool {
    #[cfg(unix)]
    {
        error.raw_os_error() == Some(26)
    }
    #[cfg(not(unix))]
    {
        let _ = error;
        false
    }
}
```

将单次 `ManagedProcessChild::spawn` 替换为最多 `TRANSIENT_SPAWN_RETRY_COUNT + 1` 次的循环；只有 helper 返回 true 且仍有次数时 `tokio::time::sleep(TRANSIENT_SPAWN_RETRY_DELAY).await` 后重新构造 `Command`、保留同一 argv/current_dir/env/stdin/stdout/stderr 设置。循环结束仍调用原 `map_spawn_error(command, error)`，不得把错误转为 command missing 或吞掉。
