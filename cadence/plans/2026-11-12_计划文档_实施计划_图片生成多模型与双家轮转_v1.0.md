## Review Focus

1. **MiniMax 在 `size=auto` 时漏发 `area=1K`**（误发 `size=auto`）→ MiniMax 官方默认面积档是 `4K`（4096²），出图会超参考图校验上限（单边 4096、总像素 4096×4096、10 MiB），MiniMax 出图之后的下一次携带断裂 → T3 的 C-02b / C-05 断言「发 `area=1K` 且不发 `size`」钉死。
2. **MiniMax 请求混入 GPT 专有字段**（`quality` / `background`）→ MiniMax 官方 schema 无此二字段，会被判参数错误（2013）→ T3 的 C-02 / C-05 用**字段全等**匹配（多一个字段即不匹配）钉死。
3. **GPT 请求混入 `response_format`** → 官方明确 GPT Image 模型不支持该遗留参数 → T3 的 C-01 / C-04 用全等匹配钉死。
4. **所选模型不可用时静默换家**（原第 4 条「轮转把失败当成一次轮次」已失效：自动轮转已按用户 2026-11-12 要求移除）→ 用户不知道实际出图与计费的是哪一家 → Task 15 的 T-04 / T-05 断言「报错且不落到另一家」、E-03 断言「失败后不重试、不换家重发」钉死。
5. **上一张生成图取不到时静默退化为文生图** → 用户得到一张无关的新图并付费，且修改意图被掩盖 → T6 的 E-10 断言「出站调用次数为 0 且返回明确错误」钉死。

- 目标解析语义（技术方案 5.1）：按逐字符相等在**已配置凭据且清单非空**的供应方里找 model id 的归属家；找到即返回 `{ vendor, model }`；id 只在缺凭据的家的清单里 → 配置缺失「{家} 尚未配置 Base URL 或 API Key」；不在任何清单 → 参数错误「模型 {id} 不在已配置且可用的供应方清单中」。**没有首选家，没有换家。**
- 生成请求：`model` **必填**；缺省或去首尾空白后为空 → 参数错误「请选择图片生成模型」，不出站；没有 `auto` 保留值。
- 生成成功响应：`{ image_id, media_type, vendor, model, reference_source }`（去掉 `selection`）；会话 DTO 同步。
- 前端 `params.model`：初值为空串；设置加载后 = 第一个可用供应方清单的首个 id；没有可用供应方时保持空串，**生成按钮禁用**并提示「请先在设置里配置并启用至少一个供应方」；设置变更后所选模型不再可用时，重置为同一规则的结果。
- 模型下拉：只列可用供应方的 model id（文案即 id），没有「自动」类选项；设置弹窗没有每家的轮转模型下拉；对话区标注不含选择方式。
