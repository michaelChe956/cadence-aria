# 图片创作 Agent 实施计划（Implementation Plan）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Cadence Aria 新增独立顶层的图片创作 Agent——用户多轮对话迭代图片 prompt（复用现有 CLI 执行器），确认后由 Aria 后端调用 gpt-image-2 网关生成单张图片并在前端展示。

**Architecture:** 后端新增 reqwest 图片客户端（按有无参考图选 `/generations` 或 `/edits`）+ image-create 会话/设置 handler（复用 `StreamingProviderAdapter` 做 prompt 迭代、`AriaStatePaths` 做持久化）；前端新增 `/image-create` 顶层路由与图片创作页面（复用 chat-workspace 展示组件，独立 entry 模型）。两阶段解耦：执行器只聊文本，Aria 后端统一调图片 API。

**Tech Stack:** Rust（edition 2024）/Axum/Tokio + reqwest(json,multipart)；TypeScript/React 19/TanStack Router/Zustand/Tailwind/Vitest。

**契约来源：** `openspec/changes/add-image-create-agent/`（proposal/design/specs/tasks，4 轮独立 review 已收敛）；PRD `cadence/prds/2026-08-03_概要需求_图片创作agent_v1.2.md`。

## Global Constraints

（所有 Task 隐含遵循；值逐字来自 spec）

- 后端测试：`cargo test --locked`（🔴 禁止 `-j 1`；并行度由 `.cargo/config.toml` 托管）；定向单测用 `cargo test --locked --lib <过滤名>`。
- 后端检查：`cargo fmt --check`、`cargo clippy --all-targets --all-features --locked -- -D warnings`、`cargo check --locked` 必须全过。
- 前端：包管理器 `pnpm`（禁 npm/yarn）；测试 `cd web && pnpm test`（Vitest）；类型检查 `cd web && pnpm tsc -b`。
- 后端新依赖 `reqwest`：限定 features `json`、`multipart`，锁版本写进 `Cargo.toml`。
- 图片参数枚举（逐字）：`size` ∈ {1024x1024, 1536x1024, 1024x1536, auto}；`quality` ∈ {low, medium, high, auto}；`background` ∈ {transparent, opaque, auto}；`output_format` ∈ {png, jpeg, webp}；`input_fidelity` ∈ {low, high}。
- 参考图约束（逐字）：单张；仅静态图（拒绝动图/多帧）；≤10 MB；解码后单边 ≤4096、总像素 ≤4096×4096；按实际文件内容校验（不只信声明 MIME）；受限解码（先读元数据/帧信息，内存/像素分配与解码超时）；不持久化。
- 出站安全（逐字）：`base_url` 仅 HTTPS 或本地回环；默认禁用自动重定向；如允许重定向仅同 origin（scheme+host+port 全同）、拒绝 HTTPS→HTTP 降级、跨 origin/降级不携带 Authorization；日志/诊断/测试夹具不明文记录 `api_key`。
- 生图：每次恰好一张；不自动重试；单会话任一时刻最多一个进行中后端操作；会话删除为线性化（tombstone→等待在途终止/条件写入→无在途写入才清理，删除后异步完成不回写）。
- key 边界：`api_key` 仅后端用于 reqwest 鉴权头；绝不传 CLI 子进程；GET 返回脱敏；PUT 对 key 保留语义（空或占位保留原值，清除需显式）。
- 语言：所有面向用户文案与文档用中文；代码注释中英均可但公共 API 文档保持简洁。
- Plan 只能展开契约，不重定义范围/架构/验收（见 `openspec/config.yaml`）。

## Task 6：prompt 迭代引擎（驱动 StreamingProvider + 结构化 suggested_prompt + 续接降级）

**Files:**
- Create: `src/product/image_create/prompt_iteration.rs`
- Depends on：`StreamingProviderAdapter`（来自 `state.provider_registry`）、`StructuredOutputContract`、Task 4/5
- Test: 内联，用 `crate::cross_cutting::streaming_provider::FakeStreamingProvider`（参考其现有用法，见 `src/cross_cutting/streaming_provider/fake.rs`）

**Interfaces:**
- `pub struct PromptIterationEngine { provider_registry: Arc<ProviderRegistry> }`
- `pub async fn iterate(&self, session: &ImageCreateSession, user_message: &str, cancel: CancellationToken) -> Result<IterationOutcome, IterationError>`
- `IterationOutcome { readable_text: String, suggested_prompt: Option<String>, new_provider_session_id: Option<String> }`
- 结构化契约：`StructuredOutputContract { nonce: "image-create-suggested-prompt", schema_name: "suggested_prompt" }`；执行器产出形如 `<ARIA_STRUCTURED_OUTPUT nonce="image-create-suggested-prompt">{ "suggested_prompt": "..." }</ARIA_STRUCTURED_OUTPUT>`（约定字段 `suggested_prompt` 非空字符串，逐字来自 spec「结构化建议 prompt 的约定」）。
- **续接降级（spec）**：首轮传 `resume_provider_session_id = session.last_provider_session_id`；若 provider 启动/运行返回「session 失效」类错误（约定一个可识别错误判定），则用 `None` 重新 start，并把「模板引导词 + 历史用户输入 + 上一轮 suggested_prompt」拼进 prompt 回灌。
- 解析：从 `ProviderEvent::Completed(ProviderCompletion { structured_output, provider_session_id, readable_output })` 取；`StructuredOutputState::Parsed(v)` → `v["suggested_prompt"].as_str()` 非空则 Some；`Failed/NotRequested/空` → None（保留上一轮，由调用方处理）。

- [ ] **Step 1：写失败测试 A（FakeProvider 正常解析）——iterate 返回 suggested_prompt=Some 且 new_provider_session_id 正确； readable_text 非空**
