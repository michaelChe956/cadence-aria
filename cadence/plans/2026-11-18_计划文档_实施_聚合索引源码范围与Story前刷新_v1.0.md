## 0. 全局约束（违反即返工）

1. **不动已落地的失败面工作。** `web/src/components/lifecycle/AggregateIndexCard.tsx` 的失败面/证据面渲染、`AggregateIndexCard.test.tsx` 的既有 9 条用例、`src/web/handlers/aggregate_index.rs` 的 `failure_copy`/`evidence_copy` 互斥，一律**保持语义不变**；本计划只在旁边加跳过告警行与成员标注。
2. **判定点唯一。** 四态判定只写在 `AggregateIndexAcceptance::verify`（模块私有 `fn`，签名见 §5.2）；UI、投影层、`freshness.rs` 都**不得**复算「有没有源码」。`freshness` 只负责「要不要重新验收」。
3. **无法确认 ≠ 无源码。** 盘检因权限/IO/超时/超限未完成且无正证据时必须 `Unknown`（失败），任何代码路径不得把它降级成 `NoSource`；**成员缺覆盖键**同样不得被当作「已确认无源码」（见 §5.2 第 4 条）。
4. **`included` 语义冻结。** `AggregateIndexMemberSnapshot.included`（`aggregate_index/types.rs:24`）保持既有原义；跳过只由新字段 `skip_reason` 表达。`included` 还被 `planning_context_resolver.rs:621` 当 `available` 使用（design D4），写 `false` 会把跳过成员变成不可用目标仓。
5. **不加 `schema_version`、不写迁移。** 兼容只靠 serde 缺省：新字段必须 `#[serde(default, skip_serializing_if = "Option::is_none")]`；老 JSON 无字段即 `None`；`None` 不得被投影成跳过证据。
6. **不扩大 CodeGraph 收录范围。** 不改 `codegraph.json` 的 `exclude` 生成口径（`aggregate_index/exclude.rs:49-105`）、不生成 `extensions`、不改版本区间（`codegraph_cli.rs:22-23`，现行 `>=1.6.0, <2.0.0`）、不要求把配置/文档纳入索引。
7. **不新增后台轮询 / 不新增服务端点。** 创建 Issue、勾选成员、刷新页面、同一次生成中的后续对话都不触发索引刷新；三个入口共用既有组件 `web/src/components/lifecycle/LogicalCodebaseLayoutTree.tsx`。
8. **中文文案单一来源。** 用户可见中文全部来自 `src/product/logical_codebase/failure_copy_table.inc.rs` 的码表；前端**只渲染服务端下发的成品文本**，不得在 TSX 里写第二份同义中文（`LogicalCodebaseLayoutTree.test.tsx:57` 已有反重复文案守卫用例 `slice5_files_contain_no_layout_copy_constants`）。
9. **告警与未检索统一为结构化对象 `{code, message_zh}`。** 卡片跳过告警、成员行标注、证据 `not_searched` 三者同构；`code` 恒为已登记的告警码 `aggregate_index_member_source_less`（同一事实同一码），**不新造平行码**，**不用裸中文字符串**承载。
10. **失败封套解析只有一个共用入口，且在产品层。** 持久化封套 `aggregate_index_failed:<code>: <message>` / `aggregate_index_degraded:<code>: <message>` → 「内层稳定码 + 原始事实 + 三段成品」的解析能力落在 `src/product/logical_codebase/failure_copy`，HTTP 投影与冷启动 Bootstrap 投影**都**经它取码；**禁止**任何一方用裸消息前缀（`warning.contains("<code>")`）判断。
11. **Story 专用刷新入口，不改只读规划。** 「必须是最新索引」这条更严的要求**只属于** Story 生成前刷新（REQ-PLN-18）；`resume_with_fresh_index`（`planning_context_resolver.rs:343-347`）、Design（`src/web/handlers/lifecycle.rs:672-673`）、WorkItemPlan（`src/web/workspace_context/builder.rs:152-154`）继续走 LKG + 可审计告警，**不得因 degraded 停机**。
12. **全局漂移判据不变。** `member_evidence_drifted`（`aggregate_index/freshness.rs:180-191`）保持既有原义（成员集合长度 + 逐成员 revision + dirty 布尔）；Story 路径的「能确认没变 / 不能确认没变」是**该路径自有**的分支决策，写在**新模块**里（§11），**不得**全局改写 freshness 的漂移判据，**不得**在 freshness 里盘检。
13. **测试产物只落 `/tmp`**（`cadence/project-rules/test-content-tmp-only.md`）。夹具仓、`CARGO_TARGET_DIR`、日志、快照全部 `/tmp`；`cadence/reports/` 下的正式截图是交付证据，不算测试临时物。
14. **提交纪律。** 每片一次或多次提交，**显式列文件**；禁止 `git add -A` / `git add .` / `commit -a`；禁止在 `main` 上提交；禁止 `--no-verify`。可单独 revert 的粒度以 §1.1 的片为单位（约束见 §22.1）。
15. **不越界的只读边界**：不改 `openspec/`、不改 `cadence/designs/`、不重跑用户现场、不调用真实 provider（页面验收的 UA-12 除外，见 §19）。
16. **机械上限（每片）**：读文件 ≤6 次、`grep` ≤8 次；超出即说明该片该拆，回去按 §1.1 拆法处理，不要硬做。
17. **盘检可见范围 = git 可见范围（G1/G0）。** 判定「该成员有没有源码」只看 `git ls-files --cached --others --exclude-standard` 的可见集合，再按 Aria 源码后缀集过滤并扣除 Aria 自身排除。**被 `.gitignore` 忽略的文件不算源码**：不判「漏收」失败，该成员按「无源码成员」跳过。**不得**再实现「不模拟 `.gitignore`、被 ignore 的源码仍是真漏收」——该口径会让任何含被忽略源码文件的仓永远建不出索引（同步多少次都没用）。
18. **Story 分支 2 的条件已收窄回（G2）**：**不再**附加「当前世代不含跳过成员」；分支 2 只要求「成员/主工作目录/Git 提交未变 + 上次与本次都无未提交修改（以 `git status --porcelain` 为准，G4）」。

### 0.2 非目标（照抄 proposal「明确不做」与「非目标」，实施者不得自行扩大）

- **不手工标注「配置仓」**：不新增仓类型、标签或人工开关；跳过只由盘检事实决定。
- **不为一行说明新建服务或新增只读接口**：三个入口共用既有 `LogicalCodebaseLayoutTree.tsx`，只改共用文案。

- **不改成员快照 `included` 的既有语义**：被跳过的成员**也在**快照里，`included` 保持原义。
- **不把「配置仓」变成需要额外授权的角色**：不加文件类型拦截、不改 ACL/配额/审计口径。
- **不新增后台定时扫描/轮询**：Story 前刷新只在生成/重新生成 Story 时触发；**「跳过成员后来出现源码」不做自动发现**，只在**下次验收/重建**时重新判断（REQ-IND-06）。
- **不改仓库登记、目录布局与授权准入**；不让全员无源码的 LC 通过。
- **不增设配置搜索、文件类型写入拦截或单仓规划回退**。
- **不为入口说明新增服务端点**；不为 Story 前更新新增后台定时任务。
- **不重做 `feat/aggregate-index-failure-face` 已完成的三段中文与失败面/证据面互斥工作**。
- **不改 `openspec/specs/`、不改本 change 的 delta 正文、不改 `cadence/designs/`**。

   ```bash
   # 用法：probe_one <version-tag> <ext> <sample-file>
   # <sample-file> 必须是该语言的最小有效样本（见 §2.3 样本表），不得用同一份 JS 样本改后缀

     local tag="$1" ext="$2" sample="$3"

       cd "$root" && codegraph files --json >"$root/files.json" 2>"$root/files.err"; echo "files_exit=$?" >>"$root/files.out" )
     # JSON 校验（必须真的解析，退出码非 0 也算失败）
     jq -e 'type == "array"' "$root/files.json" >/dev/null 2>&1
     echo "json_ok=$?"
     jq --arg p "src/" '[.[] | select(.path | startswith($p))] | length' "$root/files.json"
   ```

**可见范围口径（G1 / G0 / S3 的关键一条）**

- **源码 = git 可见范围 ∩ `ARIA_SOURCE_EXTENSIONS` ∩ 非 Aria 自身排除。**

**排除口径（S3 的关键一条）**

`exclude.rs:16-27` 的 11 条内建规则里，**7 条是目录规则**（以 `/` 结尾：`**.worktrees/` `**.aria/` `**.git/` `**/build/` `**/target/` `**/node_modules/` `**/dist/`），**4 条是非目录固定名模式**（`**/.env`、`**/.env.*`、`**/*credential*`、`**/*secret*`）。

- **目录规则** ⇒ 剪枝目录名集合 `{".worktrees",".aria",".git","build","target","node_modules","dist"}`（从 `BUILTIN_EXCLUDES` 派生，**不得**在 `source_scan.rs` 里再抄一份字面量数组）。
- **4 条非目录模式 ⇒ 按「目录名匹配」参与剪枝**（契约原文：`credentials/`、`secret-notes/` 这类目录不进入扫描）。实现口径：**目录名**若命中这 4 条模式的 glob 语义，则该目录被剪枝。
- **同时**：**文件**命中这 4 条模式（例如 `credentials.rs`、`secret_manager.ts`）时**不算源码候选** —— 因为 CodeGraph 会把这类文件排除出索引，若把它算作「盘上有源码」就会误报「漏收」。**这一点必须落在红测试里**（§3.3 第 13 条）。
  > **口径已与契约对齐（P14/D-14）**：change 的 `design.md` D2「排除口径」已改成「4 条非目录固定名模式**目录级与文件级都要扣除**」，并明确旧稿「MUST NOT 被改写成文件级规则」的措辞**作废**。本计划按契约现行措辞执行（目录级剪枝 + 文件级扣除），**不再是待确认项**。
- 模式匹配语义：`**/X` 匹配任意路径下的名为 `X` 的**目录名**；`**/.env.*` 匹配以 `.env.` 开头的目录名；`**/*credential*` / `**/*secret*` 匹配**包含**该子串的目录名。实现时用一张从 `BUILTIN_EXCLUDES` 派生的 `Vec<&str>`，**不得**硬编码第二份。

**其它实现要点（不得偏离）**

- **后缀匹配**：取最后一个扩展名，`to_ascii_lowercase` 后与 `ARIA_SOURCE_EXTENSIONS` 比对；`archive.tar.gz` 只看 `gz`。
- **两段扫描**：第一段 `member_root` 的**可见范围**（git 可见文件 ∩ 清单 ∩ 非排除）；仅当第一段「完成且无源码」时，第二段以 `member_root.join(".worktrees")` 为根做**目录遍历**（`.worktrees` 通常被 git 忽略 ⇒ 不在可见范围里，但它是**独立的第二段诊断**，用于识别「源码只在开发工作树」）。
- **`.worktrees` 入口本身**：是符号链接 ⇒ 该段判为「无候选」（不跟随）；不存在 ⇒ 该段判为「无候选」。**两者都不是 `Unknown`**（第二段是诊断段，不是主段）。
- **符号链接与非普通文件**：每个条目用 `std::fs::symlink_metadata`；`file_type().is_symlink()` 一律跳过（目录与文件都跳过）；只有 `is_dir()` 递归、`is_file()` 判后缀；其它类型跳过。
- **有界性**：每个目录条目（目录或文件）扣 1；**每成员上限 20,000**、**整批上限 100,000**（两阶段共享同一 `SourceScanBudget`）；**根深度 0、上限深度 32**（深度上限约束**物理扫描段**，即 `.worktrees/` 第二段诊断）；**可见清单的枚举与后缀过滤同样计入预算**；`remaining_entries == 0`、`Instant::now() > deadline`、`cancelled` 三者任一 ⇒ 停止并（在无正证据时）返回 `Unknown`。
- **子进程**：**只**允许可见范围探测跑 `git ls-files`；**不**调 CodeGraph、**不**读文件内容、**不**调其它命令。

### 5.2 实施步骤（落到符号锚点）

0. **具名测试模块（M9 的关键一条）**：`include!` **不创建模块**，v1.0 的 `--lib source_scope` 过滤器**跑不到**任何新用例（模块路径里没有 `source_scope` 串）。因此在 `operation.rs` 末尾（既有 `#[cfg(test)] include!("operation_tests.inc.rs");` 附近）**新增**：

   ````rust
   #[cfg(test)]
   mod source_scope_tests {
       include!("source_scope_tests.inc.rs");
   }
   ````

   `source_scope_tests.inc.rs` 里**不写** `mod tests {` 包裹（它就是模块体）。此后测试路径为
   `product::logical_codebase::aggregate_index::operation::source_scope_tests::<fn>`，
   过滤器 `cargo test --locked --lib source_scope_tests` **真实命中**。

1. **`AggregateIndexAcceptance`（`operation.rs:38-46`）** 新增 `pub skipped_members: Vec<String>`（本世代经盘检确认无源码、跳过代码检索的成员目录名，按 manifest 成员顺序）。

2. **`verify` 改判定顺序**（签名见 §5.1：**新增 `visibility` 与 `budget` 两参**）：

   - **注入点为何在 `apply_index`**：`verify` 是**关联函数**（`AggregateIndexAcceptance::verify`），拿不到 `self.source_visibility`；因此 `apply_index` 在 `operation.rs:534-539` 的调用点**显式补两参**：`self.source_visibility.as_ref()` 与 `&mut SourceScanBudget::new_batch()`。**测试要注入耗尽预算时不要走 `verify`**，直接调 `cross_verify_uncovered`（见 §5.3 第 4 条）。

   - **空索引归一（v1.0 的错误在这里）**：现行代码在 CLI 回退收到 `codegraph_files_empty_index` 时**直接早退** `return Err(member_coverage_failed(member_names))`（`operation.rs:100-103`）。**它不可能同时「另一成员被覆盖」**——早退发生在任何交叉验收之前。改法：
     - 把空索引**归一为「全员未覆盖」**：`member_covered` 设为「每成员 false」的 `BTreeMap`，**继续**走交叉验收；`tracing::warn!(code = "codegraph_files_empty_index", ...)` 留痕。
     - **只归一「已识别的空索引」**（`codegraph_files_empty_index`）；截断（`codegraph_files_output_truncated`）与非法 JSON（`codegraph_files_invalid_json`）**仍各自早退**（契约要求三者不混淆）。
   - **交叉验收入口**：`require_member_coverage(&member_covered, member_names)?` 替换为
     `let skipped_members = cross_verify_uncovered(root, &member_covered, member_names, visibility, budget)?;`
     （`require_member_coverage` **失去调用方 ⇒ 删除**，见 §5.5 第 3 条；历史兼容只保留**读侧文案**，即 `failure_copy` 侧的旧变体成品）。
   - `Self { member_covered, excluded_queries, warning }` 补 `skipped_members`。
   - 排除性查询循环位置不变——**通过交叉验收后仍必须做负查询**（不因跳过放松）。

3. **新增自由函数**（放在 `require_member_coverage` 原位置之后）：

   ````rust
   /// 交叉验收：对未覆盖成员做有界盘检并按四值汇总。
   /// `budget` 与 `visibility` 都由调用方传入（**明确的注入点**）——
   /// v1.0 在函数内部新建预算，导致「无法确认」没有确定性的注入入口，
   /// 测试只能靠真实 sleep/竞态。
   fn cross_verify_uncovered(
       root: &Path,
       member_covered: &BTreeMap<String, bool>,
       member_names: &[String],
       visibility: &dyn super::source_scan::MemberSourceVisibility,
       budget: &mut super::source_scan::SourceScanBudget,
   ) -> Result<Vec<String>, AggregateIndexError>
   ````

   - `AggregateIndexOperation` 增一个**可选**的可见范围提供者字段 + 一个 builder（与既有 `with_coverage_probe`（`operation.rs:226-229`）同风格）：`with_source_visibility(Arc<dyn MemberSourceVisibility>)`；默认 = 生产实现 `GitVisibleFiles`。
   - 扫描根用 `root.join(member_name)`（与 `checkout_root_name` 同源）；实施时确认它与 `checkout.canonical_path` 一致，不一致时以 `canonical_path` 为准。

   - 调用方在 `verify` 内**建一次** batch 预算（`SourceScanBudget::new_batch()`）并传进来。
   - 按 `member_names` 顺序，对 `member_covered.get(name) == Some(&false)` 的成员调
     `super::source_scan::scan_member_source(&root.join(name), visibility, budget)`，按四值分四桶（都保持 manifest 顺序）。
   - **覆盖键缺失的处理（S1 的关键一条）**：`member_covered.get(name) == None` 的成员**不进任何盘检桶**，也**不得**计入「全员确认无源码」——它连覆盖状态都不知道。它归入独立的 `coverage_unknown` 桶，**不**被当作 `NoSource`。
   - 汇总优先级（逐条照搬 design D3 + REQ-IND-01）：
     1. `disk_source` 非空 ⇒ `Err(member_coverage_failed_on_disk(&disk_source))`
     2. 否则 `worktree_only` 非空 ⇒ `Err(member_source_excluded(&worktree_only))`
     3. 否则 `scan_unknown`（`Unknown`）非空 ⇒ `Err(source_scan_incomplete(&scan_unknown))`
     4. 否则 `coverage_unknown`（缺覆盖键）非空 ⇒ `Err(member_coverage_state_unknown(&coverage_unknown))`
     5. 否则（全部 `NoSource`）⇒ 若 `member_covered.values().any(|v| *v)` 为真，`Ok(no_source_members)`；否则 `Err(all_members_source_less(member_names))`
   - 一条失败文案里**不得混类**：每桶只点名同类成员。

4. **五个失败构造函数**（message 必须含 `included members [`，供 `failure_copy.rs` 的 `subject_from_message` 抽名字；**中文不写在这里**）：

   - `fn member_coverage_failed_on_disk(uncovered: &[String]) -> AggregateIndexError`：code **复用** `aggregate_index_member_coverage_failed`，message `source found on disk; no indexed files under included members [{names}]; check member paths and ignore rules, then rebuild`
   - `fn member_source_excluded(members: &[String]) -> AggregateIndexError`：code `aggregate_index_member_source_excluded`，message `source exists only under .worktrees/ for included members [{names}]; move it into the member main checkout`
   - `fn source_scan_incomplete(members: &[String]) -> AggregateIndexError`：code `aggregate_index_source_scan_incomplete`，message `source scan incomplete (permission/io/depth/entry/time limit) for included members [{names}]; cannot confirm absence of source`
   - `fn member_coverage_state_unknown(members: &[String]) -> AggregateIndexError`：code **复用 `aggregate_index_source_scan_incomplete`**（**不得**复用 `aggregate_index_member_coverage_failed`；R1——缺覆盖键是「无法确认」，不是「覆盖不足」），message `coverage state unknown for included members [{names}]; no indexed files and no disk scan evidence`（机器事实原样保留，供 `subject_from_message` 抽名字）
   - `fn all_members_source_less(members: &[String]) -> AggregateIndexError`：code `aggregate_index_all_members_source_less`，message `no source found after bounded disk scan under included members [{names}]; add a member that contains source`
   - **`member_coverage_failed`（旧构造函数，`:908-917`）**：**失去调用方 ⇒ 删除**（见 §5.5 第 3 条）；但它生产的 message 前缀 `no indexable code file under included members [` **必须继续被读侧识别**（`failure_copy` 侧的旧记录变体，§7.2）。

5. **版本漂移只记警告（S2）**：验收时读到已安装 codegraph 版本（`CodeGraphCli::verify_version()`，`codegraph_cli.rs:131`）；若 **≠ 清单校准基线 1.6.3** ⇒ 在 `AggregateIndexAcceptance.warning`（`:45`）里追加一条**可审计软告警**（复用既有 `soft_warning` 通道，`operation.rs:154-156`），**不改判定、不阻断索引构建**。文案里写明「清单按 1.6.3 校准；当前版本 X 可能改变收录后缀，必要时按 `cadence/notes/2026-11-18_校准_CodeGraph源码后缀清单_1.6.3_v1.0.md` 的复校准步骤更新清单」。
   - 校准基线版本常量放在 `source_scan.rs`（片1）里（如 `pub const ARIA_SOURCE_SUFFIX_CALIBRATED_CODEGRAPH_VERSION: &str = "1.6.3";`），片3 直接引用，**不另写一份**。
   - **不得**实现自动重校准（S2）。

6. **`apply_index` 成功世代打标记**：

     （`RepositoryCheckoutRecord` 的 id 字段名已证实为 `checkout_id`，见 §26.2 U4）。

**`story_can_reuse` 的判定（REQ-PLN-18 分支 2 的全部条件，缺一不可；R3：**复用门 = Active-only**）**

1. **前置：published 世代 `status == Active`**（R3）。`Degraded` / `Stale` 一律**不**可复用（落分支 3：恢复/同步 + 重新验收；仍非 Active ⇒ 停在 AI 启动前）。
2. 成员集合未变：`published.member_snapshots.len() == current.len()`；
3. 主工作目录身份未变：逐成员 `published.checkout_id == current.checkout_id`；
4. Git 提交未变：逐成员 `published.revision == current.revision`；
5. **上次与本次都没有未提交修改**：逐成员 `!published.dirty && !current.dirty`（以 `git status --porcelain` 为准；**被忽略的文件不参与**，见 G4）。

> **「同指纹新增源码」的可观测触发点（G1/G3 之后）**：可见范围内的新增文件 ⇒ 工作区变脏 ⇒ 落分支 3 同步并重新验收 ⇒ 被跳过成员的覆盖结论按**本次盘检**重算。**被忽略的新增文件不在可见范围内 ⇒ 不构成变更 ⇒ 不触发**（这与 REQ-IND-06「下次验收/重建时重新判断、不做自动发现」一致）。

**三分支编排**

````rust
pub fn refresh_for_story(
    project_id: &str,
    backend: &dyn StoryIndexFreshness,
) -> Result<StoryIndexRefreshOutcome, StoryIndexRefreshError>
````

- **入口 lc 解析（P9，在 `build_with_fresh_index_for_story` 内、调 `refresh_for_story` 之前）**：
  `let lc_id = self.resolve_issue_authority_lc_id(project_id, issue_id)?;`
  `let backend = match lc_id.as_deref() { Some(lc) => self.story_freshness.as_ref().map(|f| f.for_lc(lc)), None => self.story_freshness.clone() };`
  —— `AggregateIndexStore::new` 是 legacy project 级作用域，**只有 `for_lc(lc_id)` 才按 LC 隔离**；不解析 lc 会让 Story 读到别的 LC 的世代。
- **分支 1（没有索引）**：`readable_generation` ⇒ `Ok(None)` ⇒ `backend.build(project_id)`：
  - 成功 ⇒ `Rebuilt`；
  - 失败 ⇒ `VerificationFailed { code, message }`（**从失败封套解析内层码**；解析不出 ⇒ `aggregate_index_unavailable`）。
- **记录读坏/歧义**：`readable_generation` ⇒ `Err(e)` ⇒ `UnreadableGeneration { code, message }`
  （`aggregate_index_active_missing` 映射为 `Ok(None)`；`aggregate_index_active_ambiguous` 与其它错误映射为 `Err`）。
- **分支 2（能确认没变，R3 = Active-only）**：有可读世代 **且 `published.status == Active`** 且 `current_snapshots` 返回 `Ok(current)` 且 `story_can_reuse(published, &current)` ⇒ `Reused { aggregate_index_id }`。
  - `published.status` 为 `Degraded`/`Stale` ⇒ **不**复用（落分支 3）；`current_snapshots` 返回 `Err` ⇒ **不能确认没变**，同样落分支 3（**不得** `Reused`、**不得**直接停机）。
- **分支 3（有变化 / 不能确认没变 / 上次失败留下的旧版）**：⇒ `backend.sync_and_verify(project_id, prior)`：
  - 成功且返回记录 `status == Active` ⇒ `Synced { aggregate_index_id }`；
  - 失败或返回记录**仍非 Active** ⇒ `VerificationFailed { code, message }`（**停机**，AI 不启动）。

**「同步成功以本次实际验收发布的记录为准」（M5）**

- 判定依据是 `sync_and_verify` **返回的那份记录**（它就是本次验收发布的记录），**不是**再跑一次 `assess()` 的结果。理由：`assess()` 会用当前工作区重新判定 dirty，可能仍报 stale/degraded，从而**否定一次已经成功的验收**。
- 因此 `refresh_for_story` **不在** `sync_and_verify` 之后再调用 `assess()`。

**「锁内复核」与「避免二次取同一锁」的边界（M5）**

- `operation.sync_and_verify` 内部走 `with_single_writer`（`operation.rs:392-395`），锁在**它内部**取与放。
- `flock`（`src/product/coding_attempt_store/locking.rs`）**阻塞等待**并**串行化写入**，但它**不替调用方复核**。
- 因此：
  - **锁内**：写操作 + 本次验收 + 发布记录，全部在 `sync_and_verify` 内完成。
  - **锁外（调用方）**：拿到返回值后**复核**——判 `status == Active`、读 `aggregate_index_id`。复核是**读 store**，**不再取同一把写锁**（避免自死锁）。
  - 若另一进程正在写 ⇒ 本次 `sync_and_verify` 阻塞等待其结束 ⇒ 返回的是**那一次或本次**的已发布记录；调用方按返回记录判定，**不**再自行加锁。

## 25. 实施者须知（每片开工前读一遍）

1. **TDD 先红后绿**：先写测试并确认它以「符号不存在/断言失败」的方式**红**，再写实现。红 commit 允许编译失败；绿 commit 必须通过该片全部定向命令。
2. **中文注释**：新增模块/函数的文档注释用中文，写「为什么」而不是复述代码；与既有文件风格一致（`operation.rs`、`failure_copy.rs` 都是中文注释）。
3. **用户可见中文只出自 `failure_copy_table.inc.rs` 码表**：Rust 投影层、TSX、通知、审计文本都不得新写中文文案；前端只渲染服务端下发的字符串。
4. **告警是结构化对象**：卡片 / 成员行 / 证据未检索三处都是 `{code, message_zh}`，**不得**退化成裸字符串。
5. **失败封套只经一个解析入口**：冷启动与 HTTP 都调 `failure_copy::parse_failure_envelope`；**禁止**裸前缀 contains 猜码。
6. **测试产物只落 `/tmp`**：夹具仓、`CARGO_TARGET_DIR`、日志、快照全部 `/tmp`；`cadence/reports/` 的正式截图是交付证据。
7. **每片 ≤3 个文件（含测试文件）**：超了就是该拆片；**不得**把两个片的改动塞进一次提交。
8. **机械上限**：每片读文件 ≤6 次、`grep` ≤8 次；先看结构化大纲再定向精读（`.claude/rules/code-reading.md`）。
9. **提交**：显式 `git add <文件…>`；禁止 `git add -A` / `git add .` / `git commit -a`；禁止 `--no-verify`；**不得在 `main` 上提交**。当前分支 `feat/aggregate-index-failure-face`。
10. **命令注意**：
    - Rust 定向单测必须带 `--lib`：`cargo test --locked --lib <过滤名>`；集成用 `cargo test --locked --test <name>`；**禁止** `-j 1`。
    - **`include!` 不创建测试模块**：新用例文件要么被声明成**具名模块**（`mod xxx_tests { include!(…) }`），要么其测试名自带可区分前缀；过滤器用 `cargo test --locked --lib <过滤名> -- --list` **先确认命中**再写验收结论。
    - 前端定向跑必须写 `cd web && pnpm test <path>`；**不要写 `pnpm test -- <path>`**（`--` 被 pnpm 吞掉，变成跑全量）。类型检查用 `cd web && pnpm typecheck`。
11. **不改范围**：不改 `openspec/`、`cadence/designs/`、`openspec/specs/`；发现契约需要变，停止并上报（`openspec-superpowers-workflow.md` §三）。
12. **收尾**：删除 `/tmp` 下的自建夹具（或明确声明保留项）；在片报告里列出「实际跑过的命令 + 输出摘要」，不要把计划里的命令当已执行。
