# Provider 流日志落盘位置修复实施计划

## 元信息

- **OpenSpec Change**：`fix-provider-stream-log-location`
- **Capability**：`provider-stream-log-placement`
- **计划类型**：基线修复
- **版本**：v1.0
- **日期**：2026-07-28

## 背景

`provider_stream_path`（`src/cross_cutting/cli_adapter.rs:414`）用 provider 子进程的工作目录（来源 `AdapterInput.worktree_path`）拼接 `.aria/runtime/provider-streams`，导致 Aria 在被开发的目标代码库中创建目录并写入流日志。

真实现象：`/home/michaelche/workspace/github/naruto/.worktrees/aria-issues/issue_0001/.aria/runtime/provider-streams`。

## 勘察结论

### 实际写入点唯一

全仓只有 `src/cross_cutting/cli_adapter.rs:436` 一处写 `provider-streams`。streaming provider 路径不写流日志文件。

### `cli_adapter` 走 `ProviderAdapter`，不是 coding 流式路径

`cli_adapter` 实现 `ProviderAdapter`（`cli_adapter.rs:62`）。coding 的 `run_legacy_stream_to_completion` 走 `StreamingProviderAdapter`，是另一条 trait。生产中实际调用 `ProviderAdapter::run` 且传入工作目录的有 6 处：

| 调用点 | 工作目录来源 | attempt 上下文 |
|---|---|---|
| `src/product/coding_workspace_engine/handoffs.rs:447` | attempt worktree | **有** |
| `src/runtime_units/coding.rs:410` | 运行单元 worktree | 无 |
| `src/runtime_units/final_review.rs:277` | 运行单元 worktree | 无 |
| `src/runtime_units/clarification/provider.rs:40` | 运行单元 worktree | 无 |
| `src/product/provider_workspace_runner.rs:53` | 仓库根 `repository.path` | 无 |
| `src/product/work_item_split_engine/engine.rs:134` | 仓库根 `repository.path` | 无 |

只有 `handoffs.rs` 能落 attempt 目录；其余按缺省不写流日志。

### 现有测试锁定了错误行为

`tests/it_core/cli_adapter_baseline.rs:282` 的 `cli_adapter_streams_provider_stdout_and_stderr_to_runtime_logs` 在第 319 行断言 `worktree.path().join(".aria/runtime/provider-streams")` 存在，并在 332-336 行断言这些日志不被计入 `files_modified`。

说明当前落点是被有意锁定的，本变更必须改写该测试，并保留「流日志不得被计入目标文件变更」这条断言。

### `AdapterInput` 构造点

非测试约 12 处、含测试共 36 处。该结构派生 `Serialize`/`Deserialize` 但无 `Default`，且无实际序列化消费点。

## 实施步骤

### 阶段一：契约字段（工作包 2.1）

**文件**：`src/protocol/contracts.rs`

在 `AdapterInput`（第 195-204 行）新增字段：

```rust
/// 流日志落盘目录。由调用方提供 Aria 侧目录；为 None 时不写流日志。
/// MUST NOT 由 adapter 从 worktree_path 推导（见 change fix-provider-stream-log-location）。
#[serde(default)]
pub provider_stream_log_dir: Option<String>,
```

放在 `worktree_path` 之后，使两个路径概念相邻便于阅读。`#[serde(default)]` 保证反序列化兼容。

补齐全部构造点：非测试 12 处显式写 `provider_stream_log_dir: None`（`handoffs.rs` 在阶段四改为实际值）；测试构造点同样补 `None`。

编译驱动：`cargo check --locked` 会列出所有缺字段的位置。

### 阶段二：失败测试（工作包 1.1、1.2、1.3）

**文件**：`tests/it_core/cli_adapter_baseline.rs`

改写 `cli_adapter_streams_provider_stdout_and_stderr_to_runtime_logs`（第 282 行）为提供目录的版本：

- 新建独立于 worktree 的 tempdir 作为流日志目录，填入 `provider_stream_log_dir`
- 断言流日志写入该目录且含 stdout/stderr 内容
- 断言 `worktree.path().join(".aria")` **不存在**（工作包 1.1 的核心断言）
- 保留原有 `files_modified` 为空的断言（第 332-336 行语义）

新增 `cli_adapter_does_not_write_stream_logs_without_log_dir`（工作包 1.2）：

- `provider_stream_log_dir` 为 `None`，worktree 正常传入
- 断言 `worktree.path().join(".aria")` 不存在
- 断言 provider 执行本身成功、结构化输出解析正常

新增 `cli_adapter_stream_log_naming_and_append_mode`（工作包 1.3）：

- 断言目录内同时存在 stdout 与 stderr 两个文件，文件名含 provider 名与流名
- 同一目录下连续两次执行，断言内容为追加而非覆盖

现有辅助函数 `adapter_input`（第 415 行）需要加参数或新增变体以支持传入流日志目录。

预期：改写后的测试与两个新增测试全部失败。

### 阶段三：adapter 实现（工作包 2.2）

**文件**：`src/cross_cutting/cli_adapter.rs`

改造 `provider_stream_path`（第 414-439 行）：

- 第一个参数由 `current_dir: Option<&Path>` 改为 `log_dir: Option<&Path>`
- 移除 `.join(".aria/runtime/provider-streams")`，直接在 `log_dir` 下生成文件
- provider 名净化逻辑（第 421-433 行）与文件名格式 `{provider}-{child_id}-{stream}.log` 保持不变

改造调用点（第 240、242 行）：传入 `input.provider_stream_log_dir` 解析出的路径，而非 `current_dir`。

`run_command_capture_with_stream`（第 199 行）需要新增流日志目录参数，与 `current_dir` 并列且语义独立。`open_provider_stream`（第 441 行）的 `create_dir_all` 行为保留。

关键：`log_dir` 为 `None` 时返回 `None` 不写文件，MUST NOT 回退到 `current_dir`。

验证：阶段二的三个测试转绿。

### 阶段四：attempt 目录解析与填入（工作包 1.4、2.3、2.4）

**文件**：`src/product/coding_attempt_store/paths.rs`

新增与 `provider_raw_output_root`（第 273-281 行）同构的方法：

```rust
pub(crate) fn provider_stream_log_root(
    &self,
    project_id: &str,
    issue_id: &str,
    attempt_id: &str,
) -> PathBuf {
    self.attempt_dir(project_id, issue_id, attempt_id)
        .join("provider-streams")
}
```

先写工作包 1.4 的失败测试：断言该路径位于 attempt 根下，且与 `provider_raw_output_root` 同父目录。

**文件**：`src/product/coding_workspace_engine/handoffs.rs`

在 `generate_work_item_handoff_from_provider`（第 401 行）构造 `AdapterInput`（第 443-452 行）时，填入 `provider_stream_log_root(&attempt.project_id, &attempt.issue_id, &attempt.id)`。

工作包 1.5：为无 attempt 上下文的路径补测试，断言不向其工作目录写流日志。可选择 `provider_workspace_runner` 或 `work_item_split_engine` 之一作为代表，理由记入测试注释。

## 风险

- **阶段一改动面广**：36 个构造点补字段，机械但量大。编译器可完整列出，漏改必然编译失败，风险可控。
- **改写既有测试**：`cli_adapter_baseline.rs:282` 锁定的是当前错误行为，改写它是本变更的应有部分。必须保留其 `files_modified` 断言，避免退化出「流日志被误判为目标文件变更」。
- **无 attempt 上下文路径不再有流日志**：这些路径此前把日志写进用户仓库，现在不写。若后续需要保留，应新建 change 为其定义 Aria 侧落点，不在本变更范围。
