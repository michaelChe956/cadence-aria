## 2. 执行纪律、环境和取证

### 2.1 禁区与串行约束

- 原树 `.aria`、真实 fixture 仓、现场进程只读；不恢复／清理验收现场，不另起 4317／5173 服务，不执行真实 provider。

- Rust 仅一个执行 agent 占编译波；Cargo 自身沿 `.cargo/config.toml` 的 jobs 配置，**不加 `-j`／`-j 1`**。测试 runner 的 `--test-threads=1` 是测试串行，不是编译单核。
- 原树全量和新增副本测试串行；测试资产可按文件面准备，但不要多个 worker 同时 cargo／pnpm 全量。看到 `Blocking waiting for file lock`：保留输出，通知 Main 等待，不杀其它构建，不另抢同 target。
- 日志、夹具、缓存、构建、失败快照全部 `/tmp/test-*`。用户允许现有 target 留存；本计划仍默认 `/tmp` target，避免污染和锁冲突。
- 空间不足先清理**本轮自己创建且已确认不再运行的 target 缓存**，不删测试资产／失败证据，不动他人缓存。
- 不重跑已知失败来“确认用户观察”。新增 bug2 测试是覆盖缺失断言，不是重复人工现场操作。测试失败后不循环直到绿。

### 6.1 门与快照——不得把“snapshot缺失”泛化成所有门非法
