# 实施计划:聚合初始化完成态显示修复 v1.0

- 日期:2026-10-11
- worktree:`.worktrees/feat-b-0808-add-monorepo`(HEAD 18db435a)
- 类型:Bug 修复(owner 授权;不立 OpenSpec change)
- 现象:聚合初始化已完成(磁盘 status=completed,冷启动五步全绿 + PlanningReady + 索引 active),但 LC 管理面板「聚合初始化」区块仍显示「尚未初始化」。

## 1. 根因证据链

### 后端:没有「最新 operation」查询端点,`active` 被 operation_id 通配吞掉

- `src/web/app.rs:127-137`:per-LC 聚合初始化只注册 3 条路由:
  `POST /api/projects/{pid}/logical-codebases/{lcid}/initializations`(创建)、
  `GET …/initializations/{operation_id}`(按 id 查)、
  `POST …/initializations/{operation_id}/cancel`。
  **没有 `active`/`latest` 子路由**。
- 实测 `GET …/initializations/active` 被 `{operation_id}` 通配路由捕获,`"active"` 被当作 operation_id:
  `get_lc_aggregate_initialization`(handlers.inc.rs:158-165)→ `coordinator.get(project,"active")`(coordinator_lifecycle.inc.rs:120-133)→ store 查 `active.json` 不存在(aggregate_initialization_store_operations.inc.rs:85-98)→ `AggregateInitializationError::NotFound` → 404 `aggregate_initialization_operation_not_found`(handlers.inc.rs:318-327)。
- store 已具备所需数据面:`AggregateInitializationOperationStore::list` 按 `updated_at` 降序返回全部 operation(aggregate_initialization_store_operations.inc.rs:55-83),只是没有暴露「最新」查询。

### 前端:面板状态只在「用户本会话点过启动」后非空,加载/刷新/切换 LC 后永远为 null

- `web/src/api/aggregate-initialization.ts`:只有 start / get(by operation_id) / cancel,**无 active 拉取函数**。
- `web/src/components/lifecycle/useLogicalCodebaseScopeData.ts:65-66`:`aggregateInitialization` 初始 `null`;:104-111 LC/Project 切换时重置为 `null`;唯一非空来源是启动 POST 响应、created/running 态按 id 轮询(:251-294)、取消响应。**不存在「作用域加载时恢复最新 operation」的路径**。
- `web/src/components/lifecycle/AggregateInitializationCard.tsx:90`:`operation ? STATUS_LABELS[status] : "尚未初始化"` → 完成态 LC 面板显示「尚未初始化」;且 :86-89 `canStart` 在 `operation === null` 时为 true → 误显「启动聚合初始化」按钮,诱导对已完成 LC 二次初始化。

### 规格核对

- `openspec/changes/lc-root-initialization/specs/repository-initialization-progress/spec.md` REQ-INIT-01:只要求「可轮询、可恢复的聚合初始化操作……暴露与单仓 operation 一致的状态查询」,**未定义面板加载时的状态恢复行为**(规格缺口,非行为另定义)。
- `openspec/changes/aggregate-policy-root-publication/design.md:87` 与 `proposal.md:32`:「现有『启动聚合初始化』UI 按钮仅在 operation 为 null、failed 或 cancelled 时可见,**Completed 态没有该按钮**」——设计预期 Completed 态在 UI 可见;当前缺陷使 Completed 永远不可见(伪装成 null),与该意图冲突。
- 结论:规格未另有定义 → 按任务取舍原则执行:**API 返回最新 operation(含 completed/failed)供前端区分展示**;不改冷启动投影与 PlanningReady 语义(本次仅新增只读投影端点 + 前端加载拉取,零触碰 bootstrap_projector)。

## 2. 修法

### 后端(Rust)

1. `coordinator_lifecycle.inc.rs`:`AggregateInitializationCoordinator` 新增 `latest(project_id) -> Result<Option<Operation>, Error>`,复用 store `list`(updated_at 降序)取首个;不写盘、零副作用。
2. `handlers.inc.rs`:新增 `get_lc_aggregate_initialization_active`(canonical)与 `get_aggregate_initialization_active`(legacy alias,`default_logical_codebase_id` 解析,与既有 alias 同构):
   - 有 operation(任意状态,含 completed/failed/cancelled)→ 200 + 现有 `aggregate_initialization_dto` 投影;
   - 无 operation → 复用 `AggregateInitializationError::not_found` → 404 `aggregate_initialization_operation_not_found`(与既有语义一致,前端可区分「未初始化」)。
3. `app.rs`:注册两条 GET 路由(axum/matchit 静态段 `active` 优先于 `{operation_id}` 参数段,并存无冲突)。

### 前端(TS/React)

1. `api/aggregate-initialization.ts`:新增 `getActiveAggregateInitialization(projectId, lcId): Promise<Snapshot | null>`;404 且 `code === "aggregate_initialization_operation_not_found"` → `null`(未初始化是正常态),其它错误照抛 `ApiRequestError`。
2. `useLogicalCodebaseScopeData.ts`:在既有作用域拉取 effect(成员/指针/索引,:115-152)中并行拉取 active 投影并 `setAggregateInitialization`;依赖沿用 `[selectedProjectId, activeLogicalCodebaseId, scopeRefreshTick]`,与切换重置 effect(:104-111)的既有顺序保持——重置后立即补拉,恢复真实状态。拉到 created/running 后既有轮询 effect(:251-294)自然接管。
3. 测试 mock:`IssueLifecycleWorkbench.test-utils-aggregate.ts` 的 `createAggregateInitializationRoutes` 增加 `/initializations/active` GET 路由:默认 404 + not_found code(与现状「未初始化」一致,保证既有测试零回归),新增 `LifecycleFetchOptions.aggregateInitializationActive` 注入快照。

### 明确不改

- 冷启动 bootstrap 投影、PlanningReady、聚合索引语义(数据源相同,本次不动);
- `AggregateInitializationCard` 组件(已完成态渲染/样式/按钮逻辑已正确,缺陷仅在拿不到数据);
- e2e/、服务 4317、git 提交。

## 5. 风险与边界

- 竞态:active 拉取与用户点启动并发时,后启动的 POST 响应后到会覆盖 active 结果(React state 最后写赢);与既有轮询覆盖语义一致,不额外加锁。
- 404 语义复用:未初始化(无 operation)与「operation 存在但 id 不存在」共用同一 code;前端把 404 统一降级为 null(未初始化),不影响按 id 轮询路径(它只在已有快照时发生)。
- 多 LC:store `for_lc` 作用域隔离已由既有布局保证,active 投影天然按 LC 隔离。
