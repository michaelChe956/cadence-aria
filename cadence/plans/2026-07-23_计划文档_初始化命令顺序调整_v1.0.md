# 初始化命令顺序调整（rule_config 优先）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将代码库初始化的固定步骤顺序由 `cadence_skills → pre_check → rule_config → mcp_configuration → project_rules_examples` 调整为 `cadence_skills → rule_config → pre_check → mcp_configuration → project_rules_examples`，仅交换 `pre_check` 与 `rule_config`，其余不变。

**Architecture:** 后端 `RepositoryInitializationStepKind::ALL` 是唯一顺序来源，初始化器按 `ALL` 迭代执行四个 Claude 命令，前端按服务端 `operation.steps` 顺序渲染。因此实现改动只有两处：交换 `ALL`（及 `from_command_index`）中的 `PreCheck`/`RuleConfig`，并把 `registration.rs` 中 Claude 阶段前置标记从 `PreCheck` 改为 `RuleConfig`；其余工作全是测试 fixture/断言与文档的同步。

**Tech Stack:** Rust 2024、React 19、TypeScript、Vitest。

**Change:** `add-repository-initialization-progress`（工作包 5.1、5.2；需求：repository-initialization-progress、non-interrupt-repository-bootstrap）。

## Global Constraints

- 固定且唯一的用户可见步骤顺序为：`cadence_skills`、`rule_config`、`pre_check`、`mcp_configuration`、`project_rules_examples`。
- 四个 Claude Code 提示词必须逐字使用：`/rule-config --no-interrupt`、`/pre-check --no-interrupt`、`/mcp-configuration --no-interrupt`、`/project-rules-examples --no-interrupt`。
- 仅交换顺序；不得改步骤状态机、API 契约结构、错误码或失败语义。
- 实现遵循 TDD：先改测试断言为新顺序并确认失败，再改实现。
- Rust 命令禁止带 `-j 1`；定向单测用 `cargo test --locked --lib <过滤名>`。
- 前端包管理器只用 `pnpm`。
- 所有代码、测试与用户可见文案使用中文。
