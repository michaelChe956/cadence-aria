# 知识库输入草稿 + 全域前置门 + 页面改版 实施计划 v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让知识库全域建立在「聚合初始化完成」的前提下；输入未准备时由 provider 起草 `/knowledge-base-user-input`、经用户逐份确认后才允许 `/knowledge-base-bootstrap`；知识库详情页改成带关联信息与返回入口的全屏工作区。

**Architecture:** 复用既有知识库 operation 机制新增 `UserInput` kind；前置门在 HTTP 层一处统一判定（口径 = 冷启动投影「规则/政策」步 completed）；确认记录落平台侧 .aria（不进 `user-input/`）；详情页走 CockpitShell 的路由级沉浸模式 + 自绘顶栏。

**Tech Stack:** Rust（tokio / axum / serde / sha2）、React 19 + TS + Vite + TanStack Router v1 + Tailwind、monaco-editor（既有）。

**Spec:** `openspec/changes/add-knowledge-base-input-draft-and-page-polish/specs/logical-codebase-knowledge-base/spec.md`（REQ-KB-13..16）
**Design:** `openspec/changes/add-knowledge-base-input-draft-and-page-polish/design.md`（D1..D7）
**方案：** `cadence/designs/2026-11-10_技术方案_知识库输入草稿与页面改版_v1.0.md`

## Global Constraints

- 中文注释 / 中文 commit message / 中文报告；代码标识符用英文。
- `src/**`、`tests/**`、`web/src/**` 单文件 ≤ 1200 行（`tests/it_core/large_file_guard.rs` 会跑）；逼近上限按仓内惯例拆 `*_tests.inc.rs` + `include!`。
- Rust：宿主机直接跑 cargo，禁 Docker，禁 `-j 1`；定向快反馈必须带 `--lib`（知识库模块的过滤名是 `knowledge_base::`）。
- 前端：只用 `pnpm -C web test` / `build` / `lint`；禁 Playwright（界面验证只用 harness 内置浏览器）。
- **禁止新增依赖**（含前端）；禁止改 `Cargo.toml` / `Cargo.lock` / `web/package.json`。
- 临时夹具只落 `/tmp`。
- 提交只显式列本任务文件，**严禁 `git add -A`**（工作区里有并发会话的未提交改动 `src/product/provider_installation/runner.rs` 与若干未跟踪 `openspec/changes/*`）。
- 同一 worktree 多 worker 并行编译 ⇒ cargo 排队等锁属正常，耐心等，不 kill 别人的 cargo 进程。
- **禁止改动**：`knowledge_base/files.rs` 的四道路径授权、`change_package.rs` 的 P1–P9 门禁语义、聚合初始化自身的任何语义（只读它的投影）。

## Review Focus

1. **前置门必须真的盖住所有端点** —— 漏一个就等于没门（尤其 file 写入）。
2. **确认失效语义**：编辑已确认文件后必须回到「待确认」，且初始化入口随之关闭。
3. **起草不得写出 `user-input/` 之外** —— 越界即 operation 失败（skill 契约）。
4. **旧 operation 记录必须仍能反序列化** —— 新 kind 不能让历史记录读不出来。
5. **沉浸模式不得影响既有路由** —— CockpitShell 改动只能影响知识库路由。

**Interfaces:**
- Produces:
  ```rust

  pub struct UserInputFileStatus { pub path: String, pub filled: bool, pub confirmed: bool, pub pending: bool }
  pub struct UserInputSummary { pub files: Vec<UserInputFileStatus>, pub confirmed_count: usize, pub total_count: usize }
  pub fn summarize_user_input(kb_root: &Path, template_root: &Path, confirmations: &UserInputConfirmations) -> UserInputSummary;

  pub struct UserInputConfirmations { /* path -> { digest, confirmed_at } */ }
  ```

  新端点（前缀 `/api/projects/{project_id}/logical-codebases/{lc_id}/knowledge-base`）：

  创建初始化 operation 时按状态分叉：未准备 ⇒ 起起草 operation；已准备未确认 ⇒ 4xx `knowledge_base_user_input_not_confirmed`（details 列未确认文件），**不产生 operation**；已确认 ⇒ 跑 bootstrap。
