## 2. 核心结论：重复报被切断（统计显著）

> 判据：第二个带 findings 的评审轮，其 `contract_field` 集合 ∩ 第一个评审轮的集合非空 ⇒ 重复报。

| | 有效 run | confirmed | 走到第二轮评审 | **出现重复报** |
|---|---|---|---|---|
| **改前** | **15** | 4（27%） | 9 | **8（89%）** |
| **改后** | **20** | 6（30%） | 11 | **0（0%）** |

**单尾 Fisher 检验 p = 0.00131** ⇒ 高度显著。

⇒ 这是全部 35 个 run、**跨 4 个不同时段窗口**（22:00 / 12:00–15:30 / 15:32– / 01:36–06:24）**都一致**的结果：改前凡走到第二轮评审，89% 会重复报上一轮的同一项；改后**一个都没有**。

⇒ 机制：D6 把前轮 findings 从「待办清单」改为「**带本轮机械复算状态的分区事实清单**」（`unresolved_findings` / `resolved_findings`）⇒ 评审**不再拿到「上一轮报过这个」的输入条件** ⇒ 重复报无输入可依。已关闭区条目也不再要求作者再次修改 ⇒ 「无可改对象」的死循环被切断。

## 4. 诚实限定

1. **比例型指标仍不显著**：计划产出 1/8 → 2/8（p=0.179）、需人工介入 4/8 → 3/8、编译通过 1/8 → 2/8 ⇒ n=8/臂 不足以判定；**唯一达到统计显著的是「重复报」**（8/9 → 0/11，p=0.0013）。
2. **「未产出计划」3/8 → 3/8 持平**：这批的 3 个 failed 全部是 `missing_section` 类（作者产出结构不合法 → parse 教学重驱一次 → 仍不合法），**与改动无关**（同时段基线臂同样出现）。
3. **「需人工介入」未改善（4/8 → 3/8）**，但**归因已变**：改前的介入由**重复报**导致；改后重复报归零，残留的介入来自① `suggestion` + `class_hint=repairable` 被判必关闭（属 `close-contract-findings-before-pass`，未实施）、② 写范围越界。
4. **三项改动的独立贡献未分离**（拆解实验进行中：4 臂 × 3 run，A 全关 / B 只 D6 / C 只 D5 / D 全开，同装置同时段）。
5. **单案例**（`公告删除`，三成员仓）、**单一 provider 状态窗口**。

## 5. 仍存在的坎（不属本次 change）

1. **多仓基线树只覆盖一个仓**：`plan_baseline_tree` 按 issue 的 `repo_id` 只解析一个物理仓，而**校验器用的就是同一棵树** ⇒ 多仓计划里其它成员仓的 AC 路径**必然**被判越界。D5 事前注入的是同一棵树 ⇒ **只能让作者看见事实、不能修复多仓判定**。需另立 change（REQ-WSC-02 域，验收语义需 owner 裁决）。
2. **必关闭判定过宽**：`suggestion` + `class_hint=repairable` 也进必关闭集合 ⇒ 仍会升级人工。属 `close-contract-findings-before-pass`（0/24 未实施）。

---

## 6. 一句话结论

**在这套改动下，抱怨③「重驱后评审重复报错 → 自动化耗尽 → 人工介入」被切断：跨 4 个时段窗口、35 个 run，改前 8/9 走到第二轮的 run 都出现重复报，改后 0/11（p=0.0013）；同时作者快 8%、评审快 9~26%、评审 findings 少 43%、must_fix 少 60%、产出字节多 6%、总墙钟少 10%，产物质量与 cross-WI 无退化。计划产出率与编译通过率方向正向（1/8→2/8）但样本不足、尚不显著；残留的人工介入已换成两个另立项的既有缺陷（多仓基线树覆盖、必关闭判定过宽）。**
