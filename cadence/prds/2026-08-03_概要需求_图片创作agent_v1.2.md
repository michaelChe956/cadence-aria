## 1. 背景与目标

Cadence Aria 当前是一个「AI 辅助软件开发平台」，所有 AI 能力通过 CLI 子进程（Claude Code / Codex）完成，后端没有任何对外 HTTP/LLM 客户端。

本需求新增一个**独立顶层**的「图片创作 Agent」：用户通过**多轮对话**与执行器迭代「图片 prompt」，prompt 满意后**由用户点按钮触发**图片生成，Aria 后端统一调用 `gpt-image-2`（colorflowai 网关）返回 base64 图片展示。典型用途是生成 PPT 配图、业务流程图。

### 1.1 非目标

- 不改造现有 Project/Issue/Coding 域。
- 不引入新的对话 LLM（prompt 迭代复用现有 CLI 执行器）。
- 不做多用户隔离、不做 key 加密落盘（与现有 `.aria` 状态文件同级明文）。
- 不支持自主工具调用式生图（生图始终由用户显式触发）。
- 不支持多图批量生成（每次生成恰好一张）。
- 不提供模板的持久化 CRUD（自定义引导词为一次性会话引导词）。

## 2. 设计决策汇总（已与用户确认 + 经 review 修订）

| # | 决策点 | 结论 |
|---|---|---|
| D1 | prompt 迭代由谁驱动 | 复用现有 CLI 执行器（Claude Code / Codex 等所有支持执行器），通过 `resume_provider_session_id` 续接多轮 |
| D2 | 两阶段衔接模型 | **模型①**：执行器只聊 prompt；Aria 后端统一调 image2；由**用户点按钮**触发生图 |
| D3 | 放置位置 | **独立顶层** `/image-create`，不依赖 Project/Issue/git，执行器跑临时 scratch 目录 |
| D4 | 参考图 | 单张可选参考图；后端按有无图自动选 `/images/edits` 或 `/images/generations`；参考图随生成请求**直接 multipart 传输、不持久化** |
| D5 | API Key 存储 | 存 Aria 后端 `.aria` 配置文件，前端设置页录入（PUT 对 key 采用保留语义），不暴露给 CLI 子进程 |
| D6 | 参数 | 枚举化下拉框；**每次生成恰好一张（不支持 n 多图）**；`input_fidelity` 仅参考图改图时发送 |
| D7 | 出站安全约束 | `base_url` 仅允许 HTTPS（或本地回环）；默认禁用重定向，仅同 origin（scheme+host+port）且不降级才跟随、不携带 Authorization；日志/诊断不明文记录 key |
| D8 | 并发与计费 | 单会话任一时刻最多一个进行中后端操作；**生图请求不自动重试**（防重复计费） |

> review 修订要点：移除 `n` 多图（避免丢图与计费复杂度）；结果按 output_format 动态构造 data URI（非固定 PNG）；参考图 multipart 直传不落盘；模板改为一次性引导词；补出站安全、失败重试、并发、生命周期、结构化降级、session 续接降级等边界。

## 3. gpt-image-2 调用方案（技术依据）

来源：OpenAI 官方 API 参考 + colorflowai 同类 OpenAI 兼容代理文档交叉验证。

### 3.1 两个端点

| 用途 | 端点 | 请求格式 | 关键字段 |
|---|---|---|---|
| 纯文生图 | `POST /v1/images/generations` | `application/json` | `prompt`、`size`、`quality`、`output_format`、`background` |
| 参考图+prompt 改图 | `POST /v1/images/edits` | `multipart/form-data` | `image[]=@文件`、可选 `mask`、`prompt`、`input_fidelity`、其余同上 |

- 返回均为 `data[0].b64_json`（base64），契合「直接前端展示 base64、不落本地」。
- **`generations` 不接受参考图**；要「以图为内容」必须走 `edits`。
- 每次生成请求**恰好请求一张**（不传 `n` 或固定 `n=1`），避免多图丢图与计费复杂度。

### 3.2 参数枚举（页面下拉框）

| 参数 | 选项 |
|---|---|
| `size` | `1024x1024` / `1536x1024`(横) / `1024x1536`(竖) / `auto` |
| `quality` | `low` / `medium` / `high` / `auto` |
| `background` | `transparent` / `opaque` / `auto` |
| `output_format` | `png` / `jpeg` / `webp` |
| `input_fidelity`（仅 edits） | `low` / `high` |

### 4.1 关键边界

- **prompt 迭代**走现有 CLI 执行器链路（`StreamingProviderInput` + `resume_provider_session_id`），跑在每次会话的 scratch 临时目录（无 git）；执行器 `env_vars` 仅由调用方显式提供，**不含 key**。
- **图片生成**走全新 `reqwest` 链路，由后端发起，key 只在后端。两者**完全解耦**，唯一耦合是「最终 prompt + 参数（+可选参考图）」从前端传给 `/generate`。
- **传输方式**：prompt 迭代走 **WS**（`/sessions/:id/chat`，流式回推）；图片生成走 **POST**（`/generate`，可选 multipart 参考图，一次性返回 b64）；settings 走 GET/PUT。

### 4.2 新增依赖

- 后端：`reqwest`（首次引入对外 HTTP 客户端；带 `json`、`multipart` feature）。

## 5. 两阶段数据流（核心流程）

### 5.1 阶段 1｜prompt 迭代（CLI 执行器，多轮，WS）

````text
用户输入"画一个产品上线流程的配图"
  → 前端经 WS /sessions/:id/chat 发送消息
  → 后端构造 StreamingProviderInput {
       prompt: 模板引导词 + 用户消息,
       working_dir: scratch_dir,
       resume_provider_session_id: 上轮的 provider session(首轮为空),
       structured_output_contract: { suggested_prompt: 非空字符串 },
       env_vars: (不含 key)
     }
  → 执行器流式输出 → WS 推前端 → 渲染成:
       (a) 对话气泡(执行器的解释/追问)
       (b) 「建议 prompt」可编辑区块(解析失败则保留上一轮并提示)
  → 执行器完成, 记录新的 provider_session_id 供下轮续接;
     若续接失败则以新 session 回灌上下文重发本轮
````

- prompt 需让执行器**结构化输出** `suggested_prompt`；解析失败时保留上一轮可编辑 prompt，不展示空 prompt。
- 多轮续接：每一轮带同一 `provider_session_id`。

### 5.2 阶段 2｜生成图片（用户点按钮，Aria 后端调 image2，POST）

````text
用户点击「用此 prompt 生成」, 前端 POST /generate:
  { sessionId, prompt(可能用户编辑过), params, referenceImage?(multipart 文件) }
  → 后端校验: 配置有效? 参数在枚举内? 该会话无进行中操作?
  → 读 settings.api_key
  → 有 referenceImage ? POST /v1/images/edits   (multipart: image[]+prompt+params)
                     : POST /v1/images/generations (json: prompt+params)
  → 恰好生成一张, 拿 data[0].b64_json
  → 按 output_format 构造 data URI → 回前端 → <img> 展示
  → 结果(prompt/参数/图)存入会话历史
  → 失败(连接/超时/4xx/5xx/空data/缺b64): 归一可读错误, 不自动重试,
     不写成功结果, 记一条失败事件(不含敏感信息)进历史
````

### 5.3 不满意循环

用户在聊天里继续输入反馈 → 回到阶段 1（续接或失效降级新 session）→ 更新 prompt 区块 → 再点生成。

## 6. API Key、设置与出站安全

### 6.1 存储文件

路径：`<workspace>/.aria/image_create.json`

````json
{
  "base_url": "https://colorflowai.com/v1",
  "api_key": "sk-xxx",
  "defaults": {
    "size": "1024x1024",
    "quality": "high",
    "output_format": "png",
    "background": "auto"
  }
}
````

### 6.2 接口与保留语义

- `GET /api/image-create/settings`：key 脱敏返回（如 `sk-****1234`）。
- `PUT /api/image-create/settings`：写盘；`api_key` 为空或为脱敏占位时**保留原值**（不清空），清除需显式动作。

### 6.3 安全

- key 仅后端读取用于 `reqwest` 请求头；**不传给 CLI 子进程**；前端不缓存明文。
- **出站约束（D7）**：`base_url` 仅允许 HTTPS（或本地回环）；image2 请求**默认禁用自动重定向**，如跟随仅限同 origin（scheme+host+port 全同）且拒绝 HTTPS→HTTP 降级、不在跨 origin/降级重定向携带 Authorization；日志/诊断/测试夹具不明文记录 key。

## 7. 参考图与参数 UI

### 7.1 参考图

- 参数面板「拖拽/点击上传」区，单张，预览缩略图 + 删除。
- 限定 MIME（png/jpeg/webp，仅静态图）与上限（≤10MB、≤4096×4096 像素）；后端按实际内容校验；越界拒绝并提示。
- **随生成请求直接 multipart 提交，不在磁盘/会话历史持久化**；无图则文生图，后端按有无图自动选端点。

### 7.2 参数控件

| 参数 | 控件 | 选项 |
|---|---|---|
| size | 下拉 | 1024×1024 / 1536×1024(横) / 1024×1536(竖) / auto |
| quality | 下拉 | low / medium / high / auto |
| background | 下拉 | transparent / opaque / auto |
| output_format | 下拉 | png / jpeg / webp |
| input_fidelity（仅 edits 显示） | 下拉 | low / high |

> 无 `n` 参数：每次生成恰好一张。文生图时隐藏/忽略 `input_fidelity`。

## 8. 模板机制与预置内容

### 8.1 机制（一次性引导词）

- 创建会话时选预置模板（卡片或下拉）或「自定义」填一段引导词。
- 模板引导词注入该会话 prompt 迭代对话。
- **预置两套内置；自定义引导词为一次性会话引导词，不提供持久化保存/列表/编辑/删除（CRUD 为后续非目标）。**

### 8.2 预置模板内容

**模板①「PPT 商务配图」**（幻灯片配图、概念图、封面）

> 生成适合商业 PPT 的配图。要求：构图简洁、留白充足、主体居中或遵循三分法；风格偏扁平/等距(isometric)/2.5D 插画，色彩克制（主色+1-2 辅色，避免高饱和）；无文字、无水印；背景干净（纯色或轻渐变）；尺寸适配 16:9 或 1:1；视觉传达一个清晰概念，专业克制，不花哨。

**模板②「业务流程图/示意图」**（流程、架构、步骤说明）

> 生成清晰的业务流程图/示意图。要求：明确表达步骤/角色/流向，使用箭头、方框、连线等结构化元素；配色用语义色（开始/结束/判断/动作各一色），整体克制；节点文字为英文或简短中文，排版整齐对齐；风格扁平、线条统一粗细；适合插入文档说明，背景干净。

参考 `[educational-platform]` 风格：**Claymorphism + 鲜艳块状 + 扁平 + 清晰层级 + 微交互**。
