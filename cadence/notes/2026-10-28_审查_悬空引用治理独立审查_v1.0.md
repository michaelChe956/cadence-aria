## 裁定二：代码质量

### 1) 正确性 / 并发与锁语义

- **刚修的 TOCTOU 修复正确**：`cleanup_rules.rs:302-320`（`missing_intent_in_lock`）在锁内读失败后先 `stat`——文件仍在 → 原样上抛；已不在 → 转「已清」的 `ReportOnly`。锁外 `path_exists`（`:118-120`）只做快速退出，不参与任何删除决定。删除段（`cleanup.rs:477-495`）再次进同一把锁并**逐字节比对内容**，内容被并发改写即本轮不删（fail-closed）。锁目标与既有取代路径完全同路径（`issue_automation_store.rs:55-67` + 取代路径在同一锁内 `remove_file`，`issue_automation_store.rs:1735-1752`），互斥成立。
- **同类 TOCTOU 排查结论**：台账条目删除（`cleanup.rs:505-525`）无锁无内容复核，但该文件按 session id 落盘、id 由耐久高水位保证不复用且身份漂移 fail-closed（`lifecycle_store/workspace.rs:216-222`）→ 不可达，不构成缺陷。窗口簇「判定→purge」之间无锁，但 L2 要求终态+无租约+目标两路皆无，且启动期单线程，风险可忽略。
- **P2 缺陷 A（新发现）**：巡检的窗口簇聚合**不把不可解析的窗口记录计入**，而销账面用全局 `unreadable` 阻断，两侧口径不一致。
  现象：`window_partition.rs:17-60` 解析失败只 `push_undetermined` 且不加入 `windows` 集；`:63-120` 只对**已解析**窗口聚合 → 若某 attempt 名下有一扇坏窗口、其余窗口四条件成立，巡检给出 `删除记录（窗口簇）`（`patrol/context.rs:139-150`，动作常量 `PATROL_ACTION_DELETE_GROUP`）。销账面同一现场因 `cleanup_rules.rs:404-421` 的 `unreadable` 判为整簇只报不删。
  后果：清单 §2「明细（可删）」推荐删除、实际一条不删，同一批条目在 §6 变成「只报不删残留」；运维按清单手工处置会与系统判定相悖，也削弱 REQ-DRG-12「任一窗口不满足即整簇不删」的保守口径在清单侧的体现。
  落点：`patrol/window_partition.rs:63-120`（`build_attempt_clusters` 收到不可解析记录时应把该 attempt——或与销账一致地全局——降为 `证据不足`）。

- **P2 缺陷 B（新发现）**：台账条目 `entity_kind=plan` 但 `entity_id` 为空时，**整轮自动销账失败**。
  现象：`cleanup.rs:317-345` 用 `json_string_field` 取字段（缺失/非字符串 → `""`）；`cleanup_rules.rs:515-560` 只校验 `entity_kind`/`project_id`/`issue_id`，未校验 `entity_id` → `tombstone_scope` 构造出 `entity_id=""` 的 `EntityScope` → `resolve.rs:423` → `EntityDeletionStore::get` → `entity_deletion_record_path`（`entity_deletion_store.rs:519-529`）`scope.validate()`（`json_store.rs:109-125`）返回 `PathEscape("")`；`?` 一路穿出 `decide_ledger_entry_cleanup` → `collect_decisions` → `run_cleanup` 返回 `Err`。
  后果：单个坏台账文件使**本轮所有删除都不执行**、清单只有「销账失败」、无自证节、无逐条输出（需等文件被人工修掉才恢复）。同一条记录在巡检侧是静默 `continue`（`patrol/identity_partition.rs:60-66`）——两侧对「缺 `entity_id`」的处理不对称，说明不是刻意设计。
  落点：`cleanup_rules.rs:515`（补 `entry.entity_id.is_empty() → ReportOnly`）+ `patrol/identity_partition.rs:64`（改为记入不可判定）。

- 墓碑永不删：删除集只来自三类白名单（`cleanup.rs:394-455`），路径形状护栏排除 `entity-deletions`（`:568-600`）；巡检对墓碑不产发现（`issue_partition.rs:16-45`，用例 `patrol_tests.rs:594`）。✓
- 用户业务数据：只删两种 intent 文件、`state/entity-identity/sessions/*.json`、窗口簇（复用既有清理器）；用例 `cleanup_tests.rs:321-353`、`:70-93`（业务数据 digest）。✓
- 路径护栏（`cleanup.rs:615-668`）：拒绝绝对路径/`..`/非直接子项；父目录 canonical 必须仍在状态根内；目标是符号链接则不删；用例 `cleanup_tests.rs:431-467`。✓

### 3) 错误分类边界

- 只吞「目标不存在」：`resolve.rs:486-494` 把 `NotFound` 折成 `false`、其余错误上抛；①层的 `Unknown` 既不跳过也不告警（`listing.rs:214-240`）；`tolerance.rs` 对墓碑解析失败上抛（有用例）。✓
