## 2. 组件：`web/src/components/lifecycle/ProviderInstallActionButton.tsx`（B2S7B 新建）

**props**：

| prop | 类型 | 说明 |
|---|---|---|
`target` | string | provider 标识 |
`cliAvailable` | boolean | 本地是否有 CLI |
`localVersion?` | string \| null | 本地版本 |
`latestVersion?` | string \| null | 最新版本（`null` = 离线未知） |
`capabilityConfirmed` | boolean | 三 aspect 全部 confirmed |
`onSettled?` | () => void | 作业结束回调 |
`onVerify?` | () => void | 点【核验】的回调（**可选**，不改变 import 形状） |

**行为**：
- 最新版本 → **返回 `null`（不渲染按钮）**
- 已安装未核验 → 【核验】
- 版本落后 → 【更新】+ 显示当前/最新
- 未安装 → 【安装】+ 显示手动命令
- **自带作业轮询**
- **Kimi 特殊**：点击先告知「将执行来自 code.kimi.com 的安装脚本」，用户确认后才 POST 并带 `acknowledge_remote_script: true`；**Kimi 永不出现「更新」**

## 3. 端点（片7A 后端已逐字确认）

```
GET  /api/providers/install-targets
→ {"targets":[{target, display_name, cli_available, local_version, latest_version,
               latest_checked_at, install_source, action}]}

POST /api/providers/{target}/install
→ {job_id}
   ⚠️ kimi 必须带 body {"acknowledge_remote_script": true}

GET  /api/providers/install/{job_id}
→ {job_id, target, status, created_at, updated_at, outcome,
    failure{kind, message, manual_command}}
```

## 4. 块3 片5 在登记向导里的用法

- `capabilityConfirmed` **传 `true`** —— 向导场景无 capability 语境；传 `false` 会渲染**禁用的【核验】**，用户点了没反应
- 未安装 → 自动渲染【安装】+ 手动命令
- **Kimi 的 `acknowledge_remote_script` 由组件内部处理**，片5 **不要**自己拼这个字段
- `onSettled` 里重跑 `getInstallTargets()` 刷新状态

## 5. 已知的保守取舍（B2S7B 声明，片5 不得"改进"）

- 动作在前端按版本重算，**不直接用后端 `action` 字段**（props 只给版本号）
- 离线（`latest_version = null`）时**不显示「更新」**（保守）
- 前端保留一份手动命令表**仅用于展示**；执行与失败兜底**以后端为准**
