### 0.3 ⚠️ 两个阻断性前置发现（影响整份矩阵）

1. **成员登记（REG）无 Web 入口**：`LogicalCodebaseRegistrationCoordinator` 实现完整且被 it_web fixture 使用，但 `src/web/app.rs` 路由表无 `/registrations`、`/manifest`、`/batch`、`/preflight` 路由；`src/cli.rs` 无登记子命令；`POST /api/projects/{id}/repositories` 走 legacy 路径只写 `repos.json`。→ 无 manifest 则多仓链路无法开始。
2. **聚合索引构建（IDX）无生产触发点**：`AggregateIndexOperation::rebuild/sync`、`CodeGraphCli` 仅在 `#[cfg(test)]` fixture 中构造；无生产代码写 active index record。→ 规划读索引会 `aggregate_index_unavailable` fail-closed。

（注：两项已经另派 worker 深入审计核实，结论见后续笔记；矩阵中 REG/IDX 用例照列作为验收面。）

### 0.4 数据就绪前置（所有「正常路径」用例共同前置）

`.aria/projects/{project_id}/logical-codebase/` 下需有：

```
manifest.json                                   # membership_revision + member_ids + provider_context_root
members/{logical_repository_id}.json            # logical id / physical id / alias / source_identity / checkout_ids
checkouts/{checkout_id}.json                    # canonical_path / git_dir_identity / revision / availability
policy-artifacts/{revision}.json                # AggregatePolicyArtifact（gateway 需要）
```

播种方式：运行 it_web `seed_logical_codebase` 等价逻辑，或补齐 REG 端点。

### 0.5 remote 前置（DEL/PTR push 用例必须）

```bash
mkdir -p /tmp/test-demo-remotes && for r in demo-common-lib demo-user-service demo-order-service demo-web-ui; do
  git -C /tmp/test-demo/$r init --bare /tmp/test-demo-remotes/$r.git 2>/dev/null || true
  git -C /tmp/test-demo/$r remote remove origin 2>/dev/null || true
  git -C /tmp/test-demo/$r remote add origin /tmp/test-demo-remotes/$r.git
done
```

不配 remote 时 push 用例自然走「失败 → partial → RetryPush」路径（DEL-03 构造手段）。

### 0.6 每仓 git 副作用快照审计手法

```bash

done

```

## 5. 非阻塞项与已知偏差

1. openspec validate --all 的 `scalable-group-final-review` 既存失败——不必报
2. REG/IDX 入口缺口——另派 worker 审计中，作为矩阵执行前的前置卡
3. 指针文件落地为 `.aria-pointer.md`，与设计文档措辞不一致——以代码为准
4. 成员仓无 remote——按 §0.5 配置
5. Codex 阻断是预期行为（REQ-ENV-05 禁止降级）
6. 只读/单写为 best-effort + supervised，验收口径是配置目标 + pre/post 检测
