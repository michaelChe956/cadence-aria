## 🔴 高优先级（结构性缺陷，prompt 临时缓解）

### 契约结构两处显式化

详见 [`2026-07-29_契约结构两处显式化改造.md`](2026-07-29_契约结构两处显式化改造.md)。

- **项一：capability 的标识符与描述分离**。`input_contracts.required_capabilities` 与 `output_contracts.capabilities` 都是 `Vec<String>`，被当标识符消费却写成自然语言描述，`BTreeSet` 纯字符串匹配必然失配。建议 `ContractCapability { capability_id, description }`，匹配只用 id。影响 ~200 文件，已用 prompt「逐字引用上游」缓解。
- **项二：verification check 的执行者显式化**。`VerificationCheck` 只有 `required: bool`，同时承担「验收必需」与「Coder 交付前提」，人工事项无法表达，实测导致 Coder 因无浏览器输出 operational_gate 静默停机。建议 `executor: coder | human`。已用四处 prompt 统一口径缓解，但待人工事项只以自然语言存在，UI 无结构化清单。

**建议合并为一个 change 立项**（两项同源：契约字段语义不显式）。
