## 1. 改了什么（逐文件）

### 1.1 新建 `web/src/api/provider-install.ts`
安装 / 更新的前端唯一调用面（**没有写进 `client.ts`**，遵守 §9.3 禁碰）。

- `getInstallTargets(): Promise<InstallTargetView[]>` → `GET /api/providers/install-targets`，接受 `{targets:[...]}`（后端已确认）与裸数组两种形态，两者都不合规时抛错（不静默空白）。
- `startInstall(target, { acknowledgeRemoteScript? })` → `POST /api/providers/{target}/install`，Kimi 时 body 为 `{acknowledge_remote_script:true}`，其它对象 body 为 `{}`；返回 `{job_id}`。
- `getInstallJob(jobId)` → `GET /api/providers/install/{job_id}`。
- `manualInstallCommand(target)`：手动兜底命令唯一来源（npm 类带 `--registry=https://registry.npmmirror.com`；Kimi 为 `curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash`），**永不带 sudo**。

- 常量 `DEFAULT_NPM_REGISTRY` / `KIMI_INSTALL_SCRIPT`。

### 1.2 新建 `web/src/components/lifecycle/ProviderInstallActionButton.tsx`

## 4. 给块3 片5 的对接契约（路径 / 方法 / 请求体 / 响应字段）

### 4.1 后端端点（片7A 已回执确认，与本节逐字一致）

| Method | Path | 请求 | 响应 |
|---|---|---|---|
| `GET` | `/api/providers/install-targets` | — | `{"targets":[InstallTargetView...]}`（固定顺序 `claude_code, codex, pi, kimi_code, codegraph`） |
| `POST` | `/api/providers/{target}/install` | `{"acknowledge_remote_script": true}`（**仅 kimi_code 必填**，缺/false → 400 `install_acknowledgement_required`；其它对象可省 body） | 200 `{"job_id":"..."}`（立即返回）；未知 target → 400 `install_target_unknown` |
| `GET` | `/api/providers/install/{job_id}` | — | `InstallJob`；未知 job → 404 `install_job_not_found` |

```ts
type InstallTargetView = {
  target: "claude_code" | "codex" | "pi" | "kimi_code" | "codegraph";
  display_name: string;
  cli_available: boolean;
  local_version: string | null;
  latest_version: string | null;      // kimi_code 恒 null；npm 对象离线时也 null
  latest_checked_at: string | null;
  install_source: string;             // "npm @openai/codex" / "official script https://code.kimi.com/kimi-code/install.sh"
  action: "install" | "update" | "none" | "verify";
};

type InstallJob = {
  job_id: string;
  target: InstallTargetView["target"];
  status: "running" | "completed" | "failed";
  created_at: string;
  updated_at: string;
  outcome: { installed_version: string | null; path_hint: string | null } | null;  // completed 非空
  failure: {                                                                       // failed 非空
    kind: "permission" | "network" | "package_not_found" | "other";
    message: string;                 // 中文分类提示
    manual_command: string | null;   // npm 带 --registry；kimi 为官方脚本；永不带 sudo
  } | null;
};
```

### 4.2 前端调用面（块3 直接 import 这两个模块即可）

```ts
// web/src/api/provider-install.ts
getInstallTargets(): Promise<InstallTargetView[]>
startInstall(target: InstallTargetWire, options?: { acknowledgeRemoteScript?: boolean }): Promise<{ job_id: string }>
getInstallJob(jobId: string): Promise<InstallJob>
manualInstallCommand(target: InstallTargetWire): string
compareVersions(left: string, right: string): number   // 预发布 < 正式；不可解析 = NaN
DEFAULT_NPM_REGISTRY / KIMI_INSTALL_SCRIPT              // 常量

// web/src/components/lifecycle/ProviderInstallActionButton.tsx
import { ProviderInstallActionButton, type ProviderInstallActionButtonProps } from
  "../lifecycle/ProviderInstallActionButton";   // 块3 从自己的目录算相对路径

interface ProviderInstallActionButtonProps {
  target: InstallTargetWire;
  cliAvailable: boolean;
  localVersion?: string | null;
  latestVersion?: string | null;        // Kimi 恒 null → 永不显示「更新」
  capabilityConfirmed: boolean;
  onSettled?: () => void;               // 作业终态后回调（父级刷新 health/投影）
  onVerify?: () => void;                // 可选：把既有 capability-revalidate 通道接进来
}
// 返回 null = 不显示任何按钮（版本最新）；组件自带作业轮询，调用方无需再写轮询。
```

**块3 用法建议**（登记向导里「装 CLI 才能继续」的入口）：
1. `const targets = await getInstallTargets()` → 按 `action`/`cli_available` 找到目标；
2. 渲染 `<ProviderInstallActionButton target={t.target} cliAvailable={t.cli_available} localVersion={t.local_version} latestVersion={t.latest_version} capabilityConfirmed onSettled={refetch} />`；
   ⚠️ **向导场景没有 capability 探针上下文**：`capabilityConfirmed` 传 `true`（即「不要显示核验」），组件就只做安装/更新 —— 未安装得到【安装】+ 手动命令，已安装落后得到【更新】，最新则 `null`。若传 `false` 且不给 `onVerify`，会渲染一个禁用的【核验】按钮（那属于能力核验卡的语境，向导里不该出现）；
3. 未安装 → 直接得到【安装】+ 手动命令；Kimi 的远程脚本告知与 `acknowledge_remote_script` 由组件内部完成，**向导不需要自己处理**；
4. `onSettled` 里重跑 `getInstallTargets()`（及自己的 bootstrap/health 投影）。**安装 ≠ 核验**：装完仍须走既有 capability-revalidate 通道（在能力核验卡里）。
