**判成「已变更」的那一步**：旧 receipt 的 after 快照里，`File` 条目的

> 对 `file_type.is_file()` 写 `content_digest: Some(digest_bytes(&bytes))`，dir/symlink/special 写 `None`。
> 即：旧 receipt 中**每个文件条目都带摘要**，这正是存量数据必然踩中的原因。

## 2. 语义判定（为什么既不能判「已变更」也不能判「没变」）

| 两端状态 | 能得出什么结论 | 处置 |
|---|---|---|
| 旧 `Some(..)` + 新 `None`，其余元数据一致 | **无法判断内容是否变了**：新快照对该文件只有 path/kind/link_target/special_type/escapes_root，**没有任何内容证据**；旧摘要也无法与新快照比（对面没有摘要） | **单列「无法用旧摘要复验」**，拒绝恢复并给出可执行处置（重新审计） |
| 两端都 `None`（新 receipt vs 新快照） | 现有逻辑不变：元数据全等 ⇒ 未变；任一元数据字段不同 ⇒ 已变更 | 现有逻辑 |
| 两端都有摘要 | 现有逻辑不变：摘要相等/不等照旧判定 | 现有逻辑 |

**为什么不能判成「已变更」**：摘要差异是**格式差异**，不是内容差异的证据。判成 changed 等于把
「这张 receipt 是改造前写的」谎报成「文件被改过」——存量用户的每一条旧 operation 的恢复都会被永久封死，
且给出错误的原因（用户会去查一个根本没发生的改动）。这是本次要修的回归。

**为什么也不能判成「没变」**（即「比较时忽略 `content_digest`」那种写法）：新快照对未变更文件
**不读内容、不留内容证据**（REQ-AUD-01 已批准口径），忽略摘要就等于断言「内容一致」——而内容完全
可能在审计之后被改过。那是相反方向的谎报（漏报），恢复分支会拿一份「假定未变」的树去发布政策正文。

⇒ 唯一诚实的表达是**第三档**：「无法用旧摘要复验」。它不是「已变更」，也不放过；它把
**不确定性如实交给用户**，并给出唯一能消除不确定性的动作：**重新审计末命令，让 receipt 落成当前口径**。

## 3. 改前 → 改后

### 3.1 判定谓词（新增，仅在恢复分支的比较侧）

```rust
/// 旧 receipt（改造前口径：文件条目带内容摘要）与新快照（REQ-AUD-01 元数据
/// 口径：`content_digest` 恒 `None`）之间，摘要**不可比**：其余元数据一致的
/// 条目既不能判「已变更」（那是把存量 operation 的恢复一律误报），也不能判
/// 「没变」（内容可能真的改了，只是新口径不再留证据）⇒ 单列这一档，如实
/// 报告「无法用旧摘要复验」，由调用方给出「重新审计」这一可执行处置。
fn legacy_content_digest_unverifiable(old: &RootRecipeSnapshotEntry, fresh: &RootRecipeSnapshotEntry) -> bool {
    if old.content_digest.is_none() || fresh.content_digest.is_some() {
        return false;   // 新-新（两侧 None）与「有-有」都不进这一档
    }
    let mut without_digest = old.clone();
    without_digest.content_digest = None;
    without_digest == *fresh   // 摘要之外全部一致 ⇒ 只是摘要不可比
}
```

- 归一化**只发生在比较侧**：持久化格式、`serde` 形状、反序列化行为一字未动
  （B2S6 的 `legacy_receipt_with_content_digests_still_deserializes` 不受影响）。
- 摘要之外**任何**字段不同（kind / link_target / special_type / escapes_root / path）⇒ 谓词为假
  ⇒ 落回原 `Some(_) => changed` 分支 ⇒ **新-新敏感度不变**。

### 3.2 比较分支

```rust

Some(_) => return Err(invalid("path {path} changed since the audited final command of {operation_id}")),

// 改后（在两者之间插入一档，原两条分支原样保留）

    return Err(ProductStoreError::InvalidRecord {
        kind: LEGACY_DIGEST_UNVERIFIABLE_KIND,   // "aggregate_policy_publication_legacy_digest"
        reason: format!(
            "path {path} of the audited final command of {operation_id} carries a legacy \
             content digest that the metadata-only audit cannot re-verify; re-run the \
             audited final command to record a fresh audit snapshot, then resume"
        ),

}
Some(_) => return Err(invalid("path {path} changed since the audited final command of {operation_id}")),
```

- 报错**不再**声称「已变更」，而是如实说明「旧摘要无法复验」，并给出可执行处置：
  **重跑末命令重新审计**（落一份当前口径的快照）**再恢复**。
- 该档用**独立 record kind**（`aggregate_policy_publication_legacy_digest`）标记，唯一用途是让
  `root_recipe_publication_failure` 把它映射成 `retryable: false`（见 §3.3）；其余故障仍走原
  `invalid(...)`（`kind: "aggregate_policy_publication"`）与 `retryable: true`。
- **恢复不会签发最终 receipt**（不可复验绝不当通过）。
- 另外只新增了一行 `use ... root_recipe_receipt::RootRecipeSnapshotEntry;`（谓词参数类型）。

### 3.3 裁决落实：该档 `retryable: false`（controller 2026-11-03 裁定）

**理由（controller 裁定原文）**：`retryable` 的语义就是「重试有没有用」；本档**重试 Continue 只会拿到
同一条错误**（结论取决于盘上那棵树的既有 receipt 格式，不会因重试而变）⇒ 必须先重跑末命令重新审计 ⇒
标成可重试就是错的（会把 UI 引导进重试死循环）。

**不加新 `cause` token**：新 cause 要动块2 的失败面分类器与码表（`failure_copy` 归 B2S2 独占、码表已冻结），
为一条一次性迁移期的边缘情况改分类体系代价大于收益；可执行信息已由 `reason` 文本完整承载。

落实方式（只改一处 + 一条断言，消息文案与档位归类均未动）：

```rust
// 新增（唯一用途：让这条失败不可重试）
const LEGACY_DIGEST_UNVERIFIABLE_KIND: &str = "aggregate_policy_publication_legacy_digest";

fn root_recipe_publication_failure(step, error: ProductStoreError) -> AggregateInitializationError {
    // 「旧摘要无法复验」重试无用 ⇒ 不可重试；其余发布失败保持可重试。
    let retryable = !matches!(
        &error,
        ProductStoreError::InvalidRecord { kind, .. }
            if kind.as_str() == LEGACY_DIGEST_UNVERIFIABLE_KIND
    );
    AggregateInitializationError::ProviderTurn {
        step,
        reason: format!("root recipe policy publication failed: {error}"),
        retryable,
    }
}
```

**断言**（`resume_legacy_compat.inc.rs` 用例 1 内）：

```rust

    "旧摘要无法复验必须先重新审计，Continue 重试无用 ⇒ retryable 必须为 false"
);
```

并已验证这条断言**不是空断言**：用「裁决前版本」（legacy 档已存在、但 `retryable: true`，
sha256 `3ccf81b7…`）跑同一用例 ⇒ 恰好在这一行失败（见 §4.1 PHASE A）。
