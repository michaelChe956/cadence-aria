## 4. 三条基础设施教训（本轮实测，跨项目有效）

### 4.1 前端是**编译期嵌入**进二进制的 ⇒ 构建顺序不能反

`src/web/static_assets.rs` 用 `#[derive(RustEmbed)] #[folder = "web/dist"]` 把前端打进二进制。

⇒ **只跑 `cargo build` 不会带上新的前端**。本轮实测：`cargo build` 后前端 asset 仍是旧的（`index-Bk5msPU7.js`），因为 `web/dist` 是在那之后才重建的。
⇒ **正确顺序：`cd web && pnpm build` → `cargo build` → 重启**。门禁脚本 `/tmp/aria-gate.sh` 已按此顺序修正。

### 4.2 worker 卡死是**brief 形状**问题，不是模型问题

**证据**：`OrderAndRedText` 48 分钟、58 次调用**全是 read/grep、零 write**，转录里「let me check the last details before writing tests」同一句说了 9 遍。
**根因（4 条叠加，全在 brief 上）**：
1. brief 给了**无界活**（「逐条同步各 fixture」）⇒ worker 必须先穷举全部命中点才敢动手；
2. brief **已含完整答案** ⇒ 无决策可做 ⇒ 只剩「验证整个爆炸半径」；
3. 无**机械步数上限** ⇒ 「读完就写」靠模型自觉；
4. controller **未按铁律 8 主动 DM 催分批提交** ⇒ 卡住时产出为零、无中间态可捞。

**改法（已写入全局 subagent 规则的待办稿，owner 转交另一会话）**：
- `agent-defs/{ds-task,glm53-task,minimax-task}.md` 加 `<execution_budget>` 段（write first / 读≤6 grep≤8 / 单切片≤3 文件 / 每红测试一 commit / 10 分钟内报 BLOCKED）；
- `agent-rules/subagent-protocol.md` §三 加闭集清单、禁先读全仓库、机械上限、controller 15 分钟无 commit 即 DM；
- `agent-rules/subagent-roster.md` 加一行提示（选角时就想闭集）。

**验证**：按新模板重派后，前端切片 **3 分 19 秒**完成（红测试 → 实现 → 20/20 绿），后端切片 18 分钟（含两轮闭集扩权）零空转。
