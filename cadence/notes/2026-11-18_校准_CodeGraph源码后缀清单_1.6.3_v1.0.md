# 校准：CodeGraph 源码后缀清单（基线 1.6.3）· v1.0

**日期**：2026-11-18　**执行机**：本机 Linux x86_64　**codegraph 版本**：`1.6.3`（部署兼容区间 `>=1.6.0, <2.0.0`）

## 目的与定位

本文件是《聚合索引源码范围判定与 Story 前共享索引刷新》的一次性**校准动作**证据（Plan §2，契约 `REQ-IND-01`）：确定 **Aria 自有的静态源码后缀清单**。

- 清单是**代码内静态常量**（落在 `src/product/logical_codebase/aggregate_index/source_scan.rs`），由 Aria 自有。
- 校准是**实施期一次性动作**：本文件 + 片1 的清单与基线注释即全部产物。**不是运行期流程、不是开工门禁、不做机器级 durable 记录、不做运行期测量、不做版本键缓存、不做自动重校准。**
- **版本漂移只记可审计 warning、不阻断索引构建**（owner 裁决）。已知风险见文末。

## 测量方法（可复现）

逐后缀**独立临时根**，每种语言用**该语言的最小有效样本**（不得用同一份 JS 样本改后缀），按生产 argv 执行：

```bash
# 生产 argv 以代码为准（src/product/logical_codebase/aggregate_index/codegraph_cli.rs）
#   init . (:155) / sync . (:165) / files --json (:203)
root="/tmp/cg-suffix-probe/1.6.3/<ext>"
mkdir -p "$root/src" && cp "<该语言最小有效样本>" "$root/src/sample.<ext>"
cd "$root"
codegraph init .      # 记录退出码
codegraph sync .      # 记录退出码
codegraph files --json > files.json   # 记录退出码 + JSON 校验 + 收录文件数 + 本样本是否收录
```

**判定**：该后缀的最小有效样本出现在 `files --json` 的结果里 ⇒ 该版本**会收录**该后缀；否则 ⇒ 不收录（区分「后缀不被支持」与「样本无效」）。

产物目录：`/tmp/cg-suffix-probe/1.6.3/<ext>/`（临时，不入库）。

## 结论：Aria 源码后缀清单（代码内静态常量，基线 = codegraph 1.6.3）

取「1.6.3 会收录」集合的**子集**：只保留**我们希望当源码看待**的常见语言；配置/文档格式与冷门语言**不算 Aria 源码**。

**清单（44 项）**：

```
.astro .c .cc .cpp .cts .cu .cuh .cs .cshtml .cxx .dart .go .h .hpp .hxx
.java .js .jsx .kt .kts .lua .luau .m .mm .mts .php .py .pyw .r .rake
.rb .razor .rs .scala .sc .sol .swift .ts .tsx .cjs .mjs .svelte .vb .vue
```

**明确排除**：

| 类别 | 后缀 | 排除理由 |
|---|---|---|
| 配置/文档格式（虽被 1.6.3 收录） | `.yaml .yml .xml .properties .tf .tfvars .tofu` | 按口径**不算源码**（配置/声明文件，不是代码） |
| 1.6.3 **不收录** | `.json .md .toml .txt .csv .html .htm .sh .bash .zsh .sql .ini .cfg .conf .pl .pm .gradle .bat .ps1` | 上游不索引 ⇒ 不可能是「源码漏收」 |
| 冷门语言（1.6.3 收录但非目标） | `.erl .hrl .nix .cob .cobol .cbl .cpy .escript .dpr .pas .liquid .metal .cfc .cfm .cfs` | 不纳入 Aria 口径（避免把非主流格式当源码而误报漏收） |

**清单性质**：是 1.6.3 收录集合的**真子集** ⇒ 「磁盘上有源码却未被索引」这一失败判定不会把「上游根本不索引的文件」误判为漏收。

## 复校准步骤（换 codegraph 版本后）

1. 重跑上文「测量方法」的全量脚本，逐后缀独立临时根 + 该语言最小有效样本。
2. 比对新旧收录集合：**若 1.6.3 收录而新版不再收录的后缀在清单内** ⇒ 该类仓会被判成「漏收」而失败 ⇒ 按新集合更新 `source_scan.rs` 的静态清单，并把基线注释里的版本号改成新版本。
3. 复校准后同步更新本文件的证据表与结论段。

## 已知风险（owner 已裁决：先按 1.6.3，遇到问题再解决）

- **版本漂移**：聚合初始化会更新 codegraph 版本。若新版不再收录清单内某个后缀，该类仓会被判成「源码存在却未被收录」⇒ 索引构建失败（文案指向「检查路径与忽略规则」，实为版本漂移）。处置＝按上文复校准步骤更新清单。**当前不实现自动重校准，也不把漂移升级为失败**（只记可审计 warning）。
