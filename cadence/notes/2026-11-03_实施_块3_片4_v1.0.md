## 2. 1 成员与 N 成员同路径的具体证据（同一分支/同一函数）

1. **判据级**：bootstrap 投影器 identity 步完成判据是 `active_members >= 1`（`src/product/logical_codebase/bootstrap_projector.inc.rs::project_identity_step`：`active_members == 0 → NotStarted；≥1 → Completed`）——1 成员即完成，无 ≥2 门禁（T4.4 断言之）。
2. **登记链**：单成员与第 N 个成员走**同一个** `LogicalCodebaseRegistrationCoordinator::{preflight, submit_confirmed_batch, resume_batch}` → `attach_member_inner` → `ensure_manifest_membership`（成员数只影响循环与 `member_ids.push` 次数）。T4.7 用同一条链把同一 LC 从 1 成员挂到 2 成员：manifest `member_ids` 1→2、`membership_revision` 2→3、成员表 1→2 条，**没有任何第二步专用流程**。
3. **仓序自动边**：唯一规则源 `compile_support.rs::change_order_pairs`（REQ-PLN-09，注释自证「同仓/单仓/空顺序无对，单仓 compile 行为不变」）是**严格后继双重循环、零分支**——`n <= 1` 在数学上产出 0 对；Final Compile 合并路径与 SG1 纯投影两个消费点共用它。T4.5 把这一点锁成结构断言（唯一定义 + 零 `if`/`== 1`/`is_empty` + 恰两个 `for` + 恰两个调用点）。
4. **成员/聚合索引**：成员表与聚合索引快照构造（`AggregateIndexMemberSnapshot::indexed` 循环）对 1 与 N 成员是同一循环——T4.6 实测单成员 LC 落盘恰 1 份快照且绑定登记成员/Main checkout。
5. **写范围前缀**（静态核查，属守卫覆盖面）：`member_checkout_prefixes.rs::plan_member_checkout_prefixes` 对 `manifest.member_ids` 逐成员算前缀，无成员数分支；T4.1 的扫描同时保证生产代码不会新造 `len() == 1` 特判。
6. **源码级零分支**：T4.1/T4.2/T4.3 扫描 `src/**`+`web/src/**` 生产代码零命中（模式含 `members.len() == 1`、`member_ids.len() == 1`、`member_count == 1`、`require_multiple_members`、`min_members`、`minimum_member`、`>= 2`/`> 1`/`< 2` 家族、中英文拒绝文案）。已知保留项不误报：`registration_coordinator.inc.rs` 的 ≥1 candidate 检查（REQ-REG-17 兼容）、`repository_store_parts/create.inc.rs:176` 的 `matching_members.len() > 1`（物理仓身份重名检查，词边界天然排除）。
