### 8.3 `gates.rs` 零余量死结的解法（本次最关键的技术决定，D-13）

事实链（全部实测）：

1. `gates.rs` = **1436 行**，祖父上限 **1436**（`large_file_guard.rs:77`）⇒ 零余量；
2. `gates.rs:1001` 是 `EnrollmentError::Conflict { current_revision }` 的**穷举结构模式**（无 `..`），加 `kind` 字段后必然 E0027；
3. 「同行加 `, ..`」**不可行**：`{{ current_revision, .. }}` 内容 20 字符 > rustfmt 默认 `struct_lit_width = 18` ⇒ 被拆成 3 行（**+2 行**）——用 rustfmt 1.10.0 实测确认；
4. 「新增独立变体 `ConflictKinded`」**同样不可行**：`gates.rs` 的 `match error` 无 catch-all，加变体 ⇒ 非穷举 ⇒ 仍须加臂 ⇒ 仍净增行。

采用解法（实测 **净 0 行**，行为逐字等价）：

```rust
ref err @ EnrollmentError::Conflict { .. } => ProductStoreError::Conflict {
    kind: "enrollment_command_ledger",
    id: format!("current_revision={:?}", err.conflict_revision()),
},
```

- `{ .. }` 内容 2 字符 ≤ 18 ⇒ 模式保持单行（整行 83 字符），arm 体仍 3 行 ⇒ **整臂 4 行不变**；
- 配套在 `src/product/models/automation.rs`（561/1200）新增 `EnrollmentError::conflict_revision()`（+约 7 行）；
- `ProductStoreError::Conflict.id` 字符串**逐字不变**（同一个 `Option<u64>`、同一个 `{:?}`）。
