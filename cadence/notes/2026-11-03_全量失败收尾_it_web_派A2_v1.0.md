## 4. 剩余 3 条（根因实证，修法方向在案）

①② `coding_plan_repair_group_final_review_normal_path...` / `..._orchestrated_path...`（part_08:605 / part_13:96）
- 现象：attempt 走完两轮 CodeReview（report 均 Approve，实测 dump 在案）直达 FinalConfirm+WaitingForHuman；测试期望独立终审路由 plan finding ⇒ AwaitingPlanAmendment
- 根因（初证）：group 独立终审轮的 prompt 未命中 `GatewayDialectStreamingStub` 桥接的 prompt→schema 标记集（现集 = `你是 CodeReviewer`/`你是 WorkItemGroup GroupFinalReview reviewer`，prompts.rs:54/:161；group 审查分片模板为英文 `You are reviewing deterministic group-review shard`，group_review_prompts.rs:112）⇒ 替身落 generic Reviewer 臂恒 Approve
- 修法方向：给桥接标记集补 group 审查分片/归约 prompt → 对应 schema 的映射（需核对 IndependentCodeReviewPlanDefectProvider 的 plan-finding 臂消费哪个 schema），纯夹具层
③ `coding_ws_new_connection_receives_and_answers_pending_choice`（part_18:258）
- 实证两难：有快照 ⇒ 直驱 `CodingWorkspaceEngine`（测试自建，execute_coding_with_commands）被判 logical target 拒裸启动（`logical_provider_gateway_required`，provider_stream.rs:418）；无快照 ⇒ 租约门停等（`coding_run_lease_unknown: target_snapshot_missing_for_logical`，run_exclusion）
- **需生产侧决策**：直驱引擎无 gateway 注入入口（CodingWorkspaceEngine::new 无 gateway 参数）——要么给引擎构造面开注入（生产改动，**已报 Main**），要么测试改走 WS StartCoding 驱动（夹具大改）。当前保留快照形态与其余夹具一致
