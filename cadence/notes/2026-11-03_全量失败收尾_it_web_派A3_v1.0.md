### 2.1 根因链（三层，逐层实证）

   修法：经权威事实源 `build_attempt_target_snapshot` 冻结快照传入（本轮沿用，未改）。
2. **桶键层（本轮新增根因）**：补上快照后，attempt 的 target 桶键从 `None` 变为
   `Some(logical_repository_id)`（`coding_attempt_store/group.rs::attempt_target_bucket`，该文件头注已明文：

   `work_item_group_id` 取，不看桶）。
3. **身份复验层**：checkout 记录写了 `revision: Some("fixture-initial")`，而生产不变量是
   `RepositoryCheckoutRecord.revision` **恒 None**（`snapshot_validator.rs` 头注：登记与 identity 迁移从不持久化
   revision，恒为 None；快照的 revision 是 admission 时冻结的 git HEAD）。
   ⇒ `validate_snapshot_fields` 逐字比对失败 ⇒ `target_snapshot_identity_drifted`。
   **改法**：checkout 记录的 revision 改 `None`（夹具对齐生产不变量）。
4. **聚合索引层**：child workspace context 报

   ⇒ 夹具无 active 聚合索引（PlanningContextResolver 读 `AggregateIndexStore::active_required`）。
   **改法**：夹具自建 **active** 合成索引世代（成员快照 revision 取权威 checkout 的冻结 HEAD，
   与 freshness 采集同源 ⇒ 不漂移 ⇒ 不触发 codegraph 同步），落盘 scope 与
   `for_lc(legacy 别名)` 一致（legacy 别名 LC 的 scope root 即项目级 legacy 根，见 `lc_scope_root`）。
