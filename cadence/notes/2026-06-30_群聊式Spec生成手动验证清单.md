# 群聊式 Spec 生成手动验证清单

> 本清单不启动真实 Provider。以下项目均标记为「待用户手动验证」，用于发布前在具备实际 Provider 配置的环境中验收。

## 流水线模式回归

- [ ] **待用户手动验证**：在主工作台右上角打开「设置 → Spec 生成模式」，选择「流水线模式」，刷新页面后设置仍保持流水线模式。
- [ ] **待用户手动验证**：选择一个 Issue，创建 Story Spec，确认仍进入原有 Provider Workspace 流程，生成、Review、人工确认与版本历史行为无变化。
- [ ] **待用户手动验证**：从已确认 Story Spec 派生 Design Spec，确认仍进入原有 Design 流程，且上下游关联与看板展示无变化。

## 群聊模式

- [ ] **待用户手动验证**：在「设置 → Spec 生成模式」选择「群聊模式」，返回 Issue 看板后确认群聊式 Spec 生成入口可见。
- [ ] **待用户手动验证**：从 Issue 进入群聊入口，确认群聊会话创建成功并打开对应聊天室；重复进入同一 Issue 时确认复用同一会话，不产生重复房间。
- [ ] **待用户手动验证**：在群聊房间添加/确认所需角色，发送讨论消息并使用角色提及，确认讨论消息、角色回复和时间线按顺序展示。
- [ ] **待用户手动验证**：分别在 Story、Design 产物线完成讨论与定稿，确认定稿操作成功，聊天室仍可继续讨论和再次定稿。
- [ ] **待用户手动验证**：回到 Issue 看板，确认已定稿版本可见，版本号、产物类型和最新内容与聊天室定稿一致，并可打开版本历史。
- [ ] **待用户手动验证**：从看板中已定稿的 Story/Design 进入 WorkItem 派生入口，确认入口可用且跳转/准备流程正常。
- [ ] **待用户手动验证**：将模式切回「流水线模式」，确认同一工作台恢复旧版 Story/Design/Work Item 内容区，既有流水线入口仍可操作。

## 验证边界

- 本清单仅覆盖 UI 与真实运行环境中的人工回归，不替代自动化测试。
- 自动化验证使用 fake/provider-free 场景，不会调用真实 Provider。
