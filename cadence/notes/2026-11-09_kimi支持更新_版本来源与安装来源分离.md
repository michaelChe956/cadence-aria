# Kimi Code 也支持「更新」（版本来源与安装来源分离）

> 日期：2026-11-09 ｜ OpenSpec change：`openspec/changes/kimi-provider-update-support/`
> ｜ Plan：`cadence/plans/2026-11-09_实施计划_kimi支持更新.md`

## 1. 起因（实测）

Kimi Code 在界面上**永远没有【更新】按钮**：本机 kimi 是 **2.4.1**，官方最新 **2.5.2**，
但平台显示 `latest = None` ⇒ 版本差距不可见、拿不到更新入口。

根因在安装源表：同一个字段 `npm_package` 同时表达「版本判定源」与「安装源」。
Kimi 走官方脚本（非 npm）⇒ `npm_package = None` ⇒ registry 查不到 latest ⇒
`action` 恒为 `none`。

而版本信息其实是公开可得的（实测 2026-11-09）：

| 来源 | 取法 | 值 |
|---|---|---|
| 官方 `/latest` 端点 | `GET https://code.kimi.com/kimi-code/latest` | 2.5.2 |
| npm registry | `@moonshot-ai/kimi-code` 的 `dist-tags.latest`（npmmirror 与官方 registry 一致） | 2.5.2 |
| 官方 manifest | `https://code.kimi.com/kimi-code/binaries/<version>/manifest.json` | 各平台文件名 + sha256 |

官方安装脚本自身也在用 `/latest` 解析最新版，并在替换二进制前把旧件备份为
`${KIMI_INSTALL_DIR}/bin/kimi.bak` ⇒ **重跑脚本 = 原地升级**。

## 2. 契约

- REMOVED REQ-PCI-04 + ADDED REQ-PCI-07：版本来源按对象声明；
  Kimi Code 的版本来源 = npm 包 `@moonshot-ai/kimi-code`，**安装来源仍是官方脚本**。
  （REMOVED+ADDED 而非 MODIFIED：`openspec validate --strict` 要求 MODIFIED 块保留
  主规格该 requirement 的全部既有 scenario 名，而「Kimi 不做版本判定」与新语义直接冲突。）
- MODIFIED REQ-PCI-01：来源告知与用户确认覆盖「安装**与更新**」两种触发。
- MODIFIED REQ-PCI-05：Kimi 的更新复用官方脚本通道。

## 3. 实现

| 面 | 改动 |
|---|---|
| `src/product/provider_installation/source_table.rs` | `InstallSourceRow` 新增 `version_package`（版本来源）；`npm_package` 收敛为「安装源」；Kimi = 安装源 None + 版本来源 `@moonshot-ai/kimi-code` |
| `src/web/handlers/provider_installation.rs` | `install-targets` 的 latest 查询改用 `version_package`；`resolve_install_action` 保持通用（无 Kimi 特例） |
| `web/src/components/lifecycle/ProviderInstallActionButton.tsx` | 去掉 Kimi 的更新排除；来源告知文案与确认按钮覆盖「安装/更新」 |
| runner / job / 失败分类 | **不改** —— Kimi 的执行计划本来就是官方脚本，重跑即升级 |

## 4. 验证

- 单元：`cargo test --locked --lib provider_installation`（44 项全绿，含新增
  「版本来源与安装源分离」与 handler 的 Kimi `action=update` 断言）；
  `pnpm -C web test`（2829 项全绿；`KnowledgeBasePage` 的既有失败来自**另一会话**
  在同一 worktree 的在途改动，与本改动无关）。
- 端到端（发布态 4317，`/tmp/deploy-target/release/aria`，启动走
  `bash /tmp/aria-deploy/start.sh` + `--check` 6 项自检全过，指纹
  「@moonshot-ai/kimi-code」新件命中 1 / 回滚件命中 0）：
  1. `install-targets`：kimi `local=2.4.1 latest=2.5.2 action=update`（此前 latest 恒为 None）。
  2. 内置浏览器（禁用 Playwright）：Kimi Code 行出现「版本落后 → 2.5.2」+
     【更新】+「当前 2.4.1 → 最新 2.5.2」；「核验 Kimi Code」与【更新】同顶边（y=681.5）。
  3. 点【更新】→ 来源告知框「将执行来自 code.kimi.com 的安装脚本（远程 shell 脚本）。
     确认后才发起更新。」+【确认并更新】→ 确认后发起作业。
  4. 作业完成后：`kimi --version` 由 **2.4.1 → 2.5.2**；`install-targets` 变为
     `local=2.5.2 action=none`；界面「版本落后」标签与【更新】按钮消失（按钮计数 0）。
  5. 回归：claude / codex / pi 三行的按钮规则与版本显示未受影响。

## 5. 备注

- 本次同时把**行首版本号**改为优先显示 provider health 的最新值（安装目标面），
  而非能力投影的旧值 —— 后者只在点「核验」时刷新，会让用户以为更新没生效。
- 同批清理：旧逻辑装出来的 `~/.npm-global`（915MB，含 claude/codex/pi 三份陈旧副本，
  不在 PATH）已删除；PATH 上生效的仍是 fnm 前缀里的那三份。
