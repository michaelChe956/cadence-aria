**环的真实形态**（agent 核到）：`WI-004(gateway) depends_on WI-003(frontend)` 与两仓 `change_order`（gateway 在前）冲突 → 自动边 WI-004→WI-003 + 显式依赖 WI-003→WI-004 → 成环。

**为什么「点确认」必然再失败**：`close_human_gate(Approve)` → 静态资格 → CAS `Running` → **立即重跑编译** → 只有 durable `Confirmed` + phase `Completed` 才算确认。**没有「跳过编译放行」分支** → 候选编译不过时，确认是死路。

**为什么「看不到报错内容」**：编译诊断原先只落在 timeline node 的 `summary`，且是**机器话**（哈希 id `work_item_1284b6…_003/_004`）；`…` 是前端展示省略（不是 Rust 截断）；`final_compile_prepare_failed` 是 plain `?` 站点，**不写** `policy_diagnostics`（现场实测长度 0）→ 门卡上什么都拿不到。
