## F-A 待处理列表把「状态」当成「待办」（owner 截图：租约活跃 + 旧代绑定）

### 现象
待处理抽屉「需要人工处理」下出现两条**不需要人动手**的条目：

1. **租约活跃，自动链等待中** — `lease active; automation keeps waiting (lease coding_attempt_3681bce5…)`，无任何按钮。
2. **存在旧代绑定（只读可查）** — `5 previous binding generation(s) kept read-only`，带「去换代」按钮，但当前绑定有效时是空转。

### 证据
- `src/web/plan_confirmed_info.rs:398-420`：后端把两种租约处置**都**推成等待项——
  - `LeaseDisposition::ActiveWait` → kind `lease_wait`，`actions: vec![]`（**无动作**，语义是"到期自动恢复"）
  - `LeaseDisposition::DeadNeedsTakeover` → kind `lease_takeover`，`actions: vec!["confirm_takeover"]`（**真需要人**）
- `src/web/plan_confirmed_info.rs:507-540`：`generation_history` 的触发条件是
  `history.previous` **非空**，**不判断当前绑定是否有效**；固定 `actions: ["rebind"]`、`next_phase: "rebind"`。
- 现场（`project_0001/issue_0001`）：enrollment `enabled=true`、rev 17；当前绑定 `binding_version=6`
  → plan/session `97eb9c83-…-f5d423168c02`，**两者均存在**；5 条旧代
  （`618ea4e54c0c / af5eaacd76ab / 08d8f4099819 / 6d3bae1da6a4 / 1bd27808bb45`）的
  plan/session 已被单 plan 级联删除（plans 目录只剩当前 1 个）→ 旧代只剩只读审计痕迹。
- 现场 attempt：`3681bce5` = `created / prepare_context`（从未 started）；`4ce6f4d7` = `running / coding`（真在跑）。

### 影响
待处理计数被"自动等待"与"只读历史"灌水，owner 分不清哪些"不点就过不去"。

### 建议改法（待 owner 裁定）
1. `lease_wait` 移出「需要人工处理」，归入「自动等待中」（可显示到期时间），**不计入待处理数**；
   `lease_takeover` 保留在待处理。
2. `generation_history` 仅当**当前绑定的 plan/session 不存在**才保留为待办 + 「去换代」；
   否则降级为只读信息（折叠/详情）。
3. 待处理计数只算"真需要人决策"的一类。

## F-B 「查看全部 WI」入口形态：现在是跨页导航 + 主页抽屉，期望同页弹窗（owner 截图 + 原话）

### owner 原话
> "这个查看全部 WI 的弹窗不对，我期望弹窗是在【Coding Attempt】页面的弹窗，不是主页的抽屉。"

### 现状链路（文件:行号）
- `web/src/pages/CodingWorkspaceGroupProgress.tsx:95-104`：按钮「查看全部 WI」
  （`data-testid="plan-coding-open-overview"`），未接线时不渲染。
- `web/src/pages/CodingWorkspacePage.tsx:242-247`：透传 `onOpenPlanOverview(groupPlanId)`（planId 取 `store.workItemGroupId`）。
- `web/src/router.tsx:176-182`：`openPlanOverview` = `seedWorkbenchOverlayAddress(...)` +
  `navigate({ to: "/workbench", search: { overlay: "plan-overview", planId } })`
  → **离开 Coding Attempt 页、跳到主页、由主页抽屉承载总览**。
- `web/src/router.tsx:192-196`：`onBack` 复用同一函数 → 返回也跳主页抽屉。

### 为什么这是问题（不止形态）
- **离开本页 = Coding 页 WS 断开 + 全局 store reset**（UI-1 硬约束的前提：
  `useCodingWorkspaceWs` 地址变化即断连 reset）。用户点一次「查看全部 WI」，
  就丢掉当前 attempt 的运行上下文/滚动/门状态，回来还要重连重建。
- 设计原文（`cadence/designs/2026-10-16_技术方案_UI四条改动_v1.0.md` §1）要求
  "Issue 工作台为背景，宽抽屉承载总览↔详情"；owner 现在的期望是**在 Coding Attempt 页内用弹窗承载总览**，
  即把"背景"从工作台换成 Coding Attempt 页——属对已拍板终态的**修正**，需 owner 明确。

### 建议改法（待 owner 裁定，暂不动）
- 在 `CodingWorkspacePage` 内加本地 state 打开 **modal**（复用 `DialogShell` / `useModalBehavior`，
  或 UI-1 已建的 `WorkbenchOverlayDrawer` 壳），内嵌 UI-1 拆出的 `CodingPlanOverviewView`
  （已含 `PlanCodingFinalConfirm`），**不导航、不建第二套 store、不双挂载**。
- 组件归属：总览视图在两个宿主（工作台抽屉 / Coding 页 modal）复用同一数据源
  （`usePlanCodingProgress`），避免双份轮询；同页只允许一个实例。
- `onBack` 是否也改为同页返回/或保留跳主页抽屉，需 owner 一并裁定。
- 若采纳：UI-1 的"总览在 workbench 抽屉"定位需要记为**双入口**（工作台抽屉保留 + Coding 页 modal），
  还是**改为只在 Coding 页**，也要 owner 定。
