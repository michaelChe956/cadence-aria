## ⑧ ⚠️ 载体收窄口径（controller 2026-11-03 实施期裁决，实施者务必先读）

**`single_repository` 的前端渲染：保留只读，不删。**

**错误来源**：块1 Plan 片4 的跨块协调段写「块3 片3 **删** `single_repository` target 分支」，我据此给 B3S3 的派工单也说「你要删的就是它」—— **那是错的**。

**正确口径（块3 Plan 专责原文）**：

```
块3 Plan :529  片 3｜enrollment 载体收窄（方案 A：只收窄发起侧 + legacy 投影保留）
块3 Plan :541  直接删变体 ⇒ 老单仓 enrollment 从「单仓 repo_x」退化为「target 未知」… 这是**行为回归**
块3 Plan :547  carrierTargetFromEnrollmentTarget → single_repository 映射为 null
               ⇒ 调用方禁用重新开启/提交并提示「需重建为逻辑代码库授权」；不得静默降级、不得猜 LC
块3 Plan :556  `enrollmentTargetLabel` 的 `case "single_repository"`（:533-534）**保留渲染**（legacy 只读）；
               只在提交 Enable 的路径禁用 + 提示；只动这两处，不碰 :404-408 文案面与 SubmitErrorState
块3 Plan :557  `WorkItemPlanOptionsDialog.target.test.tsx` 的 :151/:319 legacy 展示用例**保留**
               （改为「legacy 投影仍渲染、但不可提交」）
块3 Plan :588  T3.1 legacy 投影仍渲染「单仓 repo_x」，Enable 提交被禁用并给出提示
块3 Plan :592  T3.5 终止记录 target 为 single_repository → 重新开启禁用 + 提示
```

**四条裁决依据**：
1. 块3 Plan 是该改动的**专责 Plan**；块1 Plan 只是跨块协调时的**转述**。
2. 块3 Plan 的**切片标题本身**就是「方案 A：只收窄发起侧 + legacy 投影保留」。
3. Rust 侧删的是 **`RepositoryRouting::Legacy` 枚举变体**（19 文件 / 32 处出现点）；前端 `single_repository` target 渲染是**存量数据的只读展示** —— 删掉会让存量单仓授权**退化成「target 未知」，丢失信息**。
4. 契约上：**单仓入口下线 ≠ 单仓数据不可见**。

**⇒ 仍然照删的是** `AutomationCarrierResolution::SingleRepository`（`src/web/handlers/support.rs:210-215`，Rust 侧载体判定下线）。
**⇒ 仍然禁删的是** `EnrollmentTarget::SingleRepository`（`types.rs:31-33`）与 `RepositoryTargetKind::SingleRepo`（`repository_routing_types.inc.rs:151-152`）。

块1 Plan 的错误描述已派单更正（`2026-11-03_波B载体收窄口径更正_v1.0.md`）。
