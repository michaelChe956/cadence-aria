## 1. 改写口径（契约，未自创）

`RepositoryRouting` 现仅两态：`Logical` / `FailClosed`（`Legacy` 变体由 B3S1 删除）。逐处判定规则：

| 原 `Legacy` 处形态 | 处置 | 理由 |
|---|---|---|
| **构造点**：`resolve_for_issue(...)? == None` 时构造 `Legacy` | 改 `RepositoryRouting::unbound_issue()`（= `FailClosed { TargetMissing }`，稳定码 `repository_routing_target_missing`） | `None` = 无 LC 归属且无 legacy 别名 record 的**旧数据/无归属** → 契约要求改 FailClosed，不新造错误码 |
| **匹配臂**：`load_for_issue` / `classify` 结果上的 `Legacy { .. } => ...` | 删除该臂；原 Legacy 语义（旧单仓回退）不再存在，无归属落入既有 `FailClosed` 臂（fail-closed） | 变体删除后该臂不可达；保留即编译错误。FailClosed 臂已存在且语义即「不静默回退」 |
| 仅被 Legacy 臂使用的 helper / 绑定 / import | 一并删除（clean cutover） | 变体删除后成为死代码 |

⚠️ 行为变化是机械合并的**必然结果**（不是额外设计）：无归属 issue 以前走单仓 legacy 回退，现在一律 fail-closed。
