# 阶段 D Task 7：跨仓执行全链路可观测性核查

- 核查日期：2026-08-14
- 范围：聚合初始化、聚合规划、coding admission、spawn 前复验、按仓 push、ReviewRequest、evidence 查询，以及 REQ-COD-03 历史 shared-worktree migration inconsistent 路径。
- 核查原则：不调用真实 Provider；只接受 fail-closed 关键失败路径的最小 `tracing` 补点；已有 durable operation/audit/journal/role-run-event 不重复造日志。
- 结论：**4 个原先无 tracing 且没有同路径事件落盘的关键失败面已补最小 tracing；补后零缺口。**

## 1. 核查方法

### 1.1 检索与结构化阅读

先执行 `codegraph init`（当前 worktree 已初始化），再用 `codegraph explore` 建立聚合初始化、admission/spawn/push/evidence 的跨文件关系；对目标 Rust 文件使用 `ast-grep outline` 定位函数，再以 `rg` 做精确矩阵盘点。

主要检索：

- `rg -n --glob '*.rs' 'tracing::|audit|role_run_event' .`
- `rg -n --glob '*.rs' -e 'tracing::(trace|debug|info|warn|error)!' -e 'append_role_run_event' -e 'append_evidence_audit' -e 'GatewayRunAudit' -e 'ReviewRequest' src tests`
- `rg -n 'tracing::|append_role_run_event|record_entry_outcome|finish_failed|append_evidence_audit|LegacySharedWorktreeMigration' src/product/logical_codebase src/product/coding_attempt_store src/product/coding_workspace_engine src/web/handlers src/web/workspace_ws_handler`

### 1.2 缺口判定标准

将关键失败路径分为两类：

1. **已有可查询事实**：失败会写 durable operation failure、`role_run_event`、git journal/entry、ReviewRequest 或 `evidence-audit.jsonl`，即使没有 `tracing` 也不算缺口。
2. **必须补 tracing**：fail-closed 错误返回处既没有 `tracing` 输出，也没有审计/事件落盘；这会使线上仅凭 API 错误无法定位拒绝原因。

因此，本核查只补以下 3 类点：coding admission 组合入口拒绝、gateway validate/spawn 复验阻断、legacy shared-worktree migration inconsistent。没有做日志框架重构、结构化字段全面改造或 Provider 接入。

## 4. 修复决策与边界

已采用最小补丁：仅 3 个关键失败面增加 `tracing::warn!`，不引入依赖，不改日志框架，不改错误码/HTTP 映射/事件 schema，不调用真实 Provider。日志字段只包含 project/issue/attempt 或 project/error 等低基数定位信息；不会记录 token、prompt、源码或 stderr 大文本。

仓库没有 `tracing_test`/专用 subscriber 的既有测试设施，且本任务只要求核查型交付；因此未新增脆弱的日志文本断言。行为测试沿用既有 fail-closed 触发路径，证明新增日志所在分支真实可达：

- `combined_admission_entry_fails_closed_for_logical_attempt_without_snapshot`
- `logical_plan_validate_failure_is_reported_by_handler`
- `legacy_shared_worktree_migration_rejects_malformed_or_identity_inconsistent_records`

## 5. 自审

- 范围：仅可观测性最小补点 + 两份报告，无真实 Provider、无日志框架重构。
- 安全：不输出 evidence token、provider prompt、源代码内容；error 采用现有 Display，字段为稳定错误上下文。
- 一致性：push/ReviewRequest/evidence 等已有 durable 证据未重复写 tracing；GatewayRunAudit 仍只表达成功启动，失败不伪造成功记录。
- 迁移：`inconsistent` 集中构造器覆盖 malformed、scope、identity、redirect、journal、repository record 等所有已有不一致错误路径。
- 残余风险：日志输出依赖运行时 tracing subscriber 配置；若宿主不配置 subscriber，warn 不可见，但 durable 失败证据仍按原有路径保留。token 无法反查 attempt 的 evidence 拒绝没有 attempt 分区可写，这是既有边界而非本 Task 扩大范围的理由。

## 6. 核查后结论

**N=4 个关键无日志失败路径已补；补后零缺口。** 跨仓执行主链路具备“成功审计 + 失败 durable 事实/事件 + 必要 tracing”三层可观测性，满足 WP6 可观测性核查契约。
