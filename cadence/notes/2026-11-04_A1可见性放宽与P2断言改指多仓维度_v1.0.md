## 二、P2：断言从 issue 维改指多仓（仓）维度

### 根因

```
块3（commit fd0b9a8）删掉了 IssueSharedWorktreeRoute::Legacy 臂
⇒ 引擎只按 attempt 冻结快照里的 logical repository 读写【仓维】shared worktree 记录
  （shared-worktrees/{repository_id}.json）
⇒ 而这批用例的【锁事实】建在 issue 维 ⇒ 断言永远不成立
```

**这不是产品回归**：fail-closed 是块3 有意为之；这是块3 任务 3 的改写清单命令
自带 `grep -v '/tests/'` 导致**测试夹具从未被列入范围**的遗留缺口。

### 改动（issue 维 → 仓维，只改锁事实的存放维度与断言读取维度）

```
tests/it_product/product_coding_workspace_engine/part_01.rs   （+132/−80）
tests/it_product/product_coding_workspace_engine/part_12.rs   （+48/−8）
```

```
· 仓维键里的 logical repository 取 attempt 冻结快照的 logical_repository_id
  （= 夹具权威的 member_id），与引擎 route_issue_shared_worktree 同口径
· part_12 的 group_attempt_waiting_for_final_confirm 改为
  【权威先建 + attempt 带冻结快照 + 锁事实建在仓维三元键上】
  ⇒ 权威先建 ⇒ project 分配为 project_0001（否则 attempt 落盘会抢走它）
· 语义不变：谁持锁 / 锁何时释放 / 脏工作区是否阻断 —— 全部继续被断言住
```
