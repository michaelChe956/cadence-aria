## 2. 异步作业生命周期 / 4 家并发 / 逐项进度

```
POST …/capabilities/revalidate-all
  → require_logical_codebase 守卫
  → start(): 4 个 item（status=running, started_at=created_at）写 <job_id>.json（durable）
  → tokio::spawn(run(job))            ← 立即返回 202 {job_id, status:"running"}（零探针等待）
        run(): join_all(4 × run_provider)          ← 四家真并发
               tokio::time::timeout(1800s, …)      ← 总预算
               超时 ⇒ mark_unfinished_timeout()（未完成项 → timeout，作业 completed）
        run_provider(): (revalidate)(project, lc, provider).await → classify_outcome → apply_item
        apply_item(): 写锁内重读作业 → 替换该 provider 的 item（updated_at 刷新）
                      全部终态 ⇒ status=completed + finished_at
GET …/capabilities/revalidate-all/{job_id}
  → read_job（归属校验）→ {job_id, status, …, results[]}
  → 不存在 ⇒ 404 capability_revalidate_batch_job_not_found
```

- **创建**：只有 `start()` 建作业；`new()` 不写文件、不跑探针（T6.8 断言目录不存在）。
- **轮询**：GET 直读磁盘 ⇒ 刷新/新实例均按 `job_id` 续读；终态仍可读。
- **完成**：四家全终态 ⇒ `completed`。
- **失败**：单家失败**不**让整批失败（该家 `failed` + 原因，其余照常，作业仍 `completed`）。
- **超时**：未完成项 `timeout` + `job_deadline_exceeded`，已得结果不被覆盖（不谎报已确认）。
- **4 家并发**：`.map(|provider| async move { … })` → `futures_util::future::join_all(…)` 一次性同时轮询（不是 `for` 逐家 `await`），外层 `tokio::time::timeout`。每家内部仍走既有单家 `revalidate`（其自身逐 action 串行，语义未改）。T6.2 用 `(start,end)` 时间戳断言窗口重叠，`#[tokio::test(flavor = "multi_thread", worker_threads = 4)]`。
- **逐项进度数据结构**：`results[]`（顺序固定 = `claude_code, codex, pi, kimi_code`），每项 `{provider_type, status, reason, detail, version, started_at, finished_at}`。
