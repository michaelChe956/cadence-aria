### P1-4｜`gates.rs` 零余量死结（已改，**本次最关键**）

**原问题**：`gates.rs:1001` 是 `EnrollmentError::Conflict { current_revision }` 的穷举模式；该文件 **1436/1436 ⇒ 零余量**。

**关键实测（rustfmt 1.10.0）**：仓库 `rustfmt.toml` 只设 `style_edition = "2024"`，`max_width` = 默认 100，但 `use_small_heuristics` 默认下 **struct 模式内容上限 = 18 字符**：
- `{ current_revision }` = 14 字符 ⇒ 单行（现状）；
- `{ current_revision, .. }` = 20 字符 ⇒ **被拆成 3 行 = +2 行 ⇒ 门禁必红**。

因此「同行加 `, ..`」**不是**净 0；controller 提供的「新增独立变体」方案也**不成立**（`gates.rs` 的 `match` 无 catch-all，加变体 ⇒ 非穷举 ⇒ 仍须加臂 ⇒ 仍增行）。

**采用解法（已写进 §3-F，实测净 0 行）**：

```rust
ref err @ EnrollmentError::Conflict { .. } => ProductStoreError::Conflict {
    kind: "enrollment_command_ledger",
    id: format!("current_revision={:?}", err.conflict_revision()),
},
```

- `{ .. }` 内容 2 字符 ≤ 18 ⇒ 模式单行（整行 83 字符），arm 体仍 3 行 ⇒ **整臂 4 行不变**；
- 配套新增 `EnrollmentError::conflict_revision()`（`src/product/models/automation.rs`，561/1200，+约 7 行）；
- `ProductStoreError::Conflict.id` 字符串**逐字不变**（同一个 `Option<u64>`，同一个 `{:?}`）。

**硬约束已写入 Plan**：`gates.rs` 只许同处替换 2 行、MUST NOT 加行/加注释/改 `kind` 字面量；交付须 `wc -l` = 1436 自证；该文件收口时纳入 Step 2 行数自检。
