## 1. 诊断通道怎么造的

### 1.1 为什么原来看不见错误（结构性盲区）

1. engine 的 `EngineEvent::Error` 只经 `engine.event_tx` **单播**给
   `WorkspaceSessionManager::spawn_event_router` 持有的**唯一** receiver
   （`src/web/workspace_session/manager/mod.rs:445` 建的 `mpsc::channel::<EngineEvent>(64)`）。
2. router 的 `match event` **没有 `EngineEvent::Error` 分支**
   （`src/web/workspace_session/router.rs:178-360` 逐臂核对：ProviderRunRequested /
   HumanGateOpened / ArtifactBatchUpdate / ChoiceRequest / ChoicePendingChanged /
   LcResumeRecoveryChanged / HumanGateClosed / TimelineNodeUpdated …）⇒ Error 事件被 router 直接丢弃。
3. 失败回执另走 outbound：router 在**无 attachment** 时造一次性出站通道
   `mpsc::channel(1).0` 并**立即丢弃 receiver**（`router.rs:186-197`）
   ⇒ `outbound.try_send(...)` 静默失败（`TrySendError::Closed` 被忽略）⇒ 错误文本无处可取。

⇒ 结论：**无订阅者场景下 provider 启动失败原因没有任何可见出口**（不只本用例，生产「无 WS 连接」窗口同样不可见）。

### 1.2 造的通道（临时诊断，已按纪律删除）

`WorkspaceEngine.event_tx` 是 `pub(crate)` 字段（`src/product/workspace_engine/types.rs:878`）⇒
在**夹具层**把它换成 tee 通道，再把事件转发回 manager 原 `engine_tx`
（router 仍能收到 `ProviderRunRequested`，行为不变）：

```rust
// —— TEMP DIAGNOSTIC（诊断通道，诊断后删除）——
let (diag_tx, mut diag_rx) = mpsc::channel::<EngineEvent>(256);
let forward_tx = manager.engine_tx();
{
    let engine_arc = manager.engine();          // 具名借用（临时值上 await 会 E0716）
    let mut engine = engine_arc.lock().await;
    engine.event_tx = diag_tx;
}
tokio::spawn(async move {
    while let Some(event) = diag_rx.recv().await {
        if let EngineEvent::Error { message } = &event {
            eprintln!("[DIAG] EngineEvent::Error: {message}");
        }
        let _ = forward_tx.send(event).await;   // 回灌 router
    }
});
```

> 踩坑记录：首版写成 `manager.engine().lock().await` → **E0716**（临时值借用跨语句）
> ⇒ 全树 `cargo test --locked --lib` 编不过，挡住其他 worker。已改为具名借用
> `let engine_arc = manager.engine(); let mut engine = engine_arc.lock().await;`，
> 并已 IRC 通报「编译恢复」。**该临时段在拿到错误原文后已整段删除**（见 §3.3）。

## 2. 真实错误原因（原文）

诊断通道打出的原文，逐字：

```
[DIAG] EngineEvent::Error: provider_gateway_adapter: ProviderExecutionFailed: provider command exited unsuccessfully
provider stderr (last 67 bytes): streaming provider validated start is not supported by this adapter
```

（对应 stdout：`[aria-broadcast] provider run requested without attachment; spawning with throwaway outbound session=workspace_session_0001`
⇒ **run 确实被 spawn 了**，失败发生在 provider 启动调用点。）

### 2.1 判读：缺的**不是** gateway 准入事实，是夹具 provider 替身的能力

- 前 5 项准入事实（LC 权威 / durable capability 记录 / 恒健康 availability gate /
  真 git 成员 checkout / 成员语言规则）**全部已过**：错误发生在 gateway
  `start_validated` 调用点**之后**，说明 validate → capability 分格门 → policy artifact
  → cwd 权威早门 → spawn 前复验（policy revision/digest、capability version/dialect/
  snapshot ref、projection digest、resume fingerprint、config digest、canonical cwd、
  target 复验、availability）**均已放行**。
- 错误文案 `streaming provider validated start is not supported by this adapter` 是
  `StreamingProviderAdapter::start_validated` 的 **trait 默认实现**返回值
  （`src/cross_cutting/streaming_provider/mod.rs:1410-1424`）：

  ```rust
  /// 默认返回 unsupported，仅供未接入 validated 路径的 adapter 显式拒绝;
  /// **不得**回调裸 `start`(raw `start` 仅保留单仓 direct)。
  async fn start_validated(
      &self,
      _input: crate::cross_cutting::session_launch::ValidatedStreamingProviderInput,
      _cancel: CancellationToken,
  ) -> Result<ProviderSession, ProviderAdapterError> {
      Err(ProviderAdapterError::execution_failed(
          None, String::new(),
          "streaming provider validated start is not supported by this adapter", 0,
      ))
  }
  ```

- LC gateway 的 streaming 启动**唯一**经 `start_validated`
  （`src/product/logical_codebase/provider_gateway.rs:1806-1811`，Task 7/1b 起 validated trait 是唯一分发口）。
- ⇒ 缺的**那一项准入事实**在**夹具层**：夹具 provider 替身只实现裸 `start`，
  没有实现 validated 启动入口 ⇒ 被 trait 默认实现恒拒 ⇒ provider 零启动。
- ⇒ **不是实现缺口**，**不需要改实现**（未向 Main 申请实现改动授权）。

### 2.2 其他候选为何不是它（逐一排除）

| 候选 | 排除依据 |
|---|---|
| provider trust 记录 | `requires_workspace_trust` 只对 `Codex \| KimiCode` 成立（`src/product/logical_codebase/provider_trust.rs:924-926`）；本例 provider = `ClaudeCode` ⇒ trust 门根本不触发 |
| policy locator receipt 链 | `policy_locator` 只在「有 finalized receipt 且 artifact 非自举桩」时冻结（`provider_gateway.rs:1513-1531`）；夹具无 receipt ⇒ 该段整体跳过，spawn 前也不会重读 locator 正文 |
| worktree 身份 | 聚合根 target 已 canonicalize 通过（`ProductionPolicyTargetResolver::resolve_aggregate_target`），且 spawn 前复验的 canonical cwd / cwd_authority / target 复验三关均未报错 |
| duty 合同装配 | `bind_author_execution_contract` → `freeze_provider_execution(Author × HostCoding × AuthorToolPolicy::author_v1())` 在权威装配矩阵内无失配（`src/cross_cutting/provider_execution.rs`） |

## 3. 补了哪一项准入事实（改前 → 改后）

### 3.1 改前（替身只有裸 `start`）

```rust
#[async_trait::async_trait]
impl StreamingProviderAdapter for HeldStartProvider {
    async fn start(
        &self,
        _input: StreamingProviderInput,
        _cancel: CancellationToken,
    ) -> Result<ProviderSession, ProviderAdapterError> {
        self.starts.fetch_add(1, Ordering::SeqCst);
        let (event_tx, event_rx) = mpsc::channel(1);
        *self.event_tx.lock().unwrap_or_else(|p| p.into_inner()) = Some(event_tx);
        let (command_tx, _command_rx) = mpsc::channel(1);
        Ok(ProviderSession { native_session_id: None, events: event_rx, commands: command_tx })
    }
    async fn run_streaming(&self, _input: &AdapterInput, _cancel: CancellationToken)
        -> Result<mpsc::Receiver<StreamChunk>, ProviderAdapterError> {
        unreachable!("workspace runs use start")
    }
    // ← 没有 start_validated ⇒ 落到 trait 默认实现 ⇒ 恒拒
}
```

### 3.2 改后（补 validated 启动入口，转发到同一裸 `start`）

```rust
    /// LC gateway 启动面走 `start_validated`（validated launch 唯一入口，
    /// raw `start` 仅保留单仓 direct）；trait 默认实现恒拒
    /// 「streaming provider validated start is not supported by this
    /// adapter」⇒ gateway 零启动。本夹具 provider 只实现裸 `start`
    /// ⇒ 拆出 input 后与裸 `start` 同路径转发（与
    /// `src/web/coding_ws_handler/tests/gateway.rs::SwappableProvider`
    /// 同型）。
    async fn start_validated(
        &self,
        validated: crate::cross_cutting::session_launch::ValidatedStreamingProviderInput,
        cancel: CancellationToken,
    ) -> Result<ProviderSession, ProviderAdapterError> {
        let (input, _launch) = validated.into_parts();
        self.start(input, cancel).await
    }
```

**语义未变**：`starts` 计数、事件端扣留（run 挂起不完成）、`active_run` 断言窗口
全部与改前一致；**断言原文逐字未动**。
