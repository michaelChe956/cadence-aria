### 6.2 核心链路（按 BCD 交付顺序）

1. **成员登记（WP1/REQ-REG）**：创建 project → 批量登记 2-3 个本地已 clone 仓 → 验证 manifest 导入/目录扫描/预检分类/幂等/单项重试；登记阶段成员主 checkout 零 git 副作用。
2. **聚合初始化（WP2）**：触发聚合初始化 → 5 个稳定 step（machine_skills/aggregate_preflight/pre_check/rule_and_mcp_config/openspec_and_examples）→ 验证不对成员仓 git 提交推送；进度条前端可见；中断恢复。
3. **聚合索引（WP3）**：聚合索引建立 → `.aria/aggregate` 资产发布 → stale 后 sync；CodeGraph 查询跨成员命中。
4. **聚合规划（WP4/B）**：多仓 issue → Story 跨仓生成（aggregate_codebase=Some）→ Design 带 change_order → WorkItem 按仓拆分带 target → 无 target 时 blocker 呈现。
5. **多仓 coding（C-1/C-2）**：各 WorkItem 在自己仓 worktree coding（同仓串行/异仓并行）→ Codex 被 gateway 阻断（danger-full-access）→ Claude 可跑（需 managed settings 配置）。
6. **每仓交付（C-3）**：coding 完成 → 每仓独立 branch/commit/push + ReviewRequest → push 失败 partial 呈现 + RetryPush 重推 → Issue 完成聚合三态。
7. **指针发布（C-5）**：逻辑代码库页「发布指针」→ 每仓 `aria-pointer/<repo>/<pid>` 分支 + AGENTS.md/CLAUDE.md 标记块 → ReviewRequest（owner_kind=pointer_publication）→ 冲突人工 → revoke 撤回。
8. **跨仓证据检索（C-4）**：coding 会话中（或直接 curl）`POST /api/evidence-query`（token 在 worktree `.aria/evidence-token`）→ 查其他成员仓符号 → 预算 429 → 审计 jsonl 落盘。
9. **增量发布提示（D-T8）**：登记新成员后 PointerPublicationPanel 出现「建议增量发布」提示 → 点击触发 Incremental。
