### ① `coding_workspace_engine::tests::*`（provider_failure_recovery 47 / group_completion_authority 34 / code_review_triage 14 / provider_start_persistence 11 等，合计 235）

## 8. 捷径验证（派工单 ④）

**问题**：簇 A「issue 归属 `legacy_logical_codebase_id(project)` 但从不建 LC」是否只需在**项目级根**补 manifest + selection（不必建 `logical-codebases/{lc_id}/` 子树）？

**结论：机制上成立（判定依据见下），但只覆盖「纯解析」路径；凡经过 provider 启动/租约/完成链的用例仍必须补 `target_snapshot`（仓维），所以整体工作量只省掉一部分。**

依据（代码级，已逐行核对）：
1. `store::lc_scope_root`：`lc_id == legacy_logical_codebase_id(project)` ⇒ 落回 `logical-codebase/`（项目级根）；`LogicalCodebaseStore::new` 与该 `for_lc` 指向同一根 ⇒ 夹具原本写在项目级根的 manifest/member/checkout/selection 全部可见。
2. `ProjectStore::get` 幂等调用 `LogicalCodebaseStore::new(..).migrate_legacy(project)`；只要 `logical-codebase/manifest.json` 存在，迁移会生成别名 LC record 并复制子树 ⇒ `resolve_logical` 直读的 `logical-codebases/<legacy_hash>/record.json` 存在，不会 `NotFound{kind:"logical_codebase"}`。
3. `resolve_logical_target(None, ...)` 在**无成员**时走聚合根分支（root = `manifest.provider_context_root`），不报错 ⇒ 空成员 manifest 足以让 `resolve_for_issue` 成功。
4. 但 `run_exclusion::classify_worktree_lease_for_attempt` 对**无 `target_snapshot`** 的 attempt 恒 `UnknownNeedsHuman`（`target_snapshot_missing_for_logical`）；`gates::route_issue_shared_worktree` 对无快照同样无条件 fail-closed ⇒ **捷径救不了** provider 启动/租约/完成链的用例。
5. 已加回归钉 `repository_routing_tests.inc.rs::authority_resolver_accepts_project_level_legacy_layout`（project + 项目级根 manifest/selection + 归属 legacy 别名 id 的 issue ⇒ resolver 成功 + `load_for_issue` 为 `Logical`）。
   - **第 1 次实测：红**，报 `NotFound { kind: "issue", id: "issue_0001" }`。**这不是捷径不成立，而是夹具陷阱**：`IssueCodebaseSelectionStore`（项目级）会建出 `issues/issue_0001/` 目录，而 `IssueStore::create` 的 id 由 `next_sequential_id_in_directory` **按目录数**分配 ⇒ 先写 selection 再建 issue 会让 issue 变成 `issue_0002`，与硬编码 `issue_0001` 的夹具全部错位。
   - **修法（已落）**：issue **先建**、selection 后写；探针改用 `issue.id` 而不是字面量。同一陷阱已同步修正 `LcStoryRoutingFixture::new()`（`workspace_repository_tests.rs`）的调用顺序。
   - ⚠️ **给后续簇的提醒**：凡「补 issue 记录」的夹具，必须确认 `issues/` 目录在建 issue 之前是空的，否则 id 会漂。

**因此的落法（已按此执行）**：纯解析面（`workspace_repository`、`cross_target_check`、`evidence_mediator`）→ 只补「issue 记录（+ project，若走 authority resolver）」；准入/租约/完成面 → 必须补「LC 权威 + 冻结快照」（共享夹具 `logical_test_fixture` 已就绪）。
