## 根因（代码级）

**`src/web/workspace_ws_handler/socket.rs:373` → `mpsc::channel(1)`** —— 每个 WS 连接的出站队列**容量只有 1**。

`src/web/workspace_session/router.rs:455-503`：

```rust
match sender.try_send(OutboundControl::Text(json.to_string())) {
    Ok(()) => {}
    Err(TrySendError::Full(_)) => {
        attachment.degraded = true;      // ← 降级
        self.record_degraded_enter(connection_id, seq);
        if keyframe { /* 关键帧：spawn_keyframe_delivery 有界等待投递 */ }
    }
    ...
}
```

且 `try_send_live_event` 开头：`(!attachment.degraded).then(|| ...)` → **降级后普通 live 事件被直接丢弃**。

→ 客户端一个瞬时卡顿（渲染 32K 字符流 / GC / 事件循环忙）就足以让 `try_send` 返回 `Full` → 降级 → **role run 推进所依赖的 live 事件被丢** → provider 明明跑完的一轮被判 failed。

**证据**：`socket.rs` 在该批次**未被修改** → 容量 1 是既有设计，与 2026-10-30 交付的两个 change（面向 owner 的人工门呈现、写范围归属前置校验）**无关**（二者分别在 review 阶段与 plan 候选校验阶段，不碰 WS 出站通路；且本次失败发生在 author_run，早于 review）。
