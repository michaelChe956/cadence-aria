## 一、结论

### 1. 收口值沿用 resolved, 不新增 closed
现有枚举只有 Open/Resolved, 读侧按 Open 筛选; 增 closed 只制造无谓 schema 兼容面。
依据 src/product/coding_attempt_store/gate.rs:24-40,383-417。收口=resolved + resolved_action + resolved_at + 归档 resolved/。

### 2. 当前代码与现场分开归因
- 普通动作处理器已调用 resolve_blocked_gate_with_action(blocked_gate.inc.rs:207-216)
- code_review_provider_interrupted 专用恢复链也会解决门(failed_review_recovery.rs:216-245)
- **当前可证缺陷**: 专用链调用无 action 的 resolve_blocked_gate(recovery.rs:563-581, 尤其 :577), resolved_action 写成 None; 门模型无 resolved_at
- **次要缺陷**: 关闭实现幂等/崩溃窗口不足——只认根目录文件、无统一 gate mutation 锁, 归档写成后删根记录前崩溃则根目录仍 open(gate.rs:453-481 对照建门 :233-241)
- 现场永久 open 的精确入口不能凭当前源码定案: 现场 run_0003 为 trigger=Initial/无 prior/supersedes, 与当前专用链应产生的 ManualRetry+journal 形态不同; 结合 4317 自 10-13 未重启+编译 commit 未记录, **旧二进制/非专用入口是有支持的推测, 非已证根因**

### 3. 推荐修法: 一个持久化关闭实现 + 两个确定性补偿入口
1. 所有真正解决 blocked 门的动作共用有锁、可重放的关闭实现
2. retry 创建 run 首次落盘即携带 gate origin; 动作持久接受后立即解决旧门(保持 GateResolved-before-run 语义)
3. run 终态、服务启动对账对**明确关联的门**幂等补偿
4. 下一 stage 残留 open 门扫描只告警, 绝不自动解门
5. 无明确关联的旧数据: 启动只告警, 人工确认后一次性收口(action=legacy_reconciled)

## 三、关键设计

### 统一关闭原语
blocked-gate-mutations 锁内执行; 顺序: 校验→根记录写完整 resolved 事实→写归档→删根记录(崩溃后 list_open 不再投影已标 resolved 的根记录); write_json 已有 tmp+sync+rename(json_store.rs:33-65)。
幂等规则: 同代次同动作重放返回首关结果; 根已关归档未完→补齐; 归档完根仍在→清理; 异动作→冲突不覆盖审计; 身份/代次冲突→告警不吞; 都不存在→NotFound。

### 动作收口边界(全部动作)
- retry_review/retry_internal_review: admission+关联 run 持久化成功后关
- retry_coding/retry_coding_with_context: 说明落盘+admission+run 创建后关; 失败不关
- retry_group_*: 统一记录, 不虚构代表 run
- send_to_coder/manual_continue/accept_risk/abort/plan_terminated: 各自前置成功后关(plan 终止用 plan_terminated 审计值)
- 组门被替代: system_superseded 机器原因
- **provide_context 不关**(仅补材料); 非法动作零关闭零新增
- 注意: 页面「说明情况让 AI 继续」的实际动作是 retry_coding_with_context, 勿与 provide_context 混同

### run-gate 关联(gate_origin)
(gate_id, generation, action_id); 旧 run 缺 origin 按 None 解释, 不靠 stage/role/时间补猜。
克制范围: 仅三个 gate-retry 入口+create_retry_role_run 继承, 不扩全仓 50+ 通用 create; supersede_latest_role_run_and_create 需改为完整构造后首存(role_run.rs:273-297)。
终态补偿约束: 只处理 origin 精确匹配+代次相同; Completed/Failed/Blocked/Aborted 不代表审查通过, 仅补记「动作已接受」; 新 run 失败开新门, 旧 run 不批量关新门; run 终态先持久化, 补偿失败显式记录。

### 重开与迟到回调
计划修复重开(gate.rs:515-540)/恢复回滚(recovery.rs:392-404)时: 递增 resolution_generation+清空关闭字段+旧 origin 失效, 同锁内完成——防旧 run 迟到终态误关新一轮人工门。

### 启动对账
在现有 serve_web→reconcile_claimed_coding_runs_once(app.rs:708-715) 每 attempt 分诊前插入 gate-only 对账:
完整关闭事实未归档→自动补; open 门与 origin/journal 接受事实一致→幂等补偿; 已归档缺 action 且 journal 可证 retry_review→按证据补; 无关联/冲突/旧版本→只告警; 仲裁中的门不抢先关。

### UI 一致性
不加点按钮立即隐藏的前端特例; 以持久化事实修复为主(动作关闭成功→新 snapshot→UI 按 pending_gates 重建, 测试锚 web/src/hooks/useCodingWorkspaceWs.actions.test.tsx:111-158)。驾驶舱事项投影 open 门不过滤(coding_attention_info.rs:317-337), 修复后自然一致。
REST 事实: post_coding_gate_response 存在(coding.rs:700-704,844-892), 走普通 handler, interrupted 会被 requires_reservation 拒绝——**不得删该保护来打通**; 新增 REST 专用恢复非必须项。(scout「无 REST」否定结论与双源物理证据不符, 已仲裁不采信)

## 四、现场归因指纹(供部署后比对)

- 专用恢复链指纹: journal+ManualRetry+prior/supersedes+GateResolved
- 普通 retry 指纹: trigger=RetryReview+归档含动作
- 普通执行重入: 可产生 Initial run(本次现场形态)
- 缺动作专用关闭指纹: 归档 resolved 但 action=null(与根 open 是两个缺陷)
- 部署标记要求: 记录构建 commit/二进制校验值/启动时间; 运行版本以实际二进制为准, 不以 worktree HEAD 冒认

## 五、风险与兼容
读取侧零语义变更; 历史时间不伪造; 现存现场不自动收口(重启只告警); 一次性人工维护经统一关闭服务, action=legacy_reconciled 附确认来源, 不新增 UI/API; 关闭≠业务通过; 并发沿用 recovery arbitration→attempt/mutation→短 gate 锁方向, 不持锁跨 await。
