### 1.1 C5 实现说明（判据 / 禁用态 / 存量单仓项目看到什么）

**判据**（`createIssueGate`）：

```ts
if (!selectedProjectId) return { canCreate: false, disabledReason: "先在左侧选择一个 Project" };
if (!logicalCodebases.some((codebase) => (codebase.member_count ?? 0) > 0)) {
  return {
    canCreate: false,
    disabledReason:
      "该项目还没有含 active 成员（member_count > 0）的逻辑代码库：请先「添加代码库」→ 登记成员仓 → 完成冷启动，再新建 Issue",
  };
}
return { canCreate: true, disabledReason: null };
```

- `member_count` 语义 = 该 LC 的 **active 成员数**（后端按 manifest active 计，缺 manifest → 0）⇒ 「必须存在含 active 成员的 LC」= `logicalCodebases.some(c => (c.member_count ?? 0) > 0)`。
- **不再看 `repositories`**：存量单仓项目（项目级 `/repositories` 非空但没有合格 LC）不再放行。

**禁用态与原因提示**：
- 按钮沿用 `IssueLifecycleWorkbenchHeader` 既有的 `disabled` + 灰色禁用样式（`disabled:border-line disabled:bg-panel-muted disabled:text-ink-muted`）——**不是隐藏按钮**；
- header 槽内同时渲染可见原因（`data-testid="issue-create-disabled-reason"`，`text-xs` 弱化色），即上面那句 `disabledReason`。**不是静默禁用**。

**存量单仓项目现在看到什么**：`新建 Issue` 灰掉 + 旁边一句「该项目还没有含 active 成员（member_count > 0）的逻辑代码库：请先「添加代码库」→ 登记成员仓 → 完成冷启动，再新建 Issue」。测试断言：`toBeDisabled()` + 原因含「逻辑代码库」+ 点击不出现 `新建 Issue` 对话框。

**为什么没改 `IssueLifecycleWorkbenchHeader.tsx`**：它不在本片独占清单内。原因提示渲染在 View 传给 `header` 的插槽里（同一 banner 内、紧跟按钮行）。若要 `aria-describedby` 硬关联按钮，需要给 Header 加 prop —— 见 §5 C4。
