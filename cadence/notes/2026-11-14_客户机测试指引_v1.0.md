# 客户机测试指引（v0.1.6-rc1）

> 面向：拿到候选版的客户同学（macOS Apple Silicon）。
> 目的：装上候选版 → 把「装到哪 / 为什么没生效 / 索引是否正常」一次性看清楚；有问题按下面的口径回传，不用反复截图。
> 背景：本次修了「点【安装】没效果」「更新装错副本」「聚合索引报 JSON 解析失败」「页面一直轮询接口」四件事，并新增了只读诊断接口与结构化日志。

---

## 一、测试前请先做两件事

1. **备份索引库**（重要，约 3 GB）：上游 `codegraph` 打开库时可能触发 schema 迁移（上游行为，非本次改动引入）。
   ```bash
   cd <你的聚合根>
   du -sh .codegraph
   cp -R .codegraph .codegraph.bak.$(date +%Y%m%d-%H%M)
   ```
2. **确认磁盘余量**（安装 + 索引会用到空间）：`df -h <你的聚合根>`。

---

## 二、安装候选版

```bash
npm i -g @cadence-aria/cli@0.1.6-rc1
```
或直接从 GitHub Release 取二进制（不想走 npm 时）：
`https://github.com/michaelChe956/cadence-aria/releases/download/v0.1.6-rc1/aria-darwin-arm64.tar.gz`（附 `SHA256SUMS` 可校验）。

> 说明：候选版在 npm 上的 `latest` 标签目前仍指向稳定版 0.1.5，所以**必须写全版本号**安装；正式版 0.1.6 发布后就不用了。

---

## 三、启动后先取一份「诊断快照」

```bash
PORT=$(cat <你的工作区>/.aria/web-endpoint)
curl -s "http://127.0.0.1:$PORT/api/providers/diagnostics" | jq .
```

这份 JSON 分 9 段，请重点看这几处：

| 段 | 字段 | 说明 |
|---|---|---|
| `runtime` | `os` / `arch` / `platform_target` | 必须是 `darwin` / `arm64` / `darwin-arm64` |
| `codegraph` | `sdk.available` / `node.available` / `node.source` / `platform.package_present` / `platform.foreign_packages` | `package_present=false` 或 `foreign_packages` 里有别的平台包 ⇒ **codegraph 装错了平台包** |
| `install_targets[]` | `cli_available` / `local_version` / `install_prefix` / `prefix_bin_on_login_path` / `prefix_bin_on_service_path` | `install_prefix` = 实际装到哪；`prefix_bin_on_login_path=false` ⇒ **你的终端里敲命令会找不到**（此时用界面上的「暴露到终端 PATH」按钮） |
| `path_overlay` | `registered[]` / `effective_path_segments[]` | 平台实际用的命令查找序 |
| `install_jobs[]` | `failure_code` / `failure_message` / `manual_command` | 最近几次安装/更新的结论；`manual_command` 可直接照抄执行 |
| `aggregate_index` | `state` / `last_failure` | `active` = 索引可用；`degraded` + `last_failure` = 看失败原因 |

**日志**同时落在 `<你的工作区>/.aria/logs/aria.log`（追加写，不轮转）与 stderr。常用检索：

```bash
grep 'chosen_prefix='    <ws>/.aria/logs/aria.log | tail -5   # 装到了哪个前缀
grep 'failure_class='    <ws>/.aria/logs/aria.log | tail -10  # 为什么失败
grep 'still_old='        <ws>/.aria/logs/aria.log | tail -5   # 更新后仍是旧版
grep 'payload_bytes='    <ws>/.aria/logs/aria.log | tail -5   # 聚合索引清单大小
```

## 四、三类常见问题的自查口径

| 现象 | 先看 | 常见原因与处置 |
|---|---|---|
| 点了【安装】还是「未安装」 | `install_targets[].cli_available` + `install_jobs[].failure_code` | `network` ⇒ 镜像/网络；`permission` ⇒ 前缀不可写（可用 `manual_command` 手动装）；`package_not_found` ⇒ 包名/源问题 |
| 平台说装好了，但**我终端里敲命令找不到** | `prefix_bin_on_login_path` | 这是「装到了平台看得见、但你的终端 PATH 看不见」的位置 ⇒ 点界面上的**「暴露到终端 PATH」**（只建一个软链，不改你的 shell 配置） |
| 聚合索引仍 degraded | `aggregate_index.last_failure` | `codegraph_files_output_truncated` ⇒ 清单超出抓取上限（聚合根太大）；`codegraph_missing` ⇒ codegraph 不可用（看 `codegraph` 段） |

## 五、问题回传清单（三样就够，不用截图）

1. `curl -s "http://127.0.0.1:$PORT/api/providers/diagnostics" | jq .` 的**完整输出**（已含结论与路径，不含密钥）。
2. `<ws>/.aria/logs/aria.log` 里**最近 200 行**（含 `chosen_prefix=` / `failure_class=` / `payload_bytes=` 那几行）。
3. 三条命令的输出：
   ```bash
   codegraph --version
   node --version
   sw_vers
   ```

## 六、已知风险与边界

- **macOS 未在上游 CI 覆盖**：本次全部验证在 Linux 容器与 CI 完成；darwin-arm64 的 codegraph 平台包由诊断接口的 `codegraph.platform` 段现查（`package_present` / `foreign_packages`）。
- **codegraph 打开索引库可能触发 schema 迁移**（上游行为）⇒ 第一节的备份请务必做。
- **安装会调整平台的命令查找序**（把安装目录纳入 overlay）⇒ 这是修复所需，但会让「你终端 PATH」与「平台 PATH」不同；诊断接口的 `path_overlay.effective_path_segments` 能看到差异。
- **日志不轮转**：回传后建议手动清一次 `<ws>/.aria/logs/aria.log`。
- **候选版不走 npm `latest`**：正式版 0.1.6 发布后，`npm i -g @cadence-aria/cli` 即可。
