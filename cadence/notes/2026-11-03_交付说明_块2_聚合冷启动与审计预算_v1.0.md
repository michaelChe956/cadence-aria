## 1. 这个 change 做了什么

**一句话**：把「新机器上聚合冷启动三步全红」这一条链，从**provider 写死** → **能力核验无指引** → **stderr 恒空** → **codegraph 卡死** → **审计预算被存量压垮**的五个咬合点一次性拆开，做法是「**先立契据形状与唯一文案来源，再把有歧义的行为改成可判定的事实**」，而不是给每个报错单独打补丁。

覆盖缺陷（`proposal.md:4`）：B-1 provider 写死 / B-2 能力未核验无指引 / B-3 stderr 恒空 / B-4 codegraph 卡死 / K-1 累计记成单文件 / K-2 `.git/` 被计入 / K-3 预算偏小且调不动。

### 能力清单（proposal 目标 → 交付形态）

| # | 目标（`proposal.md` §目标） | 交付形态 |
|---|---|---|
| 1 | **provider 自动选择**：按 `pi > kimi code > claude code > codex` 逐个探测，全程只用一个，结果落盘可查 | 选择器 `provider_selection.rs`（两层判据 L1/L2、不创建 operation）+ durable `operation.provider_selection` 候选表 + provider 走 **request** 而非 driver 字段 ⇒「重试不换人」是结构性保证 |
| 2 | **能力未核验可行动**：区分「未核验」与「真实拒绝」 | `capability_rejection.rs` 三态分类器 + 三个对外稳定码 + 逐家候选表（`action_hint` 为可执行动作） |
| 3 | **失败面不空洞**：说清「是什么问题 + 怎么操作」，机器码降为次要行 | `failure_copy.rs` + `failure_copy_table.inc.rs` = **唯一文案来源**（86 条码表 / 六条布局规则 / 七个对外稳定码 / 五字段全必填 / 未知码中性兜底） |
