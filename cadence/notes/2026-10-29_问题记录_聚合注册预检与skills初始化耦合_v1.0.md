## 二、根因（代码证据）

### 2.1 预检要求「聚合根必须干净」

`src/product/logical_codebase/registration_preflight.inc.rs:160` `reject_owned_root_files`：

```rust
for name in ["CLAUDE.md", "AGENTS.md", ".aria"] {
    let path = canonical_root.join(name);
    if !path_exists_for_preflight(&path)? { continue; }
    // 窄豁免：receipt 证明的 AGENTS/CLAUDE 必须仍是普通文件、无 symlink 且字节与旧 snapshot digest 一致
    if name != ".aria"
        && let Some(expected_digest) = proven_entry_digests.and_then(|proven| proven.get(name))
        && proven_entry_matches(&path, expected_digest)? { continue; }
    return Err(preflight_error("aggregate_root_ownership_conflict", …));
}
```

`validate_common` 的六项检查：project_id 合法 / 根存在且是目录 / **根不是 git 仓** / 成员在根内且非嵌套 worktree 不重叠 / **根目录无 AGENTS.md·CLAUDE.md·.aria** / 根不与其他项目 LC 根重叠。

### 2.2 而聚合初始化（bootstrap）本身就是在聚合根上跑一整套 Cadence-skills 初始化

`src/product/logical_codebase/root_recipe_receipt_types.inc.rs:1-10`（注释即实测落盘清单）：

> 按真实 Claude Code（2.1.283）四命令 recipe **在空的非 Git canonical root** 的实测落盘证据逐项冻结：
> `/pre-check` 写 `.agents`/`.claude`/`.kimi-code`/`.pi`/`openspec`；
> **`/rule-config` 写 `AGENTS.md`/`CLAUDE.md`/`.claude/rules`/`.agents/rules`/`.omp`/`cadence`**；
> `/mcp-configuration` 写 `.mcp.json`/`.codex`/`.gitignore`；
> `/project-rules-examples` 写 `cadence/project-rules/examples`。
> 聚合 artifact 只允许落在 `.aria/aggregate/**`。

`ROOT_RECIPE_ALLOWLIST` 把 `AGENTS.md` / `CLAUDE.md` / `.claude` / `.agents` / `.omp` / `.codex` / `.kimi-code` / `.pi` / `cadence` / `openspec` / `.mcp.json` / `.codex` / `.gitignore` 全部列为**该 recipe 会在根上写**的合法产物。

### 2.3 回执只覆盖 `AGENTS.md` → `CLAUDE.md` 永远无法豁免

- `root_recipe_receipt_types.inc.rs:40`：`pub const ROOT_RULE_ENTRY_FILE: &str = "AGENTS.md";`
- `coordinator_preflight.inc.rs` 的 `proven_digests_from_receipt` 只取 `entry.path == "AGENTS.md"`
- 回执本体落在状态根 `<state>/…/aggregate-recipe-receipts/<operation_id>.json`，由聚合 bootstrap 生产

→ **任何根目录含 `CLAUDE.md` 的项目，预检永远拒绝，无路可走**（即使第一次侥幸走通，重跑也过不去）。

### 2.4 耦合点（设计错误）

| 阶段 | 端点 | 真实前置条件 |
|---|---|---|
② 预检 + ③ 提交注册（登记成员） | `.../registrations/preflight`、`.../registrations` | 只需：根存在、非 git、成员在根内且不重叠 —— **不需要根干净** |
④ 聚合初始化（写 skills / 合成政策） | `.../bootstrap`（独立动作） | 需要：根干净（`/rule-config` 要写 `AGENTS.md`/`CLAUDE.md`）|

**代码把 ④ 的前置条件塞进了 ②**：预检（②）检查了 bootstrap（④）的前提 → **已初始化过的项目永远过不了②**。

而「已做过 Cadence-skills 初始化」**必然**产出根目录的 `AGENTS.md` + `CLAUDE.md` + `.claude/rules/` + `cadence/` + `openspec/` → **必然撞死**。

### 2.5 次要缺陷：错误信息被前端吞掉

- 服务端 `details.reason` 已给出人话（"already contains user-owned …/CLAUDE.md; move or merge it…"）
- `web/src/api/client.ts` 的 `normalizeApiError` 保留 `code` + `details` ✅，`ApiRequestError extends Error` 只塞 `message`
- `web/src/components/lifecycle/LogicalCodebaseRegistrationWizard.tsx:24`：
  ```ts
  function formatError(reason: unknown, fallback: string): string {
    return reason instanceof Error ? reason.message : fallback;   // ← 丢掉 details.reason
  }
  ```
  → UI 只剩一句 `aggregate root preflight rejected`

### 2.6 另一处相关缺口：软删后无 UI 恢复入口

- 后端有 `POST /api/projects/{pid}/logical-codebases/{id}/restore`（`delete_soft` 是软删 + 墓碑；恢复保持 id、从 Released 复活成员登记；source 被其他 LC 占用则 409）
- **前端未接**：API 客户端无 restore 函数、无「已删除」列表、删除后 id 也不可见
- 删除确认框却写着「可经恢复端点还原」→ 说了能还原但没给入口

## 三、修复方向（待 owner 拍板）

| 优先级 | 改动 | 收益 |
|---|---|---|

## 五、备注：`.aria/` 是什么（owner 问）

aria 的**状态根/数据根**（非项目代码）：`projects/<项目>/`（issue/story/design/plan/work-item/session/coding-attempt/代码库成员）、`state/`（台账、provider 健康、销账留痕、聚合回执）、`web-endpoint`、`schema.json`、`aggregate/**`（聚合 artifact 唯一落点）。
预检拒绝根目录含 `.aria`，是因为那意味着**根目录自身已是 aria 状态根**（嵌套状态根冲突）。
