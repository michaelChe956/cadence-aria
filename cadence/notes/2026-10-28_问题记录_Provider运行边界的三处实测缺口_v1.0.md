## 二、缺口 ①：自查环境时用 `find` 广扫家目录

实际命令（reviewer 侧）：

```sh
find /home/michaelche -maxdepth 6 -type d -name 'playwright-core' 2>/dev/null | head
npm root -g 2>/dev/null
ls "'$(npm root -g) 2>/dev/null | head -50
```

实测结论：Playwright **已装**（全局 `@playwright`，路径
`~/.local/share/fnm/node-versions/v24.17.0/installation/lib/node_modules`；另有 npx 缓存
`~/.npm/_npx/e41f203b…/node_modules/playwright-core`）。

问题：

1. **引号错位导致整条命令空跑** —— `ls "'$(...)` 里多一个单引号，使 zsh 报
   `unterminated double quote`（退出码 2），三段都没执行。属于**命令构造质量**问题，非产品缺陷。
2. **扫描面远大于必要** —— `find /home/michaelche -maxdepth 6` 会穿过 `~/.codex/sessions`（**provider 自身
   的历史会话目录**）、`~/.claude/` 以及**其它项目目录**。当前只列目录名（`-type d -name`）未读内容，
   尚未越线；但按现有边界纪律，「旧 run 目录」本身就在禁读清单里。
3. **顺序反了** —— 应先读仓库既有 E2E 怎么跑（`tests/it_web/` 的用例与启动脚本）直接复用；自查环境应用
   一步到位的写法：

   ```bash
   node -e "console.log(require.resolve('playwright-core'))"   # 直接解析
   which playwright && playwright --version                   # 看 CLI
   ls "$(npm root -g)/@playwright"                             # 全局包详情
   ```

**建议**：把「自查依赖/工具优先用 `require.resolve` / `which` / `npm ls -g --depth=0`，禁止广扫家目录」
写进作者侧运行边界纪律。

## 三、缺口 ②：「本轮 run 的上游工作区」与「历史 run 目录」无法区分

reviewer 实际读了：

```
cd /tmp/aria-work-item-split-engine-t8 && ls projects/project_0001/issues/issue_0001/provider-runs | tail -5
cd /tmp/aria-work-item-split-engine-t8/projects/.../provider-runs && for d in ws-project_0001-issue_0001-split-ru…
```

`/tmp/aria-work-item-split-engine-t8/.../provider-runs` 是 **split 引擎为本轮 run 建的 per-run 工作区**
（其中确有 `ws-project_0001-issue_0001-split-ru…` 这类本轮 run 目录），**大概率不是历史残留**；
但它的路径形态与「历史 run 目录」无法区分，而今天的边界规则只写了一句
「禁止使用其他会话或历史运行的产物与日志」→ provider 只能靠猜。

**根因**：边界块只告知了「本轮身份」与「暂存目录」，**没有告知「本轮 run 的上游工作区/产物目录在哪里」**；
于是「读本轮上游产物」与「读历史 run 残留」在 provider 眼里是同一类动作。

**建议收口**（与 scratch 同思路）：在边界块里**显式给出本轮 run 的上下文目录**（provider-runs / plan 工作区 /
checkpoint 目录等），把「读上游产物」变成**有明确授权路径的动作**；不在清单内的其它 run 目录才是越界。
这样边界规则才可判定，而不是靠 provider 自觉区分。
