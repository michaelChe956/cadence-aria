### manifest 写入机制（既有通道找全后的结论）

- 既有通道：`LogicalCodebaseStore::save_manifest`（`store.rs:653`）——带 `validate_manifest_project`（项目一致性）、身份校验（`logical_codebase_id` 不得变）、`validate_membership_revision`（修订单调 + 至多 +1；**同修订、member_ids 不变的回写合法**）。生产代码此前**零调用方**（155 处调用全在测试），注册链写 manifest 走的也是它（`registration_coordinator.inc.rs:875-879` attach 推 member_ids + revision）。
- 决定：**复用 `save_manifest` 通道 + 新增一个 store 侧聚焦方法** `LogicalCodebaseStore::set_active_aggregate_index`，不另起 JSON 直写。因 `store.rs` 已 1177/1200 行贴近 `it_core::large_file_guard` 门禁，方法落在新 include `store_manifest_pointer.inc.rs`（45 行，沿用 `store_purge.inc.rs` 的 impl 续篇先例，文本包含可访问私有辅助）。`store.rs` 本体只 +1 行 include。
- 方法体：在 `.manifest-registration.lock`（与注册链同一把 manifest 读-改-写锁）下 `load_manifest → set 指针 → bump updated_at → save_manifest`；指针已指向该世代时幂等直返（不空刷 `updated_at`）；manifest 缺失 → `NotFound` 显式失败。

## ② 回写时机/内容 + 与 patrol 读口径的一致性

- **时机**：`apply_index` 内 `replace_active` 成功返回之后（此刻该世代已是 durable active）——不是 rebuild 请求入口。回写失败显式失败（经 `From<ProductStoreError>` 映射 `aggregate_index_store_error`），静默成功会留下「索引可用但证据链恒 503」的假象。
- **内容**：`active.aggregate_index_id`（刚落盘的 active 世代 id）。旧世代由 `replace_active` 翻 Superseded，指针只认最新 active。
- **与 patrol/lc_partition.rs:148 一致**：patrol 读口径 = `active_aggregate_index_id` 非空 `Some` → 产出 `DanglingTargetKind::AggregateIndex` 引用 → 检查该 id 的记录文件在册可解析（缺失即 dangling）。回写指向的正是 `replace_active` 刚落盘的 active 世代 → 引用恒可解析，**一致**。
- **并发/锁序**：回写发生在聚合索引 single-writer 锁内再取 `.manifest-registration.lock`；注册链持 manifest 锁时只做身份/成员/检出记录，从不反向获取聚合索引锁 → 无死锁面；与 attach 的 membership_revision 推进经同一把锁串行化，互不丢更新。

## ⑥ concerns

1. **「active 世代」定义与 patrol 口径**：patrol 只做「该字段引用的记录文件可解析」（dangling 巡检），**不校验引用指向的记录状态**。我的写入 = 最新 active 世代 id，记录必在册 → 恒一致。存在一个**既有**语义角落（本次未改动、与所有读方现状一致）：`degrade_last_known_good`/freshness 会把 active 世代翻 Degraded/Stale 而指针保持原值——patrol 仍判可解析；evidence 的 pin 语义本就允许读 superseded/stale 记录（`is_index_stale` 另行上报漂移）。若 owner 希望「指针只指向 Active 状态记录、降级即摘指针」，属新语义，需裁决。
2. **门禁余量**：`store.rs` 1178/1200、`evidence_mediator.rs` 1158/1200——`large_file_guard` 余量已小，后续该目录改动建议优先走 include/拆分先例。
3. **锁序前提**：回写锁序 = 聚合索引锁 → `.manifest-registration.lock`，依赖「注册链持 manifest 锁期间不做聚合索引操作」——当前代码成立；注册链若未来引入索引操作需复核锁序。
4. `store_manifest_pointer.inc.rs` 为新文件（未跟踪状态），合并时需随改动一并纳入版本控制。
