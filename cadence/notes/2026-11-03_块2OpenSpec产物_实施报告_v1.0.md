## 4. 两个新能力的挂载理由

| 新能力 | 为什么独立成一个 capability（而不是折进 `non-interrupt-repository-bootstrap`） |
|---|---|
`logical-codebase-audit-budget` | 预算口径（元数据差分法）、`.git/` 跳过、流式读是**跨流程的独立契约**：它约束「审计快照」这一对象本身（预算上限、分组统计、成员仓归属、超限失败面），被聚合初始化预检消费，且将来任何触发 root recipe 审计的入口都自动受约束。折进 bootstrap 会让一个 4 条 requirement 的口径契约淹没在 bootstrap 的流程性 requirement 里，也难与「recipe 写到 allowlist 之外」的既有检测能力分开表述。 |
`provider-cli-installation` | 安装/更新是**跨 provider 且跨能力**的能力（4 家 provider + codegraph），被「能力探针那块」消费，并被块3 票3「一键核验全部」**复用**（技术方案 §3.6.5 / §3.6.6 / §7.1 连锁要求）。独立成 capability 后，块3 只需引用 REQ-PCI-02 / REQ-PCI-05，无需在块3 的 delta 里重定义安装源、镜像、版本判定与作业机制。 |

两个新能力在 `openspec/specs/` 下均**不存在**（已核对目录清单），因此是 ADDED，不与既有 capability 命名构成近义重复。既有 capability 命名（`non-interrupt-repository-bootstrap` / `logical-codebase-aggregate-index` / `provider-capability-revalidation`）全部复用，未另造近义名。
