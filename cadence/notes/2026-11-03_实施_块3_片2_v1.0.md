## 0. 一句话结论

前端「单仓」入口已全部下线：`AddCodebaseDialog` 不再有模式 radio /「继续添加单仓库」按钮，`CreateLifecycleIssueDialog` 下拉只列逻辑代码库且提交必带 `logical_codebase_id`，工作台不再有单仓创建接线（含随之变成死代码的 `CreateRepositoryDialog` 挂载）。**`base_branch` 字段保留、语义未动、多仓路径恒传 `null`。** 定向验收命令全绿（`tsc -b` / `build` 的红是**块2 片4** 的在途改动，见 §5）。

## 6. concerns（需 controller / owner 知悉）

- **C1｜「多仓库逻辑代码库」radio 随整个 `mode` 状态机一并删除（回滚成本约 6 行）。** 设计 §3.1.2「保留多仓库选项」指的是**保留多仓能力**，不是保留选择器 —— 单仓选项按 REQ-REG-16 必须下线后，该 radio 只剩一个选项，成为噪音 UI。多仓表单恒为默认，单仓效果由**多仓 + 1 成员**路径覆盖（与片4 的「1 成员与 N 成员同路径」不变量一致）。**controller 裁定：不回滚。**
- **C2｜物理仓创建（`CreateRepositoryDialog`）的前端入口随单仓入口下线 —— 本轮不做「登记向导内创建成员仓」。** 该弹窗唯一 opener 就是被删的「继续添加单仓库」按钮；REQ-REG-16「MUST NOT 提供单仓代码库的创建入口」+ owner 决策 #4「单仓相关的能去掉都去掉，不保留死代码」⇒ 工作台里已成死代码的挂载已删（`repositoryDialogOpen` + 3 个 handler + 3 个 api import + 组件 import）；**组件本体、后端 `POST /repositories`、仓库初始化作业端点全部保留未动**（将来要恢复或换入口不必重建）。「登记向导内创建成员仓」属新增能力，**本轮不做**。
  **核实（读代码，非推测）：登记流程能「引入」物理仓，但不能「凭空创建」** ——
  - 能引入：`registration_coordinator.inc.rs:806-830` 的 `allocate_and_attach_member` 为成员分配 `physical_repository_id`（`format!("repository_{uuid}")`）并落 member / checkout / identity 记录（`:780-855`）；注释明写「the registration chain never routes through the feature-enabled `RepositoryStore::create`」⇒ 磁盘上**已存在**的普通 git 仓无需先有 `repos.json` 记录即可登记为 LC 成员。
  - 不能凭空创建：候选判定要求路径**已存在**且是 git 仓 —— 缺失 → `RegistrationCandidateState::Missing`、非 git → `NonGit`（`registration.rs:46-57`）；eligible 判定前先 `git_probe(&canonical_path, &["rev-parse", "HEAD"])`（`registration_coordinator.inc.rs:590-640`），dirty 仓走 `NeedsAttention`、重复/嵌套走 `Duplicate`/`Nested`。
  - 对照旧流程：`RepositoryStore::create`（`repository_store_parts/create.inc.rs:2-53`）同样 `canonicalize_repo_path(&input.path)` —— **旧流程也只引用已存在的本地路径**，并不凭空造仓；差别在于旧流程额外写 `RepositoryRecord`（repos.json）并跑 provider 初始化流水线（`repository_store/initializer.rs:73-146`）。
  - ⇒ **结论：预期收敛** —— 独立物理仓创建入口下线后，物理仓统一从登记流程进入（能力无损：登记流程能引入既有 git 仓为成员），组件与后端端点保留可逆。「登记向导内创建成员仓」本轮不做。
  - （观察，非本片范围）旧流程附带跑的 **per-repo provider 初始化**（skills / rule-config / MCP）在登记链路上没有对应调用；该能力的现役形态在**块2**（聚合初始化的 provider-turn 步骤 `aggregate_initialization.rs:90-93` + 块2 片7A/7B 的 provider 安装/核验）。
