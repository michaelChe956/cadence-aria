## GAP-F（新实证）：gateway 评审路径硬拒 Pi/KimiCode，enrollment 却允许该组合

- 证据：`src/product/logical_codebase/provider_gateway.rs` `ProviderRef::from_provider_name` 对 `Pi | KimiCode | Fake` 直接返回 `UnsupportedCapability(PROVIDER_UNSUPPORTED_FOR_GATEWAY_LAUNCH)`，仅 ClaudeCode/Codex 可经 gateway 启动；而 workspace review（`drive_review_session_via_gateway`，logical_provider_gateway 存在时必走）对 reviewer 一律过 gateway。
- 后果：enrollment/`start_generation` 可自由配置 `author_provider=pi, reviewer_provider=kimi_code`，但 evaluate 相位 reviewer 启动**必然**失败（timeline_node_005「Provider 启动失败」，零重试停等）。capability store 无 kimi/pi 记录、无 HTTP 写入面，配置层与 gateway 能力层脱节。
- 本链处置：经产品面 WS `provider_select {role:"reviewer"}` 人工切换为 claude_code（prepare_context 相位合法）后重驱成功——证明缺口在能力映射，不在评审链本身。

## GAP-G（新实证）：Evaluate 相位 provider 失败后无人工恢复入口（死局）

- 证据：reviewer 于 Evaluate 相位启动/运行失败（provider 级失败）→ `finish_failed_run` 回 Open/PrepareContext，但 durable `single_candidate_phase` 停留 `Evaluate`：
  - `rearm_failed_single_candidate_for_start_generation` 只认 `Failed` 相位（no-op）；
  - `reserve_single_candidate_provider_start` 只认 `Prepare|Generate`（InvalidRecord）；
  - `retry_interrupted_run` 只认「连接断开」+ AbortedByDisconnect 标记（INTERRUPTED_RUN_NOT_RECOVERABLE）；
  - 编排器 admission 对 `Open+Evaluate` 恒 WaitingForHuman，但人工侧无任何入口可解除。
- 偶然解锁通路（非设计）：re-arm 尝试在 reserve 失败时副作用 `persist_single_candidate_terminal_phase(Failed)`（`run/single_candidate.rs` 入口臂），随后第二次 re-arm 才真正重驱。该通路依赖失败副作用，应视为缺口而非特性。
- 建议：evaluate 相位 provider 失败应落 durable Failed（或提供显式 review 重驱/降级入口）。

## GAP-H（新实证，环境层）：推理网关账号池耗尽无健康分诊

- reviewer=claude_code 会话正常启动并通过 gateway 校验后，模型调用被推理网关 503「No available accounts」拒绝（103.236.76.196:9527）→ Provider 运行失败 → 再次触发 GAP-G 死局。
- provider-health 只探测 `--version` 可用性，不覆盖模型调用健康；评审链对瞬时 503 零重试直接停等。建议：评审 provider 失败分类中区分环境瞬态与确定性错误，或提供恢复卡重试。
