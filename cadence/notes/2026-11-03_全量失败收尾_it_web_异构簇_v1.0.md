## 2. 断言迁移逐条（旧钉什么 → 新钉什么 → 契约哪一条支持）

1. **part_17 legacy_attempt_target_snapshot_remains_none → migrated_issue_http_create_never_leaves_target_snapshot_none**
   旧钉：legacy 单仓创建后 attempt.target_snapshot==None。新钉：迁移后 HTTP 创建恒冻结快照（Some + logical_repository_id==manifest 成员 + capture_source==coding_attempt_create）。契约：per-repo-coding-execution REQ-COD-02「创建、恢复、重放一律使用冻结快照；快照缺失 fail-closed」+ web-runtime-repository-routing REQ-ROUTE-01（无归属/不成对一律 FailClosed，`attempt_target_snapshot` 两态实现 Logical→Some / FailClosed→Err ⇒ None 分支经 HTTP 不可达）。被测对象消失型迁移（同 #3 裁决口径）。
2. **part_21 logical_work_item_without_target_repository_is_blocked_over_http**
   旧钉：422 repository_routing_target_missing + reason "has no target repository"。新钉：409 repository_routing_kind_mismatch + details.id 含被拒绝的物理仓 repository_0002（点名「拒绝回落的对象」，红线本质「缺 target 不得回落 primary/legacy」未变）。契约：REQ-ROUTE-02「全入口统一分流，MUST NOT 自带单仓分支或回退物理仓」+ resolve_work_item_repository 的 C4 Task 2 kind 门设计文（「单仓请求命中 LC 归属 issue 的 kind_mismatch（fail-closed，不再回退 legacy 物理仓——REQ-ROUTE-02）」，在任何 target lookup 之前）；且 routing spec 明文把 repository_routing_target_missing 定义为「(Some,None) 数据不完整」的路由状态码，不覆盖本形态。
3. **part_01 rejects_second_active_work_item_on_same_repo_shared_worktree（改名）**
   旧钉：409 issue_worktree_active。新钉：409 repo_worktree_active。契约：REQ-COD-03 同仓串行场景 + repo_locks.rs:204 稳定码定义（仓维记录的锁事实）。
4. **part_09 concurrent_..._repo_worktree_lease（改名）/ part_10 retry_reconciles（owner 前缀）**
