## 8. 本会话教训（写给下一个 controller）

1. **edit 工具对本仓文件出现过静默写盘丢失**（`large_file_guard.rs` 首改消失）→ 关键改动改后立即 `git status`/`md5sum` 复核，必要时用 `python` 原子写+立即 commit
2. **并发 `git add` 竞态**：worker 的「核对暂存区」与「commit」之间窗口会被 sibling 的 add 侵入（6aace390 混入 3 文件）→ 裁定为不 reset 但如实登记；**同文件多线须 IRC 互认区间 + `git add -p` 逐 hunk**
3. **`cargo fmt` 是全仓操作**——会连带格式化并行方正在编辑的文件（本会话发生 3 次）→ 收口时统一 fmt 后**显式列文件**提交，并在提交说明写「fmt 收口」
4. **worker 的越界警觉救场**：a 线（ter-task）拒绝改 `run/single_candidate.rs` 并上报 → 才发现「只改收敛器修不到用户实际失败路径」；**尊重 worker 的范围上报，不要推它越界**
