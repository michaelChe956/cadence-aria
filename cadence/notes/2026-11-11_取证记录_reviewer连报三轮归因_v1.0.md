## 1. 三机制代码锚点（2026-11-12 实测行号）

### ① F5-B 防打转闸门：`single_candidate_consecutive_repeated_finding_count`

- **锚点**：`src/product/workspace_engine/review/routing_scope.rs:814-848`（任务书写 :815-849，为计划时点行号，实测以现码为准）；消费点 `review/routing.rs:908`。
- **判定语义**（逐行核实）：
  1. 先取会话 owner 已处置清单 `session_human_disposition_keys()`，对**当前**与**上一轮**两个 verdict 各自做处置归一（`normalize_review_verdict_for_dispositions`，finding_key ∈ 清单 → advisory；REQ-WSC-12/14）。
  2. `current_set = non_advisory_finding_fingerprints(当前)`；**集合为空直接返回 None**（advisory-only 轮不触发）。
  3. 上一轮 verdict 取自 timeline 中**最近的、非当前节点的 ReviewerRun** 持久化 detail（`.rev() + find_map`）——**只比相邻两轮**，不回看更早轮次。
  4. **只有 `previous_set == current_set`（集合完全相等）才返回 `Some(集合大小)`**；任一 finding 增、减、指纹变化即不相等 → None。
- **附加过滤（F-52，`routing_scope.rs:84-94`）**：`non_advisory_finding_fingerprints` 在收集指纹时**剔除 `identity_unstable` 的 finding**——即 unstable 域（见 ②-b）的措辞类指纹**不参与**本闸门的集合比较。
- **归一化读失败静默**：上一轮 detail 加载/反序列化失败（`.ok()?` / `?`）→ 整体返回 None（闸门静默不触发）。

### ② finding 指纹组成：`identity_for_finding`

- **锚点**：`src/product/work_item_plan_policy/fingerprint.rs:73`（`pub fn identity_for_finding(`）；主调用点 `work_item_plan_policy/classify.rs:141-146`（classify_finding 内）。三域（实测源码）：
  - **a. 稳定域**（`category=Some` 且 `contract_field` 含稳定 ID `WI-\d+|CT-\d+|AC-\d+`）：哈希 `["v2-stable", category, ID集, 尾段]`——**措辞、class、路径书写顺序均不参与**，同题异措辞 collapse 为同一身份。
  - **b. unstable 域**（`category=Some` 但无任何稳定 ID）：哈希 `["v2-unstable", category, message, field]`——**措辞参与**；同文重复仍同指纹（可检测），但被标 `identity_unstable`，策略层禁自动裁决（fail-safe 人工），且被 ① 的 F-52 过滤**不参与防打转断言**。
  - **c. legacy 域**（`category=None`）：保持既有 **class+message+field** 口径——**无 category 时措辞敏感**（任务书判断与现码一致）。
  - 另有机械定位符例外（`plan_options.` / `plan_preflight.` / `mechanical.` 前缀的 `contract_field`）：确定性投影，整体作为身份成分，不落措辞域。

### ③ owner 排除键：`computed_finding_key`（REQ-WSC-13）

- **锚点**：`src/web/workspace_ws_types/review.rs:148-154`（`finding_key_for`，唯一实现）与 `:157-159`（`computed_finding_key`）。
- **算法**：`sha256(severity.as_str() + 0x01 + message)` 取**前 16 位小写 hex**。**只含 severity 与 message 两个成分**——category / class / contract_field 均不参与。⇒ **换措辞（或换 severity）即得新 key**；该 key 同时是已处置清单（`HumanDispositionRecord.finding_key`）的存储键，也是 ① 中处置归一所用的键。

## 2. 合成三轮 verdict fixture 回放

fixture：同一底层事实「WI-001 的输出契约 CT-001 capabilities 与实现承诺不一致」，severity 恒为 `high`，reviewer 连续三轮产出实质相同、措辞微调的 finding。排除键为本 Task 当场按 ③ 的真实算法计算（sha256，非估算）：

| 轮次 | message（合成） | computed_finding_key（实测计算） |
|---|---|---|
| R1 | WI-001 的输出契约 CT-001 capabilities 与实现承诺不一致，必须补齐证据 | `a4b47652870e85d7` |
| R2 | WI-001 的输出契约 CT-001 capabilities 与实现承诺不一致，必须补齐证据（复查） | `6612a5a48e7e742a` |
| R3 | …必须补齐证据（第三次复核） | `599d5179da2bf885` |

### 回放分支 A：无 category（legacy 域）＋措辞逐轮微调 —— 三机制全部失效

- **② 指纹**：legacy 域 = class+message+field，message 变 ⇒ R1/R2/R3 三条 finding **指纹互不相同**。
- **① 闸门**：R2 与 R1 比、R3 与 R2 比，`previous_set == current_set` 均不成立（集合元素指纹变了）→ 两次比较都返回 None → **防打转闸门三轮都不触发**。
- **③ 排除键**：三 key 互不相同（上表实测）——owner 即使在 R1 后把 `a4b47652870e85d7` 写入已处置清单，R2/R3 的新措辞产生新 key，**归一化匹配不上**，finding 仍 actionable。
- **回放结论**：该形态下「reviewer 连报三轮」与代码行为**完全一致**——没有任何一个机制把三轮折叠或阻断。

### 回放分支 B1：无 category 但措辞逐字稳定 —— 机制 ① 生效

- ② 指纹不变 ⇒ R2 与 R1 的非 advisory 指纹集合相等 ⇒ ① 在**第 2 轮**即返回 `Some(1)`（第 3 轮同理）——防打转闸门生效，连报会被判定为「同一指纹复现」。

### 回放分支 B2：category=Some 且 contract_field 含稳定 ID（稳定域）＋措辞微调 —— ① 可触发，但 ③ 被绕过

- ② 稳定域**不看措辞** ⇒ 三轮指纹相同 ⇒ ① 的集合比较成立（该 finding 未被处置归一掉时）→ 闸门触发。
- **但 ③ 的排除键只看 severity+message** ⇒ 措辞微调 = 新 key：owner 曾排除 R1 措辞的，R2/R3 不再命中清单，finding 回到 actionable 并继续进入集合比较。
- **更尖锐的组合**（①与③身份域不一致的直接后果）：若 R1 的 finding 已被 owner 处置（key `a4b…` 在清单），R2 措辞微调后 key 为新值、不在清单 ⇒ 归一化后 **previous_set 为空而 current_set 非空** ⇒ 集合不相等 ⇒ ① **也返回 None**——已被 owner 裁定过的事实以新措辞复活，且防打转闸门不认。

### 回放核对结论（哪一机制生效）

- 措辞稳定（任意域）或稳定域带稳定 ID 时：**机制 ①（F5-B）是唯一能把「重复报告」判定出来的机制**，② 提供其指纹基础。
- 措辞逐轮漂移（legacy 域 / unstable 域）或「处置过的 finding 换措辞复活」时：**三个机制全部失效**——② 指纹随措辞变（或被 F-52 剔除）、① 集合永不相等、③ 排除键随措辞变。
- 「连报三轮」得以发生的代码路径枚举（互不排斥）：(a) 措辞漂移落在措辞敏感域（legacy / unstable）；(b) 相邻两轮 finding 集合有增减（评审面变化 ⇒ 集合不相等）；(c) 被处置 finding 换措辞复活（分支 B2 组合）；(d) 某轮 advisory-only 或 unstable-only ⇒ 集合为空/被剔 ⇒ None；(e) 上一轮 ReviewerRun 的 durable detail 加载/反序列化失败 ⇒ 静默 None。

## 3. 代码级归因结论（仅限代码级，现场根因挂起）

1. 「reviewer 连报三轮」**不需要任何机制缺陷**即可发生：只要三轮落在 §2 分支 A / (b)–(e) 任一路径，三机制按现设计就不会折叠它。这是**设计口径**（相邻两轮、集合全等、措辞敏感域、排除键只看 severity+message）的复合结果，不是单点 bug。
2. 唯一的**跨机制不一致**：② 的稳定域已实现「同题异措辞同一身份」，而 ③ 的排除键仍是 `sha256(severity+message)`（措辞敏感）⇒ **指纹判重生效的同时，owner 排除可被换措辞绕过**（分支 B2）。若 owner 决定新增「finding 身份稳定性」requirement，这是首个要对齐的点（排除键与指纹至少在稳定域应同源）。
3. 机制 ① 只比**相邻两轮**且要求**集合完全相等**——对「间隔一轮重复」或「集合微增」的重复形态天然漏判；这是任务书 10.1 ②「无 category 时措辞敏感」判断的代码级佐证与延伸。
