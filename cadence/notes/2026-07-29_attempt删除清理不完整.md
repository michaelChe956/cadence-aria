# 待立项：DELETE coding-attempts 接口清理不完整

- **日期**：2026-07-29
- **状态**：待立项
- **性质**：结构性缺陷，非实现疏漏（与 `harden-work-item-group-deletion` 同模式）

## 问题

`DELETE /api/coding-attempts/{attempt_id}` 删除一个 coding attempt 时，只删 attempt 自身数据（attempt json + 目录），**不清** `issue-shared-worktree.json` 与 coding-attempts 下的残留 lock。删完后留下指向已删 worktree / 已删 attempt 的脏记录，阻断同一 issue 重新发起 attempt。

## 实测症状

用户删掉卡住的 group coding workspace（attempt `c90db60f`）后想重试，发现：

- `issue-shared-worktree.json` 残留：`status=running`、`worktree_path` 指向**已被删除**的 `naruto/.worktrees/aria-issues/issue_0001`、`current_lock_owner_id = coding_attempt_c90db60f`（**已删的 attempt**）。
- naruto worktree 实际已删（`git worktree list` 只剩 main）。
- coding-attempts 下残留：`.coding_attempt_<id>.json.lock`、`.group-initialization-arbitration.lock`、`work-item-attempt-locks/<wi>.lock`。

结果：shared-worktree 认为有个 running worktree（锁给已删 attempt），但实际不存在。重新发起 group attempt 时 aria 读这个脏记录 → 冲突/失败。

## 根因

DELETE coding-attempts 接口的清理不完整，与 group 删除健壮化修复前**同一模式**——清理路径只清自身数据，不连带清共享产物，且要求被清理对象处于健康状态：

| 残留 | 是否清理 |
|---|---|
| attempt json + 目录 | ✓ |
| `issue-shared-worktree.json` + `.lock` | ✗ |
| `work-item-attempt-locks/<wi>.lock` | ✗ |
| `.group-initialization-arbitration.lock` | ✗ |
| `.coding_attempt_<id>.json.lock`（孤儿） | ✗ |

## 建议方案（与 group 删除健壮化同构）

DELETE coding-attempts 改为**尽力清理 + 容错**：

- 删 attempt 自身数据（已有）。
- 清 `issue-shared-worktree.json` + `.lock`（复用 `LifecycleStore::delete_issue_shared_worktree`，`harden-work-item-group-deletion` 已实现）。
- 清 attempt 残留 lock（`.coding_attempt_<id>.json.lock`、`.group-initialization-arbitration.lock`、`work-item-attempt-locks/`）。
- worktree 目录缺失时跳过 git 回滚（`cleanup_coding_attempt_workspace` 容错），不因 worktree 已删而失败——这正是 [[harden-work-item-group-deletion]] design 已知缺口一。
- 每步 NotFound=OK，绝不因缺失中断。

可与 `harden-work-item-group-deletion` 的已知缺口一（DELETE coding-attempts worktree 容错）**合并为一个 change**：两者本质都是「attempt/group 删除要尽力清理 shared-worktree + lock，不要求 worktree 健康」。

## 临时处置（已执行）

手动清理脏数据让用户能重试：

```sh
# 脏 shared-worktree（指向已删 worktree + 已删 attempt）
rm issue-shared-worktree.json .issue-shared-worktree.json.lock
# coding-attempts 残留 lock
rm coding-attempts/.coding_attempt_<id>.json.lock
rm coding-attempts/.group-initialization-arbitration.lock
rm -rf coding-attempts/work-item-attempt-locks coding-attempts/group-initializations
```

备份在 `/tmp/aria-backup-pre-cleanup-*`。plan / revisions / draft 全保留，重新发起 group coding attempt 即可。

## 关联

- `harden-work-item-group-deletion`（已完成）：group 删除健壮化，同模式（尽力清理 + 容错 + 不要求健康）。其 design 已知缺口一明确「DELETE coding-attempts 的 worktree 容错」本次不做，本笔记把范围扩展到 shared-worktree + lock 清理。
- 同源模式（清理路径要求被清理对象健康 / 清理不连带共享产物）在本仓库已出现三次：plan_store purge、group 删除、attempt 删除（本项）。
