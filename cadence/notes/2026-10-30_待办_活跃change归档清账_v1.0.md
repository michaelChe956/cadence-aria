## 口径

对每个活跃 change 的每条 delta requirement（ADDED / MODIFIED），到对应能力的
`openspec/specs/<cap>/spec.md` 里按 **requirement 标题逐字**比对。

```bash
# 复核用（逐条标题比对，不是目录存在性）
python3 - <<'EOF'
import os,re
def reqs(p):
    return {m.group(1).strip() for m in re.finditer(r'^### Requirement:\s*(.+)$', open(p,encoding='utf-8').read(), re.M)}
for ch in sorted(os.listdir('openspec/changes')):
    d=f'openspec/changes/{ch}'
    if ch=='archive' or not os.path.isdir(d): continue
    sd=f'{d}/specs'
    if not os.path.isdir(sd): continue
    tot=land=0; miss=[]
    for cap in os.listdir(sd):
        f=f'{sd}/{cap}/spec.md'; main=f'openspec/specs/{cap}/spec.md'
        if not os.path.isfile(f): continue
        mr=reqs(main) if os.path.isfile(main) else set()
        for r in reqs(f):
            tot+=1
            if r in mr: land+=1
            else: miss.append(f'{cap}/{r}')
    print(f'{ch:<46} {land}/{tot}', '← 未落: '+'; '.join(miss[:3]) if tot!=land else '')
EOF
```

## 每个 change 归档前的两道门

1. **delta 全落主 spec** —— `openspec archive <change>` 会把 delta 应用进主 spec；
   归档前须确认应用后主 spec 语义正确（尤其是 MODIFIED 类，不能把既有条款改窄）
2. **独立审查结论留痕** —— 多数 change 的 `tasks.md` 里有「归档前补独立审查结论」一项，
   需要一份独立的审查报告落到 `cadence/notes/`
