## 0. 论据的逻辑缝隙(评审前提)

1. **论据1 只证明「没有外部用户」, 没证明「没有不可信输入」**——注入的攻击源是数据不是用户: 被 review 的 diff/README、依赖 postinstall 与 mvn 插件、issue 正文、网页与 MCP 返回, 都带第三方文本进 agent 上下文; 无人值守放大(无人逐条读命令)。触发清单须按输入来源+权限面设计。
2. **论据2 是延期承诺不是现有保证**——仅当一期不堵死二期的路时可信(见第3节耦合点)。

## 3. 二期衔接

### 3.1 已核验障碍
1. 证据路由与回环绑定耦合(evidence_injection.rs:62 硬编码 127.0.0.1; app.rs:717,586 只在回环挂载)——容器内 127.0.0.1 非宿主
2. kimi terminal/fs 由 Aria 宿主执行不在 provider 进程(terminal.rs:509-536)——包容器包不住命令; 二期需 TerminalIsolation 加 Container 变体或不声明 terminal
3. 宿主 git 作用于 agent 可写树(=A5), 容器化后是唯一执行桥
4. worktree .git 指针绝对路径——容器须同路径挂载 worktree+common git dir
5. 凭据目录五家并集(PROVIDER_RUNTIME_WRITABLE_DIRS)非按 provider 最小化; HOME 重定向有现成入口(:205-208)
6. 现场 podman 用法依赖宿主路径(-v /tmp/test-m2-cache:...)
7. 「四家统一」实为三家+Codex direct(LC 两档保留), CHECK 能力矩阵有隐藏分叉, profile 文档须显式声明

### 3.2 预留项(现在便宜将来贵)
R1 控制面端点参数化(脚本收完整 URL; 挂载条件改「鉴权已启用」)| R2 宿主 git 加固(core.hooksPath=/dev/null+GIT_CONFIG_GLOBAL=/dev/null, ~10 行)| R3 启动形态单一化(8 处 spawn 收敛到 LaunchProfile: Host/Boundary/Container; spawn_with_boundary 接缝已在)| R4 保留 TerminalIsolation 抽象与 bwrap 代码(二期复用, 只改默认 profile)| R5 数据卷边界声明(可见集=worktree+git dir+scratch+缓存; 令牌/端点不进 worktree .aria)| R6 凭据按 provider 声明(替换并集, 预留 credential provider 接口)| R7 CHECK 加 runtime 字段(jdk/maven/node 版本, 待核验现有模型)| R8 缓存路径变量化($ARIA_CACHE_DIR)| R9 资源 label 约定(aria.attempt=<id>, 回收主键)| R10 网络策略字段(默认 open 只记日志)

### 3.3 嵌套容器方案
(a)宿主 socket **排除**(=宿主 root, Pillar 第一步, OpenHands 明确排除); (b)**rootless 嵌套(userns+fuse-overlayfs)推荐默认**(对齐 OpenHands docker-in-sandbox, 本机未实测); (c)sysbox/gVisor/Kata/microVM 平台化阶段; (d)控制面按 CHECK 起 service 容器——可行但易读成复活验证 runner, **需 owner 单独裁决**

## 4. 分阶段最低隔离要求

| 阶段 | 要求 | 业界对齐 |
|---|---|---|
| **A 本地自用(现在)** | 回环绑定; **Origin/Host 校验+令牌(不落盘)**; R2 git 加固; push 凭据由 Aria 宿主持有(provider 不需要 git 凭据); provider 用带额度上限独立 API key; 审计外移 agent 写域外; 仅处理自有仓库; owner 自备 $HOME 备份; 风险记录写明 ❌ 项 | 等价 Codex --yolo 前提「本机即外部边界」的书面声明 |
| **B 小团队/可信协作** | provider 切专用低权 UID 或每 attempt rootless 容器; 控制进程不与 provider 同 UID; 控制面按人鉴权; 禁 docker socket; egress 白名单; 每人独立凭据 | Codex「容器内 danger-full-access」轻量版 |
| **C 平台化** | 每 attempt 独立容器/microVM; 非特权嵌套(OpenHands 模式); 无宿主 socket; 真凭据代理代持; **fail-closed(沙箱起不来拒启动, 对齐 Devin)**; 镜像 digest 固定; 资源配额; 默认拒网+白名单; 控制面完全在沙箱外; 届时按调研第 5 条经变更提案修订 REQ-LCG-04(区分宿主特权/隔离边界内特权) | Codex 官方 Docker 指引全文 |

B 触发=T4/T5/T6/T7/T10; C 触发=T9。

## 5. 结论

**owner 约束下(单机/单用户/仅自有仓库)架构 sound**, 但依赖四条件: ①输入来源受控(论据1 真正隐含的前提) ②控制面不可被浏览器或局域网触达(**现状已不满足, 浏览器路径现在就存在, 需立即补**) ③本机无超需高价值凭据 ④一期不固化二期障碍(R1-R10, 其中 R1/R2/R4 最紧)。

风险接受记录须写入: 被注入的同 UID agent 可读凭据/外联/写持久化点, 应用层防不住(A1/A4/A11); 误操作对 $HOME 不可恢复靠备份; kimi 去沙箱后 env_clear 保留对 podman XDG_RUNTIME_DIR 是否够用未实测。

**触发清单 Top 排序**: T1 不可信内容(最可能最先) > T2 控制面暴露(浏览器路径现在就有) > T3 无人值守规模化 > T4 高价值凭据同机(不改代码就变爆炸半径) > T5 第三方 MCP > T6/T7 多人与协作者(直进 B) > T8 内网 > T9 合规(直进 C) > T10 provider 升级 > T11 异常信号(命中即升级, 不排序)。

## 补充: kimi 只关 bwrap 不够全开(6 处残留, 已核验)
