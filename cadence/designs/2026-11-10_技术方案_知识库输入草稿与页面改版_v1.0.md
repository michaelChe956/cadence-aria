## 3. 方案

### 3.1 R1：全局前置门（聚合初始化未完成 ⇒ 知识库一律不可用）

**判定口径统一到 D-3**：新增
```rust
// src/product/logical_codebase/knowledge_base/preflight.rs
pub fn aggregate_initialization_completed(paths: &ProductAppPaths, project_id: &str, lc_id: &str) -> bool
```
实现 = `LogicalCodebaseBootstrapProjector::new(paths).project(project_id, lc_id)` 的 `rules_policy` 步 `status == Completed`；**投影读不出 / IO 故障 ⇒ 判未完成**（fail-closed）。既有 `aggregate_initialization_completed`（根规则 + 政策 artifact）替换为这个口径，**不再保留两套判定**。

**门的位置**：在 KB HTTP 层做**一处**统一门（handler 入口），覆盖全部 12+ 端点；`preflight_bootstrap` / `preflight_update` 内部的旧调用改为复用同一函数，避免两套口径。

**失败面**：复用既有稳定码 `knowledge_base_requires_aggregate_initialization`，中文文案改为**可执行**版本：「需先完成聚合初始化（规则/政策）后再操作知识库」，details 带 `bootstrap_step: "rules_policy"` 与「去完成聚合初始化」的引导。

**前端**：卡片与详情页在门未过时显示同一条提示；详情页在门未过时**只读展示**并禁用保存/确认/新建等写入口（而不是让用户点了才吃 4xx）。

### 3.2 R2：两段式输入草稿 + 平台侧确认

**后端三块**：

1. **新 operation 类型** `KnowledgeBaseOperationKind::UserInput` + `KnowledgeBaseStepKind::PrepareUserInput`；
   命令 = `skill_command_prefix` + `knowledge-base-user-input`（`command.rs` 加 `user_input_command(provider)`）；
   provider turn 的 cwd = **canonical 聚合根**（skill 在目标项目根跑，成员仓是其子目录）；
   **写入面审计允许面** = `cadence/knowledge-base/user-input/**`（skill 只写这个目录；越界即 operation 失败）；
   单飞与取消沿用既有机制。

2. **「输入是否已准备」判定**：以插件模板 `cadence-init/skills/knowledge-base-bootstrap/user-input/` 为基线，
   - 9 份**全部缺失**或**全部与模板逐字相同（未填占位）** ⇒ **未准备**（需要起草）；
   - 任一份与模板不同 ⇒ 视为**已填写**（不再起草，直接进 bootstrap 校验）。
   该判定同时支撑「重新生成草稿」入口的语义（已填写 ⇒ skill 自身门禁会拒绝覆盖，平台提前挡住并提示）。

3. **确认记录（平台侧 durable）**：per-LC store，落 `knowledge-base/user-input-confirmations.json`：
   ```text
   { "<相对知识库根的路径>": { "digest": "<sha256 hex>", "confirmed_at": "<rfc3339>" } }
   ```
   - 确认请求携带客户端读到的 `digest`；服务端**重算**当前文件摘要，不一致 ⇒ 4xx `knowledge_base_user_input_confirmation_stale`（让用户刷新后再确认）。
   - 查询时逐份比对**当前**摘要与记录摘要 ⇒ 不一致即视为**未确认**（编辑后确认自动失效，无需清理记录）。
   - 记录落**平台侧 .aria**，**不写进** `user-input/`（skill 的自检要求该目录只有那 9 个文件）。

**端点**：

| 方法 | 路径 | 语义 |
|---|---|---|
| GET | `.../knowledge-base/user-input` | 列出 9 份输入文件 + 每份 `{ filled, confirmed, pending }` 状态 + 汇总 |
| POST | `.../knowledge-base/user-input/confirm` | body `{ path, digest }` 或 `{ all: true }` ⇒ 逐份/批量确认 |
| POST | `.../knowledge-base/initializations` | body `{ kind: "bootstrap" \| "update" \| "user_input", package_path?, idempotency_key }`；`kind=bootstrap` 时若输入**未准备** ⇒ 4xx `knowledge_base_user_input_required`（details 指向「生成草稿」）；若已准备但**未确认** ⇒ 4xx `knowledge_base_user_input_not_confirmed`（details 列未确认文件） |

**前端**：
- 【知识库初始化】按钮**不再区分两段**：点击 ⇒ 后端按状态决定（未准备 ⇒ 起草；已准备未确认 ⇒ 提示去确认；已确认 ⇒ 跑 bootstrap）。前端文案随之变化（按钮下的一行状态：未准备→「先生成输入草稿」；已准备未确认→「待确认 N 份」；已确认→「可执行初始化」）。
- 详情页新增**输入确认区**：列出 9 份文件（状态徽标：待确认 / 已确认 / 未填）、逐份「确认」按钮 + 「全部确认」按钮；点击某份在右侧编辑器里打开并可直接编辑（编辑后该份确认自动失效，界面提示「已修改，需重新确认」）。
- 详情页另给「重新生成草稿」入口（kind=user_input）。

### 3.3 R3：知识库页面改版（全屏工作区）

- **顶栏**（新）：左「知识库」标题 + 副标题（项目名 / LC 名，来自 bootstrap 投影的 `authority_root` 与 LC 清单）；右「返回工作台」按钮（回 `/workbench`）+ 状态徽标（已初始化 / 尚未初始化 / 前置未满足）。
- **去掉全局设置齿轮**：CockpitShell 增加**路由级沉浸模式**——当前路径命中 KB 路由时，只渲染 children，不渲染全局浮动件（设置触发器、图片创作气泡、版本更新说明浮层等），由知识库页自己占满视口。（既有路由不动；沉浸判定集中在 CockpitShell 一处。）
- **两栏自适应 + 编辑区拉满**：左文件树固定宽（可折叠），右编辑器/预览占满剩余高度（`h-full`/`min-h-0` 链路），去掉当前下半屏空白；页头/工具条固定，滚动只发生在文件树与编辑区内部。
- **视觉**：沿用仓内既有 token（`--aria-panel` / `--aria-line` / `--aria-ink-muted` / `--aria-primary`）与 `design-system/MASTER.md` 口径，不新造配色。

## 4. 非目标

- 不改 `knowledge-base-bootstrap` / `knowledge-base-update` 两个既有 skill 的契约（本次只新增对 `knowledge-base-user-input` 的调用与确认门）。
- 不做知识库文档的全文检索、不做 git 提交/发布、不做多仓各自一份知识库。
- 不改聚合初始化的任何语义（只**读**它的冷启动投影做门禁判定）。

## 5. 风险

| 风险 | 处置 |
|---|---|
| `knowledge-base-user-input` 起草依赖目标项目有 Java 或 Vue/React 形态，否则 skill 自停 | 平台把 skill 的失败原文透传（成功/失败都落 durable 事实）；失败面提示「目标项目形态不满足 skill 前置」 |
| 起草会**覆盖未填写的模板占位** | 平台在起草前明确告知「将覆盖 N 份未填写模板」，并记进 operation 输出摘要（skill 自身也要求报告覆盖了哪些） |
| 确认记录与文件内容可能漂移 | 确认时服务端重算摘要；查询时逐份比对 ⇒ 漂移即失效（fail-safe） |
| 沉浸模式影响 CockpitShell 既有行为 | 沉浸判定集中一处 + 只对白名单路径生效；既有路由测试全绿 |
| 「规则/政策」投影口径替换旧判定，可能影响既有聚合初始化相关用例 | 旧判定函数被替换而非并存；回归由 `cargo test --locked` 全量把关 |

## 6. 验收口径（UI 验收矩阵）

| 场景 | 期望 |
|---|---|
| 聚合初始化未完成 → 点【知识库初始化】 | 4xx + 中文「需先完成聚合初始化（规则/政策）后再操作知识库」；卡片与详情页显示同一提示 |
| 聚合初始化未完成 → 详情页保存/确认 | 写入口禁用，提示同款文案 |
| 输入未准备 → 点【知识库初始化】 | 起 `user_input` operation（跑 `/knowledge-base-user-input`）；卡片显示步骤与产出文件数 |
| 起草完成 → 详情页 | 输入确认区列出 9 份文件与状态徽标；未确认的文件可编辑 |
| 编辑已确认的文件 | 该份确认**自动失效**，界面提示「已修改，需重新确认」 |
| 逐份确认 → 全部确认 | 再点【知识库初始化】⇒ 起 `bootstrap` operation（跑 `/knowledge-base-bootstrap`） |
| 未确认就点【知识库初始化】 | 4xx + 未确认文件清单，**不起任何 operation** |
| 详情页视觉 | 顶栏含标题 + 项目/LC 关联信息 + 返回工作台按钮；**无全局设置齿轮**；编辑器占满右栏高度，页面下半屏无空白 |
