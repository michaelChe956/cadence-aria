# 技术方案: Reviewer 验证能力全开与零提交、产物恢复硬化(v3.0)

- 出具: design-task-sol (ReviewerFullPowerV3), 2026-10-16, 受测试会话委托; **设计完成未实施(DONE_WITH_CONCERNS)**
- 本方案替代 v2 的 no-exec 主闸; v1 审查副本机制继续废止; 源码事实均物理文件复核
- 分层定位(主线裁决): **通用去沙箱 profile=执行基线(DesandboxImpl 案); 本方案=叠加其上的 Coding Reviewer 专属硬化层**, 不推广为 Coder 或所有 provider 必备

## 一、最终结论与保证边界

### 目标
Reviewer 可自主使用构建/安装/测试/脚本/容器/工具/扩展/MCP, 恢复最大验证能力。平台不靠撤销工具约束 Reviewer, 而是硬化两条铁律:
1. **Reviewer 不得向受管仓提交或经 Aria 发起交付**
2. **审查结束必须清除自产验证产物并恢复到审查前基线; 最终交付物只有审查报告及平台保存的证据**

「恢复原样」≠回到 git clean——保留审查前已存在的 Coder 合法未提交修改(staged/unstaged/untracked/ignored)。

### 事故链(物理源码复核)
- prompts.rs:494-495 要求构建/测试/Git mutation 落在交付 worktree
- prompts.rs:514-517「提交责任归你」
- provider_retry.rs:487-495 给 Reviewer 同时注入两段
- pi_provider/mod.rs:48-52 仅排除 edit,write; :665-672,983-990 宿主 spawn
**根源=Reviewer 既有提交能力又被要求承担提交责任; 修复须同时消除错误指令与提交能力。**

### 两项明文定义(已裁决定稿)
- **零提交硬保证范围**: 本次可见受管仓全部真实 Git 元数据(.git 入口/linked-worktree gitdir/common-dir/objects/refs/index/reflog/配置/子模块 gitdir)+Aria 的 stage/commit/push/journal 恢复与取消补偿通道。自建临时仓 git init/远端副作用=owner 知情接受的注入残余; **远端 MCP 凭据不得授予受管仓 writer 权**(配置规范+启动检查项)
- **.aria 验收口径**: Reviewer 及其工具/MCP/子进程对 .aria 零写(物理只读); 平台自身受信写入仅限预枚举的报告/role-run/窗口日志路径; 验收=白名单外零变化

## 二、五件套选型

| 必配 | 选型 | 边界 |
|---|---|---|
| ① .git 物理只读 | **独立 Reviewer UID/GID + DAC 无写 + 窄保护 mount namespace** | Git 观察可用, 受管元数据写入内核拒绝 |
| ② .aria 只读 | 同一身份+挂载层, 覆盖所有平台数据根 | 无法改平台记录 |
| ③ 对账恢复+崩溃补偿 | durable 审查窗口+完整恢复快照+全退出收口+启动前补偿 | 回审查前基线, 防残留进下轮材料/提交 |
| ④ API 调用方鉴权 | 人工控制凭据与 run-scoped 只读证据凭据分离; 覆盖 REST/WS/敏感读取 | 防自批 gate/推进交付/窃取控制凭据 |
| ⑤ 凭据不可达 | 独立 UID DAC deny + 干净 HOME/XDG/TMP + 敏感路径遮蔽 | 绝对路径也读不到, 不触发 no-new-privs |

**为何独立身份而非只改 HOME**: 同 UID 进程可 cat /home/<owner>/.ssh(绝对路径)且可 chmod 自己文件; HOME 重定向/裸 chmod/hook/PATH 包装都不能承担硬保证。
**为何还要窄挂载**: .git 父目录可写时可删换 linked-worktree .git 指针——独立 UID DAC 之上, 仅保护入口与敏感路径的 mount namespace: worktree 原位可写(不建副本)、.git 入口与真实 gitdir 全只读绑定、.aria 根只读绑定(控制凭据另设不可读)、个人凭据路径不可达、propagation=private、不交付 owner fd。启动准备解析冻结 canonical 路径/设备 inode/Git 指针, 不由模型传字符串充当权威。
**与 rootless Podman 兼容**: 不用 landlock_restrict_self、不调现有 bwrap launcher、不设 PR_SET_NO_NEW_PRIVS(会继承不可撤销, 杀 newuidmap); 不用 DynamicUser(隐式 no-new-privs)、不把 newuidmap 所在 FS nosuid、不空 bounding set、不禁 unshare/mount。Reviewer 在初始 user namespace 无宿主 CAP_SYS_ADMIN, 其新建低权 namespace 不能解除继承的受保护挂载。**目标机真实 Podman 兼容是实施放行条件**。

## 三、rootless 单人机部署

**一次管理员预置, 运行期 Aria/Reviewer 都不变 root**(普通 uid 不能自行 setuid/unshare 换身份——独立身份=新增平台基础能力):
1. 管理员一次性创建固定 Reviewer 账户/池(禁交互登录, 无 sudo/rootful)
2. 配互不重叠 /etc/subuid+/etc/subgid, 装 newuidmap/podman 依赖
3. 安装 root 所有窄权限启动/回收服务: 只接受 owner/Aria 的本地 socket; 校验 peer UID/项目根/窗口身份; 建挂载/运行目录/cgroup 后永久降权执行; **不提供以 root 跑任意命令接口**; Reviewer 无权调管理 socket
4. Aria 主进程仍 owner 用户; 构建/Podman 均 Reviewer 普通用户(非 rootful)
5. 每次运行分配干净 HOME/XDG/runtime/tmp/缓存/容器存储, 归窗口租约
无预置则显式「运行环境未就绪」, **不静默退回同 UID+HOME 重定向冒充硬化**。

权限准备与恢复: 只授权本次受管 worktree 写; 父目录仅 traverse; 授权前存原始 ACL/模式, 结束恢复; 拒绝进 owner 补充组/SSH agent/D-Bus/宿主 podman socket; 回收服务须能清 Reviewer 建的 chmod 000 目录; 同一 UID 同时只租一个窗口。
干净 HOME: 可链接无密钥的技能/工具配置/trust/可执行文件; **不链接**个人 .ssh/.aws/.codex/.kimi-code/.cc-switch/credential store/云凭据/agent socket; provider/MCP 授权用独立最小权限凭据(不含受管仓 writer/Aria 管理权); 检查 owner 配置的绝对路径与 symlink 不带入个人凭据; 复用 trust adapter for_home 形状(provider_trust_adapters.rs:114-122,318-326)但登记 Reviewer HOME。不宣称「进程能用某授权又绝对拿不到该授权」。

## 四、完整审查窗口

### 可恢复快照(v2 清单摘要升级)
范围: worktree 全部目录项含 ignored; 文件内容/类型/symlink 文本/模式/owner/ACL/xattr/mtime; index/HEAD/符号引用/Git 元数据原始态; 受保护目录身份与权限; .aria 白名单外摘要; 运行目录/进程/容器存储归属。内容备份放受保护平台窗口目录(Reviewer 不可写; reflink 后回退复制, **禁硬链接**)=恢复备份非审查副本。不能忽略大 target/node_modules 还承诺全恢复; 扫描不完整/空间不足/特殊文件不可恢复/并发变动→窗口不得进 Running。「原样」以内容/路径/类型/权限/声明的可恢复元数据为准(inode/ctime 留审计)。

### 状态机与顺序
Preparing→BaselineReady→Running→Quiescing→Restoring→Reconciled→Closed(↘RecoveryRequired/IntegrityFailed)
新受信接口(设计名): begin_review_window / finalize_review_window / recover_pending_reviews_before_materials。
顺序: 窗口租约(先处理旧未完成)→停同树 Coder/平台 Git mutation 确认无在途 writer→备份/清单/身份/恢复日志持久化→**从此基线采集审查材料**+建身份/挂载/工具会话→执行 Reviewer(输出为待采信报告)→全退出统一 Quiescing(终止回收 CLI/子代理/本地 MCP/ACP terminal/脱离进程组后台; 停容器/pod/网络; 收尾输出)→对账恢复(删基线外新增; 恢复改/删/类型/权限; 清空运行 HOME/tmp/cache/容器存储; **不 git reset --hard/clean/stash, 不从 HEAD 覆盖 dirty**)→终核(worktree=基线/Git 元数据无变化/.aria 白名单外无变化)→**仅 Reconciled 才采信报告并释放交付守卫**, 清备份留报告。
恢复差异不再一律判违规(建 target/ 是允许的); **应恢复未恢复/硬保护被突破/未知 writer/快照不完整才阻断**。

### 崩溃与重启
不依赖 Drop。持久登记绑定: window/attempt/role-run/boot identity/UID 租约/cgroup/PID start identity/canonical 工作树与 gitdir/snapshot manifest/恢复进度/运行目录与容器存储。补偿顺序早于任何新材料采集: serve_web 启动 reconcile 前接入(app.rs:708-715); Coder 首启/resume/rework/retry 前幂等准入(早于 coding.rs:47-56 start commit 冻结与 :179 上下文渲染, rework.rs:34); 先停旧进程容器再按原基线续恢复, **不得把污染态重冻为新基线**; 恢复完成前不收集 HEAD/diff/构造上下文/启动 provider。清理失败/租约不明/停机期间人工改动→保留备份差异显式停等, 不盲目覆盖。

### 并发
同一物理工作树的有写验证 Reviewer **串行**(不再假设多只读窗口共存); group shard 同树共享验证产物时串行; 不重叠工作树可并行但共享 git common-dir 的平台写受窗口守卫。这是原位验证与确定性恢复的必要代价。

## 五、平台 API 最小鉴权(可独立先行)
两类授权(不建 RBAC): 人工 UI/受信本机客户端=控制会话凭据(存 owner 私有 runtime 目录, 不进 .aria/仓库/前端静态; 浏览器经本机一次性 bootstrap 建 HttpOnly SameSite 会话; **不得有「任何 localhost 来访者可领管理 token」端点**); Coder/Reviewer 工具=短期绑定 attempt/run/用途的证据凭据(仅证据/政策读取, 不得变更流程状态)。
保护面: 全部状态变更 REST(含旧 alias)+可发控制消息的 WS(upgrade 前鉴权+校验 Origin)+可读出控制凭据或绕过遮蔽的 file-content/artifact/配置读取(**不能只封 POST 留敏感 GET**); /api/evidence-query 保留专用 token 语义不与管理凭据混用; health/静态显式公开, 其余默认拒绝; 401/403 不因回环/自报角色放行; 凭据不进 URL/日志/raw prompt/错误正文。需同步前端 REST/WS/重连/测试, 避免「后端封住 UI 全坏」。

## 六、四家 Provider 与工具/MCP 接线
**不把全开伪装成旧只读 profile**: 现共享约束真实存在(streaming_provider DenyFileWriteBuiltins for Reviewer:511-557; policy.rs ReviewReadOnly writable roots 空:174-184,333-345; lifecycle 映射:132-141; kimi policy 恒拒 Reviewer Terminal/FsWrite:69-76)——不能只给 pi 删参数。

执行端全覆盖: 原生 CLI 内建 bash/文件工具; LC gateway 最终 spawn; **kimi ACP Terminal/FsRead/FsWrite(Aria 宿主代执行, 不能保留 owner 权限)**; 同步/legacy 桥与 CliProviderAdapter 旁路; 本地 MCP/扩展/子代理; fresh/resume/retry/group 三形态。kimi Reviewer 的 client-service 操作须进同一独立身份执行端; 其 Auto 现走 bwrap(terminal_handlers.rs:72-117), 新 profile 不得继续套这条杀 Podman 的路径。
工具/MCP 全开=工具可用, **不是将 owner 权限无条件代理给工具**: 本地 MCP 同身份/窗口/清理域; 远端 MCP 保留工具集但凭据无受管仓 writer/Aria 控制权(未知授权范围须部署检查); 受管仓写入型本机服务不得以 owner 权限受 Reviewer 请求; 版本/配置/MCP 摘要/身份/窗口绑定进既有审计, 不新增能力证据门。

## 七、纪律与报告证据
Reviewer 全部实际发送 prompt 删: 「提交责任归你」/「worktree 内复跑」/v2 只读措辞。统一新纪律:
> 你可自主执行构建、安装、测试、脚本、容器及工具/MCP 验证。禁止一切 Git mutation 及通过平台推进交付; 受管仓 Git 元数据与平台数据由平台物理保护。验证优先使用平台给定的受管工作树和运行目录, 不得污染成员主 checkout。临时修改和产物将在审查结束后恢复清理, 不要依赖其留存。不要修复并交付代码; 最终只输出审查报告。
「可自由验证」不改人工事项/非 E2E finding/过程证据边界。Group 静态纪律进 PromptSegments.fixed_protocol 入预算, 动态窗口信息走运行上下文; shard/reduction/repair 一致; repair 仍只修格式。
三证据源互补(coder evidence pack / A' 人工回贴 / reviewer 实际执行), 每项检查区分已复验(命令/cwd/退出码/测试数/输出引用/受审基线/是否改过源码) /仅静态审/NOT_EXECUTED(不写成 PASS)。不新增 verdict 枚举; reviewer 测试通过≠coder 曾执行, 不替代 manual_check; **reviewer 改过源码才通过的不得宣称原基线通过**; 报告绑定实际被测状态; 仅恢复对账成功后采信; group 任一窗口完整性失败不能被 reduction/repair 抹掉。
