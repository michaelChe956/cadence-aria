# 方案设计：代码库级模式修正（v1.3，替代 v1.2 的 D1/D6 组 1 设计）

> 日期：2026-08-19
> 状态：已获用户拍板（多 LC 并存零耦合 / issue 唯一归属 / 在当前 change 实施 / 单仓与逻辑为同级两种形式，非 legacy 框架）
> 前置：v1.2 已实施 22 task + UX change；本修正回滚其中 project 级 opt-in 设计，改为代码库级。

## 1. 修正动机

人工测试发现概念错误：仓库模式（单仓/多仓）是**代码库的属性**，不是 project 的属性。一个 project 允许一个或多个代码库，种类不限；多个逻辑代码库之间零耦合（纯管理手段）；issue 唯一归属于一个代码库（单仓或逻辑）。

## 2. 实体模型

```
Project
 └─ Codebase × N（统一列表，kind 区分）
     ├─ 单仓代码库 SingleRepo{repository_id}     （既有流程零变化，数据仍在 repos.json）
     └─ 逻辑代码库 LogicalCodebase{id, name}     （含 members × N）
```

- 删除 `ProjectRecord.multi_repo`（旧数据字段忽略兼容）。
- `LogicalCodebaseRecord{id, name, aggregate_root, created_at}` 每逻辑代码库一条；name 创建时必填（默认可取聚合根目录名）。
- 存储子树：`.aria/projects/{pid}/logical-codebases/{lc_id}/{manifest.json, members/, checkouts/, aggregate-indexes/, preflights/, registration-batches/, pointer-publications/, aggregate-policy.json}`。

## 3. 兼容与迁移

| 数据 | 处置 |
|---|---|
| 既有单仓 repos.json | 不动；列表呈现层适配为 SingleRepo 条目 |
| 本 change 已产生的 `logical-codebase/` 数据 | 打开时迁移为第一个逻辑代码库（lc_id 派生） |
| 母 change 已归档端点（members/pointer-publications/initializations，路径含 `logical-codebase/`） | 保留为“默认第一个逻辑代码库”的兼容别名；新规范端点挂 `/logical-codebases/{lc_id}/...` |

## 4. API 设计

```
GET    /api/projects/{pid}/codebases
       → {codebases:[{id, name, kind: "single_repo"|"logical", repository_id?|logical_codebase_id, member_count?}]}
POST   /api/projects/{pid}/logical-codebases
       body {name, aggregate_root} → 创建空逻辑代码库记录（manifest 待首批登记创建，沿用 D7 原子语义）
GET    /api/projects/{pid}/logical-codebases/{lc_id}（详情+成员+初始化/索引状态汇总）
DELETE /api/projects/{pid}/logical-codebases/{lc_id}（软删/tombstone，成员仓零 git 副作用）

# 以下端点全部从 /logical-codebase/ 换形到 /logical-codebases/{lc_id}/：
POST …/registrations/preflight | …/registrations | GET/POST …/registrations/{bid}[/resume|/cancel]
POST/GET …/initializations[/{oid}] [+/cancel]
POST …/aggregate-indexes/rebuild | GET …/aggregate-indexes/active
GET  …/members
GET/POST …/pointer-publications[…]（per-LC 迁移）

# 单仓端点保持原样（不再有多仓 project 防护概念）：
GET/POST/DELETE /api/projects/{pid}/repositories[…]（单仓代码库 CRUD，行为不变）
GET /api/projects/{pid}/repository-initializations/{oid}（行为不变）
```

- 废除 1.4 的 `legacy_repository_endpoint_on_multi_repo` 防护语义（project 无模式）；该错误码保留映射但不再产出（后续清理）。
- guard 改为 `require_logical_codebase(pid, lc_id)`（LC 不存在→404 logical_codebase_not_found）。
- 单仓代码库上调逻辑专属端点不适用（其 lc_id 不存在于该 project → 404）。

## 5. Issue 归属

- issue 创建请求：单仓 → `repository_id`（既有）；逻辑 → `logical_codebase_id` + `repository_id`（该 LC 内 primary 成员，须属其 active members）
- 逻辑 issue 的 selection=该 LC all_members（5.1 补偿事务按 LC 解析 manifest）
- RepositoryRouting / PlanningContextResolver / gateway / evidence：按 issue 所属 codebase 解析 manifest/selection/index/policy
- 不存在跨代码库 issue；多 LC 间零数据交叉

## 6. 前端

- 创建 project 弹窗恢复原样（撤销 UX 2.1 单选）
- project 页「代码库」混合列表（kind 徽标）+「添加代码库」弹窗：模式单选（单仓库 / 多仓库逻辑代码库）
  - 单仓库 → 既有 POST /repositories 流程
  - 多仓库 → POST /logical-codebases 创建 LC → 直接进入该 LC 的登记向导（auto_discover）
- 逻辑代码库页按 LC 分区：登记向导 / 初始化卡片 / 索引卡片 / 指针面板（均可多 LC 并存展示或按选中 LC）
- issue 创建对话框增加代码库选择（混合列表；选逻辑代码库时再选 primary 成员）
