## 4. A：持久恢复事实、指纹与稳定投影

### 4.1 durable schema（建议新增，不是已存在接口）

在 `models/workspace.rs` 定义纯 DTO，`WorkspaceSessionRecord` 增加三个字段，均 `serde(default)`；runtime `types.rs::WorkspaceSession` 逐字段恢复。避免把只读 gateway opaque launch 本身序列化。

| 字段／DTO | 合同 |
|---|---|
| `logical_launch_fingerprints: Vec<LogicalLaunchFingerprintRecord>` | durable map 的序列化承载；按 author role/provider/native ID 查找，不能只用 provider 覆盖旧代 |
| 指纹 record | `schema_version: u16`；`fingerprint_basis: full_lc_projection_v2`；`role`、`provider`、`role_run_seq`、`node_id`；`native_session_id: Option<String>`；`fingerprint_digest`、`planning_access_fingerprint`（来自同 run 的 PlanningContextSnapshot）；`state: prepared / active / superseded`；`created_at`、`updated_at`。相同 native 的 active 指纹不可就地改写；prepared 不自称已启动 |
| `superseded_native_sessions: Vec<SupersededNativeSessionRecord>` | 不可恢复 tombstone 集：`role/provider/native_session_id/reason_code/recovery_id/superseded_at`；历史保留，不靠清 conversation 或删 audit 吊销；以后再漂移可有多代 |
| `lc_resume_recovery: Option<LcResumeRecoveryRecord>` | 当前恢复事实；为空为常态，非空必须由后端解释，不从 Error 文本生成 |
| recovery 身份 | `schema_version:1`、`recovery_id`、`role:author`、`provider`、`superseded_native_session_id: Option<String>`（已知旧ID必填；确实不可恢复的历史缺ID保留None，不伪造）、`failed_node_id`、`reason_code`、`previous_fingerprint_digest: Option<String>`、`detected_at`、`updated_at` |
| recovery 修订续接材料 | `revision_origin: author_feedback / reviewer_revision / plan_outline_revision / plan_author`；`feedback: Option<String>`；当前 `artifact_version`／`review_node_id: Option<String>` 作为核对引用；`previous_session_status`、`previous_stage` 与原 plan run kind 的可重建事实，供合法 fresh 回原流程；保留现有 messages/artifact versions/review/gate 事实，不复制全部大 payload |
| recovery 运行状态 | `state: waiting / fresh_reserved / fresh_running / resolved`；`operation_id: Option<String>`、`fresh_node_id: Option<String>`、`fresh_role_run_seq: Option<u64>`、`fresh_native_session_id: Option<String>`；`fresh_operations: Vec<LcFreshOperationResult>` 保存本recovery已接受操作的 `operation_id/outcome(not_started / running / completed / failed / unknown)/node_id/role_run_seq`，每个已消费ID不可再次claim。旧 ID 不能写到 fresh 字段 |

`reason_code=resume_fingerprint_mismatch` 沿 gateway 原码；native 存在但 map 缺失／旧 basis／冻结材料不完整用新增 `resume_fingerprint_unavailable`；PlanningContextSnapshot 自身过期用新增 `planning_context_stale`。未知旧指纹保留 None，不能从当前环境倒算伪造旧值。DTO 可随 SessionState 投影**必要字段**，不向前端泄漏 native ID／完整 fingerprint／秘密配置；前端所需为 recovery_id、state、reason_code、failed_node_id、provider、revision_origin、时间、allowed_actions。

### 4.2 指纹 map 持久化的写入／恢复纪律

1. 替换 `WorkspaceEngine` 中仅 provider→digest 的可丢内存权威；runtime 只作已恢复 durable record 的索引。Author／choice follow-up／revision 的每次 LC launch 都走同一冻结入口。
2. 完整 prepare 得到候选 projection、opaque validated launch、run-bound audit identity 后，在 **spawn 前**存 prepared 指纹与 role_run_seq；持久写失败即零 spawn，不忽略 I/O 结果。
3. `ProviderSession.native_session_id`／真实 Completed 或该 role_run_seq 的 provider_start audit 给出 native ID 后，绑定为 active；只能绑定到同一 provider/role/run/node。会话 Completed 未到但 spawn audit 在时，允许 audit 恢复 **native 引用**，必须与同 seq 已持久的完整指纹联合匹配。audit 不提供旧 map 的“替代指纹”。
4. prepared record 只能与同 seq 的真实 provider_start 联合证明启动；无 audit／native ID 不能被恢复为 active，不能当 fresh 许可。原会话只写过 basis 指纹、不完整旧记录、map 丢失均进入 durable waiting＋显式 fresh，不静默新会话。
5. native ID 来自 conversation 或 audit 的所有 LC 入口，先排除 tombstone／旧 run superseded，再要求匹配 native 与 full-basis map；既有 active native 的指纹只能比较，不用本次 validate 覆盖它。新的指纹在新的 native/role_run_seq 绑定，不与旧代混用。
6. direct 单仓不新增 LC 指纹门、不改旧原生恢复 helper 语义。Reviewer 的独立会话不能覆盖 author map。

### 4.3 等待与终态化状态机

| 前置／动作 | durable 迁移与输出 | spawn |
|---|---|---|
| native＋完整冻结指纹全维一致 | 沿原 revision resume；active 指纹不变 | 仅原生同 ID 恢复 |
| native＋真实 mismatch／冻结材料不可用，或 planning snapshot 已过期 | 写 tombstone＋recovery.waiting；legacy status=Open，SC 保留原业务 phase/gate/status（不借恢复关闭或重臂 gate），统一 native 恢复投影为 PrepareContext；旧 revision/outline node Failed（摘要“旧原生会话已失效，等待显式新会话继续”）；清该 provider active_node_id/active_run_id；再发布 typed snapshot | 0 |
| waiting＋普通 StartGeneration（未带明确 fresh）／RequestRevision／RetryInterruptedRun／旧 recovery_id | 稳定协议拒收，等待与上下文不变 | 0 |
| waiting＋合法显式 fresh | 同 recovery_id 原子 claim 为 fresh_reserved，记录 operation_id；刷新当前 snapshot＋fresh prepare | 仍 0，直到全部门满足 |
| fresh_reserved＋preflight/admission/存储失败 | 回 waiting，保留授权操作结果／诊断与旧 tombstone；不自动重试、不自动 fresh | 0 |
| fresh_reserved＋成功 prepare／run 注册 | fresh_running，绑定新的修订节点与 run identity | 最多 1 |
| fresh_running＋完成完整 artifact | recovery.resolved（保留关联证据），新 native active；Story/Design 回原 AuthorConfirm，Plan 返回原 run kind 的既有合法门，SC phase/gate 由原流程推进，不另造 gate | 不再启动额外 run |
| fresh_running＋失败／进程重启结果未知 | 不恢复旧 native；先按现有 session-owned run/audit/stale recovery 核对是否已启动，不能盲目重放 fresh；等待可见，用户再次动作前需收口原 claim | 不能并发第二次 |

durable waiting 为重建权威：`new_persistent` 在恢复 timeline 时优先应用 recovery 的状态不变量，waiting 不被遗留 active revision 重投为 busy；进程在写 recovery 后、写 timeline 前崩溃时，重建应按 failed_node_id 幂等收口旧 provider 节点，但不收掉原人审 gate。跨 JSON 文件不宣称强原子事务；**先保存阻止 resume/spawn 的 durable tombstone/recovery，再幂等收口 timeline，再发快照**，任何失败保持 fail-closed，并给可诊断存储错误，不伪称恢复完成。规划 snapshot access fingerprint 为独立附加门：E 固定 root target 后仍检验成员 checkout/revision/dirty/availability 与 index/membership；不能因 root 无 Git 而漏掉成员真实 Git 身份变化。只改变产物 involved/focus/change_order、实际环境与 snapshot 未变时不应触发该门。

### 4.4 A/B 发布纪律与投影

A 定义 schema＋waiting/terminalization 与投影契约，但在 B fresh sender、资格过滤、context、完整 projection 同源链未接齐时：`allowed_actions=[]`，文字只说明“旧原生会话已失效，恢复动作尚未可用”，不让现有 generic 开始生成绕过等待。A/B 合并前必须共同原子发布，或将 A 保留在不可启动集成分支；不得用一个假 enabled 标志把未接线 fresh 说成可用。最终 allowed action 为 `start_generation` 且只接受显式 fresh 参数。

优先复用**SessionState 全量 authoritative 更新＋既有 journal/event_seq**，新增内部 `EngineEvent::LcResumeRecoveryChanged` 触发 router 广播 SessionState，不再额外造一个互相竞态的 recovery_delta wire。router消费时先try_lock，忙时走现durable_projection，不等待持锁provider循环；live为带新event_seq的全量更新，initial/刷新/重连／degraded fallback都从同record投影。map_engine_event对内部事件返回None，router显式消费。StageChange/Error不是恢复事实权威。

## 5. B：显式 fresh 授权、资格与上下文

### 5.1 消息协议（建议增补）

沿现有 `WsInMessage::StartGeneration`，保留 provider_config/reviewer_enabled，新增可选 `resume_recovery`：

```json
{
  "type": "start_generation",
  "provider_config": "沿现有 ProviderConfigSnapshot 的真实对象",
  "reviewer_enabled": true,
  "resume_recovery": {
    "recovery_id": "后端 SessionState 投影提供的当前身份",
    "intent": "fresh",
    "operation_id": "同一次用户动作稳定复用的命令身份"
  }
}
```

上例为**协议形状说明**，`provider_config` 的示意值不可照抄为合法消息。普通 generation 缺省 resume_recovery 行为保持；有 recovery.waiting 时缺省消息必须拒绝，不把点击泛用“开始生成”暗中解释为新会话授权。

后端资格在 claim 前检查：当前 driver lease／attachment 身份与 command fence、session 非 Confirmed/Terminated、无 active run、recovery waiting＋ID 匹配＋allowed action、原修订目标/workspace 仍有效、provider 配置不擅自换人（恢复动作沿原 author/effective reviewer；本动作拒绝配置变更，不增加新的换provider功能）。新增稳定拒收码：`lc_resume_recovery_required`、`lc_resume_recovery_stale`、`lc_resume_recovery_busy`。错误仍沿既有 ProtocolError 接口；不新增“自动重试”发送语义。

同 operation_id 重复返回已记录的操作结果与 snapshot，不二次 spawn；同 recovery 的不同 operation_id 在 reserved/running 时 Busy。prepare失败回waiting仍保存该operation的not_started/failed结果，同ID重传只能回放；再次用户显式尝试须新ID，不能因state回waiting而让旧ID又claim。claim 持久化与 run 启动之间的断点由 durable claim＋原 run registry/audit 对账，不能仅 UI disabled 防重。resolved recovery保留最后证据；下一次漂移替换当前recovery时，旧recovery_id消息一律Stale。

### 5.2 native 资格排除与 audit 兜底

### 7.2 B0 的事实来源与冻结时序

**推荐：提取现 adapter 只读事实准备＋保留现纯 projector，gateway 统一装配与冻结。** 代价是四家真实 adapter 接线与新 trait 透传必须完整切换；收益是 version/MCP/boundary 的 provider 知识只保留一处，gateway 仍是唯一权限构造与 spawn 判定者。
