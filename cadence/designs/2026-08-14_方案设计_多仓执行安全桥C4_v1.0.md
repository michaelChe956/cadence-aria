## 1. 背景与目标

Coder 在成员仓 worktree coding 时不持有聚合根；改 A 仓接口时需要了解 B 仓调用点。本设计提供**受控检索接口**：Coder/Reviewer 在需要时按需查询其他成员仓的只读证据（符号/字符串启发式检索，非精确调用图），证据经 ACL、snapshot 锚定、token 预算与审计四重约束注入上下文；「无法写入他仓」为 best-effort 表述（不宣称 OS 级强制）。

## 3. 架构总览与组件划分

新增 4 个组件 + 改造 1 处既有路径：

1. **`EvidenceQueryMediator`（新，`logical_codebase` 模块）**：检索编排核心，按固定顺序执行——身份校验（令牌 + attempt 归属）→ ACL（仅本 logical codebase 成员仓，排除本仓与聚合根非政策内容）→ 快照锚定（attempt target snapshot → 聚合索引 revision，stale/degraded 标注）→ 检索（`codegraph` CLI 启发式符号/字符串查询）→ 预算（单次 12k 字符截断 + attempt 累计 120k 配额）→ 审计（run audit 追加）。
2. **Worktree 注入（改 C-1 worktree 创建路径）**：coding worktree 创建时注入 `.aria/bin/aria-evidence-query`（只读查询脚本）与 `.aria/evidence-token`（attempt 级会话令牌，随 attempt 生命周期失效）。
3. **HTTP 端点 + 鉴权（web 层）**：`POST /api/evidence-query`（回环监听 + 令牌鉴权 + attempt 归属校验 + 角色识别 Coder/Reviewer）。
4. **`EvidenceIndexQuery`（新）**：封装聚合根 `codegraph` CLI 查询（复用 WP3 索引与 denylist），输出「文件:行 符号 上下文」纯文本。
5. **Prompt 注入（改 coding/review prompt）**：新增 `[cross_repo_evidence]` 段落——告知工具路径、用法、预算规则与角色可用性（C-5 已建的分流注入机制上加一段）。

数据流：Coder 在 worktree 内调脚本 → POST 到 daemon 回环端点 → Mediator 六步编排 → 结果文本返回脚本 stdout → Coder 上下文。

## 4. 身份/令牌/ACL/快照/预算数据模型

**4.1 Attempt 级会话令牌**：attempt 创建/恢复时生成 32 字节随机令牌；原文只写入 worktree `.aria/evidence-token`（0600）；Aria 侧只存 SHA-256 哈希（attempt 分区新增 `evidence-token.json`：`attempt_id`、`token_hash`、`created_at`）。端点收到令牌 → 哈希 → 反查 attempt 归属 + 状态（Running 阶段内有效；删除/完成即失效）；resume 沿用同一令牌（attempt id 不变）。

**4.2 ACL 数据来源**：从 `attempt.target_snapshot`（C-1 产物）取 `logical_repository_id` → `LogicalCodebaseStore` 载 manifest → 成员集合（Q2=A：全部成员仓）。排除项：本仓自身命中（直接读文件）；聚合根非政策内容（检索范围物理上只覆盖成员仓 checkout 路径前缀）。非法请求 → 401/403。

**4.3 快照锚定与标注**：查询结果头标注两类 revision——聚合索引侧 per-member 快照 revision（WP3）+ attempt 冻结的 checkout revision（C-1）；两者不一致时逐条标 `stale-snapshot` 警示；索引整体 stale/degraded（WP3 状态）时响应头显式标注 `index: stale|degraded`。

**4.4 预算 ledger（Q4=A）**：attempt 分区 `evidence-budget.json`（单写者：daemon 内查询串行 + 原子写）；字段 `attempt_id`、`cumulative_chars`、`queries` 摘要数组（time/query/result_chars/remaining）。常量：`EVIDENCE_QUERY_RESULT_CHAR_LIMIT = 12_000`、`EVIDENCE_ATTEMPT_CHAR_QUOTA = 120_000`。超限行为：单次截断加尾部标记；累计超限返回稳定码 `evidence_budget_exhausted`。

## 5. 检索执行、错误处理与审计

**5.1 检索执行（`EvidenceIndexQuery`）**：对外暴露 `query(symbol_or_text) -> Vec<EvidenceHit>`，内部按查询形态选择符号查询/字符串包含查询（CLI 精确参数在计划阶段按 v1.5.0 实测形态落实）；命中按成员 checkout canonical path 前缀过滤（剔除本仓与非成员路径）；命中上限 200 条，超出截断并提示缩小查询；再经单次 12k 字符截断。

**5.2 错误处理与稳定码**（仿 gateway_error_mapping 两段式）：

| 情形 | 稳定码 | HTTP |
|---|---|---|
| 无令牌/令牌无效 | `evidence_unauthorized` | 401 |
| attempt 非 Running / 归属不符 | `evidence_forbidden` | 403 |
| 查询词非法（空/超长） | `evidence_invalid_query` | 422 |
| 累计配额超限 | `evidence_budget_exhausted` | 429 |
| 索引不可用/查询执行失败 | `evidence_query_failed` | 503 |
| 非逻辑代码库流程调用 | `evidence_not_available` | 404 |

**5.3 审计**：每次查询向 run audit（C-2 既有机制）追加 `evidence_query` 条目——attempt、role（Coder/Reviewer）、query、命中数、结果字符数、snapshot refs、预算余量、时间戳。

**5.4 Prompt 注入（`[cross_repo_evidence]` 段）**：coding/review prompt 的 **Logical 分支**追加——工具路径 `.aria/bin/aria-evidence-query`、用法示例、预算规则（429 即停止查询）、不得触碰令牌文件以外机制；**Legacy 单仓流程不注入**。

## 6. 测试策略（TDD，先红后绿）

- **lib 单测**：Mediator 六步编排表驱动（身份/ACL/快照/预算/截断/审计，每步正反例）；`EvidenceIndexQuery` 命令构造与结果解析（fake codegraph 输出 fixture）；预算 ledger 原子写 + 配额边界（恰好 12,000 / 120,000 字符）；令牌生成/哈希/校验；快照标注（attempt revision 与索引 revision 不一致 → `stale-snapshot`）。
- **it_web 端到端（REQ-COD-05 场景）**：① Coder 合法查询跨仓命中 + 返回文本 + 审计落盘；② 无令牌 401；③ attempt 非 Running 403；④ 非成员路径命中被过滤；⑤ 单次截断标记；⑥ 累计超限 429；⑦ Reviewer 可查且审计区分角色；⑧ Legacy 单仓 404 `evidence_not_available`。
- **前端**：无（纯后端 + worktree 工具）。
- **门禁**：lib、it_web、it_core、clippy/fmt、openspec validate。
