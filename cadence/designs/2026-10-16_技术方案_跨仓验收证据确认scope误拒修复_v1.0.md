## 一、结论

**确认失败的直接根因是 Git 路径转义未还原为真实 UTF-8 路径, 不是跨仓 WI 没有合法落位仓。**

三个工作包:
1. **必要修复(根修)**: Git 文件清单用 `-z`, NUL 分隔真实路径字节+严格 UTF-8 解码; scope 匹配只消费规范路径, 禁止把 Git 展示字符串当路径
2. **归属模型**: 复用现有 `target_repository_id` 与 Plan Intent, **不新增 primary_worktree 第二真源**; 跨仓验收 WI 的 target=产物主落位仓(≠验收只涉及该仓)
3. **确认语义**: 最终确认层聚合「带仓库/WI/提交区间归属的 scope 并集」, 保留全部 per-unit scope/forbidden 拦截; 响应补「本仓 diff 含跨仓 WI 产物」结构化说明

**不推荐**把全部 WI exclusive scopes 展平成共享白名单: 既修不了带引号路径(首字节就是 `"`), 还会让普通 WI 越权借用其他 WI scope。

### 直接证据链
- **证据 A**: owner 原始报错字面量即转义形式 `"cadence/verify/2026-10-16_\351\252\214..."`(带引号八进制); 现场 git show --name-only 输出同款, 加 -z 输出真实中文——转义串一路进了范围判定

## 三、方案细节(要点)

### 3.1 路径协议: 两处修复
采集侧: 两个清单入口(git show / git diff --name-only)统一 NUL 协议——原始字节、按 0x00 分割、不 trim、逐项严格 UTF-8(失败返回 Parse 错误, 不得替换 � 后继续鉴权)、文件名中引号/空格/换行原样保留。只改路径清单命令, 普通日志输出不动, 不建第二套 Git 执行器。
**禁止替代方案**: 改全局 core.quotePath / 证据文件改英文 / 统一 trim 引号 / 启发式反转义(环境依赖/改交付物/路径身份混淆)。
匹配侧: 输入契约=已解码真实路径; 复用 validate_write_path 的 containment/.git/.aria 禁写/symlink 校验; 不加 NFC/NFD 折叠与新 glob 语义; empty-exclusive 现有语义保留。

### 3.2 最终确认: 并集保留归属, 不替代 per-unit 权限
调用链: post_plan_coding_final_confirm → 逐 target lease → handle_final_confirm → run_group_completion_gates → 每 unit 的 start..completion → 该 unit revision 的 write_policy → validate_changed_files_in_scope(现即 per-unit, 非整仓套根 WI, gates.rs:574-617)。

并集=带标签集合 (plan_revision_id, target_repository_id, logical_work_item_id, work_item_revision_id, scopes, unit_run_id, start_commit, completion_commit):
1. 按 attempt 固定 bound_plan_revision_id 读 plan 全部 WI(不读 issue 全部 WI/最新 revision)
2. 保留每条 policy 的仓库与 WI 归属
3. 从真实 unit-run 提交区间读路径
4. **先满足所属 WI 自身 policy, 再聚合为本仓合法交付集合**(本仓说明可同时含 WI-003 源码+WI-004 验收报告, 各按自身 scope)
5. 他仓仓内相对 src/** 不借给本仓

安全论证: 聚合放行的是「多个独立通过自身 policy 的交付」, 非「unit 可用任意 WI scope」——WI-003 写 cadence/verify/** 仍拒(即使 WI-004 声明了它); WI-004 写 frontend/src/** 仍被其 forbidden 拦; forbidden 不做 plan 级并集(否则会错禁 WI-003 合法改源码); 无跨仓 WI 的 plan 判定不变。
**本次存量现场不需要任何 scope 扩权或迁移——路径修复后 WI-004 按自身 policy 即可通过。**

### 3.3 主落位仓: 复用既有字段链
Markdown source(intent_target_*) → IR(PlanCandidateItemIr.target_repository_id) → outline/draft(target_repository_id: Option) → attempt(target_snapshot+worktree_path)。全链已存在(lower.rs:24-53; outline.rs:76-100; ir_adapter.rs:62-90; advance_split.rs:153-170), **不新增 primary_* 可写字段**(与 target 冲突+绑死运行环境)。
生成教学补充: 「验收可覆盖多成员仓; 文件产物必须写入该 WI 唯一 target 仓; 跨仓依赖用 depends_on/Inputs 表达≠可写依赖仓」; 延伸 draft 现有「逐字保留 outline target」规则。
存量兼容: 本次现场 target 完整直接沿用禁止重选; 旧 plan 缺显式声明→保留既有绑定不按当前 focus 重算; 新候选优先显式声明, 兼容回退沿用现有确定性 fallback; 无合法 fallback/非成员/集合冒充单 target→fail-closed; 单仓计划零新增必填。

### 3.4 Backend 语义标注 artifact_notices
GET 投影与 POST 每仓结果加 artifact_notices[{code: cross_repository_work_item_artifacts, target_repository_id, logical_work_item_ids, declared_scopes, message}]: serde(default) 旧前端可忽略; 前端消费结构字段禁解析中文 message; 从固定 revision/target binding/unit-run 派生(WI 标题模糊匹配不可用); 无充分跨仓事实不贴标签; 不把「存在说明」表述为「验证已通过」; 确认 state/预检/首失败停止/重试语义不变。

## 四、风险与兼容
-z 后仍 lossy 解码→路径走原始字节 fail-closed; 剥引号误改真含引号文件名→禁启发式; 并集洗白→per-unit+带归属标签; forbidden 合并错禁→始终属各 WI; 旧 plan 重算换仓→已发布绑定优先; integration≠跨仓→标签需 target+依赖事实; 确认流程→只加说明字段保 all/partially/not_ready 语义; 行号漂移→实施前物理复核。
非目标: 不碰 bwrap/REQ-LCG-04/验证 runner/授权体系; 不建 issue 级证据仓; 不迁移回滚两笔证据提交。
