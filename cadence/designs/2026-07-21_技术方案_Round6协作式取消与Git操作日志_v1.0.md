# Round 6：协作式取消与 Git 操作日志

## 目标

- runner 收到取消后不再丢弃完整业务 future，而是等待同一 future 在可取消边界收敛。
- Git 子进程取消时必须 kill、wait/reap；命令完成边界必须随后 reconcile，不能仅凭取消信号推断副作用。
- branch、worktree、commit、push 多步副作用使用严格 identity、单调 phase 的 durable journal。
- async flock 不创建不可取消的 blocking waiter；future drop 后立即停止竞争。
- Coding run registry 所有 entry 必带 `CancellationToken`，不保留无 token 的 legacy production/test entry。

## Finding 核验

当前 `runner/task.rs` 使用外层 `tokio::select!` 竞争完整业务 future 与 cancellation。取消分支直接结束 task，任意 Store/Git/event/provider 操作可在中间 `.await` 被丢弃，RAII registry remove 早于必要补偿。

`GitWorkspaceService` 使用 `Command::output()`，没有 cancellation、`kill_on_drop(true)` 或显式 reap。branch/worktree/commit/push 在进程完成边界收到取消时可能已经产生副作用，但调用方没有 durable phase 可用于确认或补偿。

`ExclusiveFileLock::acquire_async` 把阻塞 `flock(LOCK_EX)` 放进 `spawn_blocking`。调用 future 被 drop 后 blocking waiter仍然存在，holder释放后它仍可取得锁并延长 runtime shutdown。

Registry 的 `insert`/`activate` 仍能创建无 token entry；它们虽仅由测试使用，但保留了与 production 不同的取消语义。

## 方案选择

采用最小协作式收敛方案，不重写整个 Coding pipeline 为 actor/state machine。

### Runner 收敛

runner pin 唯一业务 future。cancellation 首次触发后继续 await 同一 future，不 drop。业务 future必须在以下边界返回 `CodingWorkspaceEngineError::Aborted`：

- runner start/probe wait；
- outbound event reserve/send；
- stage gate countdown/command wait；
- provider start、modern stream、legacy stream、provider-driven testing；
- provider command send；
- Git command；
- Plan Amendment socket-write wait。

provider cancellation 必须将当前 running role run 持久化为 `Aborted` 并记录 abort event。Attempt 的 durable `Aborted` 终态仍由 HTTP/WS handler 在 registry completion 后、mutation lease 内统一写入。

### Git 命令生命周期

所有 Git 命令统一通过 `spawn`：

- `kill_on_drop(true)`；
- stdout/stderr 独立 drain；
- select 等待 exit、timeout、cancellation；
- timeout/cancellation 分支显式 `start_kill`、`wait`/reap，再 join output reader；
- 返回 typed `Cancelled`，上层随后执行 reconcile。

### Durable Git operation journal

每个 Attempt 仅允许一个当前 journal，Schema 不做历史兼容。journal identity 固定 project/issue/attempt、kind、repo/worktree canonical identity、branch/base、before HEAD、remote 与 commit message。

Worktree prepare phase：

`Before → BranchCreated → WorktreeCreated → Completed | Compensated`

Review request phase：

`Before → CommitStarted → CommitCreated → PushStarted → Completed | Compensated`

phase 只允许相同或相邻推进；identity 漂移、倒退、跳阶段均 fail-closed。

### Reconcile 与补偿

- branch/worktree：取消后探测实际 branch/worktree。删除本次目标 worktree，再删除目标 branch，最后标 `Compensated`。handler Abort/Delete 在 durable mutation前再次执行幂等 reconcile。
- commit：`CommitStarted` 后取消先读取 HEAD。若 HEAD 已变化，确认新 commit；push 尚未开始时执行 mixed reset回 `before_head`，保留工作区内容，标 `Compensated`。
- push：`PushStarted` 后取消查询 remote branch。若 remote ref 等于 journal commit，权威推进 `Completed`，并完成 ReviewRequest/Attempt state持久化；不得伪装回滚。若 remote未更新，补偿本地 commit并标 `Compensated`。无法确认远端结果时 fail-closed。
- registry completion 必须晚于 runner 内 reconcile/补偿；Abort/Delete response必须晚于 handler二次 reconcile与 durable mutation。

## Async flock

Unix 使用 `flock(LOCK_EX | LOCK_NB)`；`WouldBlock` 时异步 sleep 固定小 backoff后重试，`Interrupted` 立即重试。future drop会 drop File并停止后续尝试，不产生后台 waiter。测试记录尝试次数，证明高竞争期间有界轮询、无 busy-loop，且所有未取消 contender最终取得锁。

## Registry

移除 legacy `CodingRunRegistry::insert` 与 `CodingRunReservation::activate`。全部测试迁移到 `insert_cancellable`/`activate_cancellable`，entry 的 token字段改为非 Optional。满 command channel只 cancel token并 `try_send`兼容提示，不进行 awaited send。

## 测试矩阵

- runner cancellation 不 drop业务future，补偿完成后才 remove。
- 满 event queue、stage gate、provider start/stream/testing 均有界返回 `Aborted`。
- 永久 flock holder 下取消 contender，current-thread runtime有界结束；holder随后释放不触发已取消业务；高竞争全部完成且尝试次数有界。
- cancel during branch、worktree add：Abort/Delete返回后目标 worktree/branch不存在，Store不再迟到变化。
- cancel during commit：HEAD恢复到before，工作区内容保留；Abort/Delete后无迟到 commit。
- cancel during push：远端未更新时本地补偿；远端已更新时 journal/ReviewRequest记录Completed，Abort/Delete后远端不再变化。
- Registry full channel与closed receiver有界完成，所有entry必带token。

## 边界

- `src/web/test_controls` Minor 保留，不新增 route。
- 不新增依赖，不修改 `src/web/app.rs`。
- 不运行 E2E、Playwright、browser、真实 Provider或网络 CLI；前端仅运行 `pnpm tsc -b`。
- 所有修改/新增 Rust、TS 文件不超过800行。
- 最终单一原子提交，不 amend、不 push，worktree clean。
