# 技术方案：无源码成员跳过与告警 · v1.0

> 历史稿。当前讨论范围见[聚合索引与 Story 生成 · v2.0](2026-11-18_技术方案_聚合索引与Story生成_v2.0.md)；下述拆分不作为本轮实施清单。

本文供产品与评审阅读；具体字段、错误码、扫描限额及验收合同以 [OpenSpec 变更](../../openspec/changes/skip-source-less-members/proposal.md) 和 [设计 D1–D8](../../openspec/changes/skip-source-less-members/design.md) 为准。

## 问题与根因

同一逻辑代码库可以有源码仓，也可以有只存部署配置、文档的仓。今天配置仓可被登记并选成 Issue 目标，但 CodeGraph 对某成员返回「未覆盖」时，Aria 会直接否决整代索引，冷启动不 ready，后续规划也缺少可读索引。这不是目标仓选择的问题，也不能靠前端放开复选解决。（执行点：`src/product/logical_codebase/aggregate_index/operation.rs:92-145,587-656`；冷启动：`src/product/logical_codebase/bootstrap_projector.inc.rs:49-52`；规划：`src/product/logical_codebase/planning_context_resolver.rs:454`；目标仓校验：`src/web/handlers/product_resources.rs:296-427,434-470`。）

「未覆盖」既可能正常（仓里只有配置、文档），也可能是工具没有收录实际存在的源码。只有两份证据同时支持「无源码」时，才允许跳过。Aria 不会依赖 CodeGraph 的内部扩展名表来定义产品行为，也不改变上游拥有哪些可检索文件（`src/product/logical_codebase/aggregate_index/exclude.rs:16-36`）。

## 用户会看到什么

```text
聚合索引     可用
已跳过无源码成员：gray-config。                          [重建索引]

创建 Issue → 选择逻辑代码库 → 选择成员
☐ api
☑ gray-config    该仓无源码，只能改配置/文档类文件
```

告警不改变按钮、选择或提交资格。只勾选 `gray-config`，且满足原有规则时仍可作为目标仓提交；规划保留它的真实 checkout，provider 在目标工作区直接读写配置和文档，不借 CodeGraph 检索该目标。不新增文件类型拦截，也不放宽现有工作区授权。（现有成员列表和复选：`src/web/handlers/logical_codebase_members.rs:13-79`、`web/src/components/lifecycle/CreateLifecycleIssueDialog.tsx:196-240`；现有 workspace 目标快照：`src/product/coding_attempt_store/target_snapshot.rs:43-90`。）

若有普通目录中的实际源码却漏收，仍使用既有三段失败面，而不是要求用户「添加源码」：

```text
问题：索引漏了这个仓的源码（api）。
原因：在成员仓普通目录发现了源码，但聚合索引没有覆盖它。
怎么做：检查忽略规则和路径，然后重建索引；连续两次仍失败时附机器码报 issue。
```

源码仅在 `.worktrees/` 时，提示把要索引的变更合入主 checkout 的普通路径；所有成员都确认无源码时，提示加入实际含源码的成员或把源码置于正常路径，**不能继续激活**。目录或权限导致无法确认时，提示检查而不是推断无源码。有上次可用索引的刷新失败仍是降级；如果上一代曾跳过成员，历史告警与本次失败分别显示。界面草图不构成另一份运行时文案；实际输出均使用 `failure_copy` 唯一码表，告警与 `FailureCopy` 五字段分开。（`src/product/logical_codebase/failure_copy_table.inc.rs:38-41,124-129`；`src/web/handlers/aggregate_index.rs:34-42,243-298`。）

## 决策与取舍

| 决策 | 方案和边界 |
|---|---|
| 判定 | 仅在逐成员索引覆盖为 false 后盘检主 checkout；不以仓名、标签或手工开关判断。只在确认无源码且至少一个其他成员被覆盖时跳过。上游已覆盖的目录不重新分类，例如上游已收录 YAML 时不贴此告警。 |
| Aria 口径 | 独立、有限的常见源码后缀表；YAML、XML、Properties、Terraform、JSON、Markdown 等不算磁盘侧源码。它是上游支持后缀的真子集，不复刻整个表；用真实样本探针守住兼容升级。 |
| 扫描 | 与索引共用内建排除，`.worktrees/` 限额内单独诊断；不跟随链接，超过深度、条目、耗时上限时不猜测。`.gitignore` 不隐藏正常路径里的漏收证据。 |
| 记录 | 保留登记成员及其 checkout/revision/dirty 快照；仅在通过验收的世代增加跳过标记。老记录不迁移；规划、freshness 与巡检仍认识该成员；索引覆盖不等于成员 checkout 可用性。 |
| 展示和执行 | 索引卡片由世代事实给出名单，选仓从同 LC 的成员 API 获取提示；前端不按名称拼表。配置目标不派发 CodeGraph 查询，普通查询仍遵守原 ACL 和钉住世代的覆盖范围。 |

**不采用**：把所有未覆盖成员视为配置仓（会掩盖源码漏收）；复制 CodeGraph 后缀和 ignore 实现（会被内部版本变化牵着走）；要求手工标记配置仓（增加操作负担，也会发生标签失真）；为配置查询扩大索引范围（不是产品需求）。与现有三段中文并行工作只做后续接线，不重写失败面。文件与前置关系见 [实施切片](../../openspec/changes/skip-source-less-members/tasks.md)。

## 影响面与待验证项

- **契约**：聚合索引、布局引导、冷启动文案、Issue 创建与每仓证据检索各有完整 requirement delta；工作台管布局和呈现，不另定义选仓准入，登记规则和执行授权不变。具体归属见 OpenSpec D6。
- **兼容性**：此前支持的非主流后缀如果不在 Aria 表、又未被上游覆盖，仍可能被误归为无源码。通过明确告警、可重建、以及用实际覆盖样本审查后缀增删纠偏；不保证未来上游小版本不漂移。（CodeGraph 兼容区间：`src/product/logical_codebase/aggregate_index/codegraph_cli.rs:16-23`。）
- **成本与时效**：文件系统异常或超限会失败，不静默放行。代码后来进入被跳过仓时，评估与重建会重新判断；告警描述的是索引世代，不声称磁盘实时无变化。（现有 freshness 路径：`src/product/logical_codebase/aggregate_index/freshness.rs:109-159`。）
- **尚未运行验证**：全无源码时实际 `init/sync` 输出、全部后缀 × 支持版本实证、真实 provider 的配置目标工作区操作。实施验收既要跑通「配置仓登记→聚合索引 active→只选配置仓建 Issue→规划→直接改配置」，也要证明「正常路径有源码、索引漏收」仍失败。具体夹具与 UI 状态见 D7 / `tasks.md`。
