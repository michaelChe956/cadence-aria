## 1. 背景与目标

Coder 在成员仓 worktree coding 时不持有聚合根；改 A 仓接口时需要了解 B 仓调用点。本设计提供**受控检索接口**：Coder/Reviewer 在需要时按需查询其他成员仓的只读证据（符号/字符串启发式检索，非精确调用图），证据经 ACL、snapshot 锚定、token 预算与审计四重约束注入上下文；「无法写入他仓」为 best-effort 表述（不宣称 OS 级强制）。

## 2. 已确认决策（brainstorming 记录）

## 3. 架构总览与组件划分

新增 4 个组件 + 改造 1 处既有路径：

1. **`EvidenceQueryMediator`（新，`logical_codebase` 模块）**：检索编排核心，按固定顺序执行——身份校验（令牌 + attempt 归属）→ ACL（仅本 logical codebase 成员仓，排除本仓与聚合根非政策内容）→ 快照锚定（attempt target snapshot → 聚合索引 revision，stale/degraded 标注）→ 检索（`codegraph` CLI 启发式符号/字符串查询）→ 预算（单次 12k 字符截断 + attempt 累计 120k 配额）→ 审计（run audit 追加）。
2. **Worktree 注入（改 attempt 启动/恢复路径）**：attempt 启动/恢复时**幂等执行**注入——`.aria/bin/aria-evidence-query`（只读查询脚本）与 `.aria/evidence-token`（attempt 级会话令牌，每次 attempt 启动重写，解决 issue 级 worktree 跨 attempt 复用下旧令牌残留）；同步写入 worktree 专属 exclude（`$GIT_DIR/worktrees/<name>/info/exclude`），确保 `.aria/` 注入文件不进 `git add -A`、不进 commit（令牌明文外泄向量闭合）。
3. **HTTP 端点 + 鉴权（web 层）**：`POST /api/evidence-query`（**Aria web 进程**回环监听 + 令牌鉴权 + attempt 归属校验 + 角色识别 Coder/Reviewer）。端点发现机制：web 启动时写 `.aria/web-endpoint` 端口文件，查询脚本读取后 POST；绑定非回环地址（`--host` 非 127.0.0.1/localhost）时该路由 fail-closed（不挂载或 404）。
4. **`EvidenceIndexQuery`（新）**：封装聚合根 `codegraph` CLI 查询（复用 WP3 索引与 denylist），输出「文件:行 符号 上下文」纯文本。
5. **Prompt 注入（改 coding/review prompt）**：新增 `[cross_repo_evidence]` 段落——告知工具路径、用法、预算规则与角色可用性（C-5 已建的分流注入机制上加一段）。

数据流：Coder 在 worktree 内调脚本 → POST 到 Aria web 进程回环端点 → Mediator 六步编排 → 结果文本返回脚本 stdout → Coder 上下文。

## 4. 身份/令牌/ACL/快照/预算数据模型

**4.1 Attempt 级会话令牌**：attempt **启动/恢复时幂等生成/重写** 32 字节随机令牌（解决 issue 级 worktree 跨 attempt 复用：同 issue 新 attempt 重写覆盖旧令牌）；原文只写入 worktree `.aria/evidence-token`（0600）+ 写入 worktree 专属 exclude（不进 commit）；Aria 侧只存 SHA-256 哈希（attempt 分区新增 `evidence-token.json`：`attempt_id`、`token_hash`、`created_at`）。端点收到令牌 → 哈希 → 反查 attempt 归属 + 状态（Running 阶段内有效；删除/完成即失效）。

**4.2 ACL 数据来源**：从 `attempt.target_snapshot`（C-1 产物，`Option`）取 `logical_repository_id` → `LogicalCodebaseStore` 载 manifest → 成员集合（Q2=A：全部成员仓）；`target_snapshot == None`（旧/单仓 attempt）→ `evidence_not_available`(404)。排除项：本仓自身命中（直接读文件）；聚合根非政策内容（检索范围只覆盖成员仓的索引相对路径首段=成员目录名）。非法请求 → 401/403。

**4.3 快照锚定与标注（钉住机制）**：attempt 首次查询时把 `manifest.active_aggregate_index_id`（WP3 钉住字段，store.rs:31 已有）记录进 attempt 分区 `evidence-index-pin.json`（`pinned_aggregate_index_id`、`pinned_at`）；**后续查询只读该钉住 record**（superseded record 仍持久可读），保证 Q3「同一 attempt 内版本一致」，不受 attempt 中途 `sync_if_stale` supersede 影响。stale 判定：attempt 冻结的 target revision / membership_revision（C-1）与钉住 record 的目标成员 revision / record membership_revision 比对，不一致 → 响应头显式标注 `index: stale|degraded`（全局标注；per-hit 仅展示来源 revision）。

**4.4 预算 ledger（Q4=A）**：attempt 分区 `evidence-budget.json`（**单 web 进程假设 + 进程内互斥**——仿 `ROLE_RUN_EVENT_LOG_MUTEX` 先例；多实例并发不在本设计支持范围）+ 原子写；字段 `attempt_id`、`cumulative_chars`、`queries` 摘要数组（time/query/result_chars/remaining）。常量：`EVIDENCE_QUERY_RESULT_CHAR_LIMIT = 12_000`、`EVIDENCE_ATTEMPT_CHAR_QUOTA = 120_000`。超限行为：单次截断加尾部标记；累计超限返回稳定码 `evidence_budget_exhausted`。

## 5. 检索执行、错误处理与审计

**5.1 检索执行（`EvidenceIndexQuery`）**：对外暴露 `query(symbol) -> Vec<EvidenceHit>`。**v1 仅符号/签名近似检索**：`codegraph query <search>`（v1.5.0，实测仅符号检索，函数体字符串包含查询无 CLI 能力）——满足「查 B 仓调用点」场景（调用点=符号引用）；裁决记录见 §8。命中按聚合根相对路径首段（成员目录名）过滤（剔除本仓与非成员）；命中上限 200 条，超出截断并提示缩小查询；再经单次 12k 字符截断。**Plan 首个 Task = 检索 spike**：真实聚合根 fixture 验证 `codegraph query --json` schema（filePath/startLine/signature）与跨成员命中，输出固化为解析器测试 fixture。

**5.2 错误处理与稳定码**（仿 gateway_error_mapping 两段式；角色=脚本 `--role` 参数自报，审计标注 `role_self_reported`）：

| 情形 | 稳定码 | HTTP |
|---|---|---|
| 无令牌/令牌无效 | `evidence_unauthorized` | 401 |
| attempt 非 Running / 归属不符 | `evidence_forbidden` | 403 |
| 查询词非法（空/超长） | `evidence_invalid_query` | 422 |
| 累计配额超限 | `evidence_budget_exhausted` | 429 |
| 索引不可用/查询执行失败 | `evidence_query_failed` | 503 |
| 非逻辑代码库流程调用 | `evidence_not_available` | 404 |

**5.3 审计（新持久机制）**：新增 attempt 分区 `evidence-audit.jsonl`（仿 `role_run_event.rs` 的进程内 mutex + sequence 先例；C-2 `GatewayRunAudit` 为进程内内存结构不落盘，不复用）；每次查询追加 `evidence_query` 条目——attempt、role（Coder/Reviewer，自报标注）、query、命中数、结果字符数、snapshot refs、预算余量、时间戳。

**5.4 Prompt 注入（`[cross_repo_evidence]` 段）**：coding/review prompt 的 **Logical 分支**追加——工具路径 `.aria/bin/aria-evidence-query`、用法示例、预算规则（429 即停止查询）、不得触碰令牌文件以外机制；**Legacy 单仓流程不注入**。

## 6. 测试策略（TDD，先红后绿）

- **lib 单测**：Mediator 六步编排表驱动（身份/ACL/快照/预算/截断/审计，每步正反例）；`EvidenceIndexQuery` 命令构造与结果解析（fake codegraph 输出 fixture）；预算 ledger 原子写 + 配额边界（恰好 12,000 / 120,000 字符）；令牌生成/哈希/校验；快照标注（attempt 冻结值与钉住 record 不一致 → 响应头 `index: stale`；per-hit 仅展示来源 revision）。
- **it_web 端到端（REQ-COD-05 场景）**：① Coder 合法查询跨仓命中 + 返回文本 + 审计落盘；② 无令牌 401；③ attempt 非 Running 403；④ 非成员路径命中被过滤；⑤ 单次截断标记；⑥ 累计超限 429；⑦ Reviewer 可查且审计区分角色；⑧ Legacy 单仓 404 `evidence_not_available`；⑨ `index: stale|degraded` 响应头场景；⑩ 422 `evidence_invalid_query` 与 503 `evidence_query_failed`；⑪ issue 级 worktree 复用下新 attempt 令牌重写（旧令牌 401、新令牌 200）；⑫ 注入文件不进 commit（`git add -A` 后 `.aria/evidence-token` 不在 index）。
- **前端**：无（纯后端 + worktree 工具）。
- **门禁**：lib、it_web、it_core、clippy/fmt、openspec validate。

## 7. 范围边界（非目标）

不做 OS 级写隔离（best-effort，契约原句）；不做精确调用图（启发式）；不开放聚合根政策正文以外内容；不做刷新语义（YAGNI）；不支持跨 logical codebase 检索。

## 8. 契约影响判定

REQ-COD-05 已覆盖本设计全部语义（受控接口/ACL/snapshot/token 预算/审计/不持有聚合根/启发式），**无需修改 OpenSpec delta spec**；预算数值、稳定码、令牌机制为实施细节。**v1 裁决（用户确认）**：契约「启发式符号/字符串近似」按**符号近似**满足——`codegraph query` 无正文字符串包含能力，调用点检索=符号引用可满足场景；字符串包含留待索引能力扩展。**Reviewer 复用同一受控接口不改变契约语义**（同 attempt 快照/预算池，审计区分角色）。
