# 图片创作 Agent 视觉方案

## 1. 文档信息

- **项目**：Cadence Aria 图片创作 Agent
- **版本**：v1.0
- **日期**：2026-08-03
- **适用范围**：`web/src/components/image-create/`
- **目标**：在不改变业务逻辑、不引入新依赖的前提下，为图片创作工作区确定与 Aria 主工作台协调的视觉方向。
- **推荐结论**：采用**方案① 融合 educational-platform 的信息组织方式与 Aria 视觉令牌**。

## 2. 调研依据

### 2.1 ui-ux-pro-max 结果摘要

使用以下检索生成设计系统并补充风格、交互和 React 落地建议：

```bash
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "AI image creation educational platform dashboard playful professional cohesive" --design-system -p "Aria Image Create" -f markdown
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "claymorphism educational platform playful card" --domain style -n 8
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "animation accessibility focus keyboard reduced motion" --domain ux -n 8
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "responsive forms cards accessibility" --stack react
```

检索结果中与本功能最相关的结论：

1. **Educational / creative tool** 适合块状卡片、明确层级、友好且有适度趣味性的反馈。
2. **Claymorphism** 的典型特征是 16–24px 大圆角、3–4px 粗边框、内外双重阴影、粉彩色与按压/弹性动效；可辨识度高，但对对比度、动效敏感用户和既有产品一致性提出额外要求。
3. **Flat Design / Bento Grid** 更适合 SaaS 与 dashboard：内容优先、模块边界清晰、性能和可访问性更稳定。
4. 交互应使用 150–300ms 的颜色或透明度过渡，避免 hover 缩放导致布局跳动；键盘焦点必须清晰；应尊重 `prefers-reduced-motion`。
5. 表单控件需保持显式标签、统一禁用态和可见焦点环。

### 2.2 Aria 现有视觉令牌

`web/src/styles.css` 已提供稳定的浅色工作台令牌，本方案不增加第二套主题变量：

| 角色 | Aria 令牌 | 当前值 | 图片创作中的用途 |
|---|---|---:|---|
| 页面背景 | `--aria-bg` | `#f6f8fa` | 工作区底色 |
| 主面板 | `--aria-panel` | `#ffffff` | 会话、对话、参数卡片、弹窗 |
| 弱面板 | `--aria-panel-muted` | `#fbfcfe` | 禁用控件、上传区、图片区 |
| 次级面板 | `--aria-panel-subtle` | `#f1f5f9` | hover 或低优先级区域 |
| 主文字 | `--aria-ink` | `#17202a` | 标题与正文 |
| 次文字 | `--aria-ink-muted` | `#52616f` | 说明、元数据 |
| 边界 | `--aria-line` | `#dde5ec` | 卡片与控件边界 |
| 强边界 | `--aria-line-strong` | `#c8d3dc` | hover/强调边界 |
| 主色 | `--aria-primary` | `#0891b2` | 主按钮、选中态、焦点环 |
| 主色浅底 | `--aria-primary-soft` | `#e0f7fb` | 选中会话、处理中、建议提示词 |
| 成功/警告/危险 | `--aria-success*` / `--aria-warning*` / `--aria-danger*` | 语义色 | 状态反馈 |

## 3. 方案①：融合（推荐）

### 3.1 核心概念

保留 educational-platform 的**块状卡片、学习路径式层级、友好反馈和轻微微交互**，但不复制儿童化配色和厚重立体材质。所有表面、文字、边界与状态均回到 Aria 现有令牌，使图片创作像 Aria 工作台中的一个专门工作区，而不是嵌入的另一款产品。

### 3.2 风格

- 布局维持“会话导航 → 创作对话 → 提示词/参考图/参数”的三级任务流。
- 主功能块使用 12px 左右圆角、1px 边框、轻量 `shadow-sm`；弹窗可使用同等级或略高阴影。
- 卡片内部以标题、辅助说明、操作区建立清晰层级；不增加装饰插画、漂浮图形或厚重 3D 元素。
- 选中会话、建议提示词、处理中状态统一使用 `--aria-primary-soft`，通过文字和边框共同表达状态，避免只靠颜色。
- 错误、警告和成功反馈分别使用现有语义色及其 soft 背景。

### 3.3 色彩

- **基础面**：`--aria-bg`、`--aria-panel`、`--aria-panel-muted`。
- **主强调**：仅使用 `--aria-primary` / `--aria-primary-soft`，不引入高饱和紫色、粉色或橙色作为第二品牌主色。
- **状态**：使用 Aria 的 success / warning / danger 语义令牌。
- **边界**：默认 `--aria-line`，hover 可提升到 `--aria-line-strong`。
- **对比原则**：正文坚持 `--aria-ink`，辅助文字使用 `--aria-ink-muted`；浅色背景上不使用过淡文字。

### 3.4 字体

- 继续使用 Aria 全局字体栈：Inter、系统无衬线字体。
- 标题采用现有 `font-semibold`，不引入 Fredoka / Nunito 等外部字体。
- 会话 ID 等机器可读信息继续使用等宽字体。
- 通过字号、字重、间距建立亲和感，而不是通过更换为儿童化圆体建立风格。

### 3.5 交互与动效

- 主按钮 hover 使用透明度变化，次按钮和可点击卡片使用背景/边框颜色变化；统一 150–200ms 的 `transition-colors` / `transition-opacity`。
- 不使用 hover scale、弹跳、视差或持续装饰动画，避免工作流界面显得躁动。
- 所有按钮、链接、选择框、输入框、文本域提供 `focus-visible` 主色焦点环。
- 禁用态同时提供 cursor 与 opacity 反馈。
- 沿用全局 `prefers-reduced-motion` 规则；不新增必须依赖运动才能理解的状态。

### 3.6 预期体验

- 新用户能快速识别从会话、对话、提示词到生成参数的任务顺序。
- 保留创意工具应有的友好感，但视觉重心仍是内容与生成结果。
- 与工作台其他设置面板、时间线卡片和状态提示保持一致。

## 4. 方案②：完整 Claymorphism（对照方案）

### 4.1 核心概念

完整采用 ui-ux-pro-max Claymorphism 建议：界面像柔软的实体积木或玩具面板，强调触感、圆润和愉悦性。此方案具有更强的独立品牌感，但会明显偏离 Aria 当前专业、克制的工作台风格。

### 4.2 风格

- 所有核心卡片使用 20–24px 圆角与 3–4px 粗边框。
- 使用内阴影 + 外阴影制造软 3D 体积；按钮呈现明显凸起和按下状态。
- 会话、提示词、参考图与参数模块使用不同粉彩底色，形成积木式分区。
- 弹窗、上传区和选择控件均强化“柔软材质”而非平面工具感。

### 4.3 色彩

建议完整粉彩组：

- Soft Peach `#FDBCB4`
- Baby Blue `#ADD8E6`
- Mint `#98FF98`
- Lilac `#E6E6FA`
- 浅暖灰或奶白背景

需要另行建立深色正文、边界与状态色，以确保 4.5:1 对比度。Aria 的 cyan 主色只适合作为品牌锚点，无法直接覆盖整套 Clay 配色。

### 4.4 字体

- 标题可使用 Fredoka 500–700。
- 正文可使用 Nunito 400–600。
- 需要引入字体资源、处理加载回退与离线环境；这不符合本 Task 的“无新依赖、轻量统一”边界，因此仅作为完整视觉概念记录。

### 4.5 交互与动效

- 按钮按下时使用轻微压缩、内阴影增强和 200ms ease-out 回弹。
- 可点击卡片 hover 增强阴影，active 呈现软按压效果。
- 动效必须在 `prefers-reduced-motion` 下关闭，并避免多个区域同时弹跳。
- 边框、阴影、按压效果之外仍需保留明确焦点环，不能只依赖材质变化表达键盘焦点。

### 4.6 预期体验与代价

优点是创意感强、易形成记忆点，适合独立的儿童教育、轻娱乐或强品牌创作产品。代价是视觉密度与阴影复杂度增加，专业工作台的内容效率下降；与 Aria 现有页面切换时会产生明显割裂，也需要新增变量、字体和更广泛的响应式/对比度验证。

## 5. 两方案对比

| 维度 | 方案① 融合（推荐） | 方案② 完整 Claymorphism |
|---|---|---|
| 风格 | 块状卡片、清晰层级、轻量友好 | 玩具感、软 3D、强材质与大圆角 |
| 与 Aria 一致性 | 高；直接复用现有面板和状态体系 | 低；需要建立独立视觉子系统 |
| 色彩 | Aria cyan + 中性面 + 语义色 | Peach / Blue / Mint / Lilac 粉彩组 |
| 字体 | 沿用 Inter / 系统字体 | Fredoka + Nunito 更完整 |
| 阴影/边框 | 1px 边框 + `shadow-sm` | 3–4px 边框 + 内外双阴影 |
| 交互 | 颜色/透明度过渡，克制稳定 | 按压、回弹、阴影位移，趣味更强 |
| 可访问性 | 更易维持既有对比度与焦点规范 | 需额外校验粉彩对比度和运动敏感性 |
| 性能与维护 | 无新依赖，修改集中在 className | 更多 CSS、令牌、字体与状态组合 |
| 适配产品定位 | 专业 AI 工作台中的创作工具 | 独立、面向轻娱乐或低龄用户的创意产品 |
| 本期落地成本 | 低 | 中高 |

## 6. 推荐理由

推荐方案①，原因如下：

1. **产品连续性优先**：图片创作是 Aria 工作台能力之一，不应在进入该页面后切换到完全不同的品牌语言。
2. **信息密度匹配**：多轮对话、参数、参考图和结果都属于高信息密度任务，克制的卡片和语义色比厚重 3D 材质更利于长时间操作。
3. **风险可控**：直接复用现有变量，无需新增字体、依赖或全局主题，能够避免影响既有页面与测试。
4. **可访问性更稳**：现有主文字、边界和状态色已形成可复用基线，焦点与 reduced-motion 规则也已存在。
5. **保留后续空间**：若用户定稿后希望增强创意感，可在保持令牌不变的前提下逐步调整卡片圆角、插图、空状态和局部微交互，无需推翻结构。

## 7. 对现有组件的最小落地改动清单

### 7.1 通用规则

- 将硬编码的 `white`、`blue-*`、`violet-*`、`red-*`、`amber-*`、`green-*` 替换为对应 Aria 面板、主色或语义变量。
- 卡片继续使用 `rounded-xl border border-[var(--aria-line)] bg-[var(--aria-panel)] shadow-sm`，不改变布局。
- 表单控件统一面板背景、主文字、hover 边界和主色 focus ring。
- 主按钮统一主色背景、白字、透明度 hover；次按钮统一面板背景、边界与 muted hover。
- 状态反馈统一 soft 背景 + 对应语义边框/图标；soft 背景上的正文使用 `--aria-ink`，以满足普通文本 WCAG AA 4.5:1 对比度。
- 只修改 Tailwind className，不改变 Zustand 状态、事件处理、API、DOM 语义或测试契约。

### 7.2 组件级清单

| 组件 | 最小改动 |
|---|---|
| `SessionList.tsx` | 新建按钮、弹窗按钮补 hover/focus；选中会话改为 primary soft；普通会话改用 panel；删除和错误态使用 danger 令牌；表单控件统一焦点与背景。 |
| `ChatPane.tsx` | 处理中与 busy notice 改为 primary soft；provider 消息和图片结果改用 panel；suggested prompt 改为 primary soft；系统/错误状态改用 warning/danger 令牌；输入与发送按钮统一交互。 |
| `PromptBlock.tsx` | textarea 使用 panel 背景、strong hover 边界和 focus ring；保留提示使用 warning 令牌。 |
| `ReferenceImageUpload.tsx` | 上传区、预览区和移除按钮统一 panel/muted/line 体系；hover 使用 panel/strong line；补可见焦点反馈。 |
| `ParamsPanel.tsx` | select 和生成按钮统一面板、禁用、hover、focus 样式。 |
| `SettingsDialog.tsx` | 弹窗圆角与其他卡片一致；输入、select、关闭/取消/保存/清除按钮统一交互；成功提示使用 success 令牌。 |

## 8. 本期不做

- 不新增图标库、动画库、字体或 CSS 依赖。
- 不重排页面网格，不改变响应式断点。
- 不改写组件逻辑、状态管理、API 或数据模型。
- 不为方案②实现独立主题开关。
- 不启动开发服务或进行视觉截图定稿；最终圆角、密度、空状态插画等细节留给用户/final review。

## 9. 视觉验收要点

- 375px、768px、1024px、1440px 下无新增横向滚动。
- 会话选中、处理中、警告、错误和成功状态可通过文字与颜色共同识别。
- 键盘 Tab 可遍历全部操作，焦点环清晰可见。
- hover 不发生缩放或布局跳动。
- 禁用态不可误认为可点击。
- 所有新增视觉表达均来自 Aria 现有变量或既有 Tailwind 工具类。

## 10. 业务全链路人工冒烟清单

> 启动后端与 `web` dev 服务后，按顺序完成以下业务闭环；每一步均记录实际结果。

1. **配置 Key**
   - 操作：打开图片创作“设置”，填写合法 `base_url` 与测试 API Key 并保存；重新打开设置。
   - 预期：保存成功，API Key 仅显示脱敏值，明文不出现在页面或日志中；未修改 key 再保存时 retain 行为正常。
2. **建会话并选择模板**
   - 操作：点击“新建会话”，选择“PPT 商务配图”模板与可用 Provider 后创建。
   - 预期：新会话出现在列表并可正常打开，模板与 Provider 信息正确，选中态和键盘焦点清晰。
3. **多轮迭代 Prompt**
   - 操作：第一轮发送图片主题、用途、受众和风格；收到回复后，第二轮提出构图、色彩或留白修改意见。
   - 预期：每轮对话均保留在历史中，每轮返回的 `suggested_prompt` 都更新对话中的 prompt 区块及右侧“建议提示词”；解析降级时保留上一版提示词。
4. **文生图**
   - 操作：不上传参考图，选择尺寸、质量、背景与输出格式，点击“生成图片”。
   - 预期：走文生图生成路径；忙碌期间输入和参数锁定，完成后正常出图并恢复控件，媒体类型与提示词信息正确。
5. **参考图生图**
   - 操作：上传一张不超过 10MB 的 PNG、JPEG 或 WebP，选择参考图保真度后生成。
   - 预期：显示预览与文件名，生成请求走 edits 路径；忙碌期间不能替换或移除参考图，完成后结果正常展示且参考图约束生效。
6. **不满意循环**
   - 操作：针对任一结果发送具体反馈，手动或通过 Agent 更新 prompt，再次生成；至少完成一轮“反馈 → 新 prompt → 再生成”。
   - 预期：新 prompt 正确更新并生成新结果，会话历史和已有结果不丢失、不串会话。
7. **删除会话**
   - 操作：先删除非当前会话，再删除当前会话，随后刷新页面。
   - 预期：目标会话从列表消失且刷新后不恢复；当前连接、生成状态及对应 scratch 数据被清理，结果不会回写到已删除会话，其他会话不受影响。
