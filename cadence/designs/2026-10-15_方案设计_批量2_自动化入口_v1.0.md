## 0. 结论摘要(先看这里)

1. 多仓授权:新增 `EnrollmentTarget` 变体承载「成员集合」(推荐),授权集合 = explicit selection 的 `included − excluded` 与 manifest 取交(与现有 `logical_repository_ids_for_preflight` 同口径,不用 focus)。真正的改动面不在 PUT 校验,而在「消费点」:`advance_plan.rs:281-305`(强制恰一桶)、`advance_plan.rs:358-368`(replay 拒多 attempt)、`coding_start.rs:844-863`(单 ID 互证)、`lower.rs:329-374`/`validate.rs:260-276,317-326`(单成员 target 语义)、编排器 `coding_chain_stage` 读「唯一 attempt」(`autopilot_orchestrator.rs:516-527`)。多 attempt 的 split 能力已存在(`advance_split.rs:27-52`,手动路径同一入口),自动化复用的关键缺口是「split 出的 attempt 一律 `start_run_policy=Manual`(`advance_split.rs:200-214`),而 Enrolled 首启要求 `AutoStartOnce`(`coding_start.rs:696-738`)」。
2. 自动批准:**重要发现**——引擎已有 `RunPolicy::AutoIfValid`(`work_item_plan_policy/types.rs:236-239`):评审 Valid 时 `routing.rs:682-683` 直入 `enter_policy_valid_work_item_plan_compile`,compile 成功后 `compile.rs:689-692` 经 `complete_policy_valid_work_item_plan` 自动落 Confirmed(`confirmed_by="auto_if_valid"`,`compile.rs:741-745`);HumanRequired 时 `StopNeedsHuman`→durable `StoppedNeedsHuman`+resumable 快照(`policy_routing.rs:80-83,146-150`),并已有「接管」把它变成 Interactive 子会话(`lifecycle_store/workspace.rs:419-527`,REST 入口 `handlers/workspace_session.rs:71`)。但现行自动化链**刻意禁用**该能力:绑定 plan session 永远 Interactive(`plan_preparation.rs:223-224`),rebind/binding 拒 AutoIfValid(`automation_enrollment.rs:127-131,304-308`),生成准入对 AutoIfValid 返回 NeedsHuman(`plan_generation.rs:279-283` 测试)。推荐方案 A:新增 enrollment 选项 `plan_approval: manual|auto`(默认 manual,旧数据不变),auto 时绑定 session 用 AutoIfValid 并放开上述 3 处约束;不推荐方案 B(编排器代点 Interactive 门),理由见 §3。
3. 新 SC 流程下「outline/draft/batch 逐步确认」不是现行路径:`plan_preparation.rs:146` 把新建 plan 的 flow 硬编码为 SingleCandidate;SC 流程里只有 Evaluate 后的 Approval 门与 Final Compile;legacy outline/draft/batch 的 WS 决策入站已退役(S-Approve §2,`decisions/inbound.rs:378-381`)。故 brief 第 3 项的 outline/draft/batch「自动通过」在现行代码中归结为:Approval 门 + Final Compile。AskUserQuestion 阻塞的是 provider run 本身(run 未结束就不会走到路由/Approval),因此方案 A 下「有提问就不会自动通过」是结构性保证,而非靠外部观察器判断。
4. 失败后继续:**plan 阶段与 coding 阶段分开**。plan 阶段=新增「继续自动化」REST(携带用户在对话窗口输入的上下文)+服务端重置 generation intent/重武装 Failed SC 会话;coding 阶段=沿用并扩展 coding 门动作(批 1 A4 `retry_coding_with_context`、既有 `retry_coding/retry_review`),门响应后 attempt 回 Running,编排器自动恢复观察,**不需要新的 enrollment 级继续命令**。
5. 终止:新增不可恢复的 enrollment `terminated` 终态 + 独立「终止自动化」REST(幂等、可重入),服务端按固定锁序做:写 terminated → 失效 CodingPlanRun → 取消 plan 阶段 run/置 session Terminated → 逐 attempt abort。FE 二次确认复用 `ConfirmTwiceButton`;自动化管理的 attempt 隐藏单 attempt 中止按钮(新增 snapshot DTO 字段 `automation_managed`)。
6. 通知:不建新通知模型;向批 1 A1 提出「扩展 kind + focus.session_id」需求(契约 B 区),批 2 自带 plan 阶段事实派生函数。
7. 批 1 依赖:A1(通知)、A2(plan 级确认按钮,最后一步)、A3(Coding Workspace 文件清单)、A4(coder 门补上下文)、A5(reviewer/coder 挂起=blocked gate)。文件面重叠见 §3(契约 C 区已同步登记)。
