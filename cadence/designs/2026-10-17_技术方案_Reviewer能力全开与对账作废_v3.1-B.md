# 技术方案: Reviewer 能力全开与对账作废(v3.1-B 档)

- 出具: 测试会话基于 v3.0 裁剪, owner 于 2026-10-17 拍板 B 档; **设计完成未实施**
- 定位: 替代 v3.0 的 A 档(独立 UID 物理铁律 55-70h)——B 档=软铁律+对账作废, ~25-30h
- 复用声明: 快照/窗口/提交通道守卫/启动补偿/纪律改法/group 覆盖的设计细节均沿用 v3.0 对应章节(该文档仍有效作为细节参考), 本文件只记录 B 档的裁剪决策与差异

## 一、B 档哲学

挡君子(prompt 纪律)+抓小人(对账发现违规即作废整轮审查+恢复现场)。不阻止恶意写入的发生, 但保证: 违规结果绝不进交付、必被发现、可恢复。覆盖全部已发生过的真实事故(构建残留/误提交/崩溃残留), 放弃对「恶意 reviewer」的物理防御(单机自用+自有仓库场景下概率极低, owner 知情接受)。

## 二、一场审查的生命周期

1. **拍快照**(S6): worktree 全目录项含 ignored(内容/类型/权限/symlink), .git/.aria 状态摘要, 运行中容器清单; 持久化到平台数据目录
2. **锁平台提交通道**(S15): 审查期间平台 stage/commit/push/journal 补偿全部拒绝(平台自身代码, 无需 UID)
3. **reviewer 全功能执行**(纪律 prompt 告知: 可自由验证; 禁 git mutation 与平台推进; 产物会被清理; 只输出报告)
4. **结束收口**(任何退出路径): 停进程/子进程/登记容器网络 → 对快照恢复 worktree(删新增/还原改动/保留 coder 未提交修改) → 清运行目录
5. **对账裁决**: .git/.aria 摘要无变化+恢复成功 → 采信报告; 有变化或恢复失败 → **整轮审查作废+告警+人工门**; 报告绑定受审状态(状态变了不采信)
6. **崩溃补偿**(S17): 启动时先查未关闭窗口 → 按原基线续恢复(不得把污染态重冻为新基线) → 恢复完成前禁止任何新材料采集/provider 启动

## 三、切片(B 档, ~25-30h)

| 切片 | 内容 | 规模 |
|---|---|---:|
| B1 最小鉴权 | Origin/Host 校验+一次性令牌(REST 状态变更+WS upgrade+敏感 GET); 防 CSWSH/DNS rebinding | 2-3h |
| B2 快照(S6 沿用) | 可恢复快照+恢复矩阵(staged/unstaged/untracked/ignored/删除/chmod/symlink) | 3-4h |
| B3 durable 窗口(S7 沿用) | 窗口状态机+持久化+未知归属停等 | 3-4h |
| B4 资源登记回收(S5 简化) | 容器/网络/运行目录登记+退出清理+启动补偿(不涉 UID/cgroup 高级形态) | 2-3h |
| B5 审查接线+提交守卫(S15 沿用) | 普通/retry/返修/终止全路径接窗口; 平台 mutation 不绕窗口 | 3-4h |
| B6 pi 接线+group 纪律(S10/S16 合并) | pi reviewer 走窗口化直跑; 删「提交责任归你」/「worktree 内复跑」注入; group shard/reduction/repair 纪律覆盖; **启动检查: 未接线 provider 不得担任 reviewer** | 3-4h |
| B7 启动补偿接线(S17 沿用) | 早于一切材料采集; 与既有 git journal 衔接 | 3-4h |
| B8 T1 提交分类(P1 可后置) | Bug 3 纵深 | 2-4h |

依赖: B1 独立先行; B2/B3 并行; B4-B7 依次; B8 最后。共享文件单一集成人。

## 四、砍掉项与知情接受(v3.0 A 档差异)

| 砍掉 | 后果(owner 已接受) |
|---|---|
| 独立 UID 基建(S3) | 恶意 reviewer 可写 .git/.aria——对账能发现并作废, 不能物理阻止 |
| 窄挂载保护(S4) | 同上; linked-worktree .git 指针可被删换(对账发现) |
| 凭据目录遮蔽 | reviewer 可读 ~/.ssh 等——单机自用+自有仓库场景接受 |
| claude/codex/kimi reviewer 适配(S11-S13) | 换 reviewer 前须先补接线(启动检查强制) |
| LC ReviewVerify action 深度改造(S9) | pi reviewer 现状约束(edit/write 工具禁)不变即可用; 其他家延后 |

## 五、红→绿(差异项)

| 编号 | 红场景 | 绿验收(B 档) |
|---|---|---|
| BR1 pi 现场同场景 | 构建+容器+自行提交 | 全功能执行+报告产出; worktree 恢复原样(coder dirty 保留); **自提交的 commit 存在但整轮审查作废+告警**; 平台不推进交付 |

## 六、升级路径

B 档不堵死 A 档: 快照/窗口/守卫全部复用; 未来触发架构评审 T1-T11 任一失效条件(跑不可信仓库/多用户等)时, 补 S3/S4(独立 UID+挂载)即升级为 A 档物理铁律。
