# 技术方案: 四 Provider 应用层去沙箱实施设计(v1.0)

- 出具: design-task-sol (DesandboxImpl), 2026-10-17, 受测试会话委托; **设计完成未实施(DONE_WITH_CONCERNS)**
- 严格只读(未读 .aria 内部/未运行构建测试); 源码事实经 worktree 物理复核(早期误入 bare 主仓根的结果已作废)
- 分层定位: 本方案=**通用执行基线层**; reviewer 例外层见 v3.0 方案; 与 v3 共享类型体系不建两套

## 1. 结论与范围(三层边界, 已裁决)

| 层 | 行为 |
|---|---|
| **Coding Coder** | 四家统一显式 HostCoding: 宿主同用户直跑、无 bwrap、无 no-new-privs、Aria 不撤编码工具; 白名单继承开发环境; 支持构建/测试/容器 CHECK |
| **Coding Reviewer** | v3 专属 ReviewerVerify(独立 UID/DAC/保护挂载/快照恢复), 本方案不重复设计, Coder 不依赖该基建 |
| **规划层** | Author/Orchestrator 现有策略/Kimi bwrap/基线树约束**原样** |

「工具全开」=Aria 不额外撤销 Coder 工具, 非取消原生审批/改所有角色政策。**Codex LC 两档与 approval 映射按 REQ-LCG-04 保留**, 不为「四家一致」改 danger-full-access。
推荐路径: 保留规划层 bwrap 原语, 为 Coder 增加显式 Host 执行选择——不全局删 sandbox.rs, 不把「Unavailable」长期冒充「主动宿主直跑」。

## 2. 关键事实(物理证据)
普通 Coder 本就无通用禁写策略(prompts.rs:651-680; streaming_provider:517-556 带策略反而拒绝); 四家主进程均普通宿主 spawn; kimi Auto 强制 bwrap(terminal_handlers:72-118)且限制不止 bwrap(固定 PATH/HOME=worktree 根/GIT_CONFIG_GLOBAL=/dev/null/120s/仅 bash -c); 同步旁路 CliProviderAdapter 不走 ProcessManager; **宿主 Git 会执行仓库 hooks(git_command 只设 LC_ALL, 无 core.hooksPath 覆盖)**; CHECK 无结构化 executor 字段; A' 仓库落点=verification-triage/command evidence(verification_surface.rs:257-358, 重跑唤回 Coder runner 非平台 runner)。

## 3. 统一执行 profile
新中性 ProviderExecutionProfile{HostCoding, ReviewerVerify}+ProviderRunResourceScope(进程/运行目录/容器资源归属清理)。规则: 受信 factory/gateway 装配→真实 spawn 消费同一冻结 profile; **prompt/ACP/env/自报 role 不得构造或升级**; 覆盖 Direct/LC/同步旁路/Kimi host terminal 全入口; 不全局改 ProcessManager::spawn 语义; 不动非 Coding 策略/Bootstrap/REQ-LCG-04。
四家一致性=共同下限: coder 均无 Aria deny 片段/共同白名单环境/HOME=owner HOME(kimi 不再指 worktree)/保留进程组回收/原生权限差异保留。
**环境=白名单继承**(env_clear+两层注入): 第一层精确变量名(PATH/HOME/LANG/LC_*/TZ/TERM/JAVA_HOME/XDG_*/代理/容器连接变量, 工具链变量经配置显式增); 第二层受信 run 注入(provider 认证/包仓库凭据/短期证据 token/TMPDIR)。GH_TOKEN/AWS_*/NPM_TOKEN/*_API_KEY/SSH_AUTH_SOCK **不默认继承**。Coder 保留 owner HOME=能力兼容(登录态/trust/缓存/Podman 配置), **非安全隔离——不声称 Coder 凭据不可达**; kimi HostCoding 不再强制 GIT_CONFIG_GLOBAL=/dev/null(与其他三家一致)。

## 4. Kimi 实施点
三路线比较: 全局删 bwrap(不采用, 超范围)/默认 Unavailable(可行但语义伪装, 不作长期)/**显式 Host 分支(推荐)**。不得偷换 permission_mode 为 Supervised 复用。
变更面: ①client_services/mod.rs dispatcher 消费 profile(HostCoding 不探测 bwrap, 规划角色旧探测) ②terminal_handlers.rs isolation_for 先分 profile; HostCoding 按 ACP command+args[] 执行**不限 bash -c**; legacy 字符串按 shell 执行不走只读 grammar; 规划角色原样; coder cwd=worktree 与 LC 主进程 cwd 不混 ③terminal.rs 增 Host 直接分支(无 bwrap/no-new-privs/netns); 共同环境构造器替代 terminal_environment(root); 保留进程组/输出预算/幂等回收/ETXTBSY 重试; MAX_TERMINALS/1MiB 保留为资源护栏 ④sandbox.rs **不全删**(openat/O_NOFOLLOW 仍用; bwrap 原语留规划层; 只清 coder 路径死代码) ⑤session.rs 传 profile/环境/总 deadline。
**预算不能只改 120s**: 规划层保 120s; HostCoding 无独立 120s 硬上限, 有效 deadline≤受信 invocation 总 deadline; VerificationCommand.timeout_seconds 用于预算声明, 超总预算须启动前暴露为配置问题; **resume 60s stall 检测不能在真实活动 terminal CHECK 期间判死**(session.rs:670-671 NotProgress + :904-909 短预算, 需增「活动 terminal」可观测状态); 无活动工作无进展的 stall 保留。

## 5. OpenSpec 变更(delta 语义, 实施用 MODIFIED 不悄悄删)
- MODIFIED 终端 OS 级隔离(auto): HostCoding 在宿主当前用户直接执行, 无 bwrap/netns/no-new-privs, bwrap 缺失不阻止; Auto/Supervised 只管审批不得代替 profile; 非编码角色原样; 记录 profile+部署上下文, **不得记为「已隔离」**。三场景: 无 bwrap 正常/构建容器命令不被阻止/规划层未放宽
- MODIFIED 终端策略与 grammar: HostCoding 接受普通 argv+legacy shell 形式, 无只读白名单/解释器限制; 子进程用白名单环境+显式注入, HOME 不指 worktree; 规划角色原样
- MODIFIED 权限与路径沙箱: coder fs 服务保留 worktree 内校验(API 行为), 不宣称约束 HostCoding terminal 宿主可达; 非编码角色原样
- 终端生命周期: 区分规划 120s 与 HostCoding deadline, 保留并发/输出/截断/回收

## 6. 应用层保留护栏
- **API 鉴权(无条件公共前置)**: 复用 v3 共同设计不建第二套; 现状无入站鉴权中间件(app.rs:631 直接装配 state); 该工作包单 owner 与 v3 一次实施; 残余边界: 非同 UID 恶意 coder 的物理边界
- **.git/.aria 选型留痕**: 窗口式权限预置(不推荐, 备查——同 UID 可恢复 chmod, .git 禁写阻断合法提交)/审计+对账(**推荐**——发现不阻止)/不做(不推荐)。coder 合法 .git 提交保留; .aria 异常变化告警对账
- **宿主 Git 加固(本次必做)**: git_command 统一 `-c core.hooksPath=/dev/null -c core.fsmonitor=false`, 阻断「coder 写 .git/hooks→平台 Git 在 owner 上下文自动执行」桥; 文档明示平台交付不执行仓库 hooks
- **产物清理(扩展到 coder, 不复制 reviewer 整树回滚)**: 共享 ProviderRunResourceScope 最小归属(run_id/boot identity/PID start identity/运行目录/登记容器/cleanup cursor); coder 窗口 kind=code_delivery, Preparing→Running→Quiescing→Reconciled→Closed; 统一规则(先登记后执行/先 quiesce 再清/启动补偿/PID 复用防护/三入口全登记); **不调 reviewer baseline restore; 保留源码/提交/dirty/共享缓存/用户容器; 只清 run-owned 临时产物; 禁按目录名无差别删/git clean/整树 reset**; 未登记 detached 进程不保证回收

## 7. CHECK 与 A' 变化
主路径=coder 自己执行 CHECK(构建/测试/依赖/容器); executor 标注定义为「环境能力声明」(JVM/Node/网络/容器)非路由指令; 本期不扩 canonical schema(prompt/purpose/说明文本输出); 标注≠授权, 不覆盖 Codex LC 原生约束; A'(verification-triage)保留为外部硬件/人工检查/临时缺项补充; 缺依赖/认证失败/权限失败/断言失败**分类清楚不都归「沙箱失败」**; 重跑仍唤回 Coder runner。

## 8. 二期 dev-sandbox 最小接缝
deployment_context 仅进 profile 冻结快照(默认 HostLocal), 不扩公开 API/DTO/178 处字面构造。本期记录: profile 版本/deployment context/resource scope/环境策略版本/原生权限画像引用。二期由部署 launcher 实现新 context, **provider+本地 MCP+ACP terminal/fs 一起进容器**(不能只容 CLI 而 kimi host terminal 回宿主)。本期不实现调度器/镜像/挂载 DSL/静默回退(未知 context 显式拒绝)。

## 9. 红→绿与测试处置
新增红测: 无 bwrap 正常/profile 身份不可自报/四家一致性/环境(工具链可用+token 不出现+HOME≠target)/命令形态(直接 argv+shell 管道+legacy)/长 CHECK(超 120s 在总预算内完成; 活动 terminal 不被 stall 杀)/资源清理(只清 owned)/Git bridge(hooks 探针不触发+合法提交成功)/Codex LC 不变/API(401/403/alias/WS/敏感 GET)。
bwrap 测试处置: 保留为规划层回归(bwrap_args/mount order/pointer symlink/规划隔离/grammar/baseline); **移除 coder bwrap 行为断言**(executor_writable_root_* 等, 换 HostCoding 提交测试——契约变化非放水); 混合 LC 测试拆分(fs API 仍限 target; terminal 不宣称 target-only; 读 sibling 成功; 不再 skip); 生命周期测试保留。
真实验收(controller 统一): 实际 kimi coder 跑 Maven/npm fixture 构建测试; 实际 Podman CHECK(rootless 覆盖 build/run 非 --version); 四家 spawn fixture; 规划/v3/LC 回归; hooks/取消/崩溃补偿; openspec validate --strict。**宿主缺工具/登录态记录缺失前提, 不 skip 后谎报全通**。

开放假设: 验收机具备 CLI/工具链/容器引擎/登录态, 验收前列版本清单; 不宣称任何 CHECK 已通过。
