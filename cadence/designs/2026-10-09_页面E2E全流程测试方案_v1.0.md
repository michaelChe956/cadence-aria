# 全流程页面 E2E 测试方案(设计稿 v1.0,Ruling 17 形式 A)

> 状态:设计待用户确认(§6 三个偏好点)→ 确认后实施。
> 定位:收官「全流程真实 E2E 一轮」的浏览器驱动形态;验证面=矩阵(后端 API/WS)未覆盖的**前端交互+人视角全链**。

## 1. 目标与边界

| 项 | 决定 |
|---|---|
| 验证面 | 前端页面真实渲染/按钮真实点击/状态真实流转 + 后端全链(product+provider+git) |
| 不重复验证 | provider 广度(四家矩阵已收官)、后端协议细节(40+live 已钉)——本轮用**单 provider 走深** |
| 通过判据 | 全流程走到交付终态(issue completed)+每阶段页面断言+越界零发生(成员主仓 mtime/digest 前后)+证据链(每步截图+trace) |

## 2. 复杂案例设计(4 成员仓×跨 3 模块功能)

**成员仓(4,比矩阵 +2)**:`alpha`(聚合文档/门面)、`beta`(核心服务)、`gamma`(接入方 A)、`delta`(接入方 B)

**功能主题**:「跨仓通知系统」——beta 新增通知服务 API;gamma/delta 各自接入(订阅+回调处理);alpha 汇聚文档与示例。天然要求:
- story 涉及多仓(打破单仓叙事)
- design 的 involved/change_order 跨仓(beta→gamma→delta 依赖链)
- plan split 产出**多 work item**(预计 3-4 个,分属不同成员仓)
- coding 至少两仓真实产出代码;review 跨仓审视

**规模预期**:story/design/plan 各 1 会话+coding 3-4 会话+review 1-2 会话;人工门(页面确认/修订反馈/分诊)约 12-20 次。

## 3. 页面旅程(真实路由,全部真实点击)

```mermaid
flowchart LR
    A[/ 首页 ChatCockpit] -->|真实点击建项目/LC/登记 4 仓| B[聚合初始化]
    B -->|workbench 发起 issue| C[story 生成]
    C -->|页面门:确认/修订反馈| D[design 会话]
    D -->|页面门:确认| E[plan 会话]
    E -->|SC 门/修复循环页面应答| F[split 多 work item]
    F -->|coding 页逐项:分诊门/choice/终门| G[review]
    G -->|页面确认交付| H[issue completed 终态]
```

关键页面断言(每阶段):
- ChatCockpit(`/`):inbox 项出现/门卡片渲染/choice 选项与后端一致/confirm 后状态翻转
- ChatWorkspace(`/workbench`):会话列表/工件(artifact)可见/plan 修订反馈入口
- CodingWorkspace(`/workbench/.../coding/$attemptId`):gate 按钮可点/verification triage 选项/plan-repair 出现与恢复/reports 出现 commit 记录/group-progress 多 work item 并进
- 终态:issue completed 标识+推送记录可见

## 4. 技术形态

| 层 | 选择 | 理由 |
|---|---|---|
| 驱动 | **Playwright(Chromium)** | 真实点击/截图/trace/网络观测一站;仓内已有 vitest 前端基建,Playwright 独立 e2e 目录不混入 |
| 位置 | `e2e/`(新顶层目录:`e2e/full-flow.spec.ts`+`e2e/fixtures/`+`playwright.config.ts`) | 与 web/(单测)/tests/it_web(后端)三分离 |
| 环境装配 | 复用矩阵 env 思想的最小子集:启产品 server(真 build 的 web/dist)+夹具 4 仓(git init+文件骨架)+bare origin;**不复用 harness.rs**(页面轮独立装配脚本,Node 侧) | 页面轮不依赖 Rust 测试二进制 |
| provider | **claude**(2.1.283) | 四家已矩阵收官;页面轮走深单家控时(全流程预估 2.5-4h) |
| 断言双面 | 页面(可见状态)+抽验后端 durable(cell 思想:每阶段结束 dump 关键 API 状态比对) | 防止「页面绿后端空」的假通过 |
| 越界守卫 | 全程看门狗:每阶段间隔快照 4 成员主仓 HEAD/porcelain,漂移即 fail 并截图 | Task 11 精神在页面轮的延续 |

## 5. 通过判据与证据

1. 全流程达 issue completed(页面终态断言)
2. 阶段断言全绿(每门都真实点击过,choice/分诊有选择记录)
3. 4 成员主仓零越界(前后 digest)
4. 证据包:`e2e/artifacts/<run-id>/`(每步截图+Playwright trace+阶段 API dump+看门狗日志)
5. 报告:落 `cadence/reports/2026-10-XX_验收报告_全流程页面E2E_v1.0.md`
