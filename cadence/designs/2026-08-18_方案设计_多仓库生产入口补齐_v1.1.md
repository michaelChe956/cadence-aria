## 1. 目标与范围

补齐多仓库支持（BCD 全阶段）经双轮审计确认的 6 项生产入口缺口，使人工测试可以按 `cadence/notes/2026-08-18_人工测试矩阵_BCD多仓支持.md` 的 P0 主线从登记一路走到规划。

**完成定义**：it_web 通过**真实 HTTP 端点**复现 REG-01 / INIT-01 / IDX-01 / PLN-01（含多仓 Design `change_order` blocker，PLN-05），且单仓 project 行为零变化（默认 feature disabled 不变）。

**出界（后续 change）**：selection 显式编辑 UI、索引定时轮询兜底（`poll_due` 仅保留库能力，不声称有生产 scheduler）、单仓→多仓升级迁移、50 成员生产压测。

## 2. 已确认的产品决策（用户拍板）

| # | 决策 |
|---|---|
| D1 | 多仓库模式=按 project opt-in：创建时勾选，创建后不可切换 |
| D2 | 登记 UI=逻辑代码库页"登记成员"弹窗向导（填聚合根 → 预检分类 → 勾选确认 → 提交 → 结果/恢复） |
| D3 | 聚合初始化=begin → 共享 registry lease → tokio::spawn(execute)，cancel 经 CancellationToken，step 边界检查 |
| D4 | selection=多仓 project 创建 issue 时服务端自动写 all_members（请求体不变） |
| D5 | 索引触发三层：初始化成功尾步首建 + resolver 读时 stale sync + 手动重建（同步） |
| D6 | 登记与索引重建均**全同步**（POST 返回最终结果），前端配 loading 动画 |
| D7 | 首个登记批次提交时原子创建 manifest（用户提交的 aggregate_root 为准） |

## 4. API 契约

### 4.1 登记（新建，全同步）

```
POST /api/projects/{pid}/logical-codebase/registrations/preflight
  body {aggregate_root, candidate_paths[]}
  → 200 {preflight_id, preflight_revision, items[{path, class, reason?, profile?}]}
  服务端顺序：AggregateRootPreflight::validate → coordinator.preflight（B-6 修复）
  class 稳定枚举：eligible / non_git / duplicate / nested / needs_attention / missing / outside_root
  （注：candidate enum 有 dirty 但生产 classifier 对脏仓返回 needs_attention，API 以 needs_attention
   单一状态呈现，UI 标注 reason=dirty；preflight 结果由服务端冻结持久化，preflight_id 供提交引用）

POST /api/projects/{pid}/logical-codebase/registrations
  body {aggregate_root, preflight_id, confirmed_paths[]}
  → 200 {batch_id, status: completed|partial_failed, items[{path, status, reason?}]}
  同步执行：TOCTOU 复验（coordinator 既有 preflight_revision 机制）→ 逐项 attach_member
  首批次原子创建 manifest（D7）；revision 漂移项标 needs_attention 跳过
  preflight_id 不存在/过期 → 404 registration_preflight_not_found
  单仓 project 调用 → 409 logical_codebase_feature_disabled

GET /api/projects/{pid}/logical-codebase/registrations/{batch_id}
  → 200 批次详情（含单项状态/失败原因）

POST /api/projects/{pid}/logical-codebase/registrations/{batch_id}/resume
  → 200 同步重跑未完成项（含义同上）

POST /api/projects/{pid}/logical-codebase/registrations/{batch_id}/cancel
  → 200 终止 partial/needs_attention 批次（终态标记 cancelled，非进行中取消）
```

revision 漂移后只能新建批次（旧批次终态保留可审计）；不提供单 item 重新确认端点（YAGNI）。

### 4.2 聚合初始化（既有端点，行为修复）

```
POST /api/projects/{pid}/logical-codebase/initializations
  → 202 {operation_id}
  handler：coordinator.begin → AggregateOperationRunRegistry.register(lease+token)
           → tokio::spawn(execute)
  execute：Created→Running→machine_skills→aggregate_preflight→3×provider turns→Completed/Failed
  cancel：POST …/{operation_id}/cancel → 取 token → cancel()；execute 在 step 边界检查
          → Cancelled；provider turn 结束后不再推进
  服务重启恢复：GET 时 Running 且 registry 无 lease → recover_interrupted（标 Failed +
          interrupted reason）；人工重触发=新建 operation，不复活旧 id
  生产依赖：AggregateInitializationDependencies 使用真实 skills 准备、AggregateRootPreflight、
          index 接线（替换 NoopSkills/NoopPreflight，B-2 修复）
```

索引首建挂接：execute 成功尾步 spawn `AggregateIndexOperation::build`（包 single-writer 锁，B-4 修复）；首建失败不回滚初始化，索引状态=missing+失败原因（无 last-known-good 时不用 degraded，m-4），可手动重建。

### 4.3 聚合索引（新建，同步）

```
POST /api/projects/{pid}/logical-codebase/aggregate-indexes/rebuild
  → 200 {record}（spawn_blocking 执行，前端 loading；single-writer 锁，
        并发重建 → 409 aggregate_index_rebuild_in_progress）

GET /api/projects/{pid}/logical-codebase/aggregate-indexes/active
  → 200 {state, revision, indexed_at}
  state 映射：Active→active；Stale→stale；Degraded→degraded；
        无记录→missing（404 body 仍 200 + state=missing，便于前端渲染）
        Building→rebuilding；Superseded→不可见（取最新非 superseded）
```

快照语义（M-10）：apply_index 改为 before-snapshot → CodeGraph 命令 → after-snapshot；期间成员 HEAD/dirty 变化则该 record 标 stale（不静默丢弃），active record 引用 before-snapshot 组。

resolver 读路径（M-8/M-9）：PlanningContextResolver 在读 `active_required` 得 Stale 时调 `FreshnessService::sync_if_stale`（spawn_blocking）；修 `assess` 对 Degraded 记录无条件返回 active 的 bug（保留 last-known-good 告警语义）；Degraded 不自动重建，注入规划上下文告警。

### 4.4 issue 创建（变更）

```
POST /api/projects/{pid}/issues（请求体不变）
  多仓 project 分支（补偿事务，M-4）：
    预校验（manifest 存在 + active members 非空）
    → IssueStore::create_with_repository（repository_id 必须属于 manifest active member）
    → IssueCodebaseSelectionStore::save(all_members)
    → save 失败：删除刚建 issue → 422 issue_selection_write_failed；
      删除也失败：记录 orphan 告警日志并 500（人工修复路径）
```

多仓 project 的 legacy repositories 端点（M-7）：GET 返回成员投影；POST/DELETE → 409 `legacy_repository_endpoint_on_multi_repo`（body 指引走 registrations）；单仓 project 行为完全不变。

## 5. 数据流与生命周期

- **登记**：无后台任务。请求内同步执行；幂等由 coordinator 既有批次机制保证。
- **初始化**：唯一 spawn 长任务。lease/token/registry 全部 AppState 共享（B-1）；worker panic 时 lease Drop 自动清理（lease 持有移到 worker 任务内）。
- **索引**：首建（初始化尾步 spawn）/读时 sync（spawn_blocking）/手动重建（同步 spawn_blocking）统一走 single-writer 锁。
- **selection**：issue 创建同步补偿事务。

## 6. 错误码汇总（新增稳定码）

| 码 | HTTP | 场景 |
|---|---|---|
| logical_codebase_feature_disabled | 409 | 单仓 project 调登记/索引/逻辑初始化 |
| registration_preflight_not_found | 404 | preflight_id 过期/不存在 |
| registration_preflight_revision_changed | 409 | 提交时 TOCTOU 复验失败（整批拒绝） |
| registration_batch_not_found | 404 | 批次不存在 |
| registration_batch_not_cancelable | 409 | 已终态批次不可 cancel |
| aggregate_index_rebuild_in_progress | 409 | 并发重建 |
| aggregate_index_unavailable | 422 | 规划读索引缺失（既有） |
| legacy_repository_endpoint_on_multi_repo | 409 | 多仓 project 调 legacy 端点 |
| issue_selection_write_failed | 422 | selection 补偿失败 |

既有稳定码族（routing/change_order/manifest_missing 等）继续沿用。

## 8. 风险与遗留

- `replace_active` 跨文件非事务（m-5）：single-writer 锁解决并发，进程崩溃窗口保留为已知限制，park（与既有行为一致，不恶化）。
- 18 处 `RepositoryStore::new` 替换为 `for_project` 是最大侵入面，Plan 中列为独立 task + 逐点核对清单。
- `poll_due` 定时兜底不在本轮（D5 出界），规格 REQ-IND 的"定时"场景以手动重建 + 读时 sync 满足，delta spec 中显式说明。
