# Design: spec-workbench-canvas-experience

## 1. 布局结构（阶段驱动）

**平时（非 author_confirm）**：`执行节点栏 | 对话流（全宽）`（现状不变）。

**author_confirm 触发**：右侧滑出产物审核面板，三栏并存：
```
┌──────────┬────────────┬──────────────────────────┐
│ 执行节点  │ 对话流      │ ┌──────────────────────┐ │
│ （常驻）  │ （收窄）    │ │ [本轮改动▾ 折叠条]    │ │
│          │            │ │ # Story Spec          │ │
│          │            │ │ （artifact 全文）       │ │
│          │            │ ├──────────────────────┤ │
│          │            │ │ [采纳Review] [送审][定稿]│ │ ← sticky 吸顶
│          │            │ └──────────────────────┘ │
└──────────┴────────────┴──────────────────────────┘
```

**切换逻辑（全部由 stage 驱动，无手动开关状态）**：
- 进入 author_confirm（产出/修订/review 报告回来）→ 面板滑出展示当前版本
- 用户聚焦对话输入区开始输入 / 点「返回对话反馈」→ 面板收起，对话全宽
- 新一轮运行开始（Revision/CrossReview 进入 Running）→ 面板保持收起
- 送审/定稿后 → 面板随阶段离开 author_confirm 收起

**面板组成**：顶部工具条（标题 + 版本切换 + 收起钮）→ 本轮改动摘要折叠条（默认展开）→ artifact 渲染区（复用并放大现有 ArtifactPane 的 markdown 渲染）→ 吸顶操作条（采纳 Review 意见 + 送审/定稿）。

**三栏宽度策略**：节点栏固定 ~200px；面板默认占剩余 ~60%；对话流收窄保底 ~320px；1440px 以下面板可覆盖对话区（overlay 模式），ui-ux 规范中定断点。

## 2. 三动作分层映射

| 动作 | 位置 | 样式 |
|---|---|---|
| 送审 / 定稿 | 面板吸顶操作条 | 成对；默认推荐项 btn-primary（蓝紫实心），另一项 btn-secondary（白底粗边框） |
| 采纳 Review 意见 | 面板吸顶操作条左侧 | btn-secondary；仅对话流有 review 报告时显示 |
| 发送反馈 | 对话输入区（输入框右侧） | 中性次级；不与终局确认并排 |
| 返回对话反馈 | 面板工具条 | 文本钮，收起面板 |

## 3. 视觉规范（token 映射，写入 design-system/MASTER.md）

| 维度 | 现状 | 目标 |
|---|---|---|
| 主色 | #0891b2 青 | #4F46E5 蓝紫（primary） |
| CTA 强调 | 无独立 CTA 色 | #F97316 橙（主按钮/激活态；selection 已有先例） |
| 页面底色 | #f6f8fa 冷灰 | #f5f3ee 微暖奶油（面板保持白色卡片） |
| 边框 | 1px #dde5ec | 2-3px var(--text) 深色边框（卡片/面板/chip） |
| 圆角 | rounded-md | rounded-xl（16px）/ 2xl（24px） |
| 标签 | 常规 | 胶囊 chip：rounded-full + 2px 边框 |
| 阴影 | 细单层 | 柔和单层（禁用双层硬阴影） |
| 字体 | Inter | Inter/DM Sans 无衬线（禁用衬线正文） |
| 反模式 | — | 无 emoji 装饰图标、无 hover scale 位移、transition 150-300ms |

实施方式：`styles.css` 的 --aria-* 变量值更新（保留变量名，改值 + 新增 --aria-cta），组件类向规范收敛；MASTER.md 由 ui-ux-pro-max 生成并按上表定制。

## 4. 行为兼容

spec-design-dialog-revision 的全部行为契约不变：stage 机、决策语义、provisional、review 回对话流、采纳按钮预填逻辑——本 change 仅改呈现层。既有前端测试断言类名/结构的需随样式迁移更新，行为断言不变。

## 5. 决策记录

| 决策点 | 选择 | 备选与理由 |
|---|---|---|
| 审核视图形态 | Canvas 阶段驱动面板 | 双栏/Tab/全屏模态均讨论过；用户确认对话主场+审核时刻切换 |
| 布局参考 | 自研三栏（节点常驻） | Kiro 文档主视图被用户否定 |
| 视觉风格 | Claymorphism 形态借鉴 + 蓝紫橙（B 方案） | A 方案（保留青）借鉴感弱 |
| 风格边界 | 借形不借幼稚（无 emoji/放大/双影/衬线） | 工具专业性要求 |
| M2 联动 | 砍掉（无诉求） | story 变更→design 作废语义，暂不需要 |
| M3 范围 | 规范全站 + 实施只落 spec 工作台 | 全站一次改规模失控 |

## 6. 测试策略

- 组件测试：面板滑出/收起的阶段驱动（author_confirm 进出）、吸顶操作条可见性、改动摘要条渲染与折叠、按钮迁移后的三动作行为复测、采纳按钮面板内行为。
- 样式回归：token 变更后关键页面快照/类名断言更新。
- 全量：`cd web && pnpm tsc -b && pnpm test`；后端无改动（cargo check 保持绿即可）。
