# Design: Scalable Group Final Review

## 架构总览

组级审查改为三段式：Rust 侧确定性编译、分片语义审查、全局归约。

```text
Authoritative Bindings / ReviewRequest / Unit Review Conclusion Snapshots / Git 与 Handoff 事实
                                    │
                                    ▼
                    Group Review Material Compiler（Rust）
              确定性检查 + 全局关系图 + 按风险选择变更片段
                                    │
                     ┌──────────────┴──────────────┐
                     ▼                             ▼
        Affinity Partitioner（每片最多 4 项）   Global Compact Ledger
                     │                             │
                     ▼                             │
              Leaf 语义审查（Provider）             │
                     │                             │
                     └────── Shard 结论 ───────────┐│
                                                   ▼▼
                                     Final 归约审查（Provider）
                                                   │
                                                   ▼
                              既有 Group Finding Validator 与 Flow Decision
                                                   │
                                                   ▼
                                            InternalPrReview
```

Work Item 数增加时，Leaf 调用数增加，单次调用输入不增长。

| Work Item 数 | Leaf 调用 | Final 调用 | 合计调用 |
|---:|---:|---:|---:|
| 2 | 1 | 1 | 2 |
| 5 | 2 | 1 | 3 |
| 10 | 3 | 1 | 4 |
| 20 | 5 | 1 | 6 |

## 职责边界

### Rust 侧承担确定性判断

以下检查具有确定性结论，必须在调用 Provider 前完成，其结果作为候选发现或明确门禁：

1. 权威 Binding 与 Handoff 完整性：Run 完成状态、Work Item Revision、Projection Bundle 标识与版本、已解析 Handoff Revision 一致性。
2. 契约与能力精确匹配：必填契约缺失、必填能力缺失、多提供者歧义、消费方来源未声明、孤立产出、跨片契约边。
3. 写入范围与归属：变更路径命中禁止范围、允许与禁止范围交集、同一文件被多个 Work Item 修改、变更片段归属不唯一。
4. Commit 与证据一致性：审查请求 Commit 可达且包含各项完成 Commit、最终变更基线与头部正确、必需证据引用归属正确且字段完整。
5. Requirement 与验收标准聚合：缺失、重复声明、Revision 不一致、已确认 Requirement 未被覆盖。
6. Finding 可路由性预校验：Reason Code、允许路由、目标种类与契约引用的合法集合。

### Provider 承担语义判断

1. 多个 Work Item 合并修改同一文件后的语义冲突。
2. 契约名称或能力相近但实现消费语义不一致。
3. 多 Work Item 对同一 Requirement 的覆盖是否名义重复而实质遗漏。
4. 最终变更、证据状态与交付叙事是否自相矛盾。
5. 影响范围、PR 描述与提交信息建议的生成。
6. 对 Rust 标注的可疑跨片关系与变更片段做语义判断。

## 材料模型

### 材料快照

组级审查启动前生成不可变快照，包含 Schema 版本、Attempt 标识、审查请求标识、基线分支、最终 Commit、权威 Binding 摘要、单位记录集合、全局关系图、变更索引、确定性发现与内容哈希。

快照采用稳定排序与规范化序列化计算哈希。重试必须复用同一快照。以下事实变化时生成新快照，并使受影响的分片结论与归约结论失效：Work Item 返修产生新的完成 Commit、Work Item Revision 变化、Handoff Revision 变化、审查请求 Commit 变化、权威 Binding 变化。

### 单位记录与全局账目

Leaf 使用的单位记录保留组级语义必需内容：身份标识、依赖关系、写入范围摘要、契约接口摘要、证据状态摘要、可路由目标摘要。它不复制完整 Reviewer Projection。

Final 使用的全局账目行进一步折叠为身份摘要、所属分片、Commit 状态、证据状态、共享范围标记与未决接口计数。

### 单位审查结论身份快照

既有单项审查报告记录缺少 Work Item 身份字段，不能作为组级聚合的身份来源。新增独立记录，在单项审查成功持久化时同步生成，携带 Attempt、Unit、Unit Run、逻辑 Work Item、Work Item Revision、报告标识、结论、发现摘要、证据与变更引用、原始报告哈希。

缺少该记录的历史数据不得按顺序或轮次推断身份，必须以明确的身份缺失原因失败关闭。

### 分片与归约产物

分片结论与归约结论作为后端审计产物持久化，携带所消费的快照哈希、参与的 Unit Run 标识、分片理由、结论、发现、未决义务、所选变更引用与原始输出引用。最终用户可见结论继续使用既有 InternalPrReview。

## 分片策略

每个分片最多 4 个 Work Item。

分片依次按以下亲和性归组：强 Handoff 依赖边、共同修改文件或范围重叠、相同契约边界、相同拓扑层、稳定顺序补位。目标是让强耦合项尽量落在同一分片。

当强耦合连通分量超过分片上限时，采用稳定最小割分片。所有被切断的契约边、共享路径边与归属歧义边必须进入全局跨片关系集合，并在归约阶段审查。

## 变更片段选择

不得把完整变更或固定长度前缀直接放入 Prompt。

变更索引始终完整提供：路径、增删行数、归属 Unit Run、共享与歧义标记、范围违规标记。

Leaf 片段按以下优先级选择：本分片共享文件、范围异常、契约相关文件、归属歧义片段、每文件至少保留头部，剩余预算按风险分配。

Final 片段只提供真正跨分片的共享、歧义、范围与契约可疑片段。普通单项变更已由单项审查覆盖，不占用组级预算。

所有片段必须经过敏感信息脱敏与按字符边界的安全截断，并标注截断状态、脱敏状态、原始片段哈希与未展示数量。

## 预算与门禁

| 项目 | 取值 |
|---|---:|
| 单次 Prompt 质量目标 | 28 KiB |
| 单次 Prompt 硬上限 | 30 KiB |
| 分片最大 Work Item 数 | 4 |
| 分片结论最大发现数 | 8 |
| 归约结论最大发现数 | 16 |
| Leaf 并发上限 | 2 |

每次构建 Prompt 后记录分段字节：固定协议、身份、单位记录、证据摘要、关系图、变更片段、重试诊断预留与总计。

行为规则：不超过质量目标时正常发送；介于质量目标与硬上限之间时发送并记录告警；超过硬上限时禁止调用 Provider，持久化溢出诊断。单个字段超限时不得静默截断身份信息，应进一步分片或进入溢出门禁。

## 发现合并

发现使用结构化指纹合并：缺陷类别、原因码、修复目标标识、契约引用、能力引用、规范化路径、变更片段标识共同参与计算。

合并规则：相同指纹合并证据与来源；严重度取最高；结论按阻塞高于要求修改高于通过规约；目标、片段或契约引用不同的发现一律保留；不使用文本相似度自动合并；计划类缺陷不得被实现类发现覆盖。

## 失败与重试

### 分片失败

分片的 Provider 调用失败或未产出结论 JSON 时，仅针对该分片执行一次小型结论转写补救，补救输入不得重新包含完整分片材料。补救失败后保存原始输出与补救输出，进入分片输出无效门禁。其他成功分片不重跑。未完成全部分片时不得进入归约通过。

### 分片要求修改

目标唯一时按既有流程路由对应 Work Item 返修或计划修订。新的完成记录或 Revision 使该分片、相连跨片关系与归约结论失效。输入未变化的其他分片结论可复用。

### 归约失败

归约调用失败或未产出结论 JSON 时先执行补救，仍失败则进入归约输出无效门禁，且不重跑输入未变化的成功分片。不得因输出包装失败而产生无发现的通过结论。

### 目标歧义

发现的修复目标缺失、多重匹配、Revision 不一致或原因码不存在时，视为无效 Provider 输出，进入人工门禁，不得任意选择首个 Work Item。

## 兼容与迁移

1. 不修改既有单项 Reviewer Projection 渲染文本，不提升 Renderer Version，既有 Execution Context Hash 保持不变，历史 Attempt 可在新架构下重试。
2. 三家 Provider 使用同一材料协议与同一文本结论契约，保留原始输出审计，不引入 Provider 特判。
3. 首期最终用户可见结果继续为 InternalPrReview；分片与归约产物先作为后端审计数据，前端仅需表达组级分片进行中与可重试状态。

## 权衡

1. 以增加 Provider 调用次数换取单次输入可靠性。20 个 Work Item 由 1 次超大调用变为 6 次预算受控调用，并获得按分片重试能力。
2. 以新增材料编译层与身份快照换取组级聚合的确定性，避免从缺少身份的历史报告反推。
3. 以压缩单位材料换取容量，压缩范围限定为单项审查已覆盖的细节；接口、范围、证据与路由元数据保留。
4. 归约输入中的单位账目仍与 Work Item 数线性相关，首期容量边界为 20 个 Work Item；接近上限时应引入树形归约而非放宽硬上限。

## 容量边界

本设计首期容量边界为单组 20 个 Work Item。归约输入在该规模下约为 26 KB 量级，接近 30 个 Work Item 时将接近硬上限。超过该规模需要引入固定扇入的树形归约，作为后续独立变更。
