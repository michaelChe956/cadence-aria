# Tasks: Scalable Group Final Review

## 1. 单位审查结论身份快照

- [ ] 1.1 定义携带 Attempt、Unit、Unit Run、逻辑 Work Item、Work Item Revision、报告标识、结论、发现摘要、证据与变更引用、原始报告哈希的身份快照记录，并落地持久化与读取。
- [ ] 1.2 在单项审查成功持久化的同一流程中生成该快照；写入必须幂等；报告已持久化但快照缺失时以身份缺失原因失败关闭，并支持从已持久化报告与权威 Binding 确定性重建缺失快照。

映射 requirement：组级审查材料必须来自权威 Binding。

## 2. 组级材料编译与确定性检查

- [ ] 2.1 实现不可变材料快照：完整字段、稳定排序、规范化序列化、内容哈希，并定义使快照失效的事实变化集合。
- [ ] 2.2 实现契约与能力精确匹配、写入范围与归属、Commit 与证据一致性、Requirement 与验收标准聚合的确定性检查，输出候选发现与门禁依据。
- [ ] 2.3 实现单位记录与全局账目两级压缩材料，保留身份、依赖、范围、契约接口、证据状态与可路由目标。
- [ ] 2.4 实现变更文件完整索引与按级别的片段选择，含脱敏前置、安全截断、截断与未展示数量标注、原始片段哈希。

映射 requirement：组级审查材料必须来自权威 Binding；确定性检查必须在调用 Provider 前完成；变更材料必须提供完整索引并按级别选择片段；分片与归约必须复用同一不可变材料快照。

## 3. 确定性分片

- [ ] 3.1 实现三类亲和边构建、order index 与 unit_id tie-break、连通分量排序、装箱、稳定切开与确定性预算再分片，分片上限为 4 个 Work Item。
- [ ] 3.2 将被切断的边与跨片关系边写入全局跨片关系集合，供归约审查。
- [ ] 3.3 实现分片语义审查的构建、调用与结论持久化，含并发上限与分片结论产物。

映射 requirement：组级审查必须按确定性分片规则切分并逐片审查；单次 Provider 输入必须受字节预算约束。

## 4. 字节预算门禁与容量门禁

- [ ] 4.1 实现每次 Prompt 以完整 UTF-8 字节度量并记录分段字节。
- [ ] 4.2 实现质量目标与硬上限判定及配置约束：硬上限只可收紧，质量目标必须小于硬上限；超过硬上限禁止调用并持久化溢出诊断。
- [ ] 4.3 实现单字段超限时的再分片或溢出门禁，禁止截断身份与契约标识。
- [ ] 4.4 实现容量超限门禁：超过 20 个 Work Item 时在调用任何 Provider 前失败关闭，不回退全量审查、不提高上限、不与材料溢出混用原因码。

映射 requirement：单次 Provider 输入必须受字节预算约束；组级审查容量超限必须失败关闭。

## 5. 归约与结论合并

- [ ] 5.1 实现归约阶段材料构建与调用，归约仅在同一快照下全部分片产出有效结论后启动，返修只从归约结论路由，产出唯一最终结论、影响范围、PR 描述与提交信息建议。
- [ ] 5.2 实现结构化指纹的发现合并、严重度取最高与判定规约，禁止文本相似度合并。
- [ ] 5.3 接入既有组级权威目标校验与流程决策，最终结论继续写入既有 InternalPrReview。

映射 requirement：归约阶段必须产出唯一最终结论；发现合并必须使用结构化指纹。

## 6. 失败语义、补救与并发

- [ ] 6.1 实现传输失败与完成但无法解析的分类、互异原因码与各自重试动作。
- [ ] 6.2 实现结论 Prompt 的判定标记要求，以及结论转写补救与保真校验：判定等于原始标记、禁止 approve、发现可溯源为原始输出子串、数量上限、证据引用子集、目标校验、双哈希、16 KiB 补救 Prompt 上限失败关闭。
- [ ] 6.3 实现快照并发与晚到结果规则：active 快照校验与写入原子化、stale 保存、同一环节单飞、事实未变化复用快照只重建 Prompt。
- [ ] 6.4 实现五类失败门禁与运行失败码分层、按优先级单活替换（含低优先级与同优先级到达规则）、门禁原子落地、按环节重试动作、失败门禁不提供人工继续、身份缺失门禁的快照重建重试与目标歧义的人工门禁。

映射 requirement：失败必须区分类型、可按环节重试且不得产生通过结论；分片与归约必须复用同一不可变材料快照；组级审查的材料、容量与输出失败必须落地可区分的阻塞门禁；组级失败门禁必须提供按环节重试的动作；组级失败门禁必须单活并按优先级替换；同一次评审结论只落地一个阻塞门禁。

## 7. 执行身份与兼容性

- [ ] 7.1 实现组级执行身份由材料快照承载；既有 internal_reviewer_execution_context_hash 只读保留、不补写；历史已绑定与未绑定 Attempt 均可在新架构下重试。
- [ ] 7.2 验证三家 Provider 使用同一材料结构、字节预算与结论契约，原始输出始终留存审计，分片与归约 raw 产物为兼容扩展。
- [ ] 7.3 验证既有单项 Reviewer Projection 渲染文本、Execution Context Hash、单项审查行为与既有门禁不受影响。

映射 requirement：组级执行身份与 legacy 执行上下文字段必须兼容；组级材料协议对所有 Provider 一致；同一次评审结论只落地一个阻塞门禁。

## 8. 输出上限与产物规范性字段

- [ ] 8.1 实现分片与归约结论的发现数上限校验与超限时的输出无效处理，并实现分片并发上限及其可配置默认值。
- [ ] 8.2 实现材料快照、分片结论、归约结论的规范性身份与溯源字段持久化，缺失关键字段时失败关闭。
- [ ] 8.3 实现组级失败门禁的诊断字段记录，使失败原因可在不重跑的情况下判定。

映射 requirement：结论输出上限与分片并发必须受约束；组级审查产物必须携带规范性身份与溯源字段。

## 9. 运行期投影适用范围

- [ ] 9.1 将 per-unit Reviewer 投影绑定要求的适用范围限定为单项 Coding Unit 的 Reviewer Provider，并使组级材料编译走权威 Revision 数据路径。
- [ ] 9.2 验证组级审查不为组级材料绑定或补写 per-unit Reviewer 执行上下文哈希，单项审查绑定行为保持不变。

映射 requirement：Work Item 运行期读取只使用 Revision Store；组级执行身份与 legacy 执行上下文字段必须兼容。

## 10. 容量与跨片完整性验收

- [ ] 10.1 建立容量与预算验收工作包，覆盖 20 个 Work Item 的分片数量、每片上限、单次输入上限与确定性再分片。
- [ ] 10.2 建立跨片完整性验收工作包，覆盖跨片契约关系、跨片共享文件、范围违规与被切断边的归约可见性。
- [ ] 10.3 建立失败与重试验收工作包，覆盖按环节重试、晚到结果处理、补救保真与不产生通过结论。

映射 requirement：组级审查必须按确定性分片规则切分并逐片审查；单次 Provider 输入必须受字节预算约束；组级审查容量超限必须失败关闭；失败必须区分类型、可按环节重试且不得产生通过结论；分片与归约必须复用同一不可变材料快照。
