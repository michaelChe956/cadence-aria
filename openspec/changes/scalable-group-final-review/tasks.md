# Tasks: Scalable Group Final Review

## 1. 单位审查结论身份快照

- [ ] 1.1 定义并持久化携带 Attempt、Unit、Unit Run、逻辑 Work Item、Work Item Revision、报告标识、结论、发现摘要、证据与变更引用、原始报告哈希的身份快照记录。
- [ ] 1.2 在单项审查成功持久化的同一流程中幂等生成该快照，并实现缺失时的确定性重建与失败关闭语义。

映射 requirement：组级审查材料必须来自权威 Binding。

## 2. 组级材料编译与确定性检查

- [ ] 2.1 实现不可变材料快照的完整字段、稳定排序、规范化序列化、内容哈希与失效事实集合。
- [ ] 2.2 实现契约与能力精确匹配、写入范围与归属、Commit 与证据一致性、Requirement 聚合的确定性检查并输出候选发现。
- [ ] 2.3 实现单位记录与全局账目两级压缩材料；将完整 reason_code、目标 Revision、路由种类与契约引用拆为快照级 routing authority index，并保持 UnitCrossReviewRecord 的既有 1,200-byte 上限。
- [ ] 2.4 实现变更文件完整索引与 A 至 E 分级片段选择，含最高级归类、owner 判定、脱敏前置与截断标注。

映射 requirement：组级审查材料必须来自权威 Binding；确定性检查必须在调用 Provider 前完成；变更材料必须提供完整索引并按级别选择片段；分片与归约必须复用同一不可变材料快照。

## 3. 确定性分片

- [ ] 3.1 实现三类亲和边、连通分量排序、装箱与 order key 稳定切分的确定性分片规则。
- [ ] 3.2 实现预算驱动再分片与跨片边集合维护。
- [ ] 3.3 实现分片语义审查的构建、调用、并发上限与结论持久化，并只向每个分片投影其可见的 routing authority。

映射 requirement：组级审查必须按确定性分片规则切分并逐片审查；组级审查输出与并发必须受上限约束。

## 4. 预算门禁与容量门禁

- [ ] 4.1 实现完整 Prompt 的 UTF-8 字节度量与分段字节记录，包含 routing authority 段。
- [ ] 4.2 实现质量目标与硬上限判定及配置约束。
- [ ] 4.3 实现单字段超限时的再分片或溢出门禁。
- [ ] 4.4 实现容量超限门禁与其失败关闭语义。

映射 requirement：单次 Provider 输入必须受字节预算约束；组级审查容量超限必须失败关闭。

## 5. 归约与结论合并

- [ ] 5.1 实现归约前置条件判定与归约阶段的材料构建、调用与结论持久化，并向归约投影快照的完整 routing authority。
- [ ] 5.2 实现结构化指纹的发现合并、严重度取最高与判定规约。
- [ ] 5.3 接入既有组级权威目标校验与流程决策，在分片结论落库前及归约结论路由前按对应权限索引校验，并保持最终结论写入既有 InternalPrReview。

映射 requirement：归约阶段必须产出唯一最终结论；发现合并必须使用结构化指纹；组级审查输出与并发必须受上限约束。

## 6. 失败语义、补救与并发

- [ ] 6.1 实现传输失败、用户主动取消与完成但无法解析的分类、运行失败码与门禁原因码分层。
- [ ] 6.2 实现结论契约的判定标记要求与补救保真校验。
- [ ] 6.3 实现快照原子 CAS、stale 结果保存与同环节单飞。
- [ ] 6.4 实现五类失败门禁的单活、优先级替换、证据合并与按环节重试动作。
- [ ] 6.5 统一失败、用户终止、删除、最终确认与组完成的 attempt-owner 共享 worktree 锁释放；锁清理失败只记录诊断且不得覆盖原始业务失败。

映射 requirement：失败必须区分类型、可按环节重试且不得产生通过结论；分片与归约必须复用同一不可变材料快照；组级审查的材料、容量与输出失败必须落地可区分的阻塞门禁；组级失败门禁必须提供按环节重试的动作；组级失败门禁必须单活并按优先级替换；分诊门禁提供可操作动作；同一次评审结论只落地一个阻塞门禁。

## 7. 执行身份与产物溯源

- [ ] 7.1 实现由材料快照承载的组级执行身份，并保持 legacy per-unit 执行上下文字段只读不补写。
- [ ] 7.2 实现快照、分片结论与归约结论的规范性身份与溯源字段。

映射 requirement：组级执行身份与 legacy 执行上下文字段必须兼容；组级审查产物必须携带规范性身份字段；Work Item 运行期读取只使用 Revision Store。

## 8. 兼容性与验收

- [ ] 8.1 完成容量与预算验收工作包，覆盖 20 个 Work Item 的分片数量、单次输入上限与再分片行为。
- [ ] 8.2 完成跨片完整性验收工作包，覆盖跨片契约错配、跨片共享文件冲突与范围违规的归约可见性。
- [ ] 8.3 完成失败与重试验收工作包，覆盖按环节重试、stale 结果、补救保真、不产生通过结论、失败/终止/删除/完成的 owner-based 共享锁释放，以及锁清理错误不覆盖原始失败。
- [ ] 8.4 完成兼容性验收工作包，覆盖三家 Provider 材料一致性、历史 Attempt 重试与既有单项审查行为不变。
- [ ] 8.5 完成 routing authority 验收工作包，覆盖 UnitCrossReviewRecord 保持 1,200-byte 上限、分片仅见局部权限、归约必见全量权限、缺失权限不调用 Provider，以及分片/归约输出的语义权限校验。

映射 requirement：组级审查必须按确定性分片规则切分并逐片审查；单次 Provider 输入必须受字节预算约束；组级审查容量超限必须失败关闭；失败必须区分类型、可按环节重试且不得产生通过结论；分片与归约必须复用同一不可变材料快照；组级材料协议对所有 Provider 一致；组级执行身份与 legacy 执行上下文字段必须兼容。
