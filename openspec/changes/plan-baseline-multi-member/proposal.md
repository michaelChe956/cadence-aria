# Proposal: plan-baseline-multi-member

> 权威来源：`cadence/designs/2026-11-11_技术方案_WIG三缺陷与多仓事实供给修复_v1.0.md` §4.5、§5.4、§6.1、§7.3、§8、§10.2；多仓分支语义按本次分面裁定显式登记。本 change 只产出契约，不启动实施。

## Why

当前 plan 基线只按 `issue.repo_id` 解析一个物理成员仓，形成**成员内相对路径的平面集合**；AC 校验直接对该集合做裸 `contains`。多仓计划因此存在其它成员真实基线路径被误拒的可达缺陷，D5 的最近候选也可能把 frontend 引用导向 busi 文件。与此同时，写范围纪律已经要求**聚合根相对成员前缀路径**，同一 prompt 内出现「事实面用成员内相对域、纪律面用聚合根相对域」的冲突；基线事实必须覆盖计划已授权的有效成员，并与现有纪律同域。

### 实测归因（基线对照值，实施后须复测）

- 复刻 `ac_paths.rs` 提取规则跑遍 **66 个真实 IR**，共提取 **4 条**基线路径引用；方案可枚举项为 `scripts/dev.sh`×2、`tests/integration/notice-delete-e2e.mjs`×1，均不在任何成员基线内，属于**真越界**。方案没有列出第 4 条的路径，本提案不补造该明细。
- **IR 级误判率实测 = 0**；本批真实 run 不能作为「多仓误拒已造成失败」的证据。该值只用于基线对照，实施后须复测。
- 现有 D5 只展示 busi 的成员内相对树；写范围成员前缀教学在实测 prompt 中出现 **1,321 次**。这是同 prompt 路径域冲突的基线对照事实，不是实施后的收益。

### 构造可达风险（不是本批已观察到的失败）

- frontend 基线真实存在的 `src/App.vue`、`src/api.js`、`package.json`、`vite.config.js` 均会被当前单树裸 `contains` 拒绝。
- D5 事后候选可把 `src/App.vue` 误导到 busi 的 `src/main/java/…`。
- F3 三成员清单为 **2,407 B**（busi 1,258 / gateway 787 / frontend 362），作为格式选型的基线对照值；实施后须复测，不写成已上线效果。

### 必须登记的分支语义变化

owner 已选定多仓逐成员 HEAD 分支权威。**多仓会话下，`issue.base_branch` 对 AC 基线核对面与 author 基线上下文面不再生效**，这两面改为逐成员同源；但 coder fork 与 advance 仍按 `issue.base_branch` 的单仓语义运行。本 change 不修改 coding/advance 实现，故**多仓三面暂时不同源是已知遗留缺口**，不得声称三面已收敛，须由后续独立 change 处理。单仓继续保持既有 `issue.base_branch` 语义与字段锁定规则。

## What Changes

- **共享事实契约**：以 `PlanBaseline { member_prefixes, trees }` 替换平面树，承载物理成员仓 ID、checkout 相对聚合根前缀及该成员的仓内相对路径集合；范围只取计划已授权的有效成员，不扫描磁盘发现新成员。
- **F3 路径域**：多仓新产出使用 `frontend/src/App.vue` 等带成员前缀的聚合根相对路径。明确前缀只查对应成员；裸仓内路径只兼容解析到该 WI 的 `target_repository_id`，不以任意成员同名文件命中代替归属。
- **严格加载**：每个必需成员按自身 HEAD 分支取 Git 树；前缀重复、归属不唯一或任一必需成员基线不可解析时显式失败，不吞成 `None`，不返回部分成功树；不读取脏文件或兄弟分支/worktree 文件。
- **四端一批切换**：基线加载、校验与最近候选、D5 的真实成员归属渲染、结构上下文摘要共同迁移，所有校验调用方同步消费同一完整结构；显示截断不得缩小 validator 的事实集合。
- **摘要覆盖范围**：非默认成员的基线路径增删、成员归属映射变化必须改变结构摘要；摘要仍是路径集合与归属事实的摘要，不承诺检测同路径文件内容或提交变化。
- **读写权限分离**：明确跨成员路径可以作为读引用事实，不因基线命中获得跨成员 exclusive 写权限。

### 接受面的明确改变

- frontend/gateway 基线真实存在的**明确成员路径**从构造可达的误拒变为接受；这不是本批真实 run 的已测收益。
- 仅其他成员存在、而本 WI 绑定仓不存在的**裸路径继续拒绝**。
- 仅其他分支存在、未提交、或新建尚未进入所选基线的文件/脚本继续拒绝；写范围声明不能豁免 AC 基线存在性。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `per-issue-base-branch`：**MODIFIED REQ-PIB-01**（基准分支设置与锁定），显式登记多仓两面的逐成员 HEAD 语义及 fork/advance 的已知差异；**MODIFIED REQ-PIB-03**（coding fork 与核对同源），把全量授权成员基线、严格加载、author/核对两面逐成员同源及三面尚未收敛的边界写成可验收契约。
- `work-item-plan-single-candidate`：**MODIFIED REQ-WSC-02**（markdown 编译器模型），补齐按成员归属解析 AC 路径、最近候选域、渲染与全量校验分离及结构摘要验收。

## Non-Goals

- 不新增模型调用或重试，不新增成员发现机制或检索工具。
- 不改变写范围权限判定，不因读引用命中而授予跨仓写入。
- 不改 rework 的 D5 装载点、装配职责与预算口径，不 MODIFIED `REQ-WSC-06`。
- 不改 `isolate-plan-criterion-namespace` 的 spec AC / plan criterion 命名域、引用或指纹代际。
- 不把路径摘要扩成全仓内容快照，不声称同路径内容提交的 HEAD 变化已受摘要保护。
- 不修改 coder fork、advance 的实现，不借本 change 收敛其它 capability 的 coding 语义。
- 不提高固定规范面 23,500 B、上下文面 32,000 B 或大文件守卫登记上限。

## Impact

- 受影响的是计划基线事实模型、加载/校验/候选提示/渲染/摘要消费面及其调用链；主规格仅通过本目录的两个 delta 文件变更，既有 active change 不改写。
- 运行成本为每成员一次 Git 树读取，内存随路径数增长，模型调用零新增。
- 预算基线对照值：基线段 1,308 → 2,407 B，上下文面 25,518 → 26,617 B、余 5,383 B；**实施后须复测**，不得把该推算写成达成结果。固定规范面必须逐字节不变，23,500 B 零新增；上下文面不得超过 32,000 B。
- 本 change 排在**全局串行序 7 之后，最后落地**。rework 的 D5 装载点保持不变，替换其加载的树结构后获得多成员事实；共享写面不得并发修改。
