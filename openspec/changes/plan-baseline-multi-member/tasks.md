## 1. B1 · 授权成员基线模型与严格加载

- [ ] 1.1 建立共享成员基线契约，承载物理成员身份、聚合根相对 checkout 前缀与各成员仓内相对路径完整集合；复用已有计划有效成员事实，不扫描磁盘另造成员发现器。验收：默认仓只指向 busi 时，结果仍覆盖三个授权有效成员，未授权磁盘仓不被纳入。映射：REQ-PIB-03「真实三仓基线覆盖全部授权成员」「磁盘额外 Git 目录不增加授权成员」。
- [ ] 1.2 多仓基线统一使用各成员自身 HEAD 分支，严格传播必需成员分支、checkout、Git 树及归属映射的错误；单仓与真正无仓保留既有语义。验收：不猜 main/master、不吞为 None、不返回部分成功，脏文件与兄弟分支/worktree 独有文件不进入树。映射：REQ-PIB-01「多仓两面逐成员使用自身 HEAD 分支」「多仓成员分支解析失败不猜替代」；REQ-PIB-03「任一必需成员缺失使完整基线失败」「前缀重复或成员归属不唯一显式失败」「单仓与真正无仓语义保留」。
- [ ] 1.3 固化真实三仓 Git 机制验收，三成员分别提交独有文件，并覆盖未提交文件、兄弟分支文件与任一必需成员缺失的反例；不得以 mock 路径集合代替 loader 验收。验收：全量覆盖、基线隔离、显式 Err 三项均可确定性观察。映射：REQ-PIB-03「真实三仓基线覆盖全部授权成员」「脏文件与兄弟分支文件不进入基线」「任一必需成员缺失使完整基线失败」。

## 2. B2 · 四端与全部调用方一次性迁移

- [ ] 2.1 将候选校验上下文与所有生成评估、对话式修订入口迁移为共享完整基线消费；明确成员前缀只查对应仓，裸路径只绑定本 WI 的目标仓，最近候选限制在正确成员与路径域。验收：frontend 明确路径通过，同名文件归属确定，仅其它成员存在的裸路径仍 Error，缺失路径不跨仓兜底建议。映射：REQ-WSC-02「明确 frontend 或 gateway 基线路径不再误拒」「同名文件按明确成员前缀消歧」「明确成员路径不得回退到其它仓」「裸路径仅绑定本 WI 目标仓」「最近候选限制在正确成员与路径域」「四端与全部校验入口消费同一基线契约」。
- [ ] 2.2 将 D5 显示适配为真实成员归属的 F3 清单，保持既有装载点、装配口径与配额机制，不从目录首段猜仓。验收：每条显示路径可回溯到完整成员树，截断或省略仅影响显示，不影响 validator 的全量存在性判定。映射：REQ-PIB-03「author 渲染按真实成员归属展示」；REQ-WSC-02「D5 分组路径可回溯到完整基线」「D5 截断不缩小 validator 事实集合」。
- [ ] 2.3 将结构上下文摘要迁移为完整成员路径与归属映射的摘要，不消费截断文本，不扩成内容快照。验收：仅非默认成员路径增加、删除，以及同路径归属映射变化，均改变 digest；同路径内容提交不被宣称已由路径摘要保护。映射：REQ-WSC-02「非默认成员路径增加改变结构摘要」「非默认成员路径删除改变结构摘要」「路径相同但归属映射变化改变结构摘要」「摘要仍限于路径与归属事实」。

## 3. 接受面、权限边界与预算验收

- [ ] 3.1 覆盖接受面与拒绝面对照：明确 frontend/gateway 基线路径从构造误拒转为接受；仅其它成员存在的裸路径、其它分支文件、未提交文件与新建未入基线脚本继续拒绝。验收：AC 基线命中不消除跨仓 exclusive 越界，写范围声明不豁免基线存在性，原三类修复建议保留。映射：REQ-WSC-02「AC 命中不豁免跨仓 exclusive 越界」「基线外文件不因写范围声明而通过」及明确路径/裸路径场景。
- [ ] 3.2 按面复测多仓清单与其它上下文段的合计字节，保持上下文面 ≤32,000 B、固定规范面逐字节不变且预算仍为 23,500 B；不得提高任何预算常量或大文件守卫登记上限。验收：截断边界与固定面零新增均有确定性证据，主方案字节数仅作基线对照，不能作为已达成结果。映射：REQ-WSC-02「多仓渲染保持两面预算」「D5 截断不缩小 validator 事实集合」。
- [ ] 3.3 对账 author 基线上下文与 AC 核对逐成员同源，同时如实保留 fork/advance 的分面差异登记；不修改后两面的实现、不宣称多仓三面已同源。验收：单仓原有基线合同不变，多仓两面逐仓 HEAD 与后两面单仓语义的已知遗留缺口在契约中清晰区分。映射：REQ-PIB-01「多仓 fork 与 advance 的分面差异明确登记」；REQ-PIB-03「三面同源」。
- [ ] 3.4 完成四端与全部调用方的集成对账，不遗留旧单树消费、部分上线结构或第二套成员发现机制；验收报告分列确定性构造结果与真实 run 归因，全部实测数字按基线对照/实施后复测口径报告，不把本批 IR 误判率为零改写为已观察到跨仓误拒收益。映射：REQ-PIB-03 全量基线与两面同源场景；REQ-WSC-02「四端与全部校验入口消费同一基线契约」「明确 frontend 或 gateway 基线路径不再误拒」。
