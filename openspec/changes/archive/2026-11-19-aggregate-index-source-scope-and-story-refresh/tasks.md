### [x] T01 · 交叉验收与有界盘检（独立；与一次性校准动作并行）
映射：REQ-IND-01、REQ-IND-03、REQ-IND-04。

- 在**聚合索引唯一验收入口**里，把「成员未被收录」与「成员没有源码」分开：先做逐成员覆盖判定，再只对未覆盖成员做有界盘检。
- 盘检只按后缀做元数据判定：Aria 自有源码类型清单（**必须是 CodeGraph 支持后缀的真子集**），是**代码内静态常量**。清单按**当前机器已安装的 codegraph 1.6.3** 实测校准（临时目录每候选后缀放一个该语言的最小有效样本 → `codegraph init .` → `codegraph files --json`，出现的后缀即 1.6.3 收录集；Aria 清单只取其中「希望当源码看待」的常见语言子集，`.json/.md/.toml/.txt/.csv/.html` 不算，`.yaml/.yml/.xml` 虽被 1.6.3 收录也不算），并在清单处写明**基线版本 = 1.6.3 / 可复现测量命令 / 复校准步骤**。校准是**实施期一次性动作**（产出固化成清单 + 基线注释），**不是运行期流程、不是本工作包的开工门禁**；**不做**运行期测量、机器级 durable 记录、版本键缓存、自动重校准。同一次校准动作还 SHALL 记录**可见范围口径**（被 `.gitignore` 忽略的文件不被 codegraph 收录、git 可见范围内的文件含未跟踪但未被忽略的被收录）。
- **版本漂移只记告警**：验收时读到已安装 codegraph 版本 ≠ 清单校准基线 1.6.3 ⇒ 在既有可审计软告警通道追加一条 warning，**不改判定、不阻断索引构建**；不改码、不做自动重校准。已知风险（写进契约与实现注释）：新版若不再收录清单内某后缀，该类仓会被判成「漏收」而失败，届时按复校准步骤更新清单与基线注释。
- 复用既有 11 条内建排除口径（**Aria 排除集 = codegraph 排除集，同源，不另建第二份**；这 11 条经 `CodeGraphExcludeGenerator::from_member_roots` 原样写进聚合根 `codegraph.json` 的 `exclude`）。其中 4 条非目录固定名模式 `**/.env`、`**/.env.*`、`**/*credential*`、`**/*secret*` **目录级与文件级都要扣除**：目录条目命中即剪枝（`credentials/`、`secret-notes/` 不进入），文件条目命中同样不算源码候选（`credentials.rs`、`secret_manager.ts`）——因为它们在 `codegraph.json` 里就是按路径 glob 生效、能命中文件，codegraph 会排除这些文件，盘检若算作源码就成了永久假漏收。**源码候选只取 git 可见范围**——成员主工作目录内 `git ls-files --cached --others --exclude-standard` ∩ Aria 源码后缀集，再扣除 Aria 自身排除（`build/`、`dist/`、`node_modules/`、`.worktrees/`、`.aria/`、`.env*`、`*credential*`、`*secret*` 等内建排除项，与内建排除规则表同源、不另写副本）；**被 `.gitignore` 忽略的文件不算源码**，不判漏收失败，该成员按「无源码成员」跳过（避免「含被忽略源码的仓永远建不出索引」的死锁）；git 侧异常（主工作目录不是 git 仓、git 不可用、命令失败或超时）按「无法确认」；`.worktrees/` 作为独立第二段诊断，入口为符号链接或不存在时视为「该段无候选且完成」（本轮**不**按 git 可见范围收窄第二段）；不跟随符号链接。
- 盘检有界且可注入时钟/取消信号与预算（交叉验收内部函数需能接收注入的预算，不得靠真实 sleep 或隐式新建预算做测试）；超限/超时/权限不足必须落到「无法确认」。
- 覆盖判定结果缺某成员键时按「无法确认」处理，**不得**把它落进「全员确认无源码」。
- **不改全局漂移判据**：`freshness.rs` 的 `member_evidence_drifted` 保持只比成员数/revision/dirty；Story 路径的「不能确认没变」由 T04 自己判。
- 验收要点：混合 LC 判通过并记跳过事实；普通路径**在 git 可见范围内**有源码 → 漏收失败码；**只有被 `.gitignore` 忽略的源码 → 按「无源码成员」跳过、不报漏收**；**只有命中 4 条非目录模式的文件（`credentials.rs`、`secret_manager.ts`）→ 同样按「无源码成员」跳过、不报漏收**；同仓内既有被忽略源码、又有可见范围内漏收源码 → 只对后者报漏收；仅 `.worktrees/` 有源码 → 专属失败码；无法确认（含 git 侧失败）→ 专属失败码；全员无源码 → 专属失败码（空索引 + 盘上有源码则必须是覆盖失败码，不是全员无源码）；任一失败都不发布新 active；成员缺覆盖键 → 无法确认；排除负查询与代表性检索的既有口径不放松。

### [x] T02 · 跳过事实的 durable 记录与向前兼容（依赖 T01）
映射：REQ-IND-06、REQ-IND-04。

- 验收要点：老 JSON 读取无警告；混合世代往返一致；失败世代不产生跳过事实；跳过成员仍参与漂移判据与引用巡检；**不做自动发现**——被跳过成员后来出现源码（含仅 `.worktrees/`）由「下一次验收/重建」发现，freshness 不盘检、不轮询。

### [x] T04 · Story 专用的共享索引刷新（依赖 T01/T02）
映射：REQ-PLN-18、REQ-IND-04。

- 新增 **Story 专用**刷新入口/模式，接在 Story 生成路径上；既有 `build_with_fresh_index` 的语义保持给 Design 生成与工作区上下文读取（stale 才同步、degraded 只告警、不停机）。两套语义不得互相借用。
- 三分支：**无可用索引**（没有任何可读世代，评估报 `aggregate_index_active_missing`）⇒ 走既有首次建库路径；**仅当 published 世代的 `status` 为 `Active`** 且能确认没变（成员/主工作目录/提交未变、上次与本次都无未提交修改）⇒ 复用；有变化或不能确认没变 ⇒ 增量同步 + 重新验收。published 世代为 `Degraded` 或 `Stale`、或 `current_snapshots` 采集失败，同样归分支 3，尝试恢复/同步并重新验收。**判定 SHALL NOT 以「当前世代含跳过成员」为条件**（G2 收窄已撤回）。「无未提交修改」以成员主工作目录的 `git status --porcelain` 为准，被 `.gitignore` 忽略的文件不参与判定；两次都脏时即使提交号相同也必须同步。记录读坏/归属矛盾不是「没有索引」，按既有失败规则报错。
- 失败或恢复/同步并重新验收后仍非 `Active` ⇒ 停在 AI 启动之前，给**稳定码 + 同源三段成品**（不得落成通用 500 `product_store_error`），允许重试，保留已有 Issue/Story/上次成功索引。
- 并发：等待并复核，不并行写两份；**锁只串行化写入**——成功与否以本次实际验收发布的记录为准，不得用仍 dirty 的重评估结果否定一次成功的验收。
- 验收要点：`Active` 且干净未变时不触发同步（含跳过成员同样复用，只有被忽略文件变化也不触发同步）；两次都脏必须同步（revision 相同不算「没变」）；成员或提交变化时同步并重新验收；`Degraded` / `Stale` 或 `current_snapshots` 采集失败时不复用，走分支 3，仍非 `Active` 则 AI 不启动；无索引时走建库而非报错；读坏记录仍报错；更新失败时 AI 不启动、旧 Story 保留且失败面带稳定码；创建 Issue、勾选成员、刷新页面不触发刷新；同一逻辑代码库只共享一份索引；Design/WorkItemPlan 在 degraded 下仍放行。

### [x] T05 · 三处提示与「未检索」证据语义（依赖 T02/T03）
映射：REQ-IND-06、REQ-MRE-01、REQ-COD-05、REQ-LAYOUT-04。

- 聚合索引卡片：从**本次实际被投影的那一份记录**（与响应 `state` 同源）派生一行结构化告警 `{code, message_zh}`；无记录/旧世代不造告警；降级时用被投影的 degraded 世代的跳过事实。不得在 `read_active_projection` 里再选一遍记录。
- 创建 Issue 选成员：成员列表（`list_logical_codebase_members_for_lc`，入参 `project_id` + `logical_codebase_id`）随成员行返回 `{code, message_zh}`；按 **(成员 ID, 当前 Main checkout ID)** 匹配；无匹配记录不猜、不按仓名贴标签。
- 跨仓证据：判定顺序为凭据 → ACL → 输入校验 → 钉住记录校验 → 再分叉；对被跳过的目标不发起 CodeGraph 查询、不探库目录，HTTP 200 + `not_searched: {code, message_zh}` + 零命中审计（审计原因字段纯加法，不改既有字段）；普通目标的结果取授权与已覆盖成员的交集。
- 验收要点：GET 类接口不触发盘检、不启动 CodeGraph/provider；配置目标的证据请求零次 CodeGraph 调用；有效钉住但库目录缺失仍返回未检索（不是 `evidence_index_unavailable`）；坏钉住/非法输入仍先拒绝；主 checkout 更换后不沿用旧提示；跳过不冒充查询无命中；提示不改变选仓资格与授权判定。

| UA-08 | 对上一 Issue 生成 Story | 生成前先更新共享索引；AI 启动时索引已是最新；同一 LC 的第二个 Issue 复用同一份索引（不新建世代） |
| UA-09 | 源码仓改一个函数名不提交，再次生成 Story | 生成前完成同步，索引能查到当次的新名字；再改一次仍不提交 → 再次同步后仍能查到 |
| UA-10 | 让索引更新失败后再次生成 Story | 生成停在 AI 启动之前，失败面给出稳定码与三段中文（不是通用 500）；已有 Story 保留；不拿旧索引冒充最新 |
| UA-11 | 打开创建入口 / 登记入口 / 聚合初始化卡片 | 三处呈现同一份目录说明与范围口径；既有操作可用 |

| UA-13 | 让某成员仓的源码只存在于被 `.gitignore` 忽略的目录，然后重建 | 不失败（该成员按「确认无源码」跳过）；卡片出现该成员的无源码提示；**不**出现「磁盘上有源码但索引未收录」的漏收失败面 |
| UA-14 | 让某成员仓的 git 可见源码只有 `credentials.rs` / `secret_manager.ts` 这类命中 4 条非目录内建模式的文件，然后重建 | 不失败（同样按「确认无源码」跳过）；**不**出现漏收失败面——文件级命中必须与目录级一样被扣除 |

**证据口径**：截图只证界面。链路结论必须另有可观测证据——`只选配置仓仍进入规划` 看规划快照里该成员的指纹与巡检结果；`非生成操作零刷新` 看索引世代 `updated_at`/世代 ID 未变；`同 LC 两 Issue 共享` 看两处 planning snapshot 的 `aggregate_index_id` 相同；`脏工作区连续两次改名` 看两次同步后的查询结果；`记录与库要分开`——验收前 `sync` 已改动实际库，不能用「记录未被替换」冒充「上次可用索引仍可查询」，要用隔离 LC 记录失败前后可读性。
