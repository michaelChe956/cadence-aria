### [ ] T01 · 交叉验收与有界盘检（独立；与探针并行）
映射：REQ-IND-01、REQ-IND-03、REQ-IND-04。

- 在**聚合索引唯一验收入口**里，把「成员未被收录」与「成员没有源码」分开：先做逐成员覆盖判定，再只对未覆盖成员做有界盘检。
- 盘检只按后缀做元数据判定：Aria 自有源码类型清单（**必须是 CodeGraph 支持后缀的真子集**）。**保守清单先开工**，逐后缀探针作为**并行前置**（每个候选后缀用该语言的最小有效样本、逐版本独立临时根、按生产 argv 跑），探针结论回来后增补清单；探针**不是**本工作包的开工门禁。
- 复用既有 11 条内建排除口径（含 4 条非目录固定名模式 `**/.env`、`**/.env.*`、`**/*credential*`、`**/*secret*` 按目录名剪枝）；`.worktrees/` 作为独立第二段诊断，入口为符号链接或不存在时视为「该段无候选且完成」；不模拟 `.gitignore`；不跟随符号链接。
- 盘检有界且可注入时钟/取消信号与预算（交叉验收内部函数需能接收注入的预算，不得靠真实 sleep 或隐式新建预算做测试）；超限/超时/权限不足必须落到「无法确认」。
- 覆盖判定结果缺某成员键时按「无法确认」处理，**不得**把它落进「全员确认无源码」。
- **不改全局漂移判据**：`freshness.rs` 的 `member_evidence_drifted` 保持只比成员数/revision/dirty；Story 路径的「不能确认没变」由 T04 自己判。
- 验收要点：混合 LC 判通过并记跳过事实；普通路径有源码 → 漏收失败码；仅 `.worktrees/` 有源码 → 专属失败码；无法确认 → 专属失败码；全员无源码 → 专属失败码（空索引 + 盘上有源码则必须是覆盖失败码，不是全员无源码）；任一失败都不发布新 active；成员缺覆盖键 → 无法确认；排除负查询与代表性检索的既有口径不放松。

### [ ] T02 · 跳过事实的 durable 记录与向前兼容（依赖 T01）
映射：REQ-IND-06、REQ-IND-04。

- 成员快照新增**可选**的跳过标记 `skip_reason`（wire 值 `no_source`）；成员快照既有的 `included` 语义保持不变，被跳过的成员仍在快照里。**只改成员快照类型定义这一处**：既有五参构造函数与采集路径（`snapshot.rs` 的 `current()` 走的是该构造函数，不是 struct literal）不需要改签名，构造函数内给 `None` 即可。
- 记录形状**没有版本号**，兼容只能靠 serde 缺省：老记录（无该字段）必须可读，缺省值不得被投影成跳过证据。
- 只有验收成功的世代才写跳过事实；失败世代不写，last-known-good 保持它自己那一代的事实。
- 跳过事实**不跨代继承**：下一次验收重新判定，不沿用上一代结论。
- 验收要点：老 JSON 读取无警告；混合世代往返一致；失败世代不产生跳过事实；跳过成员仍参与漂移判据与引用巡检；**不做自动发现**——被跳过成员后来出现源码（含仅 `.worktrees/`）由「下一次验收/重建」发现，freshness 不盘检、不轮询。

### [ ] T03 · 稳定码、文案单一来源与两出口解析（可与 T01/T02 并行）
映射：REQ-BOOT-10、REQ-BOOT-11、REQ-IND-04、REQ-LAYOUT-04、REQ-LAYOUT-05。

- 在**唯一**文案来源里登记三个新增失败码与一个新增告警码，并给出各自的三段成品与可执行处置；布局失败面的码集固定为**十个失败码**，与 `REQ-LAYOUT-04` / `REQ-LAYOUT-05` 的集合严格相等。
- 第六条规则 `rule_zh` 改为「聚合索引至少需要一个已覆盖成员；确认无源码的成员可以跳过」；覆盖失败码双变体与三个补充失败码的 `reason_zh` 都带该规则依据；既有 `layout_rules_cover_seven_external_codes` 断言更新为十码集合断言并保留逐码 `reason_zh` 校验（不放宽）。
- 既有覆盖失败码支持两个成品变体，按持久化失败事实的机器事实前缀选择；新旧变体都登记在同一张表里，不另建文案表；**变体只挑模板**，归因仍用 canonical 码，`machine_line` 仍写原始稳定码。
- 告警码以独立结构化成品登记：`{code, message_zh}`，不占失败五字段、不分配分诊、不触发失败通知。
- **封套解析唯一入口落到产品层**（`src/product/logical_codebase/failure_copy`），HTTP 投影与冷启动 Bootstrap 投影共用；冷启动失败分支改为经该入口取「内层码 + 消息」，`reason_code` 写内层稳定码，MUST NOT 再用裸消息前缀特判、MUST NOT 把三个补充失败码落成 `aggregate_index_failed`。
- 验收要点：告警不生成失败面；三个补充失败码在**冷启动**与 HTTP 两出口都给出同码同文案；旧记录仍渲染旧文案、新事实渲染新文案；十个码的三段不回归；告警码不在失败码集合里。

### [ ] T04 · Story 专用的共享索引刷新（依赖 T01/T02）
映射：REQ-PLN-18、REQ-IND-04。

- 新增 **Story 专用**刷新入口/模式，接在 Story 生成路径上；既有 `build_with_fresh_index` 的语义保持给 Design 生成与工作区上下文读取（stale 才同步、degraded 只告警、不停机）。两套语义不得互相借用。
- 三分支：**无可用索引**（没有任何可读世代，评估报 `aggregate_index_active_missing`）⇒ 走既有首次建库路径；能确认没变（成员/主工作目录/提交未变、上次与本次都无未提交修改、**且当前世代不含跳过成员**）⇒ 复用；有变化或不能确认没变（含两次都脏、**含当前世代存在跳过成员**）⇒ 增量同步 + 重新验收。记录读坏/归属矛盾不是「没有索引」，按既有失败规则报错。
- 失败 ⇒ 停在 AI 启动之前，给**稳定码 + 同源三段成品**（不得落成通用 500 `product_store_error`），允许重试，保留已有 Issue/Story/上次成功索引。
- 并发：等待并复核，不并行写两份；**锁只串行化写入**——成功与否以本次实际验收发布的记录为准，不得用仍 dirty 的重评估结果否定一次成功的验收。
- 验收要点：干净且未变时不触发同步；两次都脏必须同步（revision 相同不算「没变」）；含跳过成员的世代必须同步；成员或提交变化时同步并重新验收；无索引时走建库而非报错；读坏记录仍报错；更新失败时 AI 不启动、旧 Story 保留且失败面带稳定码；创建 Issue、勾选成员、刷新页面不触发刷新；同一逻辑代码库只共享一份索引；Design/WorkItemPlan 在 degraded 下仍放行。

### [ ] T05 · 三处提示与「未检索」证据语义（依赖 T02/T03）
映射：REQ-IND-06、REQ-MRE-01、REQ-COD-05、REQ-LAYOUT-04。

- 聚合索引卡片：从**本次实际被投影的那一份记录**（与响应 `state` 同源）派生一行结构化告警 `{code, message_zh}`；无记录/旧世代不造告警；降级时用被投影的 degraded 世代的跳过事实。不得在 `read_active_projection` 里再选一遍记录。
- 创建 Issue 选成员：成员列表（`list_logical_codebase_members_for_lc`，入参 `project_id` + `logical_codebase_id`）随成员行返回 `{code, message_zh}`；按 **(成员 ID, 当前 Main checkout ID)** 匹配；无匹配记录不猜、不按仓名贴标签。
- 跨仓证据：判定顺序为凭据 → ACL → 输入校验 → 钉住记录校验 → 再分叉；对被跳过的目标不发起 CodeGraph 查询、不探库目录，HTTP 200 + `not_searched: {code, message_zh}` + 零命中审计（审计原因字段纯加法，不改既有字段）；普通目标的结果取授权与已覆盖成员的交集。
- 验收要点：GET 类接口不触发盘检、不启动 CodeGraph/provider；配置目标的证据请求零次 CodeGraph 调用；有效钉住但库目录缺失仍返回未检索（不是 `evidence_index_unavailable`）；坏钉住/非法输入仍先拒绝；主 checkout 更换后不沿用旧提示；跳过不冒充查询无命中；提示不改变选仓资格与授权判定。

### [ ] T10 · 后端与集成验证
映射：REQ-IND-01、REQ-IND-03、REQ-IND-04、REQ-IND-06、REQ-PLN-18、REQ-MRE-01、REQ-COD-05、REQ-BOOT-10、REQ-BOOT-11、REQ-LAYOUT-04。

- 单测：四态判定的每一条分支各有一条断言；盘检限额用注入时钟/取消信号与注入预算；**空索引要分两支**——全员无源码用 `aggregate_index_all_members_source_less`、盘上有源码用覆盖失败码（「另一个成员被覆盖 ⇒ Active」只能在非空覆盖夹具里测）；成员缺覆盖键 ⇒ 无法确认；`.worktrees` 入口为符号链接/不存在 ⇒ 该段无候选；4 条非目录模式按目录名剪枝；老记录可读；跳过不改变既有漂移与巡检行为；文案变体按事实前缀选择且 `machine_line` 仍是原始码。

- 不做自动发现：同 revision、同 dirty 下新增普通路径源码 / 仅 `.worktrees/` 源码，**不会**被 freshness 立刻发现，只在下次验收（含 Story 前刷新落同步分支）重新判定；断言不沿用旧跳过事实。
- 集成：真实临时 Git 仓 + 可控 CodeGraph 夹具，覆盖「源码仓 + 配置仓」的冷启动 → 成员提示 → 只选配置仓创建 Issue → 规划拿到该目标指纹；对照「普通路径有源码但覆盖为假」必失败且保留 LKG；全员无源码不 ready。
- 证据链：断言配置目标的 CodeGraph 调用次数为零；普通目标仍返回授权范围内证据且不含跳过成员路径；有效钉住 + 库目录缺失仍返回未检索（200）；坏钉住/非法输入仍先拒绝；审计原因字段为纯加法（既有字段不变）。
- 提示身份：覆盖主 checkout 更换、候选世代不同、旧记录、无记录四种情形都不出提示。
- Story 前刷新：无索引 → 走建库；读坏记录 → 报错不建库；干净未变 → 复用；含跳过成员 → 必须同步；改一个函数名不提交 → 同步后能查到新名字；再改一次仍不提交 → 再次同步；更新失败 → AI 不启动、旧 Story 保留、失败面带稳定码；同步成功但工作区仍 dirty → 以本次发布的记录为准，不被重新评估否定。
- 完成判定包含格式与静态检查（`cargo fmt --check`、`cargo check --locked`、`cargo clippy --all-targets --all-features --locked -- -D warnings`），不只 `cargo test`。

| 创建 Issue：选中含配置仓的成员 | 该成员行「未纳入代码搜索，可修改配置或文档」（`{code, message_zh}`） | 复选与提交照旧；满足原准入即可只选该仓提交 | REQ-MRE-01 |
| 创建 Issue：所选成员均无提示 | 不出现任何标注 | 复选与提交照旧 | REQ-MRE-01 |
| 创建 Issue：当前 LC 无已验收索引记录 / 切换 LC | 不出现任何标注（不猜）；切换后立即清除上一 LC 标注 | 复选与提交照旧 | REQ-MRE-01 |

## 5. UI 验收用例（可勾选）

| 编号 | 用例 | 期望结果 |
|---|---|---|
| UA-01 | 混合逻辑代码库（有源码仓 + 只有配置的成员仓）点「重建索引」 | 索引可用；源码仓符号可搜到；卡片出现一行点名被跳过的配置仓 |
| UA-02 | 令源码仓在普通路径有源码却未被收录后重建 | 失败，失败面点名该仓并说明「磁盘上有源码但索引未收录」；不发布新索引；不出现跳过提示 |
| UA-03 | 让某成员目录不可读（或盘检超限）后重建 | 失败，失败面点名无法确认的成员且**不**说它没有源码 |
| UA-04 | 所有成员都没有源码时重建 | 失败并提示「没有可建立代码索引的源码」；不出现空索引成功（同一夹具若盘上有源码则必须是覆盖失败码，不得复用全员无源码码） |
| UA-05 | 索引 active 且含跳过成员时打开创建 Issue 选成员 | 该成员行有「未纳入代码搜索，可修改配置或文档」；可勾选、可提交 |
| UA-06 | 切换到另一个没有跳过记录（或记录不匹配）的逻辑代码库 | 标注**立即**消失（不等新请求返回）；上一逻辑代码库的提示与成员不得残留 |
| UA-07 | 只选配置仓创建一个 Issue | Issue 创建成功；目标仓即该配置仓；进入规划时该目标仍有可用指纹，巡检无悬挂引用 |
| UA-08 | 对上一 Issue 生成 Story | 生成前先更新共享索引；AI 启动时索引已是最新；同一 LC 的第二个 Issue 复用同一份索引（不新建世代） |
| UA-09 | 源码仓改一个函数名不提交，再次生成 Story | 生成前完成同步，索引能查到当次的新名字；再改一次仍不提交 → 再次同步后仍能查到 |
| UA-10 | 让索引更新失败后再次生成 Story | 生成停在 AI 启动之前，失败面给出稳定码与三段中文（不是通用 500）；已有 Story 保留；不拿旧索引冒充最新 |
| UA-11 | 打开创建入口 / 登记入口 / 聚合初始化卡片 | 三处呈现同一份目录说明与范围口径；既有操作可用 |
| UA-12 | 复核配置修改类执行（**补充证据，可后置**） | 配置仓工作区内配置文件的值确实被改掉；该次执行未发起 CodeGraph 证据查询 |

**证据口径**：截图只证界面。链路结论必须另有可观测证据——`只选配置仓仍进入规划` 看规划快照里该成员的指纹与巡检结果；`非生成操作零刷新` 看索引世代 `updated_at`/世代 ID 未变；`同 LC 两 Issue 共享` 看两处 planning snapshot 的 `aggregate_index_id` 相同；`脏工作区连续两次改名` 看两次同步后的查询结果；`记录与库要分开`——验收前 `sync` 已改动实际库，不能用「记录未被替换」冒充「上次可用索引仍可查询」，要用隔离 LC 记录失败前后可读性。
