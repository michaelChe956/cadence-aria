## 1. 后端工作包

### [ ] T01 · 交叉验收与有界盘检（独立）
映射：REQ-IND-01、REQ-LAYOUT-01。

- 在**聚合索引唯一验收入口**里，把「成员未被收录」与「成员没有源码」分开：先做逐成员覆盖判定，再只对未覆盖成员做有界盘检。
- 盘检只按后缀做元数据判定：Aria 自有源码类型清单（**必须是 CodeGraph 支持后缀的真子集**，具体清单用真实 CodeGraph 逐后缀黑盒探针在实施时验证后确定）。
- 复用既有内建排除口径，`.worktrees/` 作为独立第二段诊断；不模拟 `.gitignore`；不跟随符号链接。
- 盘检有界且可注入时钟/取消信号，测试不得依赖真实 sleep；超限/超时/权限不足必须落到「无法确认」。
- 验收要点：混合 LC 判通过并记跳过事实；普通路径有源码 → 漏收失败码；仅 `.worktrees/` 有源码 → 专属失败码；无法确认 → 专属失败码；全员无源码 → 专属失败码；任一失败都不发布新 active；排除负查询与代表性检索的既有口径不放松。

### [ ] T02 · 跳过事实的 durable 记录与向前兼容（依赖 T01）
映射：REQ-IND-06、REQ-IND-04。

- 成员快照新增**可选**的跳过标记（值：已确认无源码）；成员快照既有的 `included` 语义保持不变，被跳过的成员仍在快照里。
- 记录形状**没有版本号**，兼容只能靠 serde 缺省：老记录（无该字段）必须可读，缺省值不得被投影成跳过证据。
- 只有验收成功的世代才写跳过事实；失败世代不写，last-known-good 保持它自己那一代的事实。
- 验收要点：老 JSON 读取无警告；混合世代往返一致；失败世代不产生跳过事实；跳过成员仍参与漂移判据与引用巡检；跳过成员后来出现源码时会被 freshness 重新验收。

### [ ] T03 · 稳定码与文案单一来源登记（可与 T01/T02 并行）
映射：REQ-BOOT-10、REQ-BOOT-11、REQ-LAYOUT-05。

- 在**唯一**文案来源里登记三个新增失败码与一个新增告警码，并给出各自的三段成品与可执行处置。
- 既有覆盖失败码支持两个成品变体，按持久化失败事实的机器事实前缀选择；新旧变体都登记在同一张表里，不另建文案表。
- 告警码以独立轻量成品登记：不占失败五字段、不分配分诊、不触发失败通知。
- 验收要点：告警不生成失败面；新增码在冷启动投影与 HTTP copy 上三段完整；旧记录仍渲染旧文案、新事实渲染新文案；既有七个对外码与三段 UI 不回归。

### [ ] T04 · Story 前共享索引刷新三分支（依赖 T01/T02）
映射：REQ-PLN-18、REQ-IND-04。

- 在既有规划前索引检查路径上，把「评估」升级为「评估 → 必要时同步 → 重新验收 → 通过后才启动 AI」。
- 三分支：无索引 ⇒ 首次建库；能确认没变（成员/主工作目录/提交未变，且上次与本次都无未提交修改）⇒ 复用；有变化或不能确认没变 ⇒ 增量同步 + 重新验收。
- 失败 ⇒ 停在 AI 启动之前，说明原因并允许重试，保留已有 Issue/Story/上次成功索引。
- 验收要点：干净且未变时不触发同步；两次都显示有未提交修改时必须同步（revision 相同不算「没变」）；成员或提交变化时同步并重新验收；更新失败时 AI 不启动且旧 Story 保留；创建 Issue、勾选成员、刷新页面不触发刷新；同一逻辑代码库只共享一份索引。

### [ ] T05 · 三处提示与「未检索」证据语义（依赖 T02/T03）
映射：REQ-IND-06、REQ-MRE-01、REQ-COD-05、REQ-LAYOUT-04。

- 聚合索引卡片：从**被投影的那一份可读验收世代**派生一行跳过告警（无记录/旧世代不造告警；降级时与失败三段可并存）。
- 创建 Issue 选成员：同一 LC 的已验收记录 → 逐仓标注；无匹配记录不猜、不按仓名贴标签。
- 跨仓证据：对被跳过的目标不发起 CodeGraph 查询，HTTP 200 + 显式「未检索」（稳定码 + 同源说明 + 零命中审计）；普通目标的结果取授权与已覆盖成员的交集。
- 验收要点：GET 类接口不触发盘检、不启动 CodeGraph/provider；配置目标的证据请求零次 CodeGraph 调用；跳过不冒充查询无命中；提示不改变选仓资格与授权判定。

### [ ] T06 · 入口范围说明（依赖 T03）
映射：REQ-LAYOUT-02。

- 三个入口共用的既有目录说明组件按共用文案改写第六条口径（源码位置、`.worktrees/` 边界、确认无源码的成员可跳过、至少要有一个成员被索引覆盖）。
- **不新建服务端点、不新增只读接口**、不在三个入口各写一份同义文案。
- 验收要点：三处渲染同一份说明；旧的结构示意与既有可操作入口不回归。

## 2. 前端任务（必做，缺此视为交付未完成）

### [ ] T07 · 聚合索引卡片跳过提示
映射：REQ-IND-06、REQ-LAYOUT-04。

- 只消费服务端下发的同源成品文本渲染「已跳过无源码成员：…」一行；不复制三段模板、不自写中文正文、不添新按钮、不着失败色。
- 兼容旧响应（无该字段）时表现不变；失败三段与提示行并存时互不覆盖。

### [ ] T08 · 创建 Issue 选成员逐仓标注
映射：REQ-MRE-01。

- 在成员行渲染服务端下发的标注「未纳入代码搜索，可修改配置或文档」；不额外发起聚合索引请求、不跨逻辑代码库对表、不按名称或仓类型自行推断。
- 有无标注都不改变复选、提交与禁用规则；切换逻辑代码库后标注必须清除。

### [ ] T09 · 三处入口目录说明
映射：REQ-LAYOUT-02。

- 共用组件消费更新后的共用文案，三处入口一致呈现；网络或读取失败时保留目录示意与可操作的原表单，不在前端抄写备用规则。

## 3. 验证工作包

### [ ] T10 · 后端与集成验证
映射：REQ-IND-01、REQ-IND-04、REQ-IND-06、REQ-PLN-18、REQ-MRE-01、REQ-COD-05、REQ-BOOT-10、REQ-BOOT-11。

- 单测：四态判定的每一条分支各有一条断言；盘检限额用注入时钟/取消信号；老记录可读；跳过不改变既有漂移与巡检行为；文案变体按事实前缀选择。
- 集成：真实临时 Git 仓 + 可控 CodeGraph 夹具，覆盖「源码仓 + 配置仓」的冷启动 → 成员提示 → 只选配置仓创建 Issue → 规划拿到该目标指纹；对照「普通路径有源码但覆盖为假」必失败且保留 LKG；全员无源码不 ready。
- 证据链：断言配置目标的 CodeGraph 调用次数为零；普通目标仍返回授权范围内证据；跳过成员不出现在普通目标结果里。
- Story 前刷新：无索引 → 建库；干净未变 → 复用；改一个函数名不提交 → 同步后能查到新名字；再改一次仍不提交 → 再次同步；更新失败 → AI 不启动、旧 Story 保留。

### [ ] T11 · 前端单测与页面验收
映射：REQ-LAYOUT-02、REQ-LAYOUT-04、REQ-MRE-01。

- 组件单测覆盖 T07/T08/T09 的渲染与兼容路径。
- 页面验收用内置浏览器在开发端真实点击（不使用 Playwright）；配置仓目标以真实 provider 在自己的工作区读改配置文件，观察无 CodeGraph 证据查询。

## 4. 状态矩阵（UI 验收基线）

| 场景 | 应显示 | 按钮 / 阻断 | 依据 |
|---|---|---|---|
| 索引 active、无跳过成员 | 既有索引摘要 | 既有「重建索引」 | REQ-IND-01、REQ-LAYOUT-04 |
| 索引 active、有跳过成员 | 摘要下「已跳过无源码成员：…」一行 | 既有「重建索引」；不阻断可用 | REQ-IND-06、REQ-LAYOUT-04 |
| 索引重建中 | 既有加载态 | 重建中仍禁用；不出现跳过提示 | REQ-IND-04 |
| 索引失败（无 last-known-good） | 既有失败三段（问题/原因/怎么做） | 沿用既有重试；不出现跳过提示 | REQ-BOOT-10、REQ-BOOT-11 |
| 索引 degraded（last-known-good 含历史跳过） | 失败三段 + 以「上次可用索引」措辞标注的历史跳过提示 | 既有重建/重试；不伪造 active | REQ-IND-04、REQ-IND-06 |
| 创建 Issue：选中含配置仓的成员 | 该成员行「未纳入代码搜索，可修改配置或文档」 | 复选与提交照旧；满足原准入即可只选该仓提交 | REQ-MRE-01 |
| 创建 Issue：所选成员均无提示 | 不出现任何标注 | 复选与提交照旧 | REQ-MRE-01 |
| 创建 Issue：当前 LC 无已验收索引记录 | 不出现任何标注（不猜） | 复选与提交照旧 | REQ-MRE-01 |
| 创建 / 登记 / 聚合初始化入口 | 目录树 + 同一份共用范围说明 | 既有入口与操作；不加扫描按钮 | REQ-LAYOUT-02 |

## 5. UI 验收用例（可勾选）

| 编号 | 用例 | 期望结果 |
|---|---|---|
| UA-01 | 混合逻辑代码库（有源码仓 + 只有配置的成员仓）点「重建索引」 | 索引可用；源码仓符号可搜到；卡片出现一行点名被跳过的配置仓 |
| UA-02 | 令源码仓在普通路径有源码却未被收录后重建 | 失败，失败面点名该仓并说明「磁盘上有源码但索引未收录」；不发布新索引；不出现跳过提示 |
| UA-03 | 让某成员目录不可读（或盘检超限）后重建 | 失败，失败面点名无法确认的成员且**不**说它没有源码 |
| UA-04 | 所有成员都没有源码时重建 | 失败并提示「没有可建立代码索引的源码」；不出现空索引成功 |
| UA-05 | 索引 active 且含跳过成员时打开创建 Issue 选成员 | 该成员行有「未纳入代码搜索，可修改配置或文档」；可勾选、可提交 |
| UA-06 | 切换到另一个没有跳过记录（或记录不匹配）的逻辑代码库 | 标注消失；上一逻辑代码库的提示不得残留 |
| UA-07 | 只选配置仓创建一个 Issue | Issue 创建成功；目标仓即该配置仓 |
| UA-08 | 对上一 Issue 生成 Story | 生成前先更新共享索引；AI 启动时索引已是最新 |
| UA-09 | 源码仓改一个函数名不提交，再次生成 Story | 生成前完成同步，索引能查到当次的新名字 |
| UA-10 | 让索引更新失败后再次生成 Story | 生成停在 AI 启动之前并说明原因；已有 Story 保留；不拿旧索引冒充最新 |
| UA-11 | 打开创建入口 / 登记入口 / 聚合初始化卡片 | 三处呈现同一份目录说明与范围口径；既有操作可用 |
| UA-12 | 复核配置修改类执行 | 配置仓工作区内配置文件的值确实被改掉；该次执行未发起 CodeGraph 证据查询 |
