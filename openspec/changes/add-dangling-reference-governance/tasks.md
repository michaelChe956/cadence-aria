## 1. 第一步：统一判定能力与读侧容错列举

- [ ] 1.1 交付统一的「目标已删」判定能力：按「记录类型 → 引用字段 → 目标实体类型」的静态表判定引用目标（覆盖九类目标，判定依据为字段名而非 id 前缀）；L1 证据按四条判定（墓碑存在 + 删除阶段为已完成态 + 带完成时间 + 无待人工处置的删除失败事实），删除进行中、缺完成时间或已失败的墓碑不算 L1（归「证据不足 / 删除未完成」，只报不删）；交付「目标类型 → 存在性来源 → 唯一可达上游 → L2 专属可算条件 → 可删证据等级」表作为销账白名单的单一事实源（等级列与 spec REQ-DRG-02 逐行一致），上游无法定义或缺失属正常中间态的类型降级为只报不删。验收：九类目标各自的存在性判定正确——**三态** `Exists` / `Missing` / `Unknown`，U1 四类（checkout / aggregate_index / logical_member / enrollment）在无 LC / project-issue 上下文的判定面 MUST 报 `Unknown`（不可判定），MUST NOT 报 `Missing`；L1 四条任一不成立时不得判 L1；表外记录类型归未归类且不被猜测语义。（REQ-DRG-01、REQ-DRG-02、REQ-DRG-23）
- [ ] 1.2 交付 attempt 目标的两路存在性核对（coding attempt / 规划面 workspace session）：两路都不存在才算目标不存在，任一路命中即判目标仍在。路二 MUST 用**枚举**——遍历状态根下**全部 project × issue** 调 session 列举接口建 id 集合；MUST NOT 使用按 id 单点查询的私有路径查找（跨模块不可见）或带写回副作用的单条会话读取。验收：夹具中引用位命中 coding attempt 时判「仍在」、只命中 workspace session 时判「仍在」、两路皆不命中时判「已删」；活的规划面窗口不得被误判为悬空；巡检前后状态根逐文件不变（无写回副作用）；枚举失败归不可判定而非「不存在」。（REQ-DRG-03、REQ-DRG-21）
- [ ] 1.3 交付旁支记录的容错列举只读 API（自动化 intent 清单、reviewer 窗口清单、reviewer 快照清单、实体身份台账清单）：命中指向已删对象的条目时跳过该条目并产生一条告警，整次列举不失败；intent 清单只枚举两个 intent 文件名，不把 enrollment 记录纳入悬空判定。验收：注入悬空条目的夹具下，四类列举均返回其余条目且各产生恰好一条告警；intent 清单不含 enrollment 记录。（REQ-DRG-03、REQ-DRG-07）
- [ ] 1.4 交付错误分类边界：容错只吞「目标记录不存在」，JSON 解析失败、schema 不符、IO 失败、权限错误一律照旧上抛。验收：注入解析失败与 IO 失败夹具时错误照旧上报而非被跳过，同时主记录缺失仍返回既有错误码与既有文案、既有相关测试保持通过。（REQ-DRG-04、REQ-DRG-05）
- [ ] 1.5 交付 fail-closed 读路径的隔离：窗口租约列举、reviewer 资源物理清理扫描、台账按 owner 反查、实体 scope 准入与墓碑复核、intent 的版本化单条读全部保持既有语义，既有容错列举不注入任何既有读路径内部。验收：对比启用前后这些路径的返回集合与失败语义完全一致，且既有删除与准入相关用例保持通过。（REQ-DRG-06、REQ-DRG-19）

## 2. 第二步：巡检（dry-run，只报不改）

- [ ] 2.1 交付五分区巡检遍历：覆盖 issue 级分区、reviewer 窗口分区、reviewer 快照分区、实体身份台账分区与逻辑代码库 scope 目录（新版子树与旧版别名子树两路都扫），按判据表核对目标是否存在；判据表**点名**登记 intent 的五个授权引用字段（`enrollment_id` / `plan_id` / `session_id` / `source.stories[].id` / `source.designs[].id`）与 enrollment 的**全部引用字段**（顶层 `plan_id` / `session_id` / `source.*`、当前绑定代际 `binding_history.current.*`、历史代 `binding_history.previous[].*` 的 source）。验收：清单给出本次覆盖的记录类型清单，墓碑记录不被判为悬空、不出现在悬空明细中。（REQ-DRG-08、REQ-DRG-09）
- [ ] 2.2 交付巡检清单产出：清单含汇总与明细两节，明细每行含记录路径、记录类型、引用字段、引用目标类型、引用目标 id、已删证据与建议动作；另设「只报不删残留」与「不可判定」两节——**已判定但证据不足的条目归「只报不删残留」，「不可判定」收「读取失败 或 所需存在性数据源 / 作用域不可用（判 `Unknown`）」两类条目**，二者不混列；附可供销账闸门使用的摘要令牌（发现集合 = 判定为悬空的条目，**含「只报不删残留」条目本身**，排除不可判定与未归类条目）；落盘到分析报告目录下按日期命名的分析报告文件。验收：现场清单的记录类型分布与 owner 普查结论一致，未归类项只出现在未归类节而不带删除建议；证据不足项不出现在不可判定节。（REQ-DRG-11、REQ-DRG-22）
- [ ] 2.3 交付 dry-run 的零副作用保证与可复现性：巡检能力不含任何删除入口、不取删除准入锁；同一现场连续两次巡检的发现集合规范化序列化逐字节一致（清单正文含巡检时间，不要求整份一致）。验收：巡检前后状态根内全部文件逐文件保持不变；两次巡检的令牌相同。（REQ-DRG-10、REQ-DRG-22）
- [ ] 2.4 交付巡检的「不可判定」隔离：目标核对因读取失败**或所需存在性数据源 / 作用域不可用（判 `Unknown`）**而无法完成判定时计入独立的不可判定计数，不计入悬空数、不计入归零，并在清单中逐条列出失败原因；**巡检自身扫描到的记录解析失败、分区目录不可读同样计入不可判定**，不得静默跳过。验收：注入读失败夹具时该条出现在不可判定节、悬空计数不变；注入坏记录 / 不可读分区夹具时同样出现在不可判定节；U1 四类在无 LC / project-issue 上下文时判 `Unknown` 并进不可判定节且令牌不变；存在不可判定条目时系统不宣称归零。（REQ-DRG-17、REQ-DRG-23）

## 3. 第三步：按类型自动销账

- [ ] 3.1 交付销账规则表与白名单执行：自动化 intent 在 story/design/plan 具备 L1 证据且满足四道前置条件时删除、reviewer 窗口与其租约/违规记录/快照在 attempt 两路皆无且窗口四条件成立时一并删除（**按 attempt 聚合：该 attempt 名下全部窗口含归档都满足才删，任一不满足则一个都不删**）、实体身份台账条目在 work item plan 具备 L1 证据时删除；实体删除墓碑永不删除，用户业务数据（正文、版本历史、产物）永不删除，**不具备 L1 证据且不满足该类型 L2 专属可算条件**的旁支记录一律只报不删。验收：墓碑目录与用户业务数据目录在清理前后逐文件保持不变；无墓碑的台账条目与缺证据的 intent 在清理前后保持不变；同一 attempt 下一个窗口持租约时该 attempt 全部窗口均不被删。（REQ-DRG-12、REQ-DRG-14、REQ-DRG-19）
- [ ] 3.2 交付 intent 销账的四道前置条件：在 enrollment 文件锁内删除、**锁内重读三项**（enrollment 状态——仍启用一律不删、已终止以 `terminated_at` 有值为准且身份不一致不删；generation intent 相位；L1 墓碑证据）、只认 L1 证据（session 与授权引用缺失不构成依据）、generation intent 相位必须为「已认领且未派发」。验收：enrollment 仍启用 / 仅禁用未终止 / 身份不匹配 / 相位已派发 / 相位在锁内已推进 / 墓碑在锁内已变化六类夹具下 intent 均不被删；与既有取代路径并发时取代侧不报失败。（REQ-DRG-20）
- [ ] 3.3 交付闸 1 与闸 2：**闸 1 为自动模式**——销账在服务启动时自动执行，**无人工确认令牌环节**，删除判据 = 白名单类型 + 证据达标（不得比 REQ-DRG-12 更宽）；销账只作用于规则表列举的记录类型。验收：自动模式在证据达标时按白名单删除、无需任何令牌；证据不足或表外记录一律只报不删且清理前后保持不变；幂等 + 留痕 + 自证归零语义不变。（REQ-DRG-13、REQ-DRG-14、REQ-DRG-22）
- [ ] 3.4 交付闸 3 的幂等与留痕：每一步清理以「缺失=已清」为幂等语义（**只用于重入，MUST NOT 替代 enrollment 文件锁语义**）；每次清理在**状态根下单一全局**的追加式 JSONL 台账留一行（何时、因哪个实体被删、清了哪条、依据的证据等级），行形态沿用既有追加式审计行规范，**MUST NOT 写入 issue 级墓碑目录、MUST NOT 扩展 `DeletionEntityKind`**；同一清理动作重复执行不追加重复行。验收：以同一令牌连续执行两次，第二次删除数为零、留痕无重复行、无报错；台账落点为单一全局文件而非每 issue 一份。（REQ-DRG-15、REQ-DRG-16）
- [ ] 3.5 交付闸 3 的自证归零：清理完成后自动再巡检一次，归零计数只统计销账白名单内且本次可删的类型，「只报不删残留」与「不可判定」各自单列且不参与归零断言。验收：已清理类型的归零计数为零；存在未归零可删项或任一不可判定项时明确逐条列出且不宣称治理完成。（REQ-DRG-17、REQ-DRG-23）
