# 处理边界

## 决策

1. 覆盖探针（含既有 SDK→CLI 回退）完成后才启动整批盘检的单调时钟；不按成员反复重置，不把 Unknown 当作 NoSource，也不全局放宽时间。预算、实际枚举起点、失败与覆盖缺键分别可辨。保留负向查询、Story 与既有 LKG 行为。
2. 世代 JSON 只加可选 `source_scan` 结构化诊断（成功和验收失败均可记录），只写本次世代；缺字段表示没有证据，不能补推耗时。成员是不可见清单中的成员，记录短名、结论、有限枚举原因和是否实际开始取可见文件。阶段耗时来自单调钟；输出清单截断不能成为无源码证据。诊断不改选仓、发布或授权。
3. 告警与三段文案继续使用同一稳定码/同源文案表。只有实际测得的预算耗尽才选预算文案，混合原因不得冒充同一原因。失败 POST 的同步原因与卡片 GET 各有职责，补取后者不吞前者；旧请求不能污染新 LC。
4. 人工批准日志包仅增加受限的索引世代诊断投影：保留世代 ID、状态、版本/时间、可识别失败码/失败类型、白名单结构化扫描证据；不复制任意 warning、绝对仓路径、源码、命令或快照正文。沿用安全目录遍历、预算、manifest 和四家各最近最多 3 个原生会话。Pi 复用启动侧已有环境覆盖数据，不为导出探测/执行 provider 或搜索无关宿主目录；空目录与无法识别的候选分别记录。

## 验证约束

仅用本地确定性构造，不重跑客户环境；单元、前端组件、审查，未做的端到端/现场验证不宣称通过。客户 JSON、日志与完整路径不入库。
